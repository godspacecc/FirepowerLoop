## Spec 核对

- 时间与资格：AdvanceEnchantments 先积时再比较周期、保留余数，4 秒前无授予；源与目标均排除死亡/爬出态，按实体 ID 排除自身，6 米平方距离包含边界；其他支持者可接收。主循环的暂停、选卡、非 Playing 和结算门禁在调用之前，任务模式不推进。出范围不会删除既授状态；源死后不再被遍历或被生命门禁排除。
- 生命：出生路径先保存基础值，GrantEnchantment 按基础值和累计层数线性计算；同帧多源逐次限制 5 层，补血只加本次 MaxHealth 差额。伤者原有缺血不被额外补齐；到顶分支不会再次补血。用 double 计算、int.MaxValue 饱和及 long 当前血量加法，不发生该路径整型溢出。
- 速度：基础速度单独保存，不反乘当前速度；5 层后为基础速度 150%。现有 ElementMovementSeconds 仍折算移动时间，TickEnemies 将附魔后的速度乘该时间，未覆盖冰霜状态或绕过既有爬出、抓挠停步规则。结果经 float.MaxValue 饱和。
- 盾：附魔盾保存当前量，补充按 cap 限制且没有永久授予次数；ShieldDamage 在原生盾前消费附魔盾并返回 0，因此破盾当次不会穿透原生盾/生命。随后攻击才处理原生盾。ProjectEnchantment 与 ProjectSpecialEnemy 只读当前状态，没有从完整投影重置盾；附魔不会使已破实体盾恢复。
- 清理与金币：唯一常规伤害死亡事务在 TryDropGold 后删除附魔状态，自毁及 Stop 也清理；出生复用身份不带旧层数。金币使用出生基础最大生命，权威 survivor_rule 的 GoldDropMultiplier 仍为 0.01，其余掉落入口未改变。
- 配置：survivor_enemy 第一 Id 列及 TbSurvivorEnemy 的 Id 主键保持；新增三身份、七字段来自 Config 权威源，客户端/服务端生成字段顺序一致。六档权重合计均 100，360 秒起各 3%，未改出生预算。HP80、速度1.76及出现比例是实施默认，不能写成用户指定参数。

## Quality 与验证边界

状态与周期留在既有 SurvivorSystem 生命周期中，View 仅接收不可变完整快照和脉冲通知；未引入新 Update 或通用 buff 框架。死亡、Stop、自毁和两条实际出生路径均接入专用状态。坏配置在 SurvivorEnemyDefinition 构造边界拒绝，附魔周期拒绝非有限数及非正值；没有用运行层硬编码副本绕过权威配置。

既有附魔测试大部分通过反射直接推进专用规则；暂停测试确实走 TickFrame 的暂停门禁，但不等于已经跑通整段开局/移动/攻击生命周期。金币用例验证出生基础值查询，不是统计实际金币掉落。上述接线同时以实际调用方源码核查，未发现错误；阶段 B 完整准备、运行及视觉验证仍须单列。
