# FirepowerLoop Luban 配置

`Config/` 是客户端和服务端 Luban 配置的唯一权威源。

设置界面新增文案以 `Localization/settings-visuals.json` 为权威源；`gen.bat` 完成双端生成后调用 `publish-localization.ps1`，仅发布其中声明的键到客户端两种语言 JSON，其它历史文案保留。

- Schema：`Defines/*.xml`
- 数据：`DataCsv/*.csv`
- 目标与组：`luban.conf`
- 唯一正式生成入口：`Config\gen.bat`

从仓库根目录运行 `Config\gen.bat`，一次生成、校验并发布双端产物。生成文件不能手改；服务端配置变化后须重启本项目服务器。

| 目标 | 生成 C# | 生成 bytes | 表数 |
| --- | --- | --- | --- |
| 客户端 | `Client/Assets/Game/Scripts/Model/Config/` | `Client/Assets/Game/Config/` | 31 |
| 服务端 | `Server/GameServer/Runtime/Model/Generated/Config/` | `Server/GameServer/Config/Luban/` | 25 |

共 37 张源表。`c` 组提供客户端共用物品、武器、表现、地图、出生点、玩家、掉落与诊断命令；`e` 组提供 17 张双端街机规则表及敌人与投射物配置；`s` 组保留 6 张服务器基础设施表。基地、远征、撤离、制造、文明、临时建筑和开放世界配置已移除，服务器启动表不再启动 OnlineWorld。

`arcade_round_layout.Barrels` 复用入口点坐标格式 `x|y;x|y`，为空表示本图没有预置可射桶。当前仅 Barrage（配置 3）四图各有两个，数组零基索引与地图 ID、Version 共同确定桶身份；该主题布局版本为 2，其余主题仍为 1。桶位由共享参数校验有限数、地标和障碍重叠，并按实际场地尺寸验证可达性。

漩涡桶使用同表的 `BarrelDropSeconds=5`、`BarrelPullRadius=12`、`BarrelPullSpeed=2.5`、`BarrelHealth=40`。载桶敌人按活动战斗中的出生年龄放一次桶，随后成为普通敌人；受控停步不暂停倒计时。提前击杀保留敌人范围爆炸，卸桶后死亡不再爆炸。预置桶和动态落地桶均吸引范围内已落地物资，吞入后删除，不计拾取、不发奖励，炸桶也不返还。未打开的武器空投不被吸取；暂停、清场、切图和全员奖励房冻结。桶耐久归零后只伤敌人，玩家免受桶及载体爆炸伤害。动态桶、剩余耐久与吞物状态属于当前地图现场，沿用轮前回滚，不独立写入存档；预置桶已毁索引沿用既有恢复合同。以上数值为项目参数，不代表参考游戏原始数值。

正式休闲海岛四轮使用固定布局：中央约30×30米保持干燥畅通；山脚实体阻挡在外围，每图三条通道同时作为入场与清场出口。第一轮东海岸、第二轮东南海岸并从停船码头进敌、第三轮西海岸、第四轮南海岸。`arcade_round_layout.EntrySegmentSeconds=12` 表示每段活动战斗秒数，单双人分别从共享随机规则独立抽取当前通道，允许连续抽中相同方向，不按出生预算轮换，不增加方向预告、箭头或声音。暂停、资源准备、复活、奖励区域和清场等待不推进通道计划。

`arcade_arena.EnemySeaApproachDistance` 保留旧顺序模式的深海接近距离；配置1为6米，其余为0。正式海岛借此限定通道外生成距离为 `min(4, distance×0.67)`，当前为场地边界外4米，三条车道偏移共不超过±0.9米；生成后连续追向玩家，不能在活动区直接出现。第二轮木板船梯按干地行走。海上攻击仍按距离与冷却裁决，敌人死亡掉落投影回玩家可达岸内。

`arcade_round_layout.WeaponSpawnPoints` 使用相同的 `x|y;x|y` 坐标格式；80 张正式轮地图各配置 6 个固定候选点，`WeaponSpawnCount=2`。普通轮开始时无放回抽取本轮点位，随后逐把生成：首把按 `WeaponSpawnFirstDelayMin=3`、`WeaponSpawnFirstDelayMax=8` 秒等待，后续每把在上一把实际投放后按 `WeaponSpawnDelayMin=20`、`WeaponSpawnDelayMax=30` 活动秒重新等待，正常第二把约在开战后23～38秒投放。单次推进最多生成一把，大步长不追赶连发。按 `arcade_drop` 中当前进度可用的临时武器权重选枪，复用原拾取、地面寿命及总数量预算；预算满则保留待刷点位，解除阻塞后投放一把，再为下一把完整计时。暂停、切图、奖励房和清场冻结时钟。单人由战斗系统推进，双人由服务器通过相同的共享规则统一推进并同步掉落，挑战及独立 Boss 不额外刷枪。点位参与地图连通性校验；每轮仍只计划两把，不无限补刷。

头骨强化复用 `arcade_powerup` 的 `WeaponSkull`：小头骨倍率 2（红弹），大头骨倍率 3（紫弹），伤害和射速同时增强；两者均为本项目首版 20 秒，进入普通击杀掉落池，不是原作精确持续时间。紫级拾取小头骨只刷新时长，重复拾取不叠乘；换成其他武器或临时武器到期清除，同枪补时保留。时钟在单双人开火前推进，暂停不扣、清场等待仍扣。弹丸保留发射时层级，敌弹和支援不继承；轮级恢复保留原剩余量，不重新领取。

`arcade_drop.EnemyMinArena` 和客户端专用 `arcade_solo_drop.EnemyMinArena` 仅约束杀敌掉落：0 表示完全禁用击杀来源，正数与 `MinArena/MaxArena` 共同限制开放关卡，负数非法。所有关卡杀敌仅掉金条、红头骨和紫头骨，权重为 38:5:2，总掉落概率仍为 32%。炸弹、冲刺、临时武器、其他强化及第一人称道具的击杀来源均关闭，配置身份、资源和原权重保留供独立来源使用。地图空投和宝箱不检查该字段，继续按原解锁范围生成。2026-10-20：`ArcadeEnemyDropTests` 定向24项、`MapWeaponPickupsOnline` 定向7项通过，覆盖第1／2／6／12／20关真实击杀、普通／首领一次结算、80张轮地图空投与宝箱出枪，以及服务端拒绝负数配置。

地图刷枪使用空投箱：`arcade_rule.WeaponDeliverySeconds=1.2` 秒，前 75% 从空中落到点位，后 25% 自动开盖并显示武器；开箱完成后才可拾取，30 秒地面存留从此开始。单双人分别由本地战斗系统和服务器计时，联机快照保留空投标记及剩余时间，表现按权威进度采样。宝箱等非空投来源的武器仍立即落地可拾取；空投外观和时长是本项目需求，不作为参考游戏规则结论。

`map.firepowerloop.arcade` 是保留的稳定地图 ID，仍指向 `TaskSampleMap`。`map_scene_part` 与 `map_display` 保留空表以维持共用地图适配契约。历史地图图片及图标资源保留，不由 Luban 生成。旧地图资料生成工具已移除。

`arcade_solo_drop` 仅面向客户端，保留第一场临时第一人称的权重 5、持续 20 秒配置；服务端不生成此表。街机宝藏、装备、强化道具、金币、挑战及单人/双人规则保留。商店及交易已移除：`arcade_shop_item` 由仅含支援视觉身份、地址与偏移的 `arcade_support_visual` 替代；`arcade_upgrade` 只用于本项目旧局已持有效果的恢复，不提供新获取入口。`arcade_reward` 为现有街机目录契约保留空表，已去除 scrap/core/token 局外奖励行，不提供成长钱包。

发布阶段先读取旧版生成 `Tables.cs` 实际登记的加载名，仅删除这些名称中不再生成的 bytes；C# 仅清除带 `<auto-generated>` 标记的过时源码。现有 Unity `.meta` 与目录中的无关资源均保留。相同产物按内容散列跳过覆盖，避免不必要的 Unity 重导入。

新商店的权威源为 arcade_slayermart_item（24项）、arcade_slayermart_region（第11/31轮后区域）和 arcade_slayermart_ability（能力参数）。release.enabled=0 保持正式入口关闭，只有全部能力与接线就绪才开启；不恢复旧商品表。

`arcade_slayer_challenge` 是首批完整Slayer挑战及Guardian参数权威表，引用独立挑战身份与现有金币表现；规则1主线第12轮后才提供一次机会，不改变商店 release.enabled 门禁。

`arcade_treasure_room.Enabled` 控制奖励房入口和进入流程。第一关 `arcade.treasure.first=false`，第二场军械库 `arcade.armory.second=true`；关闭的房间仍保留普通财宝计分、倍率和加命所需参数。单人和双人均只等待实际启用的房间，第一关第三轮清场后直接开放普通出口。
