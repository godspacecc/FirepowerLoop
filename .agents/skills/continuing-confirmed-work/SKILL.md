# 持续完成已确认任务

完整确认范围决定任务何时完成。批次用于组织工作，不能自行缩小用户的总目标。本技能补充实施技能，不代替项目的预览、验证、提交和权限规则，也不授权新功能。

## 恢复完整范围

开工、继续、上下文压缩恢复、新会话接续时，读取项目总清单及它引用的确认记录。FirepowerLoop 的入口是仓库根目录下 `Docs/Plans/执行总清单.md`；其他项目沿用已有进度文档，不重复建账。缺少总清单时先从确认记录建立，冲突以用户最新明确指令为准。

每项至少记录：用户确认的目标、具体视觉是否确认、实施与验证证据、剩余工作／真实阻塞。不以摘要、子计划勾选或上次“本批完成”报告代替这些证据。

## 逐批推进

1. 选择下一项已确认且依赖满足的工作，按适用实施技能完成和验证。
2. 同步更新总清单，再选择下一项；进度汇报、子计划完成和提交成功都不是等待用户再次说“继续”的理由。
3. 视觉预览待确认时，只暂停依赖该确认的正式视觉工作；准备可查看的预览，同时继续独立的已授权功能。
4. 确有阻塞时记录缺少的决定／外部条件、受影响范围、准备好的结果和解除条件。不能用“后续再做”“本批不做”把已确认项从总清单移除。
5. 用户询问进度或纠正执行方式时，先简短回答再继续原目标。用户明确停止、暂停或替换目标时，遵从最新指令并记录接续点。

## 结束前检查

对照完整总清单核验剩余项，然后按下表行动。检查的是全部已确认目标，不仅是当前子计划。

| 当前状态 | 下一步 |
| --- | --- |
| 还有可执行的已确认工作 | 继续执行，不交回局部完成报告结束任务 |
| 某项受阻，但其他已确认工作能独立推进 | 记录局部阻塞并继续其他项 |
| 所有剩余项均有真实阻塞，且没有独立工作可推进 | 展示准备好的结果，说明具体所需决定／条件，等待回复 |
| 全部已确认项均有交付与验证证据 | 按项目规则收尾，才能报告总目标完成 |
| 用户明确要求停止或暂停 | 停止，保存已完成、未完成及接续点 |

收尾说明应简明区分本批完成、总目标是否完成、剩余已确认项、真正待确认项。测试数量和提交记录只能证明对应交付，不能证明范围完整。

## 容易误判的理由

| 理由 | 应如何裁定 |
| --- | --- |
| 子计划全部打勾了 | 回到总清单检查尚未纳入该批的已确认项 |
| 未确认的先不做 | 只排除未确认部分，其余已确认工作继续 |
| 一个功能还缺视觉确认 | 检查依赖，独立规则和其他功能继续 |
| 用户问了原因 | 回答问题，保留原目标；提问不等于取消任务 |

例如：地图已交付，掉率已确认可独立修改，无人机外观待预览。下一步应执行掉率、准备无人机预览，并推进不依赖外观的无人机规则；不能因地图批次完成或无人机外观待确认而整体停工。
