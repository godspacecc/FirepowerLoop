# Android 渠道候选包与已有 APK 检查

本工具用于国内 Unity 手游客户端发布实践。内部测试包与渠道候选包共用现有完整内置资源构建链路，签名和检查策略分别执行。

首发采用纯离线单机路线，完整行为与验证见[单机首发模式](../../Docs/发布准备/单机首发模式与验证-20261021.md)。下文的公网条件只适用于联网渠道候选。

项目当前禁止触发 Unity 打包或 Player Build；本次只实施入口和执行已有包只读检查、限定 EditMode 测试。以下真实构建操作须在该约束明确调整后使用。

## 只检查已有 APK

Unity 菜单：

- 内部测试APK的单独检查菜单已移除；底层检查能力及打包流程中的自动校验保留。
- `Tools/打包/Android/渠道发行/检查渠道包`。
- `Tools/打包/Android/渠道发行/检查单机包`。

检查渠道包默认从Client/Build/Android选择APK（目录不存在则打开现存父目录），自动保存到Backup/Artifacts/AndroidChannelInspection-<时间>-<随机标识>/channel-apk-check.json；完成后弹窗显示通过或未通过及报告位置，可打开报告位置。纯离线检查仍手选APK及新的JSON报告路径。检查器调用当前 Unity 安装附带的 aapt 和 apksigner，读取实际包名、版本、SDK、架构、权限、调试标志、证书、SHA-256 及三个启动配置。不会安装、重新签名或运行 APK，不会改 PlayerSettings。

报告包含 `profile`、`passed`、逐项 `checks`、实际 `facts`、`deviceVerified=false`、`storeApproved=false`。报告路径已存在时拒绝覆盖；不要将输出路径指定为 APK。报告中的 `passed` 只代表对应模式的技术检查结果。

内部测试模式允许 Development、测试证书和内网地址，但实际签名必须符合项目现有 `Server/ResourceServer/android-signing.json`。渠道模式要求显式证书、非调试 APK、ARM64、有效应用身份、外部服务地址及明确诊断配置。没有提供渠道公开证书策略时，该项会标为失败，不会默认信任包内任意证书。

纯离线模式要求同样的正式签名及非调试身份，另要求实际清单包含离线标记且没有 INTERNET、REQUEST_INSTALL_PACKAGES；不校验公网资源、网关或诊断地址。

公网检查只做主机和协议的字面校验，不进行 DNS、服务连通、TLS 证书或服务器身份验证。域名不是内网格式不代表已经部署。带 `REQUEST_INSTALL_PACKAGES` 的包会额外产生人工复核警告；该渠道是否允许自有安装更新，需要随渠道接入方案确认。

## 渠道签名准备

本机已于 2026-10-21 配置独立正式签名，实际文件位置、公开指纹及备份事项见 [正式签名配置记录](正式签名配置记录.md)。以下是换机器或自行管理配置时使用的通用说明。

渠道入口只读取两个显式环境变量，值必须是已存在文件的绝对路径：

```powershell
$env:FIREPOWER_ANDROID_CHANNEL_SIGNING_CONFIG = 'D:\Private\FirepowerLoop\channel-signing.local.json'
$env:FIREPOWER_ANDROID_CHANNEL_SIGNING_POLICY = 'D:\Private\FirepowerLoop\channel-signing-policy.json'
```

示例路径需要替换为本机实际配置；设置环境变量不会创建文件。Unity 进程需要能够读取这些环境变量，启动前设置只对随后启动的进程生效。

私钥配置格式与 [现有固定签名说明](README.md) 相同，包含 `keystorePath`、`keyAlias`、`keystorePassword` 和 `keyPassword`。相对 keystorePath 相对于私钥配置文件解析。渠道私钥及密码应由其所有者单独提供并保管，不复制到客户端、资源包或检查报告。

公开证书策略包含 `schemaVersion=1` 和真实的 `certificateSha256`。策略中的证书必须与提供的私钥以及最终 APK 一致；内部测试证书不能作为渠道构建证书。工具不会生成密钥、替换历史签名或修改测试白名单。

## 构建前需要完成的环境配置

联网渠道候选的启动配置必须满足：

| 文件 | 渠道条件 |
| --- | --- |
| hostConfig.json | resourceServer 为公网 HTTPS URL，不携带用户名、密码或片段 |
| networkConfig.json | gameGateEndpoint 为公网主机和显式端口 |
| diagnosticConfig.json | mode 为 Fixed，reportUrl 为公网 HTTPS URL |

配置继续遵守项目权威源与生成规则；此功能不改任何配置源或生成输出，也不填入虚构域名。公网诊断地址配置不代表已经完成隐私同意机制，相关接入仍需独立实施。

## 后续允许构建时的入口

纯离线首发使用 `Tools/打包/Android/渠道发行/打单机包`，对应 `Game.Editor.AndroidBuildUtility.BuildOfflineSinglePlayerCandidateBatch`。预检只要求独立正式签名；完整内置资源、本次 Player 编译标记、统计关闭作用域及生成清单处理共同形成离线候选，最终写入 `offline-apk-check.json`。不会启动服务器；当前工程禁止打包，尚未执行此入口。

`Tools/打包/Android/渠道发行/渠道打包` 对应 `Game.Editor.AndroidBuildUtility.BuildChannelCandidateBatch`。联网渠道候选同样先在线更新，失败回退缓存或内置资源；只有专用纯离线单机候选强制内置启动。

1. 在切换平台、创建输出和分配版本前，校验显式签名及外部服务配置。
2. 复用现有 HybridCLR、完整内置资源、版本预留和构建互斥。
3. 在构建作用域内关闭 Development、脚本调试及自动连接 Profiler；结束或异常后恢复原编辑器选项及签名设置。
4. 生成 APK 后检查实际产物，将联网报告保存于Backup/Artifacts/AndroidChannelBuild-<批次>/channel-apk-check.json；单机报告保存于Backup/Artifacts/AndroidSinglePlayerBuild-<批次>/offline-apk-check.json。
5. 技术检查未通过时保留已生成并验签的 APK 与报告；不创建“平台审核通过”状态。
6. 渠道分支只生成候选包，不发布内部资源服、不启动服务器，也不提交商店。

渠道入口不使用旧快速复用包或 Host 更新路由。现有 CI 四路由仍用于原流程，本轮没有扩展 CI 参数或部署 Jenkins。

## 验证边界

限定测试类为 `AndroidChannelBuildTests`；相关内部流程回归为 `AndroidHostBuildTests` 与 `AndroidSigningTests`。实际运行必须声明真实短类或完整方法、最大数量及 `includePassingTests=true`，不得运行完整套件或在空过滤时回退。

真实候选包构建、正式私钥应用、跨平台构建恢复、手机安装、存档升级、隐私机制及平台审核保持单列待验。发布学习记录见 [发布准备目录](../../Docs/发布准备/README.md)。
