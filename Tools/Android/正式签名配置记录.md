# FirepowerLoop 正式签名本机配置

2026-10-21 已按用户要求生成独立发布密钥，并接入现有渠道候选入口。此记录说明本机配置状态，不代表已经生成渠道 APK 或完成商店审核。

## 私钥、密码、证书和签名的关系

| 名称 | 用途 | 本项目对应 |
| --- | --- | --- |
| 私钥 | 对 APK 内容生成数字签名，是持续发布更新需要保留的核心秘密 | 存在正式 keystore 内，不能从公开证书恢复 |
| 密钥库 keystore | 保存私钥和对应证书的容器，可包含多个条目 | `FirepowerLoop-release.keystore`，当前为 JKS 格式 |
| 密钥库密码 | 打开、校验密钥库时使用 | 本地配置的 `keystorePassword` |
| 私钥密码 | 解锁所选私钥，用于实际签名 | 本地配置的 `keyPassword`；本次两种密码分别随机生成 |
| 别名 alias | 指定使用密钥库中的哪个条目 | `keyAlias=firepowerloop-release`；同名别名不保证是同一把私钥 |
| 公钥证书 | 携带公钥，供外部验证签名，可公开 | `FirepowerLoop-channel-certificate.pem`；APK 也携带签名所需的证书信息 |
| APK 数字签名 | 使用私钥针对包内容计算的结果，随签名 APK 一起分发 | 当前尚未用正式私钥签写游戏 APK；内容发生变化后需要重新签名 |
| 证书指纹 | 证书的哈希摘要，用于比对签名身份 | `channel-signing-policy.json` 中的 `certificateSha256`，不是密码 |

构建时，工具按配置找到 keystore，用别名选中密钥条目、用密码解锁，再用私钥给 APK 签名。手机安装时使用 APK 中的公钥证书验证签名，无需获得你的私钥或密码。[Android 官方签名说明](https://developer.android.com/studio/publish/app-signing?hl=zh-cn)

密码保护的是密钥的存储与使用权限；修改密码并不会自动换掉私钥。私钥与证书保持不变时，证书指纹也保持不变。另一个检查字段“APK SHA-256”针对整个包，内容改变后通常会变化，不能拿它代替证书指纹来判断签名身份。

本项目的检查器用公开证书策略核对实际签名，配置本身不能代替签名操作。常规同包名覆盖更新要求签名身份兼容；如更换密钥，需要考虑平台支持的密钥轮换机制。签名提供完整性及密钥身份验证，游戏内容不会因此变成加密数据，证书里的项目名称也不代表公司资质认证。

## 已接入的环境

当前已打开的 Unity 进程及 Windows 用户 `78176` 的用户级环境变量均已配置为：

```text
FIREPOWER_ANDROID_CHANNEL_SIGNING_CONFIG=F:\GitHub\FirepowerLoop\Tools\Android\PrivateSigning.local\channel-signing.local.json
FIREPOWER_ANDROID_CHANNEL_SIGNING_POLICY=F:\GitHub\FirepowerLoop\Tools\Android\channel-signing-policy.json
```

当前 Unity 无需重启即可读取。以后从长期运行的 Unity Hub 或终端启动编辑器时，应先重启对应的 Hub 或终端，让新进程继承更新后的用户环境。移动仓库目录后需更新这两个绝对路径。

## 备份和换机器

请将整个 `PrivateSigning.local` 目录另行保存到自己控制的安全备份位置；目前只有本机这一份，没有创建异机备份。密码配置与 keystore 都需要保留，普通 Git 拉取不会取得它们。

换机器时恢复这个目录以及公开指纹策略，按 [渠道使用说明](渠道候选包使用说明.md) 设置两个环境变量。后续更新应继续使用这份密钥，不要重新生成来替代。现有测试 APK 使用另一份证书，不能直接当作正式签名覆盖升级的验收依据。
