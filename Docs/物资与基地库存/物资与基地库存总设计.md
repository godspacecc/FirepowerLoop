# 物资与基地库存总设计

## 1. 已完成内容

### 正式物品与配置来源

- 内容：当前正式物品包括金属零件、布料、急救包、口粮、短剑、弓和箭矢，全部使用稳定字符串 `ItemId`。
- 目的：让世界掉落、背包、仓库、存档和使用效果共享同一物品身份。
- 修改简介：
  - `TbItem` 保存名称、说明、本地化 Key、图标地址、类型、最大堆叠、使用效果和效果数值。
  - 金属零件与布料为最大堆叠 20 的材料；急救包为最大堆叠 5、恢复 30 点生命的消耗品；口粮为最大堆叠 5、恢复 40 点能量的消耗品。
  - 短剑和弓为最大堆叠 1 的武器；箭矢为最大堆叠 20 的弹药。`TbWeapon` 独立保存伤害、攻击间隔、距离、近战角度、投射物和弹药引用，不把战斗数值复制进 `TbItem`。
  - `TbLoot.ItemId` 必须引用有效 `TbItem`；地图静态生成配置与敌人死亡批次共同提供正式物品来源。
  - 模型和存档只保存 `ItemId` 与数量，不复制配置字段。
- 完成时间：2026-07-31；武器和弹药身份于 2026-08-01 补充。

### 单一手持与随身库存

- 已配置的近战和投射武器保留在背包或口袋原格，拿出只改变当前手持引用；收起回到空手，满背包也可收起。仓库和搜索容器中的武器须先进入随身库存。
- `WeaponEquipmentModel` 保存来源容器、格号和物品 ID，运行期绑定库存实例身份；`WeaponEquipmentSystem` 独占拿出、收起和候选循环规则。近战/远程字段仅为既有战斗消费者提供单一当前武器的只读投影，不再储存备用武器。
- 手持来源随成功移动、口袋转移和交换跟随；转出随身库存、失效、同类实例替换或死亡风险清空时收起。重复拿出同一实例和空手收起幂等；失败不发成功事件、不改脏标记。
- 装填数量归实际库存武器实例，随移动、克隆事务和保存恢复；库存回滚后，攻击或装填前重绑实际实例。
- 手持变更清除触屏攻击输入并取消当前持续动作，保留全局武器冷却；Loading、Paused、进入、返回、恢复、失败和死亡状态拒绝操作。
- 本地旧双槽分区与库存一起迁移：武器和旧已装弹药归回背包，格子不足时只追加必需容量，保留原选中武器的手持来源。联机账号库存迁移使用同样守恒规则，新角色使用基础容量；新版入口拒绝旧库存协议。
- 完成时间：2026-10-09；取代 2026-08 的独立双槽储存规则。

### 随身库存与口袋使用（2026-10-12）

- 随身库存统一为背包与四格口袋；地图打开、当前区域地图查找及打开后的携带校验均读取两者，地图转入仓库后失去查看资格，打开地图不消耗道具。
- 玩家与临时建筑装填可以使用口袋弹药；背包优先、口袋补足，各容器按格号取用，取消动作不扣弹药，弹匣提交失败恢复两种容器。
- 制作材料统计包含口袋，扣料顺序为背包、口袋、仓库，产物仍按原背包、仓库、世界溢出路径分配；仓库扩容保持仓库优先，随后背包、口袋补足。
- 建造材料统计与扣除包含口袋，背包优先；表现创建失败恢复两种随身容器，成功创建后才发布库存变更。材料不足或多材料扣除失败不留下部分消耗。
- 库存领域沿用现有脏标记及 SaveSystem 保存机制，不引入每次制作或装填立即写盘；口袋继续在玩家背包保存分区内持久化。自动拾取目标、地图永久解锁消费与联机口袋协议不在本次修改范围。
- 河谷地图道具、地图展示配置和随机地形地图图像尚未补齐，不能把随身地图资格修复当作河谷地图内容已完成。
- 78项定向 EditMode 检查通过；投射类两条现存资源/角色断言失败及未执行的人工验收见 [验证记录](../Plans/随身库存口袋统一使用验证-20261012.md)。

### 共享容器与独立背包仓库

- 内容：玩家背包和基地仓库使用同一套固定格子规则，但保持数据、职责和存档分区独立。
- 目的：避免两套格子规则分叉，同时固定“随身风险物品”和“基地安全物品”的边界。
- 修改简介：
  - `ItemContainer` 支持按低格号补充同类堆叠、使用空格、部分接收、移除、移动、合并、交换、对半拆分、扩容、快照恢复和跨容器原子转移。
  - `PlayerBagModel` 初始容量 12 格，分区为 `another-day.player-bag`，同时保存背包风险状态。
  - `WarehouseModel` 初始容量 40 格，分区为 `another-day.warehouse`，是基地持久物品的唯一权威来源。
  - 两个分区严格校验容量、格号、`ItemId`、数量和重复格号；任一记录损坏时拒绝整个分区。
  - 地图解锁只消耗仓库中的金属零件，背包物品不能直接用于永久消费。
- 完成时间：2026-07-31。

### 正式世界掉落与部分拾取

- 内容：地图静态物资和敌人实体掉落统一读取 `TbLoot`，并按背包剩余空间支持完整或部分拾取。
- 目的：让正式多物品直接进入玩家背包，删除旧测试物资临时计数和撤离自动转仓链。
- 修改简介：
  - `LootModel` 保存当前地图实例中的 `ItemId`、剩余数量、位置和收集状态；`UnitModel` 只保存共同身份与空间状态。
  - `LootSystem` 校验玩家身份、地图实例、活动状态、1.25 米距离、远征状态、风险状态和玩家生命。
  - 敌人死亡动态掉落在领域登记前根据实例根 Trigger Collider 的世界边界自动落到死亡位置代表的地面高度，不依赖固定模型尺寸；地图配置物资仍使用各自配置姿态。
  - 背包先补同物品未满堆叠，再使用空格；零空间不改变世界，部分接收保留并刷新原掉落，完整接收才移除 Unit 和表现。
  - 背包、Loot 和 Unit 使用同一事务边界；移除 Unit 前的异常恢复三方快照，完整拾取事件完成后同步清理 Loot 状态和表现，提交后的表现监听异常只记录错误，不反向破坏领域结果。
  - 世界名称读取物品本地化名称，数量大于 1 时显示“名称x数量”；View 保存最后一次运行时名称和数量，禁用后重新启用不会回退到序列化占位值。
- 完成时间：2026-07-31；敌人动态掉落落地与完整拾取生命周期于 2026-08-01 完成修正。

### 敌人保底武器与剩余弹药掉落

- 内容：普通敌人死亡保底掉落一把短剑；弓箭手死亡保底掉落一把弓和当时剩余的全部箭矢；原有金属零件等额外掉落保持不变。
- 目的：为短剑、弓和箭矢建立正式的重复获取来源，同时保证一次死亡的多项掉落不会只生成一部分。
- 修改简介：
  - 敌人配置分别声明保底武器 Loot、可选保底弹药 Loot、弹药容量和近战回退距离；运行配置在地图准备前校验武器/弹药类型、数量和引用。
  - `EnemyDropSystem` 按保底武器、非零剩余弹药、既有额外掉落的固定顺序形成一次死亡批次；弓手剩余 0 发时不创建箭矢条目。
  - `LootCtrl` 保留每个 LootConfigId 对应的 ItemId 与数量，按 Prefab 地址共享资源；批次全部登记成功后才显示，失败时反向回滚全部 Unit、Loot 和表现。
  - 同一敌人死亡只处理一次；掉落批次失败后不自动重放死亡或复制掉落。
- 完成时间：2026-08-10。

### 急救包使用与战斗边界

- 内容：有效远征中的存活玩家可以使用背包急救包恢复生命。
- 目的：建立首个正式物品消耗用途，同时保持战斗数据权威唯一。
- 修改简介：
  - `InventorySystem.TryUsePlayerBagItem` 校验风险、远征、失败状态、玩家生命、格子和物品配置。
  - `CombatSystem.TryRestorePlayerHealth` 只修改 `CombatModel` 中的玩家生命，并沿用生命事件、表现刷新和存档标脏。
  - 满生命、死亡、无效配置、材料、非治疗效果或没有实际恢复时不消耗物品；成功治疗恰好扣除一个急救包。
  - `UnitModel` 不保存生命、治疗量或物品使用结果。
- 完成时间：2026-07-31。

### 口粮、静态来源与能量恢复

- 内容：新增正式口粮及两张探索地图的固定来源，并建立恢复能量的原子物品使用事务。
- 目的：让持续能量压力具有明确、可携带且受背包风险约束的恢复手段。
- 修改简介：
  - 口粮稳定 ID 为 `item.consumable.ration`，最大堆叠 5，使用效果 `RestorePower` 固定恢复 40 点能量。
  - 生存地图在 `(-8, 0.45, 6)`、任务地图在 `(0, 0.6, -4)` 各生成一份静态口粮；普通敌人掉落表不加入口粮。
  - 口粮可在基地 `BaseSafe` 或存活玩家的有效远征中使用；非 Playing、风险状态不安全、玩家死亡和能量已满时拒绝消耗。
  - `InventorySystem` 快照背包后先移除一个口粮，再通过 `PlayerConditionSystem` 恢复能量；效果失败或异常时恢复快照，成功只提交一次库存变化。
- 完成时间：2026-08-01。

### 远征背包风险与结算

- 内容：玩家携带同一个背包往返基地和远征；成功撤离保留背包，死亡或异常远征清空背包，仓库始终不受影响。
- 目的：使随身成果具备明确风险，并在地图和存档失败时避免物品复制或逃逸。
- 修改简介：
  - 风险状态固定为 `BaseSafe`、`EnteringExpedition`、`InExpedition` 和 `RecoveryRequired`，唯一保存在 `PlayerBagModel`。
  - 进入远征前先保存 `EnteringExpedition`，地图成功并开始远征后保存 `InExpedition`；保存或加载失败按进入前背包快照回滚。
  - 成功加载基地后，成功撤离原样保留背包并保存 `BaseSafe`，不自动转入仓库。
  - 玩家死亡后立即禁止拾取、使用和装备变更；基地加载成功后清空背包和两个正式武器 ItemId、把当前槽恢复为 Melee 拳头并保存 `BaseSafe`，仓库逐格不变。
  - 收口保存失败进入 `RecoveryRequired`；重试只保存已确定的背包结果，不重复切图、清空或增减物品。
  - 读取到非安全风险状态时强制加载并持久化基地地图，清空背包和正式武器、恢复 Melee 拳头、保留仓库，再保存 `BaseSafe`；首批不恢复远征现场。
- 完成时间：2026-07-31。

- 目的：保留旧进度，同时删除旧库存作为第二权威来源的可能。
- 修改简介：

  - 超过 40 格时只扩展到完整容纳旧数量的最小容量；非法旧数量或损坏结构拒绝迁移。
  - 迁移后删除旧分区，玩家背包为空且风险为 `BaseSafe`。
  - 2→3 迁移只增加近战、远程均为 null 且当前槽为 None 的装备分区，保留背包、仓库和未知分区。
  - 基地地图解锁继续只通过 `InventorySystem` 消耗仓库物品并保存解锁状态。
- 完成时间：2026-07-31。

### 背包仓库界面与格子交互

- 内容：玩家可以通过同一界面查看和操作玩家背包，并在基地库存终端打开背包与仓库双栏。
- 目的：让正式物品、固定格容器和基地仓库具备完整玩家操作入口，同时保持两个容器的既定职责不变。
- 修改简介：
  - Tab 是可重新绑定的背包热键；基地和有效远征打开右上玩家物品面板，基地库存终端只在 `BaseSafe` 状态打开背包与仓库双栏。
  - 右侧玩家面板按装备、4×3 背包、容量、同区详情和有效操作排列；名称单行省略、说明两行省略，无有效操作时隐藏整行按钮，不提供独立取消选择按钮。
  - 库存 Prefab 使用全屏透明射线阻断根承载两套互斥表现：右上 `BagOnlyRoot` 固定为 518×713、参考偏移 -115/-140；居中 `BagAndWarehouseRoot` 保留 960×610 的原双栏仓库布局。
  - Controller 为两种表现分别维护 12 个玩家背包 Slot View，但两者共享同一选择、拖动、装备、使用、拆分和领域状态；当前模式只显示对应集合，切换模式不移动 RectTransform。
  - 随身武器通过“拿出／收起”操作；仓库和搜索物品先转入随身库存，不再提供武器装备格拖放目标。
  - 仓库继续使用 8×5 可视滚动网格、扩容入口、双栏详情和取消选择按钮，玩家背包与仓库的双向转移规则不变。
  - 点击和拖动共用 `InventorySystem.TryTransfer`，支持整组移动、同物品合并和不同物品交换；拆分使用 `TrySplitHalf`，急救包使用既有物品使用入口。
  - 格子 View 只保存格号和表现引用，数量、名称、说明、图标和操作结果始终从模型与配置重新读取。
  - 拖动具有来源反馈，结束、取消、界面关闭、地图加载和应用状态变化都会清理拖动与选择状态。
  - 库存操作失败只显示本地化通用提示，不把 System 内部英文错误暴露给玩家。
  - 界面打开不暂停世界，但 `PlayerInputSystem` 统一停止移动、攻击和普通交互；关闭后恢复。
- 完成时间：2026-07-31 建立固定格库存界面；2026-08-11 完成右侧玩家物品面板改版。

### 右键菜单与悬浮详情

- 内容：玩家在背包中使用右键菜单与独立悬浮详情；快捷栏界面、六格绑定、3–8 快捷槽动作及其设置入口已移除。
- 目的：保留背包的物品操作入口和原有右侧固定详情区，避免维护没有显示界面的快捷槽功能。
- 修改简介：
  - 使用、装备和打开地图继续复用 `IItemTransferPort` 既有入口，背包右键保留可执行的使用、拆分与丢弃操作。
  - 背包格悬停显示独立 Tooltip；原有名称、说明、数量与操作按钮区域不改结构、不替换行为。
  - 右键菜单继续使用 `CustomListView` 和外部 `ItemContextActionBox`，由正式 Prefab 和生成 View 驱动。
  - 背包分区不再持有、校验、读取或写入快捷槽状态；旧存档中的额外 `quickSlots` 字段被自然忽略，正常保存和文明远征结算只生成现行背包字段，不提高存档版本。
  - 旧设置中的六个快捷槽动作由设置清洗移除，其它玩家自定义绑定保持不变；启动资源检查不再要求快捷栏 Prefab。
- 更新日期：2026-10-06。

### 背包测试指令

- 内容：开发测试界面提供 `clone <ItemId> <Amount>` 和 `clear bag`，只修改当前玩家背包。
- 目的：复用正式库存规则快速构造背包状态，不让测试入口形成第二套容器规则或污染仓库与世界状态。
- 修改简介：
  - `clone` 精确校验正式 `ItemId` 和正整数数量，复用地面拾取相同的堆叠、空格与部分接收规则；至少加入一个物品时只提交一次库存变化。
  - `clear bag` 返回清空前的物品总数；非空背包只提交一次变化，空背包不制造虚假变化。
  - 两个指令只允许在基地 `BaseSafe` 或存活玩家的有效远征状态执行；加载、进入、返回、恢复、失败和非 Playing 状态拒绝修改。
  - 指令不修改仓库，不创建世界掉落，不发送拾取事件或增加任务进度；意外异常恢复执行前背包快照。
- 完成时间：2026-08-01。

### 仓库扩容领域事务

- 内容：建立仓库容量增长的正式报价和原子扩容入口，初始 40 格可逐格购买到 80 格。
- 目的：让基地成长直接消费正式材料并沿用现有仓库容量存档，不引入第二份等级或升级数据。
- 修改简介：
  - `InventoryDefaults` 统一保存 80 格上限、金属零件 4 个和布料 3 个的单次扩容成本。
  - `WarehouseExpansionQuote` 合并统计仓库与玩家背包材料，报告当前/最大容量、材料拥有/需要数量、状态许可、上限和可扩容结果；查询不修改模型。
  - `InventorySystem.TryExpandWarehouse` 每次重新获取报价，先消费仓库低格号材料，再由玩家背包低格号补足；先处理金属零件，再处理布料。
  - 扩容事务同时快照仓库和背包，任一失败恢复两边物品与原仓库容量；成功容量只增加 1 格，并只提交一次库存变化。
  - 79 格可扩到 80 格；80 格和历史大于 80 格的仓库拒绝继续扩容，历史容量与物品不被缩减。
  - 容量继续写入现有仓库存档分区，不升级存档版本，不在扩容事务中强制保存。
- 完成时间：2026-08-01。

### 仓库扩容界面

- 内容：基地仓库双栏界面提供可滚动的容量显示和末尾扩容入口，玩家可查看材料报价并确认逐格扩容。
- 目的：把仓库扩容领域事务接入玩家可见操作，同时保持 UI 不直接统计、扣除或修改库存数据。
- 修改简介：
  - 仓库区域保持 8×5、426×264 的可视范围，使用固定 8 列的纵向滚动网格；普通仓库格数量随实际容量增长，历史超大容量也能完整查看。
  - 容量小于 80 时，在全部普通格之后显示独立扩容格；扩容格没有 `InventorySlotRef`，不参与选择、拆分、使用或拖放。容量达到或超过 80 时入口直接隐藏。
  - 点击扩容格从 `InventorySystem` 获取仓库与背包合计报价，显示增加 1 格及金属零件、布料的当前/需要数量；条件不足时确认按钮禁用，取消仍可用。
  - 确认只调用 `TryExpandWarehouse`；成功依靠库存变化事件刷新真实格与新入口，库存界面保持打开，控制器不主动改变滚动位置。
  - 扩容入口、确认内容和失败提示支持中英文切换；内部领域错误不直接显示给玩家。
- 完成时间：2026-08-01。

### 弓箭弹药原子消费

- 内容：基础弓发射时从玩家背包消耗一支正式箭矢，射击创建失败时完整恢复背包。
- 目的：让远程武器使用正式库存物品承担消耗，同时避免资源或表现失败造成物品丢失。
- 修改简介：
  - WeaponSystem 在正式接受弓攻击前确认背包至少一支箭，并捕获背包快照后移除一支。
  - 投射物成功进入运行态后只提交一次库存变化并开始冷却；创建失败恢复快照，不提交库存变化、不开始冷却。
  - 射偏、撞墙或达到最大距离的箭会生成一支可拾取箭矢；命中玩家或敌人后箭矢消失，不能回收。敌我双方和临时箭塔发射的箭遵循同一规则。
  - 箭矢是最大堆叠 20 的正式 Ammunition 物品；首版没有弹匣、自动换弹或手动换弹。
- 完成时间：2026-08-01 完成主体；2026-08-03 完成投射物资源返修复审。

## 3. 总体设计说明

### 3.1 职责边界

- `ItemContainer`：只处理容量、格子、堆叠和可回滚容器操作。
- `PlayerBagModel`：保存随身容器和风险状态。
- `WarehouseModel`：保存基地安全容器，不读取远征状态。
- `WeaponEquipmentModel`：只保存两个固定武器 ItemId 和当前槽，使用独立严格存档分区。
- `InventorySystem`：编排容器操作、拾取接收、物品使用、风险转换、清空和保存。
- `WeaponEquipmentSystem`：独占随身武器的拿出、收起、候选循环、来源跟随和风险清空。
- `WeaponSystem`：执行当前武器攻击；弓箭分支负责箭矢快照消费、创建失败恢复和成功后的单次库存提交。
- `WarehouseExpansionQuote`：只读报告仓库扩容的容量、合计材料和状态结果；不保存数据，不执行扣料。
- `LootModel` / `LootSystem`：保存世界掉落并编排背包与世界数量的原子事务。
- `CombatModel` / `CombatSystem`：保存并修改玩家生命；不直接操作物品容器。
- `PlayerConditionModel` / `PlayerConditionSystem`：保存并修改能量；不直接操作物品容器。
- `ExpeditionFlowSystem`：决定进入、成功返回和失败返回的地图事务时机。
- Trigger、View 和 UI：只显示状态并发起请求，不直接修改任何模型。

### 3.2 当前物品流

```text
地图配置或敌人死亡
→ 创建带 ItemId 和数量的世界掉落
→ 敌人死亡批次固定包含保底武器、弓手非零剩余弹药和既有额外掉落
→ LootSystem 计算背包可接收量
→ 全部或部分写入 PlayerBagModel
→ 急救包可在有效远征中通过 CombatSystem 使用
→ 口粮可在基地安全状态或有效远征中通过 PlayerConditionSystem 使用

Tab 或基地库存终端
→ 打开右侧玩家物品面板或基地双栏
→ 点击或拖动请求 InventorySystem 操作
→ 模型成功后刷新全部可见格子并标记存档

背包中的正式武器
→ WeaponEquipmentSystem 设置随身格手持引用
→ 拿出或收起不转移数量，只有一个当前手持
→ 成功刷新手持标记和 HUD，失败保留原状态

TestCmd 开发测试入口
→ clone 复用 InventorySystem 的正式背包接收规则
→ clear bag 只清空 PlayerBagModel
→ 成功事务统一刷新库存并标记存档

仓库扩容事务
→ InventorySystem 合并查询仓库与背包材料
→ 仓库优先、背包补足消费金属零件 4 与布料 3
→ WarehouseModel 容量增加 1 格，最高购买到 80 格
→ 成功只刷新一次库存并沿用现有容量存档

基地仓库扩容界面
→ 纵向滚动网格显示全部真实仓库格和末尾扩容入口
→ 确认框只展示 InventorySystem 返回的合计材料报价
→ 条件满足时提交 TryExpandWarehouse
→ 库存变化事件原位刷新格子，达到或超过 80 格后隐藏入口

成功撤离
→ 背包原样保留并保存 BaseSafe
→ 玩家回基地后自行转入 WarehouseModel

死亡或异常远征恢复
→ 基地加载成功后清空背包和武器装备
→ WarehouseModel 保持不变
→ 保存 BaseSafe
```

### 3.3 长期原则

- 玩家背包和基地仓库永远是两个独立权威，不合并模型或存档分区。
- 当前手持只是随身库存引用；拳头是空手的内建行为，不是库存物品。正式物品移动仍由 `InventorySystem` 执行。
- 世界拾取直接进入背包，不经过远征临时整数，也不在撤离时自动转仓。
- 成功撤离保留背包和正式武器装备，死亡和异常远征清空两者后恢复空近战 Melee 拳头，仓库不承担远征风险。
- 生命只属于 `CombatModel`，能量只属于 `PlayerConditionModel`，物品配置只属于 `TbItem`，共同身份和空间状态只属于 `UnitModel`。
- 配置、领域模型、流程和表现各自保持单一职责；表现失败不能改写已提交领域结果。
- UI 只发起格子操作和物品使用请求，不保存第二份数量，也不直接修改背包、仓库、生命或玩家条件模型。
- 测试指令同样只通过 `InventorySystem` 修改背包；不得绕过容器校验、伪造世界拾取或触碰仓库。
- 仓库扩容只能通过 `InventorySystem.TryExpandWarehouse` 执行；UI 不得自行扣料、扩容或保存第二份等级。
- 扩容格是独立操作入口，不得获得真实格号或参与物品格选择、拆分、使用和拖放合同。
