- 目的：保留“停用旧地图 → 卸载场景 → 反向释放控制器”的失败恢复能力，同时消除 Unity 假空访问和 Collider 映射残留。
- 修改简介：
  - Enemy、Loot、Extraction ViewCtrl 统一识别已销毁 Unity View，销毁态表现调用不再访问 GameObject、Transform 或组件。
  - ViewCtrl 在外部销毁后仍注销 Registry，并保持重复释放安全；只有存活实例才执行解绑和实例提供器释放。
  - EnemySystem 在地图阻断状态下跳过无效导航端口；EnemyCtrl 仍在最终释放时注销 Unit、Combat 和 AI 领域状态。
  - 已销毁 Collider 通过原引用从映射移除，整图释放后 Collider 映射强制归零。
  - MapSceneSystem 的卸载、恢复和控制器反向释放顺序保持不变。
- 完成时间：2026-08-03。

### 生存地图固定敌群与候选导航有效性检查

- 内容：生存样例地图通过 TbMapSpawn 固定配置 4 个基础近战敌人和 2 个弓箭手，形成两处各 2 近战加 1 弓手的区域；任务地图敌人配置保持不变。
- 目的：让混合敌群继续服从统一地图候选事务，并在进入 Playing 前拒绝不可导航的敌人出生配置。
- 修改简介：
  - 六个敌人随候选地图一次性准备，不使用刷新、波次、补充生成、小队警报或对象池；敌人死亡后不再刷新。
  - EnemyCtrl 在提交任何 Unit、Combatant 或 AI 前统一校验全部 staged 敌人出生位置的 NavMesh 可用性，任一失败释放全部候选表现和临时资源。
  - 提交期后续敌人注册失败时，已成功登记的前序敌人按 Collider、AI、Combatant、Unit 的领域顺序反向移除，再统一释放六个候选实例。
  - 地图停用会取消弓手未完成预警；旧地图因卸载失败恢复时不会继续停用前的晚到射击。在途投射物仍由 ProjectileSystem 按地图停用合同清理。
- 完成时间：2026-08-04。

## 3. 总体设计说明

### 3.1 目标

- 所有地图使用稳定地图 ID。
- 地图静态定义、场景上下文、远征运行态、同步规则和异步地图事务彼此分离。
- 地图加载失败必须保留可恢复状态。
- 基地入口、出口和 HUD 只发起请求并显示状态，不直接改变远征模型。

### 3.2 职责边界

- MapCatalog：保存地图类型、玩家显示名 Key 和规则参数，不保存资源地址。
- IRuntimeConfigProvider：提供地图场景地址、地图生成记录以及玩家、敌人、物资和撤离点配置的只读查询。
- MapContext：只保存 PresentationRoot 和 RuntimeUnitRoot，不保存配置编号、Prefab 或任何玩法对象接线。
- MapSceneSystem：统一加载、卸载、准备、提交和回滚地图内容，独占地图 Handle、MapSceneModel、进度、取消和地图结果事件，并直接编排四个 Controller。
- AdditiveSceneMapLoader：加载和卸载加法地图，并在交付候选 Handle 前验证上下文及关闭候选 PresentationRoot。
- ExpeditionModel：保存一次远征的运行态。
- ExpeditionSystem：接收统一游戏分钟推进，处理任务击杀和返回资格，不独立读取帧时间。
- PlayerConditionSystem：在有效世界状态中统一推进远征游戏分钟、探索能量下降和基地能量恢复。
- ExpeditionFlowSystem：编排进入、成功返回和失败返回的异步事务。
- BaseMapSelectionSystem：处理基地地图解锁与进入两个事务。
- PlayerInteractionSystem：维护基地交互焦点并消费交互意图。
- ExtractionCtrl：按生成记录和撤离点配置准备、提交、停用、恢复和释放动态撤离点，接管可用表现和原始 Trigger，并向 ExtractionSystem 发起返回请求。
- ExtractionModel：保存当前撤离点的 MapInstanceId、可用性和 Returning，不持有 Unity 对象。
- ExtractionSystem：负责撤离点登记、移除、可用性更新、玩家与地图校验、返回防重和异常复位。
- TaskExitView：只负责撤离点可用表现和原始 Trigger 信号。
- CombatFlowSystem：把玩家死亡结果转换为远征失败返回流程，隔离状态通知异常，并保证自身防重状态在所有结束路径复位。
- ProjectileCtrl：准备并持有当前地图与候选地图的投射物 Prefab 资源，负责实例和碰撞表现的创建、停用、回滚与释放。
- ProjectileSystem：推进非存档投射物运行态，并在命中、障碍、超距、地图停用、失败或释放时统一结束。

### 3.3 状态与数据流

    基地靠近交互对象
      -> PlayerInteractionSystem 设置焦点并显示名称
      -> F 交互意图
      -> BaseMapSelectionSystem 解锁或请求进入地图
    
    生存远征
      -> PlayerConditionSystem 按真实时间换算游戏分钟
      -> ExpeditionSystem 推进远征时间
      -> 达标后 ReturnQualified
      -> 达标后继续推进时间与能量
      -> 玩家主动请求返回
    
    任务远征
      -> CombatantDiedEvent
      -> ExpeditionSystem 去重并推进击杀目标
      -> ReturnQualified
      -> ExtractionCtrl 刷新撤离点可用表现和领域状态
      -> 玩家进入出口请求返回
    
    玩家死亡
      -> CombatantDiedEvent
      -> CombatFlowSystem
      -> ExpeditionModel.Defeated
      -> 状态通知异常只记录并继续
      -> 既有失败返回事务
      -> 业务失败时保留 Defeated 等待 HUD 重试
      -> 意外异常保留事务实际状态，不自动重试或重复回滚
    
    地图替换
      -> 从配置读取场景地址和生成记录
      -> 加载并隐藏候选地图 PresentationRoot
      -> MapSceneSystem 依次准备四个 Controller
      -> 反向停用旧内容并卸载旧地图
      -> 释放旧内容并依次提交候选内容
      -> 打开候选 PresentationRoot 并写入当前 MapSceneModel
    
    旧世界停用且内部恢复失败
      -> 回滚候选会话并卸载候选地图
      -> 释放旧内容并尽力卸载旧地图
      -> 停止地图音频并清空 MapSceneModel(Failed)
      -> AppState.MainMenu
    
    暂停界面返回主菜单
      -> 会话流程刷新存档并请求卸载当前地图
      -> MapSceneSystem 捕获 Paused 并进入 Loading
      -> 成功卸载、释放地图内容并进入 MainMenu
      -> 卸载失败时恢复旧地图、Paused 和暂停时间缩放

### 3.4 长期原则

- 地图显示、目标和解锁规则保留在 MapCatalog；资源地址与生成配置通过 Luban 读取，不写死在 UI 或场景组件中。
- 远征 HUD 不显示背景小地图或地图标记；地图查看只通过独立地图界面提供。独立地图为非阻断界面，背景不占用玩法指针，打开期间仍允许移动和俯视角转向；关闭按钮等实际控件继续拦截点击。大地图可通过 `TbMapDisplay` 配置展示网格，界面按玩家所在分区裁切同一张地图纹理，并隐藏区外标记；何家村使用 `2×2` 分区以放大玩家位移。
- 同步远征规则由 ExpeditionSystem 处理，异步地图事务由 ExpeditionFlowSystem 处理。
- 任何库存结算都以基地地图加载成功为前提。
- 返回失败必须保留重试所需的完整状态。
- 解锁成功和进入地图是两个不同结果。
- 表现层不能直接写入远征资格、击杀进度或清空远征。
- 玩家界面不得直接显示内部地图 ID；应通过地图目录解析本地化显示名，查询失败时使用统一回退。
- 加法地图可以在切换事务中同时驻留内存，但任意稳定时刻只允许一个 PresentationRoot 激活。
- MapSceneSystem 是地图场景与五类内容事务的唯一编排者；各 Controller 只管理本领域候选和当前内容。
- 敌人候选提交必须先完成整批出生位置 NavMesh 校验；提交期部分注册失败必须清理本批已建立的 Unit、Combatant、AI、Collider 映射和 View。
- 候选地图在提交完成前必须保持隐藏，旧世界只有在仍可恢复时才能重新写回 Playing。
- 无法恢复有效旧世界时必须尽力清理候选和旧地图，释放 Unit、ViewCtrl 与运行时端口，并进入 Failed/MainMenu 安全状态。
- 从暂停状态卸载当前地图必须先进入 Loading，再在成功后进入 MainMenu；失败恢复继续使用卸载前捕获的稳定状态，不放宽应用状态机的非法直跳保护。
- 场景卸载成功到控制器反向释放之间允许 Unity View 和 Collider 已销毁；各 ViewCtrl、运行时端口和 Collider 映射必须按 Unity 对象语义安全收口，不得改变地图事务顺序来规避该窗口。
