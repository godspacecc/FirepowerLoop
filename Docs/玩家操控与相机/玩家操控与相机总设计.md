### 河谷自动水面游泳（2026-10-14，人工画面与连续手感待验收）

- 只在版本3文明河谷依据实际水位与河床深度自动切换；进入深水浮到水面，可站立浅水或上岸恢复步行，沿用移动方向。进入阈值1米、保持阈值0.7米，浮水脚底位于水面下0.9米，垂直纠正不超过2米/秒；迟滞防止岸线反复切换。
- 游泳速度为正常步行的0.6倍，不支持水中冲刺，不新增潜水、溺水、游泳按键或额外体力惩罚；原生存消耗继续。水中拒绝攻击、采集、建造和启动撤离，入水取消这类既有读条，上岸恢复。
- `PlayerMoveSystem`拥有状态与移动规则，`PlayerCtrl`捕获和恢复原位置及游泳状态；View只镜像姿态与脚步表现。现有Humanoid使用基础程序游泳姿态，不改玩家根变换、不承担业务状态；敌人仍使用陆地/浅滩导航，深水导航禁止。
- 聚焦EditMode通过规则、实际导航、移动端口、正式角色姿态恢复及岸上/水中保存继续验证。详见上述河谷实施结果文件。实际连续涉水、角色水线、持物与镜头观感尚未人工验收。

### 玩家运行时职责拆分与动态地图玩家

- 内容：建立唯一玩家 View、输入适配器、动态玩家控制器、移动系统、相机系统和地图实例运行时身份。
- 目的：让玩家表现随地图实例成对创建和释放，并让输入、移动、相机与战斗只通过身份和窄端口访问当前活动玩家。
- 修改简介：
  - PlayerView 是玩家 Prefab 上唯一的产品 MonoBehaviour，持有 CharacterController、TopDownCameraProfile、悬浮体力圆环和当前武器灰盒表现引用。
  - Main 场景不再常驻玩家实例；PlayerCtrl 从地图生成配置读取 Prefab 地址和出生姿态，在候选地图的 RuntimeUnitRoot 下实例化玩家。
  - PlayerViewCtrl 管理玩家表现生命周期并提供移动、相机和战斗反馈窄端口；System 不持有具体 PlayerView 或 PlayerViewCtrl。
  - UnitModel 以稳定 PlayerUnitId 和随地图变化的 MapInstanceId 保存当前活动玩家的共同身份、ConfigId、空间快照及活动状态，不保存生命或战斗数据。
  - PlayerReadyEvent 只携带 UnitId 与 MapInstanceId；移动、相机和战斗系统再通过 Unit 的 ConfigId 读取同一玩家配置。
  - PlayerMoveSystem 和 PlayerCameraSystem 分别通过公共 Update 与 LateUpdate 生命周期运行。
  - Main Camera 不挂载玩家产品逻辑。
- 完成时间：2026-07-24 建立基础职责；2026-07-30 完成动态地图玩家与 Unit 接线。

### 统一游戏输入边界

- 内容：移动、鼠标武器攻击、武器槽切换和交互确认统一由普通输入适配器与 PlayerInputSystem 管理。
- 目的：避免移动系统、战斗系统和场景对象分别读取键盘。
- 修改简介：
  - PlayerInputCtrl 读取 WASD、方向键、鼠标左键、数字键 1/2、F 和左 Shift；Space 已退出攻击绑定且暂未分配其它操作。
  - PlayerInputSystem 向移动系统提供标准化移动输入，并发布携带鼠标 XZ 方向的攻击意图、固定武器槽切换意图和交互意图。
  - 鼠标方向由主相机屏幕射线与玩家高度水平面求交得到；相机、鼠标、交点或方向无效时不发布攻击。
  - 非 AppState.Playing、远征处于 Defeated 或存在阻塞型 UI 时禁用游戏输入；阻塞型 UI 可保持世界运行，但移动、攻击和普通交互立即停止。
  - WeaponSystem、CombatSystem 和场景交互组件不创建或读取独立 Input Action。
- 完成时间：2026-07-27；鼠标武器输入和数字键切槽于 2026-08-01 完成。

### Shift 冲刺与短周期体力

- 内容：在统一玩家输入和移动链中加入 Shift 加速、体力消耗、两档恢复和耗尽后的重新冲刺条件。
- 目的：增加短周期移动决策，同时保持输入、状态和位移职责分离。
- 修改简介：
  - PlayerInputCtrl 读取左 Shift，PlayerInputSystem 继续应用 AppState、失败状态和阻断型 UI 状态校验。
  - PlayerConditionModel 是体力和公开耗尽锁定的唯一权威；PlayerConditionSystem 计算消耗、恢复、按键边沿和 20 点重启门槛。
  - 实际移动并按住 Shift 时使用 1.5 倍速度并每秒消耗 20 体力；普通移动每秒恢复 15，站立每秒恢复 25。
  - 原地按 Shift 不消耗；耗尽后持续按住既不恢复也不自动重启。
  - 松开后开始恢复；如果低于门槛时提前按住并跨过 20，仍需再次松开并重新按下才可冲刺。
  - PlayerMoveSystem 每帧只提交移动与 Shift 意图并使用返回倍率，不保存第二份体力或重启状态。
  - 联机 World 复用同一套 Shift、体力消耗、恢复与 1.5 倍移动规则；实际位移继续通过既有联机 Transform 上报链同步，不增加第二套联机冲刺状态。
- 完成时间：2026-08-01；2026-09-16 接入联机 World。

### 玩家左下悬浮体力圆环

- 内容：玩家画面位置左下侧使用悬浮空心圆环表现短周期体力，不在远征 HUD 重复显示生命或体力。

- 修改简介：

### 玩家生命持久化与基地恢复

- 内容：玩家当前生命成为独立持久状态，并在基地缓慢恢复。
- 目的：让成功返回、失败返回、重试和再次出发保持一致生命语义。
- 修改简介：
  - CombatModel 是玩家当前生命、最大生命和攻击力的权威数据源；最大生命来自 TbPlayer，不在 Model 中假设固定 100。
  - 存档分区为 `another-day.player-health`，字段为 `hp`；版本 4 不读取旧生命字段。
  - 成功返回、失败返回和进入远征均不瞬间恢复生命。
  - 当前生命为 0 时拒绝进入远征，恢复到正数后即可进入。
  - 只有基地地图且 AppState.Playing 时恢复；恢复速度来自 TbPlayer，暂停、加载、主菜单和探索地图不恢复。
  - CombatModel 保存权威生命，屏幕 HUD 读取当前生命；CombatSystem 不再订阅生命变化来刷新玩家世界血条。
- 完成时间：2026-07-27；生命配置与 CombatModel 迁移于 2026-07-30 完成。

- 修改简介：
  - 指令固定为 `set hp`、`set power`、`set tili`、`set maxhp` 和 `set movespeed`，不接受别名；非法格式、数值越界、状态拒绝和执行异常使用不同结构化结果。
  - `PlayerAttributeSystem` 统一校验 Playing、活动且存活的玩家，以及基地 `BaseSafe` 或 Playing/ReturnQualified 有效远征，再调用 Combat、PlayerCondition 和 PlayerMove 领域入口。
  - MaxHP 和 MoveSpeed 使用 `PlayerAttributeModel` 的可空存档覆盖；无覆盖时读取 `TbPlayer.MaxHP` 与 `TbPlayer.MoveSpeed`，修改 MoveSpeed 后立即刷新当前移动缓存。
  - 同值设置成功但不创建覆盖、不发送事件、不标记存档；异常恢复存档分区、既有存档脏状态和实际 MoveSpeed 缓存。
- 完成时间：2026-08-04。

### 玩家生命展示

- 玩家生命由屏幕玩家信息 HUD 展示，街机模式使用街机玩家状态列表。
- 玩家 Prefab 不再包含头顶生命条，PlayerView 与移动端口不提供血条刷新或显隐能力；基地、远征和联机玩家统一遵守。
- CombatModel 的生命存档、伤害、死亡与基地回血规则保持不变。
- `#unitbar on / off` 只控制普通地图存活敌人的头顶生命条；街机敌人的 Boss 常驻和受击短暂显示规则保持独立。
- 2026-10-08：移除玩家头顶生命条及相关刷新、朝向、命令订阅。

### 本地玩家手电筒

- 内容：为动态玩家 Prefab 增加可改键的本地聚光灯，并让光照方向持续跟随统一鼠标或视口瞄准方向。
- 目的：在夜间保留基础轮廓可见度的同时，为玩家提供主动照明能力，不把表现对象或输入读取放入昼夜系统。
- 修改简介：
  - PlayerFlashlightSystem 保存当前地图实例内的临时开关状态，通过 IPlayerFlashlightPort 驱动玩家表现；地图加载、玩家停用、移除或死亡时自动关闭并清理端口。
  - PlayerView 持有 Prefab 序列化的 Spot Light，只处理启用状态和带向下俯角的世界方向；PlayerViewCtrl 提供窄表现端口。
  - 默认热键为 F，并进入现有设置页改键列表；旧设置中的 F 已被占用时依次回退到 L 或 F4。
  - 手电筒只在本地显示，不消耗电池、不写入存档，也不向其它联机客户端同步。
- 完成时间：2026-09-16。

### 当前武器与弓箭发射表现

- 内容：玩家 View 根据当前固定武器槽显示短剑或弓，并从固定发射点按鼠标 XZ 方向播放弓箭发射反馈。
- 目的：让玩家朝向、武器切换和远程攻击具有明确灰盒表现，同时不把输入、弹药或伤害权威放进 View。
- 修改简介：
  - PlayerView 只保存短剑、弓、挥击根和发射点引用；当前槽切换时显示对应武器。
  - 已接受的攻击会让玩家立即朝向鼠标方向；弓点击后播放固定发射反馈，不锁定目标、不蓄力。
  - 箭矢运行态、弹药消费、冷却和伤害分别由投射物、库存、武器和战斗系统管理，PlayerView 不直接修改。
- 完成时间：2026-08-01 完成主体；2026-08-03 完成箭矢资源返修复审。

### 移动端第三人称操控

- 手机 HUD 右上角提供“背包”按钮，位于基地暂停按钮左侧；基地与有效远征均复用现有背包热键入口。背包打开时隐藏手机操控并归零摇杆，保留虚拟 Gamepad；关闭后恢复。按钮使用既有背包标题本地化键，暂停、加载或其它阻断状态下忽略过期点击。验证记录位于 `Client/Assets/Tests/Results~/MobileInventory-20261004/`，安卓真机触控仍需人工验收。
- 手机端基地俯视模式保持镜头完全固定：左摇杆按相机相对方向移动，右半屏空白处横向滑动只控制人物转身，竖向滑动不生效。移动不覆盖人物朝向，松手保持最后朝向，首次无输入时保持出生朝向；转身速度沿用玩家配置。滑屏复用越肩触点捕获及 UI、失焦、加载、死亡门禁。此规则仅作用于基地俯视模式，桌面鼠标瞄准、普通远征和第三人称瞄准保持原有行为。
- 普通越肩模式保留左下固定摇杆，以相机 Yaw 为基准移动；右半屏空白处单指滑动控制镜头水平旋转和俯仰。
- 2026-10-10：桌面与手机越肩模式的身体朝向直接取当前镜头 Yaw，并在移动更新中立即同步，以保持背对镜头；后退和侧移不改变身体朝向，低头时不再使用可能落到人物背后的水平面交点转身。俯视与第一人称规则保持原样，四向动画仍按实际位移选择。

- 触摸从 UI 开始、滑入 UI、暂停、失焦或地图加载时取消本次镜头捕获；恢复后需要重新起按，不接管仍按住的旧触点。
- 通用手机 HUD 在越肩模式显示右下攻击按钮和物理屏幕中心准星，交互按钮移到攻击按钮上方。准星不接受 UI 射线，不因安全区偏移。
- 攻击按钮每次点击只排队一次意图，`PlayerInputSystem` 先应用本帧镜头增量，越肩模式按镜头 Yaw 生成水平朝向，第一人称保留同帧中心射线的水平面转向规则，再发布正式攻击事件。本地第三人称与第一人称事件同时携带准星射线，远程武器从实际发射点朝三维瞄准点射击，支持抬头与低头；近战与俯视仍使用水平规则，玩家联机弓箭共享三维瞄准并由服务器裁决。冷却、弹药和伤害继续由现有武器系统裁决，不新增自动连发。

- Editor Play 会话可用 `#mobileinput on` 开启手机模拟，使用 `#camera shoulder` 切到越肩模式。右侧空白处按住鼠标左键拖动模拟滑屏，点击攻击按钮模拟攻击；模拟期间不锁鼠标，空白处点击不触发攻击。`#mobileinput off` 恢复桌面输入。
- 验证记录位于 `Client/Assets/Tests/Results~/MobileShoulderInput-20261003/`；已检查静态 HUD 布局，安卓真机多指手感仍需人工验收。

## 3. 总体设计说明

### 3.1 目标

- 玩家对象保持轻量，只保存 Unity 引用和直接表现能力。
- 输入读取、移动规则、战斗意图、相机规则、生命状态和地图出生定位互不混杂。
- 玩家移动手感以屏幕方向为准。
- 持久生命由模型保存，View 只显示模型结果。

### 3.2 系统边界

- PlayerView
  - 持有 CharacterController、相机配置、悬浮体力圆环、短剑与挥击根节点引用。
  - 提供朝向、当前武器显示、挥击、受击和体力圆环直接表现。
  - 不读取输入、不执行地图切换、不保存权威生命。
- PlayerInputCtrl
  - 创建、启用、禁用并释放移动、左键攻击、数字键切槽、交互和 Shift 等具体 Input System Actions。
  - 只暴露标准化输入状态。
- PlayerInputSystem
  - 统一决定游戏输入是否可用。
  - 把鼠标瞄准攻击、固定槽切换和交互按键转换为架构事件，不执行武器规则。
- PlayerCtrl
  - 作为地图事务参与者准备、提交、停用、恢复和释放玩家表现。
  - 根据玩家配置的 PrefabAddress 和地图生成记录的局部姿态，在 RuntimeUnitRoot 下动态创建候选玩家。
  - 提交后注册玩家 Unit，并发送只携带 UnitId、MapInstanceId 的 PlayerReadyEvent。
  - 同一时间只允许一个玩家 Prefab 加载；取消请求及时结束地图事务，晚到回调负责安全结算资源 Handle。
- PlayerViewCtrl
  - 管理玩家 GameObject 和 PlayerView 生命周期。
  - 实现玩家移动和战斗反馈窄端口，不保存权威业务数据。
- UnitModel / UnitSystem
  - 保存并维护当前活动地图中玩家 Unit 的共同身份、MapInstanceId、空间快照和活动状态。
  - 不保存玩家生命、战斗结果或 Unity 对象。
- PlayerMoveSystem
  - 通过玩家移动端口负责相机相对水平位移、重力和移动朝向，并把位置与朝向写回 UnitModel。
  - 向 PlayerConditionSystem 提交实际移动和 Shift 意图，只消费其返回的冲刺倍率。
  - 从玩家属性覆盖或配置读取 MoveSpeed，接收属性变更立即刷新；属性事务失败时通过内部入口恢复原运行时缓存。
- PlayerConditionModel / PlayerConditionSystem
  - 保存并统一修改 Power、Tili 和耗尽重启状态；不保存生命或玩家空间数据。
- PlayerAttributeModel / PlayerAttributeSystem
  - 保存每个存档的可空 MaxHP、MoveSpeed 覆盖，并统一编排五项属性测试设置、指令执行条件和失败回滚。
  - 不直接写 CombatModel 或 PlayerConditionModel 私有状态。
- PlayerCameraSystem
  - 通过相机与移动端口应用 TopDownCameraProfile，在 LateUpdate 跟随活动玩家并统一更新世界交互 HUD 与体力圆环朝向。
  - 越肩相机使用 500 米远裁剪距离以保留大型地图的远处 Terrain；俯视相机保持近距离构图，远景对象仍由各自 LOD、细节距离和阴影距离控制。
  - 街机模式应用独立高角度构图并每帧直接跟随本机玩家，保持玩家居中以避开移动端手指遮挡区；普通俯视沿用原有跟随规则。
  - 越肩模式由 PlayerCameraCtrl 手动驱动 Cinemachine 2.10.1 的 3rdPersonFollow，配置独立轴向跟随阻尼与遮挡恢复时间。进入遮挡立即收镜，近墙避障优先于最小跟随距离；不对避障结果叠加旧 SmoothDamp。主相机不添加自动 Brain，输入后的方向即时供现有瞄准射线使用，同帧只推进一次阻尼。
  - 越肩镜头架归地图玩家所有，由 PlayerCtrl 在释放玩家前幂等清理。自身 Collider 使用 Player 标签供 Cinemachine 排除，端口记录并恢复原标签，不改变物理层。首次接入需要重新生成完整安装包，宿主 link.xml 保留 Cinemachine；之后在该首包基础上调整 Game 逻辑及镜头配置可沿现有热更新流程发布。
- CombatModel
  - 保存玩家与敌人的战斗生命状态，并以 `another-day.player-health/hp` 保存玩家当前生命。
  - 配置到达前不假设最大生命、不建立玩家战斗记录；首次配置后再按新存档或已有存档值初始化。
- CombatSystem
  - 负责生命伤害、恢复和死亡规则，并通过玩家运行时端口刷新生命与战斗表现。

### 3.3 运行链路

    候选地图加载并隐藏 PresentationRoot
      -> MapSceneSystem 读取玩家生成记录
      -> PlayerCtrl 加载配置 Prefab 并在 RuntimeUnitRoot 下创建隐藏玩家
      -> 地图事务提交并注册玩家 Unit
      -> PlayerReadyEvent(UnitId, MapInstanceId)
      -> 移动、相机和战斗系统取得当前活动窄端口
    
    地图内容停用 / 恢复 / 释放
      -> 玩家 View 与 Unit 同步停用 / 恢复 / 移除
      -> System 在 Unit 非活动或移除后清空旧端口
    
    Input System
      -> PlayerInputCtrl
      -> PlayerInputSystem
      -> 移动输入 / Shift 意图 / 鼠标方向攻击事件 / 武器槽切换事件 / 交互事件
      -> PlayerConditionSystem 结算体力并返回速度倍率
      -> PlayerMoveSystem 驱动位移
    
    存档恢复或战斗生命变化
      -> CombatModel.PlayerHP
      -> 屏幕 HUD 读取生命快照

### 3.4 长期原则

- 玩家 Prefab 不新增承担业务系统职责的 MonoBehaviour。
- 输入层只表达意图，不能直接修改战斗、地图或库存状态。
- 玩家不常驻 Main 场景，必须由 PlayerCtrl 随当前地图实例动态创建和释放。
- 移动、相机和战斗统一使用 PlayerReadyEvent 的 UnitId、MapInstanceId 接线，不传递 View。
- 玩家 Prefab、出生姿态、生命、攻击、移动、转向和基地恢复数值来自配置，不在 System 或 Model 中保留玩法默认值。
- System 只依赖 Model、事件和窄运行时端口，不查询 ViewCtrlRegistry，也不持有具体 PlayerViewCtrl。
- 相机参数集中保存在 TopDownCameraProfile。
- 生命存档恢复只刷新表现，不冒充一次新的伤害或恢复业务事件。
- 体力圆环只消费 `PlayerConditionSystem` 发布的公开状态，不保存或反推第二份体力；耗尽时完整红圈只是显示覆盖，不改变权威体力值。
- 玩家体力圆环与敌人生命条共用唯一 World HUD 置顶材质；渲染材质只解决深度遮挡，不接管位置、朝向或状态逻辑。
