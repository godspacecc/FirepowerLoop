## 第一场单人临时第一人称（2026-10-14）

- 用户后续确认第一场第 1—4 波允许掉落临时第一人称道具；这是项目新设计，不宣称已经查实原作第一场的开放条件。此前“第一人称首批暂缓”的记录在此范围内被替代，其余场次、全程模式和联机支持未开放。
- 复用正式玩家相机、Humanoid 手臂与共享武器外观；街机规则拥有独立剩余时间，HUD 只显示状态与提交退出意图。拾取不换枪、不刷新临时枪时间、不增加伤害、射速、回血或积分倍率，也不新增跳跃、滑铲、潜水。

- HUD 显示中心准星、独立倒计时和返回入口，保留生命、命数、波次、能力次数与临时武器信息。PC 使用 X 或返回按钮，Esc 继续暂停；手机使用独立返回按钮。暂停、炸弹和冲刺位于右上，返回在其下方，临时武器信息再向下排列。手机额外显示右摇杆操作提示，结束后恢复俯视双摇杆解释。
- 暂停或阻断窗口冻结规则推进；退出、切换及暂停清理旧操作，射击须释放旧持续按压后重新触发。同类拾取刷新为配置时长，不相加、不重复创建手臂或订阅。只有实际相机准备成功才移除地面物品并显示成功反馈；失败保留俯视与物品。

## 普通战斗满额补给拒绝拾取（2026-10-14）

- 单人及联机普通战斗中，炸弹、冲刺已达当前配置上限时，拒绝对应地面补给，不移除、不增加数量、不产生成功反馈。使用能力后，持有量低于上限并再次进入有效拾取范围，即可正常领取；无需重新生成掉落。
- 成功实例先从权威掉落集合注销，再按当前奖励规则增加库存并移除表现。连续停留、快速进出和重复通知不重复结算；拒绝一件补给不阻止附近财宝、武器或其它可领取掉落。联机仅在可接收者中沿用距离、玩家 ID 的确定性仲裁，满额玩家不阻挡队友。
- 提示读取实际增加量，例如剩余容量为 1 时只显示“炸弹 +1”。联机协议新增本场成功补给记录，携带稳定掉落 ID、领取者与实际增加次数；客户端仅显示本机新记录，首次快照建立历史基线，重复快照去重，不根据库存差值或掉落消失推断奖励。
- 保留当前持有上限、原有掉落清理/消失路径和普通开波空库存补足，不调整寿命、不新增永久掉落、背包页面或跨局库存。成功记录仅随本场临时现场存活，不进入安全存档；奖励房与商店规则本轮未扩展。
- 验证：Unity EditMode 精确类 `ArcadeSupplyPickupTests` 6 项，以及 `ArcadeOpeningFlowTests.NewOrdinaryWave_ReplenishesOnlyEmptyInventoryAndQueuesFullWave` 1 项通过；实际名称与数量均符合过滤范围。`Tools/ArcadeSupplyChecks` 服务端 7 项通过，覆盖真实能力消耗后重拾、队友仲裁、其它掉落与截断量的快照克隆/MemoryPack 序列化；服务端编译无错误，有 NuGet 漏洞数据查询网络不可达警告。协议经 `Tools/gen-protocol.ps1` 双端生成，未手改生成文件。连续试玩、真实双端及移动端画面仍待人工验收；未打包、重启服务端或提交。

## 2. 已确认玩法规则

### 2.0 休闲主流程与终局（2026-10-11 已确认，功能版已实施）

- 一局实际经过 10 个竞技场，每场 4 轮，主线共 40 轮；10 场指本局实际走过的场数，不等于整个游戏只能制作 10 张候选地图。
- 沿途通过路线分支选择后续场地；未选择的场地本局跳过。每轮不换地图，同一竞技场内连续进行四轮，场内实体出口负责竞技场之间的推进。
- 击败最终 Boss 后结算并结束本局，不继续第 11 场或进入更难的循环周目。用户确认本次先实现追击、预警冲锋、预警后锁向射线及普通敌群干扰；暂缓矿车彩蛋和专用结束动画。复用现有敌人、弹丸及预警表现，不作为原作 Boss 美术成品。
- 第 10 场的四轮主线全部完成后，进入独立最终 Boss 战；Boss 不占第 40 轮，也不作为第 11 个竞技场或第 41 轮计数。击败后停止增援、清除残余敌人及危险弹丸，出现胜利出口；进入出口后先保存通关节点，再自动结算结束。保存、发奖或清档失败时保留重试，不开放第 11 场、商店购买或循环。参考：[最终 Boss 战与结束出口](https://gamefaqs.gamespot.com/pc/539641-call-of-duty-black-ops-7/faqs/82246/boss-fight-the-papaback)。
- 本目标替代旧的 20 场顺序循环。单人和合作联机使用一致的主流程；2026-10-11 用户已要求将最多四人扩展纳入设计，范围见第 2.0.2 节。已有单人和双人入口继续保留。

### 2.1 入口与隔离

- 玩家从基地独立 NPC 进入，可选择本地单人、私有房间码双人联机或公共快速匹配。
- 正式入口先调用 `ArcadeRunSystem.TryStartConfiguredRun`，从 Luban 读取初始生命、紧急资源和基础武器并写入初始安全节点，随后立即提交继续操作进入第一竞技场，不展示商店。
- 基地背包、装备、弹药、角色属性和货币都不能带入街机局。
- 一局未结束时不能覆盖创建另一局；入口关闭后仍需保留继续、结算或放弃已有局的路径。
- `TryStartNewRun` 是低层与测试入口，使用固定三命和基础武器；正式 UI 不应绕过配置入口调用它。

### 2.2 战斗

- 战斗采用高角度俯视、移动和瞄准分离、玩家手动射击，不使用自动攻击或升级暂停三选一。
- 移动端使用官方 Input System 双摇杆：左摇杆移动，右摇杆同时控制方向与持续射击，松开右摇杆停止射击。实体手柄保留右摇杆瞄准与扳机射击，键鼠保留鼠标落点瞄准与左键射击。
- 移动端左右摇杆触控区均为 `180×180`，位移半径为 `75`；冲刺按钮位于左摇杆上方，炸弹按钮位于右摇杆上方，两者与对应摇杆保留 `95px` 触控间距，避免连续摇杆操作时误触。
- 战斗 HUD 左上角使用动态玩家状态列表，本机固定排在首行；每行显示玩家名、图形血条、剩余生命和该玩家的局内金币，不显示难以在手机上快速辨认的血量数值。列表元素使用独立 `ArcadePlayerStatusBox`，当前双人房按权威快照增删条目，不在 HUD 内写死玩家数量。
- 波次与剩余敌人数收拢在顶部中央；暂停按钮位于右上角，临时武器和支援只在生效期间显示在暂停按钮下方；复活、掉线与暂停状态居中提示。取消常驻底部武器栏，为双摇杆保留清晰操作空间。
- HUD 内容根统一受 `SafeAreaFitter` 约束；玩家状态行采用 `500×64` 和不小于 `28` 的主要文字字号，暂停按钮触控区不小于 `88×88`，保证窄屏与异形屏上的辨识和点击空间。
- 街机地图复用现有地图事务、正式玩家 Prefab、CharacterController 和 PlayerCamera；街机规则只隔离生命、波次、局内装备与奖励，不再创建平行玩家、相机、灯光或地面。
- 街机相机固定为 72 度俯角、16 米距离和 45 度视野，并每帧直接跟随本机玩家、保持玩家居中，避免移动端双指操作时角色进入手指遮挡区。贴近竞技场边缘时允许视口露出少量场外区域。
- 联机模式仍由每台设备跟随自己的本机玩家，不做共享屏幕队伍框选。
- 敌人、投射物与掉落复用现有 `EnemyCtrl`、`ProjectileCtrl`、`LootCtrl` 的 Prefab 加载、表现同步和对象池；街机掉落关闭正式拾取 Collider，不注册 `Unit/Loot` 领域，仍由 `ArcadeCombatSystem` 独立裁决距离拾取、移动、命中、血量与波次。
- 街机掉落光柱由 `ResourcePickupView` 管理：金币使用较弱的金色光柱，临时武器使用蓝色，其它道具使用紫色；地址与外观绑定保存在 `TestResourcePickup`，重复同步不重建，模型替换、拾取和停用时一起释放，普通远征拾取物不启用光柱。
- 光柱、能量球和护盾分别选用备用库 ARPG Effects 的 `ItemEpicModular`、`BlueOrb` 和 `Shield`；所需贴图及材质独立复制到 `Game/Art/Effects/ArcadeARPG`，材质适配 URP，正式 Prefab 不引用备用库。`ArcadeDropLightning` 保留地址并用于能量球掉落和装备表现，`ArcadeShieldEffect` 保留实例挡伤闪光及恢复逻辑；各粒子系统上限为 32，不改变拾取范围、伤害或持续时间。
- 敌人、投射物与掉落的瞬时规则对象同样按配置上限复用；帧推进、命中、炸弹、拾取和敌群分离使用可复用工作列表，不按帧创建实体快照数组。
- 竞技场活动范围由规则与无渲染碰撞边界共同限制，不绘制可见围墙或风格化边框；场内轴对齐障碍由竞技场配置生成可见功能灰盒。
- 玩家、敌人和投射物共享同一套障碍判定；普通敌人直线路径受阻时按膨胀矩形的可见角点确定性绕行，移动后再执行受同屏上限约束的成对分离，避免穿障和模型重叠。Boss 锁向冲锋保持直线技能语义。
- 每个已配置竞技场包含四个敌群，即四轮；清除全部轮次才允许提交竞技场完成结果。
- 死亡消耗一条当前竞技场生命。仍有生命时由未来战斗模块在安全位置复活；最后一条生命耗尽时整局失败。
- 竞技场中的金币、掉落、击杀、位置、敌人、投射物和其它瞬时状态都不是安全存档。
- 同屏敌人、投射物和地面掉落必须遵守全局移动端预算；战斗模块不得自行放宽配置上限。

### 2.3 安全商店

- 新局创建、竞技场完成和每次购买成功都是安全节点写入时机；初始安全节点用于首场战斗开始后的退出恢复，不作为首次入场商店展示。若首次战斗尚未建立就失败，入口删除刚创建的新局；只有删除失败时才保留恢复入口。
- 局内金币只用于本局商店，不能兑换为基地货币。
- 商品可提供强化、额外生命、消耗品和临时装备。
- 商店按竞技场解锁范围和权重无放回抽取；价格为 `BasePrice + PricePerArena × (ArenaNumber - 1)`。
- 已达到强化配置层数上限的强化不会进入后续商店候选。
- 商店保存生成种子、刷新次数和实际报价。恢复时以已保存报价为权威，不因配置或随机实现变化而重抽。

### 2.4 奖励与结束

- 待结算正式奖励与局内金币完全分离，竞技场完成时只加入当前街机局的 `PendingRewards`。
- 只有安全商店阶段允许正式结算。
- 结算先以 `RunId` 把奖励原子写入基地存档，再删除街机局文件；删除失败时保留局文件供重试。
- 重试结算时，基地奖励账本识别已经结算的 `RunId`，不会重复增加奖励。
- 主动放弃或生命耗尽会删除街机局文件，不修改基地原有余额。
- 正式奖励目前保存为通用 `RewardId -> Amount` 余额；奖励如何消费或转换为正式物品尚未实现。

### 2.5 测试指令

独立测试指令界面提供“街机小游戏”分类。本地 `#arcade` 只作用于当前单人战斗；联机 `$arcade` 通过服务器目录下发并在 `OnlineRoom` 权威场景执行。指令层只解析测试意图，生命、资源、掉落、波次和完成事务仍由对应街机领域系统处理。

- `#arcade status`：查看竞技场、波次、生命、剩余命数、金币、资源、武器和敌人数。
- `#arcade heal` / `#arcade damage <正整数>`：测试恢复、正式受伤、护盾、无敌、复活与失败流程。
- `#arcade gold <正整数>`、`#arcade bombs <0-9999>`、`#arcade dashes <0-9999>`：调整当前竞技场瞬时资源；只有正式完成竞技场后才进入安全节点。
- `#arcade drop <DropId>`：按 `arcade_drop.csv` 的正式定义模拟拾取，可覆盖金币、紧急资源、临时武器和强化道具。
- `#arcade clear wave` / `#arcade clear arena`：沿用正式波次奖励、挑战完成和安全节点事务推进流程。

没有进行中的本地单人街机战斗时，以上指令必须明确拒绝，不创建新局、不准备地图，也不修改安全节点。

联机双人局提供同组服务器指令：`$arcade status`、`$arcade heal`、`$arcade damage <数值>`、`$arcade gold <数值>`、`$arcade bombs <数值>`、`$arcade dashes <数值>`、`$arcade drop <DropId>`、`$arcade clear wave` 和 `$arcade clear arena`。它们有以下边界：

- 必须登录、属于进行中的双人街机局，并且由当前房主执行；普通成员明确拒绝。
- 生命、金币、炸弹、冲刺和模拟拾取作用于房主角色；`status` 展示双方权威状态。
- 队友断线暂停期间拒绝修改；成功修改后服务器立即把新快照推送给双方。
- 清波和清场继续走正式奖励、过渡及安全节点提交流程，不由客户端伪造结算。

## 4. 安全节点数据

独立文件位于 `Application.persistentDataPath/Saves/arcade-run.json`，同时使用 `arcade-run.tmp.json` 和 `arcade-run.backup.json` 保证替换与恢复。它不属于基地存档的普通分区。

### 4.1 保存内容

- `RunId`、版本、更新时间。
- 已完成竞技场数量和下一竞技场编号。
- 剩余生命、局内金币、紧急资源和消耗品。
- 强化 ID 与已购买层数。
- 局内装备槽与产品 ID。
- 商店竞技场编号、种子、刷新次数、实际报价和购买状态。
- 尚未写入基地的正式奖励。

### 4.2 不保存内容

- 玩家在竞技场内的位置、动作、朝向、生命表现和瞬时状态。
- 当前轮次、击杀数和未完成竞技场的金币、资源或掉落。
- 敌人位置、生命、行为状态和寻路状态。
- 子弹、投射物、特效、场景对象和资源 Handle。

### 4.3 基地奖励分区

`ArcadeRewardWalletModel` 使用基地专属分区 `another-day.arcade-rewards`，保存通用奖励余额和已经结算的 `RunId` 集合。旧基地档允许缺少该分区，下一次成功保存会补齐空账本。

### 5.4 完整强化道具池

强化道具只存在于当前竞技场；不同类型可以同时生效，同类重复拾取会刷新持续时间、次数与固定设施锚点。单人由 `ArcadeCombatSystem` 结算，双人由服务器 `OnlineArcadeRunSystem` 结算并通过玩家战斗快照同步剩余时间和次数。

| 道具 | 核心规则 | 首次掉落场次 / 持续时间 |
| --- | --- | --- |
| 神圣护盾 | 抵消下一次有效伤害，消耗 1 次后结束 | 1 / 25 秒 |
| 疾行靴 | 移速提高 35%，与商店移速强化相乘 | 1 / 18 秒 |
| 宝物磁铁 | 拾取半径至少提升到 5 米 | 2 / 20 秒 |
| 战斗鸡伙伴 | 跟随持有者，每 0.45 秒向最近敌人射击 | 3 / 25 秒 |
| 自动哨戒炮 | 固定在拾取点，在 12 米内自动射击 | 4 / 20 秒 |
| 电能球 | 每 0.35 秒对玩家周围 2.4 米敌人造成伤害 | 5 / 18 秒 |
| 诱饵猴 | 固定吸引普通敌人，结束时在 3.5 米内爆炸 | 6 / 6 秒 |
| 防护爆桶 | 敌人靠近时自动范围爆炸，共 3 次 | 7 / 24 秒 |
| 旋转锯 | 每 0.25 秒伤害玩家周围 1.8 米敌人 | 8 / 18 秒 |

| 停滞怀表 | 全场敌人移动速度降至 45% | 10 / 8 秒 |

当前道具功能池已经完成；11 种道具均通过配置提供可替换的生效视觉 Prefab、跟随方式和位置偏移，现阶段允许复用简单占位资源。独立正式模型、跟随/环绕动画、爆炸和电击特效、音效仍属于后续表现工作。车辆、第一人称模式、Fates、钥匙、宝箱和传送门不是本表强化道具，继续由各自系统承载。

### 5.5 配置校验

运行配置首次加载时整体拒绝半可用目录，主要约束包括：

- `arcade.default` 全局规则必须恰好一行，初始值、预算和增长率必须在合法范围。
- 敌群 ID 唯一，敌人引用必须存在，数量和倍率有效，敌群同屏上限不得超过全局上限。
- 竞技场必须从 1 连续编号，每场必须正好四个有效敌群，Boss 标记必须符合全局间隔。
- 强化、商品、掉落和奖励 ID 唯一，枚举、价格、权重、数量和跨表引用必须有效。
- 临时武器与强化道具必须具有正持续时间，其它掉落不能伪装成限时效果。
- 武器命中行为必须是单体、贯穿、命中爆炸或定时爆炸之一；单体固定命中 1 个敌人，贯穿必须允许多个不同敌人且爆炸半径为 0，两种爆炸均固定消耗一次命中且半径必须为正数。

## 6. 调整数值与生效流程

1. 只修改对应的 `Config/DataCsv/arcade_*.csv`。只有新增字段、枚举、Bean 或表时才修改 `Config/Defines/`。
2. 在工作区根目录运行唯一生成入口：

   ```bat
   Config\gen.bat
   ```

3. 让 Unity 刷新资产，并确认没有配置加载或编译错误。
4. 至少定向执行 `ArcadeRunSystemTests`；禁止为验证街机改表而运行整个 EditMode 或 PlayMode 套件。
5. 使用新开局观察新数值。已有安全节点保存实际商店报价和购买状态，不会因改表自动重抽。

十一张街机表当前属于双端共享组。`gen.bat` 会统一生成客户端与服务端代码及 `.bytes`；修改任何街机表后必须同步更新 `arcade_rule.csv` 的 `ConfigFingerprint`，重新生成，并重启服务器后再验证联机模式。
