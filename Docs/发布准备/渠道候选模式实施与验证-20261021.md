# 渠道候选模式实施与验证

日期：2026-10-21。目标是积累国内 Unity 手游客户端的版本交付经验。本轮实现候选构建入口和实际 APK 自动检查，未执行游戏打包、手机安装或平台提交。

## 已实施范围

- 新增独立渠道完整包入口，复用现有 HybridCLR、完整内置资源、构建互斥及版本预留；原内部测试入口继续使用既有策略。
- 在切换平台、创建产物和预留版本之前，要求显式正式签名配置、独立公开证书策略及公网服务配置。缺失时拒绝继续，不回退到内部测试私钥。
- 渠道构建作用域关闭 Development、脚本调试和 Profiler，结束后恢复编辑器选项及签名设置。最终产物检查失败时保留已验签的 APK 和报告；渠道分支不调用内部资源服发布。
- 新增两个不打包的已有 APK 检查菜单。通过 aapt、apksigner、SHA-256 和 ZIP 读取实际产物的身份、版本、签名、架构、权限、调试标志及启动配置。
- 检查期间持有禁止写入和替换的读取句柄，避免不同检查步骤观察到不同文件。报告拒绝覆盖已有文件，始终标明 `deviceVerified=false`、`storeApproved=false`。

操作入口、环境变量和配置格式见 [使用说明](../../Tools/Android/渠道候选包使用说明.md)。渠道签名及公网配置由其所有者提供，本轮没有生成正式密钥或填入虚构部署地址。

## 保留的验证边界

没有调用 `BuildPipeline.BuildPlayer` 或触发任何 Unity 打包。候选构建主链、正式私钥应用、真实跨平台重载恢复及构建后报告的组合行为尚未通过实际构建验收；本轮的编辑器选项恢复和重载入口解析只经过限定测试。

公网地址检查只校验协议与字面主机形式，不验证 DNS、服务连通或 TLS。`REQUEST_INSTALL_PACKAGES` 作为待渠道确认的警告保留；隐私同意、平台 SDK、备案、防沉迷及平台审核均未因此完成。现有 CI 路由没有扩展。

红米 K50 Ultra 的人工安装、运行、性能、联机及存档升级测试按用户要求后置。未提交 Git 或推送。面试可表述为“实现 Android 内部包与渠道候选包策略隔离、实际 APK 自动体检和限定回归，并定位调试签名及内网地址问题”；不表述为已上架或正式运营。
