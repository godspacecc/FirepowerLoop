## 启动与隐私梳理

实际实现证据：

- [Launcher](../../Client/Assets/Boot/Launcher.cs) 在 Boot 期间调用诊断启动入口。
- [DiagnosticReportSender](../../Client/Assets/Boot/Runtime/DiagnosticReportSender.cs) 的 Tick 在配置有效、有待传记录且满足退避条件时可自动发送，不是只有点击上传才发送。
- LocalGameServer 模式从内网网关 IP 推导 `http://<IP>:31012/diagnostics/errors`。空 reportUrl 不会关闭该模式。
- [DiagnosticReportStore](../../Client/Assets/Boot/Runtime/DiagnosticReportStore.cs) 的统计字段包括来源、错误类别、位置指纹、版本、平台、日期、次数和 Boot 阶段等。
- [OnlineAccountSystem](../../Client/Assets/Game/Scripts/System/Online/OnlineAccountSystem.cs) 已有账号注册、登录链路；[账号快照](../../Client/Assets/Game/Scripts/Model/Online/OnlineAccountContracts.cs) 含用户名、账号 ID、玩家 ID 等状态。

因此后续隐私材料需要覆盖诊断及账号服务，不能按“只在本地保存分数”直接填写为不处理任何用户数据。本轮限定的源码、插件 Manifest 和包清单关键词检查没有找到 TapSDK、隐私同意或防沉迷接入记录；这不是完整的依赖或合规审计结论，下一步应核对实际依赖及启动调用顺序。

## 检查方法

使用 Unity 安装附带的 Android SDK `build-tools/34.0.0/aapt.exe`、`apksigner.jar` 和 OpenJDK，分别对两个已有 APK 执行：

1. `aapt dump badging <APK>`。
2. `aapt dump permissions <APK>`。
3. `aapt dump xmltree <APK> AndroidManifest.xml`。
4. `java -jar apksigner.jar verify --verbose --print-certs <APK>`。

以上 8 条命令退出码均为 0；这表示元数据读取及两份 APK 的签名完整性验证成功，不表示设备或平台验收通过。额外对 0.1.27 运行项目现有 `validate_android_signature.ps1`，退出码为 0，证书符合测试策略。文件 SHA-256、条目大小和包内配置使用 Python 标准库读取，未提取或执行包内代码。

Android 官方发布准备说明要求准备、构建和测试 release 版本，并区分调试与发布设置：[Prepare your app for release](https://developer.android.com/studio/publish/preparing)。目标渠道的具体 SDK、签名及权限要求在正式提交时另行核对。
