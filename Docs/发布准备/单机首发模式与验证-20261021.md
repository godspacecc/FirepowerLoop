# FirepowerLoop 纯离线单机首发

2026-10-21。首发学习路线采用独立的纯离线候选模式：玩家直接进入单人街机，分数、关卡安全节点和本局结果继续使用现有本地存档。既有双人对局及本局强化规则保留在内部和联网模式。

当前已完成代码及限定 EditMode 验证，尚无新离线 APK。根 AGENTS.md 禁止 Unity 打包与 Player Build，红米 K50 Ultra 人工测试继续后置。

## 模式与入口

| 模式 | Unity 菜单 | 服务要求 |
| --- | --- | --- |
| 内部测试 | `Tools/打包/Android/完整包`、`Tools/打包/Android/启动包` | 先联网更新，失败尝试缓存；完整包另有内置回退资源 |
| 联网渠道候选 | `Tools/打包/Android/渠道发行/渠道候选包完整打包` | 独立正式签名，公网资源、网关及诊断配置 |
| 纯离线单机候选 | `Tools/打包/Android/渠道发行/单机首发候选包完整打包` | 独立正式签名，完整内置资源，无公网服务要求 |

以上构建菜单仅供后续允许构建时使用。本轮没有调用这些入口。只读检查现有包使用 `Tools/打包/Android/检查工具/检查现有APK（纯离线单机，不打包）`。

命令行构建方法为 `Game.Editor.AndroidBuildUtility.BuildOfflineSinglePlayerCandidateBatch`。现有 CI 路由未扩展。签名沿用[正式签名本机配置](../../Tools/Android/正式签名配置记录.md)的两项环境变量；不复用内部测试证书，不改变旧包签名。

## 玩家侧行为

| 范围 | 离线模式行为 |
| --- | --- |
| 开始菜单 | 隐藏联机、检查更新及更新状态；保留新局、继续／结果、设置及退出 |
| 设置 | 隐藏网络分页；如果静态分页选择残留为网络，返回通用页 |
| 启动与资源 | 强制使用完整内置资源，资源缺失仍走原本地失败提示 |
| 更新 | 菜单与 ResourceUpdateSystem 均停止远程检查，更新由后续分发新版本完成 |
| 连接 | NetworkRuntime 在触及传输端口前拒绝 ConnectAsync |
| 诊断 | 不启动诊断驱动、不捕获统计组、不自动或手动上传；本地启动／运行日志仍保留 |
| 存档 | 继续使用 FirepowerLoop 独立存档；安全节点分数及失败结果可落盘并重读，不读取 AnotherDay 玩家数据 |

## 构建和实际产物校验

本次 Player 参数同时包含 `FIREPOWERLOOP_ANDROID_BUILTIN_RESOURCES` 与 `FIREPOWERLOOP_OFFLINE_SINGLE_PLAYER`。发布策略位于稳定的 `Boot.ClientReleasePolicy.OfflineSinglePlayer` 属性，Game 热更程序集读取该属性，避免把编辑器编译时的布尔常量内联到 Game.dll。

模式不写入全局 scriptingDefineSymbols；普通编辑器运行仍保持内部模式。`OfflineOverrideForTests` 仅在包含测试的编译中用于限定验证，每项测试结束均清理。

候选构建保持非 Development、正式签名、ARM64。每次实际 Player Build 的作用域关闭 Analytics 的 enabled、initializeOnStartup、packageRequiringCoreStatsPresent，结束或异常时恢复。后处理仅修改已生成的 launcher 主清单，用 Android 合并规则移除 INTERNET 和 REQUEST_INSTALL_PACKAGES，覆盖普通及 sdk-23 权限声明，并加入 `com.firepowerloop.release-profile=OfflineSinglePlayer`。

最终检查读取实际 APK 的清单和签名，要求：正确包名及版本、ARM64、独立正式证书、非 debuggable、非 testOnly、离线标记存在、两项权限缺失。不因编辑器设置正确就判定产物合格，也不以公网地址作为离线候选条件。报告为 `OfflineSinglePlayerCandidate`，同批输出名为 `offline-apk-check.json`，始终保留设备与审核未验证状态。
