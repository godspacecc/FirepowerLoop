# 美术资源库使用约定

## 1. 目录职责

- `Backup/Artifacts/` 是仓库根目录的备用资料目录，统一保存开发预览图、视频、音频、验证报告和日志；不放入Unity的Assets目录。制作工具后续输出及文档链接统一使用此位置，具体说明见[备用资料](../Backup/README.md)。
- `Client/Assets/Art/` 是项目本地备用美术资源库，保存尚未正式接入业务的完整资源包和候选资源。需要角色造型、Humanoid 动画、武器、场景物件、特效或图标时，应先搜索这里。
- Unity Package Manager 的 `My Assets` 是第二层备用资源入口，其中包含尚未下载或尚未导入当前项目的已拥有资产。
- `Client/Assets/Game/Art/` 是正式游戏资源目录，保存已经筛选、整理、重命名并由 Prefab 或运行时配置正式引用的资源。
- `Client/Assets/Game/Prefabs/` 保存正式 Prefab。Prefab 不应为了省事长期直接依赖备用资源库中的第三方原始文件。

`Assets/Art` 的“备用”含义是尚未完成业务接入，不代表资源可以删除、随意改名或直接修改。完整资源包也可能包含示例场景、演示 Prefab、材质、贴图、Avatar 和动画依赖。

## 3. 查找顺序

1. 先用 Unity MCP 或 `AssetDatabase` 按 `Model`、`AnimationClip`、`Prefab`、`Material`、`Texture` 类型搜索 `Assets/Art`。
2. 再使用 `rg --files Client/Assets/Art` 按角色、武器、动作或资源包名称缩小范围，例如 `character`、`soldier`、`attack`、`death`、`bow`、`rifle`。
3. 本地库没有合适资源时，再检查 Unity Package Manager 的 `My Assets`，记录可能匹配的资产名称、类型和用途。
4. 检查候选资源的 Avatar、骨骼类型、材质/贴图依赖、模型尺度、动画 Root Motion 和授权说明。
5. 与 `Client/Assets/Game/Art/` 已接入资源比较，确认不是重复导入，也不会破坏现有美术风格。
6. 确认采用后，只把必要资源及依赖整理到对应的 `Game/Art` 业务目录，并由正式 Prefab 引用。

## 4. Package Manager My Assets

- `My Assets` 中尚未下载的条目不属于当前工作区同步内容，也不能通过现有 Prefab、GUID 或 AssetDatabase 路径直接引用。
- 搜索阶段可以把它们列为候选，但下载和导入会向项目加入文件，应先确认具体资产和接入目的。
- 导入后先放在资源包原始目录进行检查，不直接改原文件；确定采用后再按本约定整理到 `Client/Assets/Game/Art/`。
- 如果某个候选只存在于 `My Assets`，方案中必须标记为“待下载验证”，不能提前承诺骨骼、材质、URP 兼容性或移动端性能。
