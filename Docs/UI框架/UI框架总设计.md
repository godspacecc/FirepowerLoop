### Esc 关闭指定阻断窗口

- 内容：默认 Esc 在存档、背包/仓库、运行日志或测试指令位于最上层阻断位置时关闭该窗口；没有阻断窗口时继续执行暂停或恢复。
- 目的：让常用非全屏窗口具备一致的键盘退出方式，同时避免 Esc 越过消息、设置、加载等其它阻断界面或恢复通用关闭任意窗口的旧动作。
- 修改简介：
  - `UIRoot` 固定绘制顺序为 `HUD < Dialog < Popup < Tips < Top`。玩法说明与暂停入口、手机背包与摇杆、玩家属性 HUD 使用 `HUD`，管理窗口以 `Dialog` 遮挡；普通窗口打开时背包与暂停入口保持显示，玩法输入仍由原门禁阻断，窗口打开时释放已按住的移动摇杆。活动对话期间隐藏背包、建造、口袋、移动和战斗控件及电脑操作提示；对话结束按当前设备与玩法条件恢复，保留虚拟输入设备、对话操作和测试指令入口。暂停入口保持可用，对话透明背景只转交暂停按钮区域的点击；对话中的 Esc 同样打开暂停菜单，继续后恢复原台词和选项。
  - 远征、街机与临时建造 HUD 同样位于 HUD；手机布局编辑属于 Dialog，测试指令窗口与可拖动测试入口属于 Top。物品菜单、Tooltip 和持久下载徽标位于 Popup，确认消息、资源公告和加载页保留 Top。Top 阻断窗口显示时清理临时 Popup 并拒绝重开；下载徽标保留进度，由更高层自然遮挡。UIHelper 在窗口显示或移顶时将可见测试入口移到 Top 最后，保证按钮仍可点击；入口不阻断玩法输入，测试窗口继续阻断。浮动提示和尸体纯展示提示不接收射线。
  - `UIHelper.GetTopmostBlockingUI()` 只读选择可见且阻断游戏的独立窗口，按固定绘制顺序判定优先级（保留枚举旧身份值），同层采用最后显示或最后移顶顺序。
  - `HotKeySystem` 保留唯一 `Esc -> game.pause.toggle` 默认绑定；最上层窗口仅对白名单中的 `SaveUICtrl`、`InventoryUICtrl`、`RuntimeLogUICtrl`、`TestCmdUICtrl` 调用既有 `Hide()`。
  - 非白名单阻断窗口会屏蔽其下窗口及暂停切换；非阻断 HUD 和提示不参与屏蔽。快捷键重绑期间 Esc 仍只取消捕获，Tab、F1、C 的既有窗口动作保持不变。
- 完成时间：2026-08-13。

### 独立窗口实例生命周期收口

- 内容：补齐 `BaseUICtrl` 的 View 实例销毁生命周期、架构事件所有权和无消费者逐帧入口清理。
- 目的：保证独立窗口在正常隐藏、活动销毁、隐藏后销毁和重新加载时，不遗留事件、公共生命周期委托、计时器或 Controller 临时状态，也不在销毁期间访问失效 View。
- 修改简介：
  - `OnHide()` 继续只表示存活 View 的正常隐藏；`OnUnload()` 在当前 View 实例销毁并完成加载/显示状态复位后调用一次，不补调 `OnHide()`。
  - `OnUnload()` 只处理外部订阅、公共生命周期、计时器和纯 Controller 状态；异常被完整记录，不恢复已经复位的状态。
  - 十个独立窗口在 `OnInit()` 注册的架构事件统一绑定到当前 `BaseUI` 销毁，View 重载不会累积旧订阅。
  - Expedition HUD、设置、测试指令、背包、通用消息和浮动提示按实际所有权拆分隐藏与卸载清理；Inventory 销毁期只复位选择状态，不查找或操作拖拽 View。
  - `BaseUI` 删除无人消费的 `OnTriggerUpdateEvent` 和私有 `Update()`，保留实例销毁通知。
- 完成时间：2026-08-10。

### 小型列表元素复用

- 内容：`CustomListView` 作为小型有限列表容器复用已经创建的列表元素。
- 目的：避免消息按钮、设置项和热键等列表在每次刷新时销毁并重新创建全部对象。
- 修改简介：
  - 缓存仅包含组件自身创建的元素，不接管其它子对象。
  - 数量相同时复用原实例；缩容时停用多余实例；再次扩容时优先重新启用缓存。
  - `ClearCells()` 将数量归零并停用缓存，不销毁元素。
  - 缺失元素 Prefab 时记录错误并保留当前活动元素。
- 完成时间：2026-07-28。

## 3. 总体设计说明

### 3.1 列表分类

- 小型、有限且需要整体刷新或拖拽的列表使用 `CustomListView`。
- 数据量无明确小上限或可能频繁变化的列表使用已有 LoopScrollRect 系列组件。
- 浮动提示继续使用自身的生命周期队列和对象池，不纳入通用列表组件。
- 缺弹提示通过固定身份 `combat.ammo_insufficient` 去重：等待队列或屏幕上同时最多一条，连发、重复点击、武器切换或语言变化不会叠加同类提示，也不延长原提示寿命；到期、隐藏或卸载后释放身份，允许再次显示。不指定身份的其他提示保留原队列行为。本地与联机缺弹分支共用这一入口。
- `CustomListView` 不扩展为无限滚动或虚拟化组件，避免重复实现 LoopScrollRect 已有职责。

### 3.2 `CustomListView` 责任

- 保存元素 Prefab、总数和单一元素刷新回调。
- 只维护自身创建的缓存元素。
- 每次刷新都重新调用活动元素的绑定回调，业务数据不保存在列表组件中。
- 不负责 Viewport、滚动位置或长列表虚拟化。

### 3.3 循环列表责任

- 存档和运行日志使用有限快照与明确 `totalCount`，不是网络分页或无终点数据源。
- LoopScrollRect 负责可视元素创建、回收、滚动和位置维护。
- Controller 负责取得数据快照、设置 `totalCount` 和按索引绑定当前元素。
- 循环元素必须在复用时清理旧按钮事件并绑定当前数据，不能依赖 Box 保存历史业务对象。
- 固定高度元素必须使用 `LayoutElement.preferredHeight` 为 LoopScrollRect 提供可靠行尺寸。

### 3.4 `BaseBoxUI` 责任

- 只表达“这是可复用 UI 元素 View”的类型身份。
- 不统一保存业务数据、事件注册状态或生命周期缓存。
- 具体字段由派生 BoxUI 声明，数据和交互由所属 Controller 的刷新回调接线。

### 3.5 Boot UI 边界

- Boot 场景只保留资源启动流程实际使用的对象与显示字段。
- UI 文本必须位于有效 Canvas 层级，或被明确的运行组件引用。
- 未绑定、没有父 Canvas 且重复出现的根级 UI 对象属于场景遗留，不承担运行职责。

### 3.6 消息弹窗交互

- 通用消息默认不允许点击背景关闭，避免用户绕过必须明确确认或取消的流程。
- 语言、分辨率、窗口模式等无副作用的选择弹窗可以显式启用背景取消。
- 点击背景只表达取消本次选择：关闭消息弹窗，不调用任何选项回调，不修改设置状态。
- 横向排列的消息按钮由元素 Prefab 提供稳定首选尺寸；文本保持单行，在有限空间内先自动缩小字号，再使用省略显示。
- 消息按钮的 `ButtonText` 只负责显示；确认、取消和具体业务值由 `MessageButtonRole` 或无参数回调表达。
- 按钮回调结束时只关闭发起该点击的原配置；回调同步替换为新配置后，不得由旧点击流程关闭新消息。
- 消息按钮可通过 `MessageButtonConfig.Interactable` 表达当前是否允许点击，默认保持可用；循环元素每次绑定都必须重设实际 `Button.interactable`，不能继承旧配置状态。

### 3.7 设置文本本地化职责

- 固定存在于 Prefab 中的标题、按钮文字和标签使用 `LocalizedText` 的 Key 模式。
- 当前语言、当前分辨率、窗口模式、快捷键名称和绑定值等动态内容由 Controller 根据模型刷新。
- 语言配置的 `Code` 是选择和持久化身份，`LocalizedLabel` 是按当前语言解析的显示文本；翻译缺失时才回退到配置原生标签。
- 快捷键冲突提示先把稳定动作 ID 映射为本地化动作名称；未知 ID 使用统一兜底文案，不直接显示给玩家。
- 同一个 TMP 文本只能有一个刷新责任；接入 `LocalizedText` 后，Controller 不再重复赋值。
- Prefab 序列化调整必须保持 TMP 文档连续，每个 `LocalizedText` 都是独立 MonoBehaviour 文档，并由契约测试固定关键组件和样式。

### 3.8 设置提交与重置职责

- 设置窗口使用左侧通用、音频、操作、网络分页；宿主只负责 Page 绑定与选择，各 PageCtrl 管理本页展示和交互。
- 语言、显示、音频和快捷键均即时应用，并继续通过 `SettingsSystem` 延迟写盘；关闭窗口不提供保存、取消或未保存确认。
- 窗口模式使用保存的分辨率预设作为实际窗口尺寸；无边框全屏模式跟随当前桌面分辨率，窗口大小行只显示“跟随桌面”并禁用。
- 切换无边框全屏不得覆盖保存的窗口分辨率 Code；切回窗口模式后继续显示并应用此前选择的窗口尺寸。
- 恢复默认设置属于当前分页：通用页恢复语言与显示，音频页恢复音量与静音，操作页恢复快捷键；网络页的两个服务器地址分别恢复安装包默认值。
- 当前只提供三个固定分辨率以及窗口、无边框全屏两种模式，不保留倒计时显示预览；若以后开放任意分辨率或独占全屏，应重新评估安全回滚。

### 3.9 Page 职责与生命周期

- Page 是完整宿主 UI 内部已经存在的子 View，不是独立顶层窗口。
- 宿主 Controller 负责加载 Prefab、绑定 Page、选择当前页，并在宿主隐藏时收起当前页。
- PageCtrl 不提供资源路径、UI 层级或 UIHelper 注册，只管理自身 View 的初始化、显示和隐藏。
- 同一绑定的初始化只发生一次；显示、隐藏、重绑、解绑和销毁必须保持幂等且不遗留旧 View 状态。

### 3.10 UI 异步调用

- 已经使用 UniTask 的 Controller 异步流程统一返回 `UniTask`。
- 同步 UI 事件启动不等待的 UniTask 时使用 `.Forget()`，不使用 `_ =` 丢弃返回值，也不改成 `async void`。
- 这种收口只统一调用表达，不改变下层系统为了共享并发请求而采用的内部任务机制。

### 3.11 输入消息职责

- 通用 Message 的正文模式与输入模式共享按钮、背景和显示生命周期，但状态必须相互隔离。
- 输入提交只把 Trim 后的文本交给业务回调；业务系统返回本地化错误文本决定是否留窗。
- 输入错误应靠近输入区域显示，不能占用按钮区或改用顶部独立输入框。
- 取消和背景行为不得隐式提交输入。

### 3.12 字体字符生成职责

- 字符扫描只读取确定为文本的资源格式；目录归属不能替代文件格式判断。
- `3500hz.txt` 是中文字体生成的字符源，TMP 字体资源必须完整覆盖该字符集和中文本地化表。
- 字体重建失败必须恢复原资源并报告错误，不得保留半生成状态。

### 3.13 测试指令 UI 职责

- TestCmd 是独立开发测试 Dialog，不与 RuntimeLog 合并；RuntimeLog 继续只负责日志查看、筛选和导出。
- TestCmd Controller 负责输入焦点、分类、模板、历史、说明和结果刷新，只发送命令，不直接修改玩法模型。
- 分类和条目展示 Catalog 的唯一数据源是 Luban 配置；`TestCmdModel` 只保存本次运行历史和最后结果，不复制分组或模板。
- Recent 是程序保留分类并固定在第一位，不参与正式分类的 Order 比较；其余配置和服务器分类、条目按 Order 和稳定 ID 排序。每次打开选中 Recent，历史说明使用最长模板前缀匹配且默认详情不会覆盖输入。
- 服务器目录和 `$` 指令唯一以 `OnlineAccountModel.Snapshot.IsAuthenticated` 作为账号门禁。未登录时不生成服务器状态分类、不请求目录，并仅在显示层过滤 `$` 历史；可见期登录切换取消旧目录请求并重绘，晚响应必须再次通过账号状态校验。
- 玩家状态分类的 `advance time` 只提交结构化游戏分钟参数，由正式领域入口处理时间、能量和伤害；UI 不修改时间缩放或模型。
- 玩家属性分类的五条 `set` 模板只提交固定字段和值；解析、范围、状态、领域修改、持久化和回滚均属于 TestCmd 与 PlayerAttribute 领域。
- 分类与条目使用循环列表；复用元素时必须移除旧按钮监听，再绑定当前数据。
- 指令名称、说明、语法和示例以稳定本地化 Key 保存当前 UI 语义，切换语言时重新解析显示文本。
- 阻断玩法输入继续复用 `UIHelper.HasUIOpen`，不得通过暂停世界实现。

### 3.14 可增长固定格职责

- 有明确容量但会逐步增长的固定格容器可以使用普通 `ScrollRect`、裁剪视口和固定列网格，不需要引入循环列表的数据绑定职责。
- 普通格 View 数量从领域容器容量取得；操作入口必须使用独立 BoxUI，不能伪造为具有格号的空物品格。
- 容量变化由领域事件触发整体刷新；Controller 不为显示效果直接修改容量，也不主动重置玩家滚动位置。

### 3.15 玩家条件表现职责

- 左下能量 HUD 属于独立玩家状态表现，不并入远征任务 HUD，也不重复显示生命。
- 能量背景与填充复用同一现有空心环资源；Controller 只驱动 Playing 显隐、Clamp01 比例、身份文本和数值，不加载 Sprite、不修改能量模型。
- “能”字与当前数值保持独立表现引用，圆环中心透明区域不得由实心图片遮挡。
- 玩家左下悬浮体力圆环随玩家 View 生命周期创建和释放；表现层只渲染公开比例、低体力和耗尽状态，完整红色耗尽圆环不反写权威体力。
- 玩家生命条、体力圆环和敌人生命条统一使用唯一 World HUD 置顶材质；位置仍由各自 Prefab 保存，运行时代码不通过位置补偿解决遮挡。
- 能量图标固定使用字符“能”，不随语言切换改变为其它词义或英文占位。

### 3.16 武器装备 UI 职责

- 装备格是独立领域槽表现，不属于背包或仓库容器，不得伪造 `InventorySlotRef`。
- 当前槽、选中状态、物品名称和图标每次从装备模型与物品配置刷新；UI 不保存第二份装备状态。
- 装备、替换、卸下和切槽只能提交给 `WeaponEquipmentSystem`，UI 不直接移动武器或标记存档。
- 空手文字是当前手持的非物品状态表现，不伪造物品 ID 或背包格；语言变化时重新读取本地化文本。

### 3.17 条件显隐按钮组职责

- 稳定顺序的按钮组发生条件显隐时，优先由 Prefab 布局组件排除 Inactive 元素并自动补位。
- Controller 只决定业务可见性，不维护按钮坐标、兄弟顺序或重复布局常量。
- 布局合同应验证实际可见元素的位置与间距，不能只验证 `activeSelf`。

### 3.18 Boot 覆盖层职责

- Boot 资源界面在 Main 场景和开始界面准备期间仍由 Boot `Launcher` 管理，不进入 `UIRoot` 层级，也不建立第二套通用 UI 框架。
- 全屏背景、Canvas 排序、Raycast 和 `HotUpdateView` 引用属于 Boot 场景的稳定序列化合同；运行时代码不创建背景或搜索替代引用。
- Main 只通过 Boot 提供的静态窄入口回报阶段、就绪和失败，不获取 Canvas、View 或其它 Boot Unity 对象。
- 就绪与失败是首写终态：就绪后延迟一帧释放 Launcher 和 Canvas，失败后保留覆盖层；重复实例不得覆盖当前所有者或留下第二套活动 Canvas。

### 3.19 独立窗口实例生命周期

- `BaseUICtrl.OnInit()` 对每个实际加载的 View 实例执行一次；随该实例存续的架构事件必须绑定到当前 `BaseUI` 销毁，不能依赖重置初始化标志自动反注册。
- `OnHide()` 只用于仍存活 View 的正常隐藏，可以清理输入焦点、回调和可见期表现；`OnUnload()` 只用于实例销毁后的非 View 清理，不能读取 `BaseUI`、派生 UI、Transform、子元素或把正在销毁的对象返回池。
- 同时属于隐藏和卸载的非 View 清理应提取为幂等私有方法；只属于存活 View 的清理必须留在 `OnHide()`。
- 销毁回调先确认实例身份，再复位加载与显示状态、通知 `UIHelper` 隐藏，最后保护调用 `OnUnload()`；旧 View 的晚到销毁不得影响新 View。
- 可见期间注册的事件和公共生命周期委托仍在 `OnHide()` 主动解除，并由 `OnUnload()` 兜底；Prefab 按钮、Toggle 和列表回调继续由 View 实例持有。
- `BaseUI` 不提供无人消费的逐帧 Update 入口；需要持续更新的职责使用已有公共 `LifeCycle`，并由实际所有者成对注册和解除。

### 3.20 运行日志状态职责

- `RuntimeLogUICtrl` 只负责提交清空意图、响应变化事件和刷新界面，不直接写入 `RuntimeLogModel`。
- `RuntimeLogSystem` 是运行日志采集、入模与清空意图的领域入口；其清空操作只清除 Model 中的当前集合，不修改 pending 队列。
- `RuntimeLogModel.Clear()` 继续发布既有 `RuntimeLogChangedEvent`，不得为清空动作建立第二套事件或通用命令层。
- 隐藏期间收到变化事件只标记 dirty，下一次显示时再读取最新快照。
- 运行日志筛选和当前虚拟列表快照只属于 Controller 表现状态；Hide/Show 保留筛选，View 销毁重载回到全部。
- 重新显示必须执行普通刷新以恢复权威详情，但不得套用筛选切换的强制最新语义；离底查看位置继续由循环列表保持。

### 3.21 库存双模式表现职责

- `InventoryUICtrl` 只维护一份选择、拖动、详情判断和领域调用；右侧玩家面板与基地仓库双栏是同一业务状态的两套序列化表现。
- 两套玩家背包格 View 可以分别缓存，但当前模式的公开格集合必须指向可见表现，测试和交互不得调用隐藏模式按钮或装备格。
- 模式切换只允许互斥显示 Prefab 根，不得在运行时重算或搬动 RectTransform；仓库模式的滚动位置和既有双栏布局不得受右侧面板影响。
- 右侧面板不提供取消选择按钮；重复点击当前选择、关闭界面或生命周期清理仍可取消选择。双栏仓库继续保留原取消选择入口。
- 热键名称、容量、物品详情、装备标签和操作文字必须从当前绑定与权威模型完整重绘，隐藏表现不能拥有第二份业务文本状态。

### 3.22 Esc 与最上层阻断窗口职责

- Esc 继续只有 `game.pause.toggle` 一个默认动作，不恢复通用 `ui.close-top`，也不由各窗口分别监听键盘。
- `UIHelper` 只负责按固定层级和同层显示顺序返回最上层阻断 Controller，不保存按键或可关闭类型，也不主动隐藏 UI。
- Esc 关闭范围固定为存档、背包/仓库、运行日志和测试指令；两种库存显示模式均关闭整个 `InventoryUICtrl`。
- 设置窗口位于最上层时，Esc 只关闭设置并露出其下菜单；消息、加载和其它非白名单阻断窗口继续屏蔽下层窗口与暂停切换，非阻断 HUD 和提示不参与屏蔽。
- 关闭统一调用 Controller 的 `Hide()`，继续执行输入焦点、拖动、选择、列表和临时回调等既有 `OnHide()` 清理。
- 游戏中暂停使用独立 `Home/Pause` Prefab 与 `PauseUICtrl`：居中半透明面板宽度固定为 `560`，高度由标题、可见按钮及留白自动计算；按钮组保持 `68` 高度和 `16` 间距，隐藏按钮时背景同步收缩，打开时立即刷新布局。面板提供继续游戏、联机游戏、设置、返回主菜单、退出游戏，背景只轻微暗化并保留游戏画面。“返回主菜单”仅在基地显示，打开全屏 `Home/Start` 并关闭暂停面板，保留暂停中的基地现场；点击开始菜单的继续游戏恢复同一活动世界，不卸载地图或重新读档。街机与远征不提供此入口，暂停面板不引用开始背景图。
- 没有阻断窗口时，Esc 在 Playing 与 Paused 之间执行暂停/恢复；暂停面板位于最上层时 Esc 也可恢复完整活动世界，重绑捕获期间 Esc 只取消捕获。设置关闭后保留暂停面板；恢复世界、地图加载或地图释放会清理暂停面板。

### 3.23 联机服务器地址编辑职责

- 设置网络页统一提供联机服务器与资源服务器两个独立输入、应用和恢复默认入口；登录界面不再显示地址编辑控件。
- 联机服务器使用 `IP/域名:端口`，保存后供下一次联机连接读取，不强制迁移或中断当前已认证会话。
- 资源服务器使用绝对 HTTP/HTTPS 根地址，玩家覆盖文件由 Boot 稳定程序集读取，并在下一次启动资源更新时生效。
- UI 只负责格式反馈和提交意图；安装包默认值、玩家覆盖、原子写盘与恢复默认分别由对应配置 Provider 管理。

### 管理任务与日志分页

- `TasksManagement` 与 `JournalManagement` 均嵌入 `Bag`，沿用全屏、统一关闭图标和底部导航，不创建独立窗口。
- 任务页采用分类、任务列表与详情三栏，读取 `ExpeditionTaskModel` 的当前远征快照和正式任务配置；支持进行中与已完成筛选，击杀数量和游戏内存活时长。
- 任务列表由 `CustomListView` 引用独立 `ManagementTask` Box Prefab；分页只展示，不推进任务、不授予撤离资格、不制作任务历史。
- 展示数据必须与当前离线地图、远征身份一致；语言及远征事件在显示时订阅，切页、关闭或重绑时释放。
- 日志页提供生存日志、笔记和收集内容三个固定分类，目前均为未开放占位；不使用诊断日志充当玩家经历，不提供尚无存档支持的笔记编辑按钮。
