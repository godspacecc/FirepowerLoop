# 可配置内容总览

本文面向策划记录：当前项目里哪些内容可以通过配置文件调整、改哪个文件、主要影响哪里，以及是否支持运行中动态变化。结论以当前已同步项目为准。

## 配置文件怎么用

配置源统一在根目录 `Config/DataCsv/` 下。策划通常只需要关注这些 `.csv` 文件；`Config/Defines/` 是字段结构，只有新增列、改字段类型或新增配置文件时才需要程序处理。

修改配置后，需要由程序通过 `Config/gen.bat` 重新生成并打进客户端或服务端资源。不要直接改生成后的文件。

## 新增远程武器配置指南

### 适用范围

以下步骤适用于新增一把沿用当前机制的远程武器：玩家朝鼠标指向发射一个直线投射物，成功发射时消耗一件指定弹药。伤害和攻击冷却来自武器配置；实际投射物速度和最远飞行距离来自投射物配置。

如果只是增加另一把弓、弩或其它“单发直线投射武器”，当前运行时代码按 `WeaponKind=Projectile` 通用处理，通常不需要新增 C# 逻辑。

以下能力当前不能只靠现有配置完成：换弹和弹匣、散射、多发、蓄力、连射规则、抛物线、射线即时命中、穿透、爆炸、范围伤害、命中特效差异和武器独立动画。需要这些行为时，应先由程序设计并扩展配置契约，不能通过把特殊含义硬塞进现有字段实现。

### 最小必填内容

新增一把可装备、可显示、可发射的远程武器，至少完成以下内容：

1. 在 `item.csv` 新增一条武器物品。
2. 在 `weapon.csv` 新增同 `ItemId` 的投射武器参数。
3. 在 `weapon_appearance.csv` 新增同 `ItemId` 的玩家手持外观。
4. 确认武器外观 Prefab 实际存在，并能被客户端资源系统按配置地址加载。
5. 在所有启用语言的本地化 JSON 中补齐物品名称和描述 Key。
6. 通过 `Config/gen.bat` 重新生成客户端和服务端配置输出；不要直接修改生成后的 C# 或 `.bytes`。

如果直接复用现有箭矢和箭投射物，则不需要新增弹药物品或 `projectile.csv` 行。武器配置可以继续引用弹药物品 `7` 和投射物 `projectile.arrow.basic`。

### 三张必填表怎么写

下面以“新增一把弩”为示例。示例暂用物品 ID `10`；实际填写前必须先检查当前 `item.csv`，保证 ID 在当前内容中唯一，不能把示例 ID 当成长期保留号。

#### 1. 物品基础：`Config/DataCsv/item.csv`

```
,10,弩,发射箭矢的远程武器,item.weapon.crossbow.name,item.weapon.crossbow.desc,,Weapon,1,None,0
```

关键规则：

- `Id` 必须为尚未使用的正整数，并作为后续两张表共同使用的 `ItemId`。
- `ItemType` 必须为 `Weapon`。
- 武器当前应保持 `MaxStackAmount=1`、`UseEffect=None`、`UseValue=0`。
- `NameKey` 和 `DescKey` 不能为空；配置中的中文名称和描述只是回退文本，正式显示优先使用本地化 Key。
- `IconAddress` 当前允许为空；需要显示独立图标时再填写实际资源地址并确认对应界面已接入图标显示。

#### 2. 武器战斗参数：`Config/DataCsv/weapon.csv`

```
,10,Projectile,14,1.1,16,0,projectile.arrow.basic,7
```

字段含义和约束：

| **字段示例规则**        |                          |                                                              |
| ----------------------- | ------------------------ | ------------------------------------------------------------ |
| `ItemId`                | `10`                     | 必须引用 `item.csv` 中 `ItemType=Weapon` 的现有物品。        |
| `WeaponKind`            | `Projectile`             | 远程投射武器固定填写 `Projectile`。                          |
| `AttackDamage`          | `14`                     | 必须大于 `0`。                                               |
| `AttackCooldownSeconds` | `1.1`                    | 两次攻击之间的秒数，必须大于 `0`；越小攻击越快。             |
| `AttackRange`           | `16`                     | 当前配置校验要求必须大于 `0`，但玩家投射攻击实际没有使用这个字段限制飞行距离；当前实际射程由投射物的 `MaxTravelDistance` 决定。不要只修改这里来调整远程武器射程。 |
| `MeleeArcDegrees`       | `0`                      | 投射武器必须为 `0`。                                         |
| `ProjectileConfigId`    | `projectile.arrow.basic` | 必须引用 `projectile.csv` 中已存在的投射物。                 |
| `AmmoItemId`            | `7`                      | 必须引用 `item.csv` 中 `ItemType=Ammunition` 的物品。每次成功发射消耗 `1` 件。 |

#### 3. 玩家手持外观：`Config/DataCsv/weapon_appearance.csv`

```
,10,Prefabs/Characters/Weapons/GrayboxCrossbow,RangedWeapon,0,0,0,0,0,0,1,1,1
```

关键规则：

- `ItemId` 必须同时存在于 `item.csv` 和 `weapon.csv`。
- 远程投射武器的 `AttachPoint` 必须为 `RangedWeapon`。
- `PrefabAddress` 不能为空，且资源必须真实存在并可加载。
- 位置和旋转必须是有限数值；三个缩放值都必须为正数。
- 挂点、位置、旋转和缩放只控制玩家手中武器外观，不改变弹道、伤害或攻击方向。
- 当前运行时会检查每一条 `weapon.csv` 都有对应的 `weapon_appearance.csv`；只增加前两张表会导致整组运行时配置校验失败。

### 本地化文本

在当前启用的每种语言文件中加入相同 Key。至少检查：

- `Client/Assets/Game/Config/Localization/zh-CN.json`
- `Client/Assets/Game/Config/Localization/en-US.json`

示例：

```
"item.weapon.crossbow.name": "弩",
"item.weapon.crossbow.desc": "发射箭矢的远程武器"
```

英文文件应使用对应英文文本，不能复制中文占位。编辑 JSON 时还要保持逗号和整体格式合法。

### 什么时候还要增加弹药或投射物

#### 使用新的弹药物品

如果新武器不使用箭矢，需要在 `item.csv` 再增加一条 `ItemType=Ammunition` 的物品，并将新弹药的物品 ID 填入武器的 `AmmoItemId`。新弹药也需要名称、描述、本地化文本，以及制作或掉落来源。

当前“背包里找对应弹药并成功发射后扣除一件”的行为是通用的，但缺弹浮动提示固定为“缺少箭矢”。使用子弹、能量电池等非箭类弹药时，如需正确显示具体弹药名称，必须由程序调整提示逻辑和本地化文本，不能只改配置。

#### 使用新的投射物

如果需要不同的飞行速度、最大距离或投射物外观，在 `projectile.csv` 新增一行：

```
,projectile.bolt.basic,Prefabs/Combat/GrayboxBolt,18,16
```

然后把武器的 `ProjectileConfigId` 改为 `projectile.bolt.basic`。关键规则：

- `Id` 必须唯一且不能为空。
- `PrefabAddress` 必须指向真实可加载的 Prefab。
- `MoveSpeed` 和 `MaxTravelDistance` 必须大于 `0`。
- 投射物 Prefab 必须符合当前 `ProjectileCtrl` 的组件与资源校验要求；任意已配置投射物 Prefab 无法准备时，可能导致地图投射物依赖准备失败。
- `projectile.csv` 只描述投射物的表现和移动距离，不定义武器伤害；玩家发射伤害来自 `weapon.csv`。

### 给武器增加正式获取来源

只完成武器本体配置后，系统能够识别、装备并使用该武器，但玩家不会因此自动获得它。至少选择一种符合玩法的来源：

- 测试发放：配置生成并加载后使用 `clone 10 1`，适合开发检查，不是正式获取来源。
- 制作：在 `craft_recipe.csv` 新增配方，产物 `OutputItemId` 指向新武器物品。
- 地图初始掉落：先在 `loot.csv` 新增指向新武器的掉落定义，再在 `map_spawn.csv` 用 `ObjectType=Loot` 放置该掉落。
- 敌人死亡掉落：先在 `loot.csv` 新增掉落定义，再由 `enemy.csv` 的普通掉落或保底武器掉落字段引用。

不要把“物品已经配置成功”和“玩家已经有正式获取途径”当成同一件事。

### 生成、加载与检查顺序

1. 检查所有新物品 ID、投射物 ID 和掉落/配方 ID 唯一。
2. 先补 `item.csv`，再补引用它的 `weapon.csv`、`weapon_appearance.csv` 和可选来源配置。
3. 补齐所有新 Prefab、图标及本地化文件。
4. 从工作区根目录运行 `Config/gen.bat`，一次生成客户端与服务端目标。
5. 不要手改 `Client/Assets/Game/Scripts/Model/Config/` 下的生成 C#，也不要手改生成的 `.bytes` 来绕过源配置问题。
6. 确认生成产物和新增 Unity 资源连同对应 `.meta` 一起进入交付范围，并按项目正式资源流程重新构建资源。
7. 进入游戏后先用测试指令发放武器和弹药，再检查装备槽、手持外观、切槽、瞄准、发射、弹药扣除、伤害和地图切换后的资源释放。

### 最终检查清单

- 新武器在 `item.csv` 中是唯一的 `Weapon` 物品。
- `weapon.csv` 和 `weapon_appearance.csv` 使用完全相同的 `ItemId`。
- 远程武器使用 `WeaponKind=Projectile`、`MeleeArcDegrees=0` 和 `AttachPoint=RangedWeapon`。
- `ProjectileConfigId`、`AmmoItemId` 及所有获取来源引用都真实存在且类型正确。
- 武器、投射物和图标 Prefab 地址真实可加载，本地变换数值有效。
- 所有启用语言都包含名称和描述 Key。
- 已通过唯一入口 `Config/gen.bat` 生成，没有手改生成文件。
- 已明确正式获取来源；如果暂时只有 `clone`，文档或任务中应注明仍是开发检查状态。
- 若需求超出现有单发直线投射机制，已经转为程序设计，而不是继续堆配置字段或复用不相干字段。

| 背包和仓库数量                             | 拾取、制作、消耗、结算、测试指令、存档        | 物品定义来自 `item.csv`，实际数量来自运行时和存档。       |
| 敌人生命、AI 状态、弹药                    | 战斗、AI、地图状态                            | 初始参数来自 `enemy.csv`，战斗过程由运行时系统控制。      |
| 掉落物名称和数量显示                       | 掉落配置、敌人死亡掉落、拾取刷新              | Prefab 来自 `loot.csv`，显示内容会按实际物品和数量刷新。  |
| 测试指令界面内容                           | `test_cmd_category.csv`、`test_cmd_entry.csv` | 配置只控制显示，不自动新增命令逻辑。                      |

## 当前不支持或待补齐

- 玩家衣服、护甲、皮肤、身体部件、多套外观方案：还没有配置文件、存档字段和运行时换装入口。
- 玩家尸体单独外观：暂不做；当前不作为玩家武器外观配置化的一部分。
- 敌人、NPC、掉落物、撤离点、临时建筑的运行中换外观：当前主要支持创建时换 Prefab。
- 非玩家单位的武器外观：当前还没有像玩家武器一样的独立外观配置和运行时装配逻辑。
- 运行中热改配置即时生效：当前只确认重新生成并加载后的配置生效，不确认游戏运行中热替换配置。

## 策划新增配置时先判断

1. 只是改已有数值、文案 Key、资源地址或排序：通常改对应 `.csv`。
2. 需要新增一列、一个对象类型或一类新配置文件：先和程序确认字段结构。
3. 需要玩家保存选择，例如已穿戴皮肤、当前套装：不能只加配置，还需要存档支持。
4. 需要运行中换外观：不能只填 Prefab 地址，还需要程序提供加载、替换和释放逻辑。
5. 需要新增实际玩法效果：配置只能提供参数，规则仍需要程序实现。
