# 随机河谷与白天出发设计

日期：2026-10-07。状态：已按确认方案接入首版生成地形、随机白天出发与探索保存。自动化验证通过；完整人工试玩与移动设备性能待验收，见同目录《随机河谷与白天出发验证记录-20261007》。

## 目标与范围

玩家希望目的地需要探索才能找到，而非扩大一个可以背路线的固定地图。采用每次新远征生成河谷布局、利用地形与线索寻找旧营地的方式；同一次远征读档保持布局不变。用户补充要求开局不是晚上，允许每次随机时刻：新远征从第 1 天 08:00～12:00 随机出发，累计耗时从零开始。

首版只改离线文明河谷的地图生成与探索内容；出发时刻统一用于新建的离线生存和任务远征。基地与联机地图保留现有正午表现。保留当前斧头砍树、镐头采石、河岸取水、木棚建造及返程兑换规则。木棚暂不增加休息、跳时或避寒能力。和家村、联机地图、街机局及建筑模型制作不在本次地图生成范围。

## 现状依据

- 当前河谷地表约 60×60 米，边界内可活动范围约 58×58 米；布局和交互点是固定场景内容。
- 玩家默认移动速度为 5 米/秒，现实 1 秒推进 1 游戏分钟。因此仅把地表扩大到 256 米，直线穿过也只需约 51 秒，无法提供希望的远行体验。
- 现有 MapTerrainGenerator 根据高度图生成 Terrain 场景；MapSceneSystem 多场景模式依次加载全部场景。它们不是现成的随机远征或距离流式加载系统。
- ExpeditionModel 的 ElapsedGameMinutes 同时用于耗时、目标进度、HUD 日期和昼夜。DayNightVisualSystem 直接计算其一天内进度，所以耗时为零时显示午夜。
- MapSceneSystem 已有隐藏候选地图、控制器准备、按顺序提交和逆序释放事务。CivilisationSceneCtrl 在地图提交后绑定场景内的交互 View；交互规则来自运行时配置目录。

上述依据来自当前工作区实现，不把设计中的生成能力当作已有功能。

## 地图生成与探索

### 地图尺度与节奏

初始生成参数采用 1024×1024 米边界。地表尺寸用于提供布局空间；距离和时间以实际 NavMesh 路径验收，不以直线距离验收。

普通步行到旧营地的主路线目标为 1.8～2.4 公里，对应 6～8 游戏小时。加上辨认方向、搜索与采集，首次找到旧营地目标为出发后 7～10 游戏小时，完整往返目标为 12～16 游戏小时。它们是试玩调参目标，不是强制计时门槛；熟练玩家找到捷径后可以更快。

白天出发后，首次找到营地可能落在下午、傍晚或夜间，返程可能入夜。只保证开局为白天，不强制整个远征保持白天。保持现有时间比例，不另外加倍时间流速或降低基础移动速度。

### 先生成拓扑，再生成地形

每次新远征以独立随机种子生成区域连接图：出发区、河岸区、林坡区、旧营地区和资源支路。再根据连接图生成河道、坡地、过河点和可通行走廊，最后摆放树木、岩石和交互点。

- 出发点和旧营地从有效区域中选择，满足完整可走路径及上述路径长度区间。
- 每局改变河流走向、过河点位置、山口和支路连接关系；不只随机更换树木位置。
- 至少两种可选行进方式：较长、较易获得水的河岸路径，以及较短、补给较少的林坡路径。具体方位随种子变化。
- 河谷仍遵循可读的自然规律：旧营地位于上游较高地势，水流、岸线和坡势能辅助判断方向。
- 资源支路可以绕行，但必要目标与基础补给必须连通。首版不生成必须靠砍树或搭棚才能通过的路障。

### 线索与返程

初始提示只告知“沿河寻找上游旧营地”，不暴露准确坐标。可搜索的遗留痕迹逐步提示通向上游的过河点、坡地旧路和营地所在区域；线索与本局连接图绑定，避免指向阻断路线。

必经探索区域内配置至少两条可以独立帮助定位的线索链，线索搜索后可以重读。线索不负责解锁道路，也不成为必须按固定顺序点击的任务。

不在开局通过全图目的地标记或方向箭头泄露目标。玩家找到旧营地后可获得通往已探索区域的返程捷径；捷径在同局内持久保存，读档不会重新关闭。没有发现捷径时仍能沿原路返回，不制造单向死路。

## 采集、建造与稳定身份

保持现有采集耗时、产量、工具要求、背包校验、失败丢失和兑换数值。砍树与采石仍每点每局一次，水源仍可重复采集。

生成结果为每个点记录稳定 ID、规则模板 ID、位置和朝向。ID 来自生成清单的稳定序号，不使用 Unity InstanceID，也不依赖 View 出现顺序；同局重建时保持一致。静态 Luban 配置保存规则模板，当前地图实例提供生成点目录；搜索和表现消费同一份地图目录，不向全局配置 Provider 写入临时点。

一次性采集点的访问状态、线索状态与返程捷径状态按稳定 ID 保存。恢复时先生成原地图，再投影这些状态；已采树木和岩石不复活，水源不隐藏。木棚沿用当前保存位置和拆除退款流程，恢复时验证它属于本局地图并位于允许建造区域。

现有固定河谷存档继续按原场景和原交互点 ID 恢复；不把已进行的旧远征自动迁入新布局。新远征继续使用原稳定地图 ID，通过生成版本区分固定内容和随机内容。

## 随机白天出发与时间语义

在远征存档增加独立的起始钟表分钟与明确的时钟格式版本：新建离线远征从整数分钟区间 [480,720] 均匀随机选取一次起始钟表分钟，即 08:00～12:00，ElapsedGameMinutes 仍为 0。该时刻在远征创建事务中选取并保存，加载、读档和地图候选重试不重新抽取；不消耗地形生成的随机数序列，避免时间规则变化影响地图布局。钟表总分钟由两者相加推导，昼夜和日期显示消费这个推导值，不创建另一个逐帧推进的计时器。

下表以本次随机抽到 08:00 为例；其它起始时刻使用相同换算规则。

| 场景 | 累计耗时 | 显示时间 |
| --- | --- | --- |
| 新远征开始 | 0 分钟 | 第 1 天 08:00 |
| 行进 2 游戏小时 | 120 分钟 | 第 1 天 10:00 |
| 行进 16 游戏小时 | 960 分钟 | 第 2 天 00:00 |
| 读档 | 保存的耗时 | 根据保存的起始时刻恢复 |

生存消耗、任务达标、结算条件只使用累计耗时。任务的“目标时长”用时长语义显示，不能当作起始时刻偏移后的日期。远征 HUD 与昼夜快照必须统一使用同一钟表换算。当前地图选择显示的是任务目标时长，不是保存的钟表时刻；该处只调整时长语义，不叠加出发偏移。

旧存档缺少新增时钟版本时，解释为原来的 00:00 出发，保持恢复时刻和光照不跳变。新版本校验起始分钟为有限值且处于 [0,1440)，克隆、保存、恢复和失败回滚均保留这个字段。暂停、加载、基地和远征结束后的推进条件沿用当前实现。

## 职责、存档和加载事务

- 远征领域状态保存生成版本、种子、完整布局清单、时钟起点及访问状态。布局清单含地形必要参数、连接图、出生点、目的地、交互点和捷径身份，不能只存种子而依赖后续算法恰好不变。
- 生成规则负责纯数据候选生成、连通约束和确定性随机计算。使用局部随机数源，不改变 Unity 全局随机状态。
- 地图加载适配负责创建 Unity 地表、碰撞、资源实例和 NavMesh，资源归属当前候选 Handle；MapSceneSystem 保持地图事务权威。CivilisationSceneCtrl 负责提交后的绑定与表现，不承担生成规则或存档写入。
- ExpeditionFlowSystem 沿用远征进入/恢复事务。候选生成失败不能消耗物品、改变旧远征布局或提前开启计时。

加载顺序：取得新局候选清单或已保存清单 → 在隐藏候选地图中创建地表与碰撞 → 构建 NavMesh → 验证出生、目标、过河点、必要补给与路径长度 → 准备玩法控制器 → 沿既有地图事务提交并激活 → 绑定交互表现。

每次异步完成后校验取消标记、请求代次和地图归属。失败按已完成步骤逆序释放 Mesh、NavMesh、实例和资源 Handle，避免过期结果接入当前地图。生成候选最多重试 8 次；全部失败时明确报告进入失败并恢复既有安全状态，不交付不可达地图。读档清单验证失败时停止恢复，不悄悄换一个新种子。

首版地表采用分块网格与视距裁剪，所有块归属一个地图上下文并在加载期间准备完整导航；不把现有多场景加载宣称为距离流式加载。先复用正式引用的河谷自然资源；需要额外资源时按仓库美术接入规范处理。

## 验收

1. 多个固定种子的布局测试验证出生/目标/必要补给连接、主路线长度、线索链和两种通路；检查不同种子改变路线拓扑，而非仅改变装饰。
2. 同局保存恢复后地形、点位、已采集状态、木棚与捷径一致；新局生成新的种子，重新初始化该局访问状态。
3. 新远征抽取的时刻始终处于 08:00～12:00，区间两端光照均为白天；0、120、960 分钟的时间换算符合上表，另覆盖 12:00 起始与跨日。旧存档保持原时刻，读档及重试不重新抽取或重复增加起始偏移。生存目标、消耗与失败回滚继续按累计耗时执行。
4. 验证取消、候选无可走路径、资源加载失败和读档清单错误，确认无提前提交与残留地图资源。
5. Unity 测试仅用经核对的类/方法过滤，执行前声明最大数量，审计执行名称；不运行完整套件，不触发 Player Build。
6. 在编辑器中实际试玩不同种子的寻找与返程，验收线索是否清楚、昼夜衔接、河岸取水、采集和拆除是否正常。代码测试不能代替画面与行进体验验收。
7. 在既有设备上记录地图加载耗时、帧耗时和内存，再决定是否需要下一阶段流式加载；当前没有测量证据，不承诺移动设备性能或给出虚构预算。
