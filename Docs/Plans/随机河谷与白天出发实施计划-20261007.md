# 随机河谷与白天出发实施计划

> **For agentic workers:** 使用仓库 `executing-plans` 技能在当前会话逐项实施；此执行方式已获用户确认。不得因通用技能默认建议而启动子代理、创建 worktree 或自动提交。步骤以复选框记录。

**Goal:** 每次新远征在白天随机出发，新文明河谷通过不同的可走路线与线索寻找旧营地，同局读档保持地图与探索状态。

**Architecture:** ExpeditionModel 保持远征计时和布局保存权威；纯数据生成器产生稳定清单，地图构建 Utility 在 MapSceneSystem 隐藏候选事务中创建地形、导航和交互物。地图点目录随地图句柄提交，搜索 System 负责原子状态变化，ViewCtrl 只投影规则与状态。

**Tech Stack:** 当前 Unity、QFramework、UniTask、UnityEngine.AI、Newtonsoft.Json、Luban、YooAsset；不增加产品依赖，不调用 UnityEditor API 执行运行时生成。

**Spec:** [随机河谷与白天出发设计](随机河谷与早晨出发设计-20261007.md)。状态：实施计划待审阅，未修改产品代码。

## Global Constraints

- 新建离线生存和任务远征，起始钟表分钟在整数区间 [480,720] 均匀随机一次；耗时仍为 0，现实 1 秒推进 1 游戏分钟。
- 基地、联机地图保留正午表现。旧远征无时钟版本时沿用 00:00，无生成清单时沿用固定场景。
- 首版随机地图只用于新文明河谷远征，原地图 ID 不变；和家村、街机及联机地图不改。
- 初始地图 1024×1024 米，可走主路线 1800～2400 米；探索往返 12～16 游戏小时是试玩目标，不增加计时门槛。
- 保留采集数值、工具要求、背包与访问记录原子提交、木棚退款和返程兑换。木棚不增加休息或跳时。
- 同局保存完整布局清单与版本，读档不重新生成、不重抽出发时刻。最多尝试 8 个生成候选。
- 当前本地 checkout 与 Unity MCP 继续使用；测试必须有有效类或完整方法过滤，includePassingTests=true，先声明模式、过滤和最大数量，后审计实际名称与数量。
- 禁止完整测试套件、空过滤探测、打包、Player Build、手改生成文件。核心类、函数及关键字段补中文注释。
- 保留并行任务与设备文件改动；用户要求提交时才提交本任务文件，提交说明用中文。

## Review Focus

1. 无时钟/布局字段的旧远征：恢复原光照、点 ID 与木棚位置，不能自动迁移新地图。任务 1、2、4 验证。
2. 地图提交完成但首次存档写入失败：恢复基地与背包风险，不能遗留可游玩的无存档远征。任务 4 验证。
3. 候选地形有坡度且活动基地 NavMesh 同时存在：距离校验使用完整坐标，路径验收不能误走基地导航。任务 3、5 验证。
4. 读档清单遭破坏或生成版本不支持：拒绝恢复并保留文件，不能换种子或局部修补后继续。任务 2、4 验证。
5. 跨地图的迟到行动与重复释放：不得为新地图发物品或释放新地图资源；采集事务失败仍能回滚。任务 3、5 验证。

## 文件与接口约定

所有现有路径已在工作区核对；标为“新建”的路径和类型是本计划约定，不代表已经存在。新增 Unity 文件配套 `.meta`，测试不制作或改写正式资产。

- 时钟只增加起点，不增加第二个计时器。保留 ExpeditionSaveData 顶层版本 3，以 ClockSchemaVersion=0/1 区分旧/新时钟。
- 生成布局存入 ExpeditionSaveData.ValleyLayout（可空），ExpeditionModel 持有其独立副本；不再在另一个 Model 保存一套布局。null 明确表示旧固定河谷。
- 生成器按模板 ID 读取 CivilisationCatalog 的规则，不修改原 CSV 点坐标或原 Provider 集合。动态目录包括真实 Vector3 坐标，使用完整三维距离。
- MapPreparationContext 增加仅供候选阶段使用的布局和点目录；提交前不能向当前 MapSceneModel 发布它们。活动目录通过 CurrentHandle 的生成句柄查询，不复制一份到 UI。
