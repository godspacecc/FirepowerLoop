# 远征首轮制作实施计划：旧营地与干粮

> **For agentic workers:** 使用 `executing-plans` 在当前本地会话逐项实施。步骤以复选框记录；不自动创建 worktree、派发子代理或提交 Git。

**Goal:** 在现有游戏中完成“基地出发—搜索干粮工艺—返回解锁并兑换收获—基地生产—携带干粮再次出发”的可玩闭环。

**Architecture:** 新增旧营地地图及文明远征专属状态；沿用现有地图事务、行动交互、背包和存档入口。永久科技由基地 Model 持有，当次科技由远征 Model 持有，搜索与生产规则由 System 执行；Controller/View 只负责交互和表现。新结算策略仅匹配新地图，使用候选存档原子提交，沿用既有远征 ID 去重。

**Tech Stack:** Unity、URP、QFramework、Luban、Newtonsoft.Json、NUnit、Unity MCP。

**Spec:** [远征第一阶段资源驱动方案](远征第一阶段资源驱动方案-20261005.md)、[游戏玩法需求记录](游戏玩法需求记录-20261005.md)。

**状态：** 用户已确认并授权实施，已写入科技、结算、生产与搜索代码以及干粮生产 UI。制作途中 Unity MCP 调用失败，按项目约束暂停；新地图、结算窗口和完整闭环尚未交付。恢复连接后按[实施进度记录](远征首轮制作进度-20261005.md)继续，不重复已完成调查。

## 首轮边界与调参值

这是首阶段制作顺序中的前两项：美术操作样片与干粮闭环。湿地、寒风、有限休息、绳索、种植和下一阶段入口按后续批次接入；本轮完成不代表整张首阶段地图已经完成。

新增地图 ID `map.another-day.civilisation-valley`，名称“旧营地河谷”。先做约 60 × 60 米的起点、林缘、旧火塘与储藏处，通过既有基地地图选择入口进入；返程入口始终可用。第一轮不使用走路时长模拟完整 8～12 分钟体验。

新增科技 ID `technology.dry-ration`。工艺样本是专属科技状态，不以普通物品或现代图纸代替；首轮 UI 显示两格科技携带栏，但地图仅放一项科技。

新增普通食物物品 ID 29“采集食物”、ID 30“干粮”，实施前再次校验 ID 未被其他修改占用。采集食物恢复 20 点现有 Power、每格最多 2 份；干粮恢复 60 点、每格最多 2 份，使用时长均为 1 秒。只复用现有 Power 规则，本轮不新增营养模拟。

基地生产一份干粮消耗 8 金币，表示购买和加工原料；干粮返回兑换 4 金币，采集食物兑换 2 金币，木材兑换 2 金币。免费基础准备领取一份采集食物，领取及当次标识一起保存，每趟只领取一次；该免费份不能兑换，避免反复进出刷钱。科技点附近固定提供两份可兑换的采集食物和两份木材，共 8 金币，以支持首次生产；首次科技点不是空手玩家无法启动的经济门槛。

首轮沿用现有普通背包容量，不全局改成 6 格；6 格携带和准备取舍放在环境挑战批次一并制作。新地图出发前展示当次物品返回会兑换的提示，基地已有物品可先存仓；不能悄悄把玩家背包里的旧装备清除或自动赠送金币。

## 调查结论与风险重点

1. 现有 `SaveSystem.ApplyExpeditionSettlement` 成功返回保留背包，尚无科技解锁与兑换；必须按新地图分派，避免影响旧地图。
2. 结算可能已经写入基地，但远征文件删除失败；相同远征 ID 重试不能重复发钱或解锁。
3. 新科技分区缺失代表旧版存档；只允许显式迁移为空科技，错误类型、未知版本和损坏内容不能默认吞掉。
4. 背包中的未知兑换物、金币溢出、生产背包满和存档写入失败都必须无损失败；不能先扣钱再报告失败。
5. 场景卸载、搜索中断和读档会影响目标身份；使用地图实例 ID 与稳定搜索点 ID，不能重复取得或产生幽灵交互。
