# 联机三维弓箭设计

状态：方案方向已确认，具体架构设计待用户审阅；尚未实施联机改动。

## 目标与范围

玩家弓箭在联机世界中真正飞行，到达目标后才造成伤害。第一人称和第三人称都以准星确定三维目标，从实际发射点向目标发射；俯视角保留水平瞄准，近战继续使用水平朝向。双端共享现有投射物速度和最大距离配置。

本次保持直线匀速，不新增重力、风偏、穿透、爆炸、爆头或玩家之间的伤害。枪械即时射线是后续武器设计方向，本次不顺带转换已有枪械。敌人攻击、临时箭塔和独立街机规则不纳入本次玩家弓箭改动。不运行 Unity 打包，不自动提交其他待改文件。

## 已核实的实现基础

- 客户端 `PlayerInputSystem`、`WeaponSystem` 已有本地第一/第三人称准星射线和发射点修正；`ProjectileSystem`、`ProjectileView` 已能保留三维方向。这些改动仍未提交。
- 联机输入分支目前没有携带准星射线，`OnlineWorldSystem.TryRequestWeaponAttack` 只传水平 AimX/AimZ。
- `OnlineWorldComponentSystem.MeleeAttack` 在开火时扣弹并通过 XZ 路径立即结算敌人伤害；没有远征弹体运行态。
- `OnlineWorldComponent.Tick` 已有服务器世界推进入口，地图状态有 WorldId、MapId、敌人位置和玩家生命周期，适合承载弹体状态。
- 服务器没有 Unity 场景碰撞数据，不能直接调用 Unity Physics 检测地形或障碍物。
- `Config/DataCsv/projectile.csv` 中基础箭速度为 14 米/秒，最大距离为 14 米，已有回收掉落配置。
- 协议源为根目录 `Config/Proto`，唯一生成入口为 `Tools/gen-protocol.ps1`；生成代码不手改。

## 数据与权威边界

客户端提交攻击序号、玩家生命周期、武器身份、发射点和归一化三维方向。客户端给出的目标只用于确定方向，不能提供伤害结论或绕过服务器碰撞。

服务器先验证会话、地图、生命周期、序号、装备、弹药、冷却、浮点合法性和发射点范围。发射点必须位于当前权威玩家位置附近，并通过服务器的静态遮挡检测；不得允许相机越过障碍物替代枪口出生位置。发射点合法范围取实际玩家/武器发射点资源合同，建立具名规则与测试，不通过放宽阈值掩盖坐标错误。

合法请求原子扣除装填数、更新冷却并创建弹体。创建失败不消耗弹药，也不推进攻击序号。已接受的重复序号不会重复生成、伤害或回收掉落。

每支箭携带服务器 RuntimeId、WorldId、MapId、发射者 UnitId/生命周期、攻击序号、投射物配置 Id、位置、方向、速度、剩余距离、伤害和服务器时间。身份和伤害在接受攻击时锁定；客户端 View 不能修改这些值。

## 服务器推进与碰撞

复用世界 Tick，按服务器实际经过时间推进，距离不超过剩余射程。对上一位置到下一位置做连续三维碰撞查询，避免单帧越过敌人或薄障碍物。

动态目标使用服务器位置和从实际敌人资源提取的碰撞代理；代理数据明确中心偏移、尺寸、坐标系和资源来源，不再沿用水平半径忽略高度。静态场景使用离线导出的碰撞数据，查询地形和障碍物。按沿飞行路径的首个接触结算；静态遮挡与敌人命中距离相等时优先遮挡，目标并列时用稳定身份排序。

敌人命中调用现有服务器伤害/死亡/掉落入口。箭碰到场景或射程耗尽后结束；未命中敌人的箭通过既有回收掉落事务在实际终止点附近落地，避免在空中生成可拾取物。一次终止只能伤害或回收一次。

玩家死亡或离开地图时清理其尚未结束的箭，避免跨生命周期伤害；断线宽限期间保留已被接受的箭继续飞行。地图销毁释放全部弹体。

## 静态碰撞数据

新增 Unity Editor 离线导出工具，读取正式地图资源中的启用、非 Trigger 静态 Collider 和 TerrainCollider，导出地图本地坐标下的碰撞几何。忽略运行时角色、拾取物和表现触发器；动态临时建筑不作为本次静态数据的一部分。

数据包含地图 Id、格式版本、源资源依赖哈希、地形/网格三角形及原始基本形状。服务器建立空间索引，用箭的连续碰撞体查询候选，再精确判断首个接触。箭的碰撞尺寸来自实际投射物 Prefab，与客户端表现保持一致。支持类型必须有测试；不支持的 Collider 在导出时明确失败，不静默遗漏。

导出数据作为共享项目产物随服务器发布，导出不触发 Player Build，也不保存当前 Boot 的临时场景状态。客户端和服务器使用一致的地图碰撞版本；数据缺失、版本不匹配或读取失败时拒绝该地图的新弓箭请求并返回可诊断错误，不回退到穿透场景的即时伤害。

这一环节比仅追加 AimY 更大，但用于保证真实飞行同时具备可信遮挡。

## 协议与客户端表现

在现有攻击消息末尾追加三维瞄准/发射点字段，保留原字段编号。增加弹体快照和出生、终止增量消息，携带稳定身份、版本和服务器时间。进入地图或重连全量快照包含仍在飞行的箭；事件丢失后的收敛也以快照为准。

Gate/Player 只负责验证身份与转发，World 负责弹体权威。新字段和消息均从 `.proto` 正式生成。MemoryPack 混合版本兼容不能仅靠追加字段保证，客户端与服务器需配套更新。

客户端 `OnlineWorldSystem` 合并快照和增量，拒绝跨地图、旧生命周期及旧版本消息。弹体表现使用与本地伤害状态隔离的命名空间，复用 `ProjectileCtrl` 的资源准备和 `ProjectileView` 三维姿态，通过共享生命周期按服务器时间播放直线飞行。不得创建本地 `ProjectileSystem` 伤害实体，也不得用本地碰撞自行决定敌人扣血。

开火输入立即反馈动作；箭的可见实例由服务器接受后的出生消息建立，首版不增加可造成双箭的本地弹体预测。消息到达较晚时从服务器时间推算当前位置，终止消息优先于后到的出生消息；地图卸载、取消加载、退出和重连收敛都清理过期实例和资源引用。

## 验证与验收

- 服务器定向测试：开火瞬间不扣敌人血；经过正确飞行时间才命中；上射、下射、同 XZ 不同高度；薄障碍物、地形遮挡和最近命中；重复序号、非法发射点、NaN、弹药原子消费、射程终止、只回收一次、死亡/离图清理。
- 客户端定向 EditMode 测试：第一/第三人称联机输入保留垂直方向；俯视和近战行为不变；协议序列化；晚到消息、终止先到、快照重连、地图切换和表现资源释放。
- 静态数据测试：坐标变换、Terrain/基础形状/网格首接触、错误格式、不支持 Collider 和资源哈希不一致时失败。
- 每次 Unity 测试仅指定有效短类名或完整方法名，调用前声明最大执行数，并审计实际结果。不运行整个测试程序集或全套测试。
- 双客户端画面验收：互相看到同一支箭上下飞行；箭飞到敌人时才扣血；障碍物遮挡；重新连接仍能看到未结束的箭。自动测试不代替画面验收。

## 实施顺序

具体设计审阅通过后，再形成逐步实施计划：先协议和可测试的服务器弹体/碰撞规则，再静态数据导出与校验，随后接入三维联机输入与表现，最后做定向验证和双端验收。未完成碰撞数据接入前，不将联机弓箭实现标记为可用。
