# 和家村全图粗布局实施计划

> 目标：先让四块场景显出道路、水域和林地的大致空间关系；占位物可按来源重新生成，细节在下一轮处理。和家村不制作建筑或建筑占位。

## 输入与边界

- 道路使用已有 `HeJiaVillage_VerifiedRoads.json` 与已生成的 Terrain 泥土带，不根据 `visibilityWidthMeters` 制作实测路宽。已知道路/池塘交叉点保留为争议。
- 池塘使用 `HeJiaVillage_VerifiedSurface.json` 的 13 个保守内部范围。首轮做贴地色块，不声称是水平水面或完整岸线；不改变 Terrain 高度。
- 林地使用 `HeJiaVillage_ForestReference.png` 的 WorldCover 区域，按固定 64 米网格稀疏摆放项目已有树 Prefab。排除道路、水域、建成区和出生点周边。树种、密度都只是轮廓占位；建成区参考只用于地表与植被判断，不生成建筑。
- 所有新对象位于对应瓦片的 `MapRoot/MapContentRoot/HandAuthoredContentRoot/MacroBlockoutRoot`。源数据不写入场景对象坐标的唯一权威；生成脚本和记录共同保留，已有 7 个试摆自然物不动。

## 执行步骤

1. 读四块场景结构、项目自有树 Prefab、地形来源和输入文件；运行 dry-run 统计每块树和池塘数量，并检查所有引用存在。
2. 在 `Tools/MapTerrainData/HeJiaVillage/BuildMacroBlockout.cs` 实现编辑器执行脚本。先创建共用占位材质与池塘网格资产，再逐块打开场景、建立粗布局根节点、保存并关闭该瓦片。发现已有同名根节点时直接停止，避免覆盖手工修改。
3. 用 Unity MCP 执行脚本；核查四块场景的根节点、对象数量、来源 ID、场景保存状态和 Console 错误。只检查目标场景，不保存或清理 `Boot` 的未保存修改。
4. 更新路线图与验收记录，说明仍需真实岸线、树种/密度、道路坡面和材质复核；编译错误存在期间不运行玩法测试。

## 完成口径

四块 Terrain 中能看见来源可追溯的水域与植被占位，现有道路泥土带保持原样；场景没有建筑或建筑占位，不长期依赖 `Assets/Art` 原包，且没有改变地图运行对象、出生点、Terrain 高度或来源 JSON。此阶段不宣称现实细节和可通行性已验收。
