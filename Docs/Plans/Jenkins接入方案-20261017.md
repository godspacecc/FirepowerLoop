# FirepowerLoop Jenkins 接入方案

日期：2026-10-17。

状态（2026-10-18更新）：已实现四路CI请求／互斥／报告、独立宿主归档、构建与固定产物发布分离，以及节点脚本和手动Jenkins模板。文件定向测试及正式入口ValidateOnly已通过；Jenkins未部署，真实首包／Host构建、授权／节点工具链、取消／恢复未实测。当前禁止触发Unity打包或Player Build。具体入口与使用边界见[Tools/CI/README.md](../../Tools/CI/README.md)，证据见[接续记录](剩余模型加载与构建适配-20261018.md)。

## 目标与范围

采用一个 Jenkins 参数化任务、一个专用 Windows 构建节点，支持 PC 与 Android 的首包和 Host 更新。四种构建统一串行，第一阶段只允许手动触发。

第一版交付标准：四种构建可手动选择、重复请求排队、产物可下载、Host 基线可追溯、失败可定位。

不纳入定时任务、提交触发、Webhook、多构建机并行、自动启动资源服或代码自动提交推送。FirepowerLoop 与 AnotherDay 的构建配置、Library、UserSettings、服务数据和发布目录必须隔离。

## 任务入口

建议任务名：`FirepowerLoop-Build`。使用“带参数构建”手动启动。

| 参数 | 规则 |
| --- | --- |
| 构建平台 | PC、Android |
| 构建类型 | 首包、Host 更新 |
| 代码版本 | 分支、Tag 或 Commit；启动后固定并记录具体 Commit |
| 宿主基线 | Host 更新必选；首包无需选择 |
| 发布资源 | 默认关闭；开启后发布本次已验证产物 |

## 四种构建

| 类型 | 主要流程 | 产物 |
| --- | --- | --- |
| PC 首包 | 生成 HybridCLR/AOT → 完整远端资源 → 精简 Player → 安装器 | 安装包、资源包、宿主基线 |
| PC Host 更新 | 校验宿主基线 → 生成热更代码资源 | 资源包 |
| Android 首包 | 生成 HybridCLR/AOT → 完整远端资源 → APK | APK、资源包、宿主基线 |
| Android Host 更新 | 校验 Boot/AOT 基线 → 编译热更 DLL → 构建资源 | 资源包 |

首包流程本身已经生成完整远端代码资源，无需在同一份输入下再执行一次独立 Host 更新。

复用现有构建逻辑，后续增加 CI 适配层。PC Host 当前流程与 Android 不完全相同，实施时必须单独审核 AOT 生成及复用方式，确保更新面向所选宿主，不能直接套用 Android 行为。

## 构建节点与隔离

使用专用构建目录，例如 `E:\JenkinsWorkspaces\FirepowerLoop`，不得直接占用开发者正在打开 Unity 的 `E:\GitHub\FirepowerLoop\Client`。构建目录拥有自己的 Library、Temp、构建状态与输出目录；不默认创建 Git worktree。

构建机安装项目指定的 Unity `2022.3.55f1c1`、对应平台模块、有效 Unity 授权、Android 工具链、HybridCLR 所需环境和 Inno Setup。明确配置工具路径，避免依赖开发者账户的 EditorPrefs。

启动 Unity 时明确指定目标平台，避免依赖编辑器上一次使用的平台。检查所有无人值守路径，确保不会等待确认或文件选择弹窗。

## 串行与互斥

采用两层控制：

1. Jenkins 配置 `disableConcurrentBuilds()`，重复请求进入队列，当前任务继续执行；不启用自动终止前一任务。
2. 构建脚本取得工作目录的进程间独占锁，防止其他入口绕过 Jenkins 调度。现有编辑器内构建锁继续保留。

未来若拆成多个 Job，需要共同的 Jenkins 资源锁；单个 Job 的禁止并发不能保护其他 Job。

## 执行流程

1. 手动提交参数。
2. 排队并取得独占锁。
3. 拉取代码，固定 Commit。
4. 检查 Unity、平台工具、授权、磁盘空间和参数。
5. Host 更新恢复并校验指定宿主基线。
6. 启动 Unity 批处理，执行对应构建。
7. 校验产物，归档日志与构建结果。
8. 如选择发布，发布本次固定版本。
9. 释放锁，结束任务。

## 宿主基线管理

每次首包成功后，按平台和 Jenkins 构建编号归档：

- 对应安装包及其哈希。
- AOT DLL、运行清单及必要生成文件。
- Android Boot 指纹，以及 PC 对应的宿主兼容性信息。
- Unity 版本、Commit、应用版本、资源版本。
- 文件哈希清单。

Host 更新明确指定一份基线，恢复到本次工作目录后再校验。缺失、平台不符或宿主不兼容时直接失败，不自动退回首包构建。

当前 `Library/FirepowerLoopBuild/BuildState.json` 与基线记录包含本机路径，不能直接搬到新工作目录使用。实施时需要恢复文件并重新定位引用。分支切换或清理工作目录后，也必须能够从归档恢复指定基线，不依赖构建机残留文件。

## 构建与发布分离

第一阶段默认只构建、归档，勾选发布时才执行发布阶段。后续代码适配要求：

- 构建成功后不自动启动本地资源服。
- 发布使用本次任务明确的资源目录和版本，不扫描“最新资源包”。
- 安装包与资源版本完成一致性校验后才能发布。
- 发布失败将 Jenkins 标为失败，同时保留可下载产物。
- 首包发布同时处理安装包更新信息；Host 更新只处理对应代码资源。
- 发布目录与开发环境隔离，发布目标由 Jenkins 配置。

现有部分发布失败路径仅提示后返回，CI 适配层需要将其转换成明确的失败结果，防止 Jenkins 显示成功。

## 停止、失败与恢复

取消分为正常请求取消与强制结束：

- 正常取消在安全检查点退出，后续发布不再开始。
- Unity 内部长调用依赖底层提供的取消点，不保证立即停止。
- 发布替换事务完成或回滚当前替换后结束。
- 超时或强制停止只清理本次任务启动的进程，将工作区标记为需要检查；下次构建通过检查后才能使用。

Jenkins 的停止能力不能代替项目内清理及回滚。不得按进程名称批量终止 Unity、Java 或 PowerShell，以免影响开发者与其他项目。已改写的 DLL、AOT、StreamingAssets 和发布状态需要按实际阶段核对，不能将释放构建锁视为完整恢复。

## 落地顺序与验收

| 阶段 | 工作 | 验收条件 |
| --- | --- | --- |
| 1 | 准备节点、独立目录及依赖 | 环境检查明确报告缺项，无弹窗等待 |
| 2 | 增加 CI 入口、串行锁和结果报告 | 四种任务正确路由；重复请求排队 |
| 3 | 归档、恢复及校验宿主基线 | 清理工作区后仍可使用指定基线执行 Host 更新 |
| 4 | 接入按本次版本发布 | 发布版本与构建一致；失败不显示成功 |
| 5 | 验证取消、失败及恢复 | 不误杀其他进程，不推广半成品 |

后续先做参数、互斥、基线与失败状态的定向检查，不执行完整测试套件。Unity 测试必须使用真实、非空的短 testClass 或完整 testMethod，声明范围与最大数量，`includePassingTests=true`，不得无效过滤回退。

当前项目禁止触发 Unity 打包及 Player Build；真实首包与 Host 构建验收须在用户明确调整该约束后进行。保存本文不构成部署或构建授权。
