## 审计口径

- 纵坡沿人工核对中心线约每 `2m` 读取当前 Terrain 高度，记录相邻采样的最大局部坡度。
- 横坡按中心线左右各 `2m` 的 Terrain 高差估算，只用于发现风险，不代表道路设计宽度或现实横坡。
- 道路与池塘使用椭圆内部的解析相交判断；外扩 `5m` 仅是制作复核缓冲，不代表真实岸线。
- `pond_southwest_03` 已标为 `disputed`，保留历史轮廓但不再参与道路阻断。复核使用高德 GCJ-02 坐标 `112.187108, 27.625791`，卫星图在该中心显示林地/梯田而非池塘。
- 原始道路、池塘 JSON 和 Terrain 均未修改。完整的 50 段结果保存在 `Tools/MapTerrainData/HeJiaVillage/HeJiaVillage_StageB_RouteAudit_1_1.json`。

## 当前结论与下一步

1. 现有 95.71m 道路样板仍是可靠的首段视觉候选。东侧连续三段存在 `31%～42%` 局部纵坡，不能自动延伸；西侧下一段在当前 Terrain 坡度审计中已转为安全候选，不再因历史池塘描线阻断。
2. `1_1` 当前没有一条能够仅依据现有 Terrain 与中心线自动连通的完整道路。红段数量多反映的是约 30m DSM、人工描线与道路尺度不匹配，不证明现实道路本身不可通行。
3. 高德卫星图在陡坡链中点（GCJ-02 `112.189616, 27.626627`）能看到乡村道路与建筑，但没有工程中心线叠加，尚不足以裁决 `(950,491) → (752,381)` 是绕坡还是需要局部切填方。
4. `pond_southwest_03` 保留为可追溯的争议历史记录，待重新描绘完整水域；在此之前不据它生成水面或岸线。其余红段仍不压平、不自动延伸道路 Mesh。

审计工具为 `Tools/MapTerrainData/HeJiaVillage/AuditStageBRoute.cs`，由 Unity MCP 执行并读取当前 TerrainData；重复执行只覆盖派生 JSON 和审计图。
