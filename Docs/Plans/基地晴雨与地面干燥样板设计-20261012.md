# 基地晴雨与地面干燥样板设计

日期：2026-10-12。状态：用户已确认实施计划；测试指令与基地样板已接入，连续玩家试玩、听感和移动端性能待验收。实施证据见同目录实施记录。

## 已确认目标

在正式基地地图实现晴天 → 下雨 → 放晴 → 地面逐渐变干的可观察样板。

用户补充：先通过测试指令切换天气，查看效果表现。复用既有测试指令窗口的自由输入入口，不新增天气选择 UI。进入基地默认晴天，不自动播放样板。

| 拟新增指令 | 行为 |
| --- | --- |
| `#weather rain` | 立即设置中等雨量及湿润度 1，持续下雨，方便直接检查效果 |
| `#weather clear` | 立即停止降雨并恢复晴天，保留当前湿润度，随后在 90 秒内线性降至 0 |
| `#weather dry` | 立即恢复晴天并将湿润度设为 0，方便同机位对比 |
| `#weather demo` | 从干燥晴天开始播放下述 220 秒完整渐变样板 |
| `#weather status` | 返回当前雨量、云量、湿润度和样板阶段；不改变状态 |

直接切换命令会终止正在播放的 demo；重复 rain/dry 幂等，重复 clear 不重启干燥计时。指令只在 Editor/Development Build 的已加载离线基地执行，非法语法与非基地操作无副作用。状态查询可在非基地返回“天气样板未激活”。

长期方向为四季按累计游戏日期循环。用户已明确本轮只做天气样板，累计日历以后接入；本轮不新增日期、季节或存档字段。

## 当前实现证据

- Unity MCP 成功读取已打开的 Boot 场景。
- `DayNightVisualSystem` 通过共享生命周期推进基地会话时刻，暂停及离开基地时停止，不保存。
- `DayNightView` 统一应用方向光、环境光和雾色。
- 基地 `BaseMap.unity` 已接入 `MapProceduralSkyView`，后者持有独立天空材质并在释放时恢复原状态。
- 现有基地预览入口为 `Tools/Unity/BaseDayNightPreview.cs`。
- Unity AssetDatabase 找到备用库 ARPG Effects 中的 Rain.prefab、rain_loop.wav、雨线和溅水贴图。它们是候选；尚未确认原粒子的 URP 兼容性、观感及性能。正式接入时只提取必要资源，保留原件。

## 样板行为与建议参数

以下时长为本样板的建议初值，审阅确认后实施。沿用现实一秒对应一个游戏分钟的基地节奏；不推进第二套游戏日期。

| 阶段 | 现实运行时长 | 表现 |
| --- | --- | --- |
| 晴天 | 30 秒 | 原有昼夜天空、干燥地面 |
| 转阴起雨 | 20 秒 | 云层渐厚，日光渐弱，雨量和雨声渐强 |
| 持续降雨 | 60 秒 | 中等雨量，地面湿润度升至 1 |
| 雨停放晴 | 20 秒 | 雨量、雨声逐渐归零，云和光照恢复；湿润度暂保持 |
| 地面干燥 | 90 秒 | 湿润度由 1 降至 0 |

一轮共 220 秒；完成后停在晴天。通过 `#weather demo` 重播，不把频繁固定循环当成正式随机气候。

只在离线基地已加载、AppState.Playing 时推进。暂停停止状态推进和粒子模拟；卸载销毁雨声、粒子及临时材质，解除天气对全局光照的影响。退出再启动从初始晴天开始。本轮不承诺跨地图延续或读档恢复天气进度。

## 视觉范围

- 复用基地已有天空；云量、天空颜色和光照平滑变化。昼夜继续正常运行，夜间不因放晴变成白天。
- 雨线集中在玩家附近的可见范围，随玩家移动；不覆盖整张地图。镜头不作为天气状态权威。
- 雨声跟随雨量淡入淡出。溅水只在合适的地面位置产生，不在半空、帐篷顶部和水面统一套用相同效果。
- 雨量和湿润度独立；雨停不立即清除地面湿润效果。
- 明确指定可湿润地面 Renderer；材质逐渐加深，并按其现有风格增加适度高光。草、角色、屋内物件和水面不因全局材质替换被错误处理。兼容性调查决定采用材质参数或项目自有专用 Shader，不改变地面几何、碰撞和导航。
- 对实际基地中的帐篷等主要遮蔽物检查降雨遮挡；遮蔽物下不直接贯穿雨线。样板只保证指定基地遮挡，不承诺完整洞穴气候系统。
- 不制作雪、雷电、体温、湿身数值、移动惩罚、敌人视野变化及季节植被。

## 职责与修改范围

拟修改 `Client/Assets/Game/Scripts/System/Environment/`、`Controller/View/Environment/` 和 `Game.cs`，新增基地天气状态推进与表现连接；具体新类名在实现计划中按现有所有者确定。

在 `System/TestCmd/TestCmdSystem.cs` 新增 weather 解析并委托天气 System；命令层不直接操作灯光、材质或粒子。只增加自由输入命令，本轮不改测试指令目录 CSV、Luban 生成产物、UI Prefab 或 Controller。

状态推进由 System 使用共享生命周期完成，View 只消费快照。天气不直接改太阳灯：由 DayNightView 将天气影响与现有昼夜结果合成，避免两个写入者争抢。天空仍由 MapProceduralSkyView 持有和释放。

基地场景配置限定在 `BaseMap.unity`。正式天气资源进入 `Assets/Game/Art/Environment/` 下的专用目录；只复制所需备用贴图、音频，重新装配符合项目的粒子。每个运行时资源由地图表现所有者唯一释放，切图后不允许迟到回调重新创建旧地图效果。

新增定向 EditMode 检查与 `Tools/Unity/` 基地天气预览入口。保留工作区已有未提交修改，尤其 Main 场景、街机、相机、配置和生成产物；本轮不自动提交、推送或打包。

## 验收方式

1. 状态检查：阶段边界、一次推进跨多个阶段、雨停后湿度保留、干燥完成后维持晴天；暂停和非基地不推进。
2. 生命周期检查：重复初始化、卸载和重新进入，无重复粒子、雨声或资源泄漏；退出基地后原天空与昼夜光照恢复。
3. 回归检查：天气作用时昼夜仍有效，晴天默认行为与原实现一致；不改变远征计时和生存数值。
4. Unity 测试只运行实际存在的精确类或方法，调用前声明 Mode、过滤条件与最大用例数，返回后审计执行范围；不运行完整套件。
5. 正式基地资源同机位渲染干燥晴天、降雨湿地、雨停仍湿、彻底干燥四张图，另检查玩家高度近景及遮挡位置。标记为编辑器预览，不代替连续运行证据。
6. 检查实际运行中完整一轮、暂停恢复、切图清理和雨声变化。人工听感及移动设备性能未验证时如实保留为待验收，不以自动测试代替画面验收。
