# 口袋与可穿戴背包设计

状态：玩法与容量已在会话确认，本文待审阅；尚未进入代码和 Prefab 实施。

本次整理游戏内背包页，并将玩家随身库存分成独立口袋和可穿戴背包。参考《漫漫长夜》的物品区域与选中详情布局，使用 AnotherDay 自身视觉风格。装备、玩家属性和任务页在后续分别设计。

## 已确认玩法

| 项目 | 首版规则 |
| --- | --- |
| 口袋 | 固定 8 格，始终可用，暂不与衣物联动 |
| 基础背包 | 穿戴后提供独立 32 格，未穿戴时不提供容量 |
| 新角色 | 只有口袋，不赠送基础背包 |
| 旧角色 | 一次性补发并穿戴基础背包，完整保留旧物品 |
| 转移 | 口袋与背包支持双向物品移动 |
| 堆叠 | 沿用每种物品的现有堆叠上限 |
| 物品限制 | 口袋允许存放现有物品，不新增类型、重量或尺寸限制 |
| 武器槽 | 独立于两个容器，不占口袋或背包格数 |
| 卸下 | 背包内容必须清空，卸下的背包本体需要有合法接收位置 |
| 更换 | 将旧背包内容转入新背包，容量或旧背包本体接收空间不足则整笔拒绝 |

实际现状为玩家背包 12 格、基地仓库初始 40 格。新方案穿戴后合计 40 格，是随身容量扩展，不是维持现有容量。

## 首版背包页面

手机横屏左侧保留窄导航区，主要内容分为物品区和右侧详情区。口袋在物品区上方完整显示 4×2 格；背包位于下方，固定每行 4 格、纵向滚动，基础背包共 8 行。PC 使用相同内容分区，沿用顶部导航的总体方向，具体宽度和可见行数在画面制作时调整。

口袋和背包各自显示已用格数与总格数。未穿戴时，背包区域显示“未装备背包”，不显示可交互的空槽，不允许向该区域转移物品。

选中物品后，右侧显示名称、大图标、数量、说明和有效操作。来源为口袋时提供“移入背包”，来源为背包时提供“移入口袋”；未穿戴背包时前者不可执行。可堆叠物品允许选择数量。点击格子只选中，操作按钮才执行事务；保留 PC 拖放和右键入口，手机不依赖悬停或右键。

首版不新增分类筛选，避免筛选与固定槽位、拖放身份之间产生歧义。页面隐藏或绑定实例更换时清理拖动、拆分和短期操作状态。

本次只完成背包页，不制作装备、状态、任务的新页面，不添加可点击但没有内容的分页入口。当前武器操作继续保留可用入口，待装备页完成后再迁移。

## 补充规则提案

下列规则用于补齐已确认玩法的闭环，随本文一起审阅。

### 背包本体和获取

基础背包是不可堆叠的正式物品，装备后占据独立背包装备位置。未装备的背包本体没有内部物品，禁止带内容的背包嵌套存储。穿戴操作在背包页提供，不等待后续装备页。

基础背包首版接入已有基地补给商店，建议买价 40、卖价 20，与当前急救包价格相同。新角色需要先获得金钱再购买，不自动赠送、不新增任务或制作配方。图标先检查正式资源和备用美术资源库，选用明确的背包图标；不修改第三方原始资源包。

### 自动收取和消费

未指定目标的拾取、购买和奖励优先放入已穿戴背包，再使用口袋剩余空间；没有背包时只使用口袋。保留来源入口原有的完整接收或部分接收语义，不因自动分配而凭空改变世界物品数量。

弹药、建造与制作材料等自动消耗统计两个容器，优先扣背包、再扣口袋，同一容器按稳定槽位顺序处理。玩家点击某格使用物品时优先操作明确选中的来源格，不悄悄改用另一栏物品。

口袋与背包之间的移动不属于世界收集，不触发拾取奖励或任务进度。基地仓库和搜索容器支持向两个随身容器转移；仓库扩容报价合计仓库、口袋和背包材料，并保留仓库优先的消费顺序。

### 失败和远征风险

口袋不作为安全容器，不因加入新栏而获得死亡保留能力。单机死亡及异常恢复沿用当前远征规则，将风险清空扩展到口袋、背包内容和背包装备；成功返回保留这些内容。

联机死亡沿用服务器现行尸体掉落和持久化规则，纳入两个容器和背包本体；清空角色后只剩 8 格口袋。联机与单机已有的死亡差异不在本次统一。

所有移动、穿戴、更换和卸下在领域层校验后提交。容量不足、来源失效、重复请求、配置错误或保存失败不能造成部分扣除、复制、背包内物品丢失或 UI 假成功。

## 实现职责

现有 `PlayerBagModel` 持有单个 `ItemContainer`、风险状态及存档分区；`InventorySystem` 编排库存事务；`WeaponEquipmentSystem` 编排武器装备事务。优先扩展现有持有者，避免建立第二套权威库存。

玩家库存需要明确表达口袋容器、已穿戴背包物品身份和背包内容容器。无背包时内容容器不可操作，容量由配置中的已穿戴物品决定，不能信任客户端或存档任意填写的容量。

现有 `InventoryContainerKind` 的 PlayerBag、Warehouse、Search 数值保持稳定，新增 Pocket 标识；请求和选择状态同时携带容器身份与槽位，不把两栏映射成一个连续槽位数组。

背包穿戴事务归库存领域入口，武器装备仍归 `WeaponEquipmentSystem`；两者共用容器候选、回滚与最终刷新机制。View 只持有展示引用，Controller 只读取快照和提交意图。

现有联机 `OnlineInventoryRecord`、`OnlineInventorySnapshot` 和 `OnlineInventoryInfo` 都表达单个容量与槽位集合，需要增加口袋、背包身份和内容契约。服务器负责容量、数量、装备及事务校验，客户端只应用服务器确认的快照。操作重试沿用既有 OperationId 和 Revision 去重，不允许重复发包复制物品。

协议以 `Config/Proto/` 中源文件为权威；配置以 `Config/Defines/` 和 `Config/DataCsv/` 为权威。容量与背包定义进入共用配置契约，正式生成产物不得手改。新旧网络契约不混用，上线时客户端和服务器需要配套更新。

## 存档迁移

新库存结构增加明确版本或分区结构版本，区分真正的新角色与尚未迁移的旧角色。单机基地、远征快照和联机账号记录均需覆盖，不能仅凭某个背包字段为空就再次补发。

普通旧库存迁移为口袋为空、基础背包已穿戴，旧槽位按原索引进入 32 格背包。原有武器、仓库、风险状态和其它存档分区保留；迁移后的原有风险恢复仍按原流程执行。

若历史扩展库存不能完整装入基础背包，保持原存档不覆盖，报告容量异常并停止迁移；不截断槽位、不删除物品、不自动搬入仓库。实现计划需加入该失败路径的专项验证。

迁移成功后记录新版本，再次加载不得重复赠送。新角色创建和死亡后的库存初始化必须走新规则，不能把空库存当成旧存档。

## UI 制作与验证

两个库存区域使用独立 `CustomListView`，直接引用正式 `InventorySlotBox.prefab`。格子刷新完整覆盖容器身份、索引、数量、图片、选择状态和回调。稳定布局、滚动区域、格子尺寸及 Box 来源在 Prefab 序列化，Controller 不动态搭建布局。

宿主与 Box 继续使用 ReferenceCollector 及对应 UI 生成器。修改后从 Unity 反序列化检查生成 View、字段和实际引用；界面固定文字使用正式本地化键和可读的默认语言预览。

定向验证覆盖新角色口袋开局、旧库存完整迁移与幂等、两栏转移和堆叠、无背包拒绝收取、穿戴与换包回滚、双容器自动消费、仓库和搜索交互、死亡恢复、联机重复请求与旧 Revision 拒绝，以及 Prefab 接线。

Unity 测试只使用真实类或完整方法过滤，执行前声明 Mode、过滤项及最大执行数量，结果包含通过项；不运行完整套件，不触发 Player Build。手机与 PC 的点击、滚动、详情可读性、安全区和连续操作需单独画面验收。
