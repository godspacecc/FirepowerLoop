# 手持火把道具设计

状态：用户确认优先制作手持火把，采用单一手持；本文具体设计待审阅，尚未实施。

## 已确认目标

先制作可手持的火把，基地营火与火盆的燃料改造暂缓。光来自火把实际燃烧，点燃后照亮周围；火把与武器不能同时手持，战斗前切换武器。木柄和燃烧头模型、自然火焰、点光源共同构成表现，不使用没有能源来源的永久发光装饰。

## 首版具体方案

- 火把为工具物品，独立实例、不可堆叠。通过现有制作入口，用木材 1 和布料 1 制作一根；不新增科技门槛或免费初始发放。
- 制作完成时未点燃。每根初始可燃烧 600 秒正常游玩的现实时间；这是首版调试值，通过配置调整，不等同于历史燃烧时长结论。
- 从背包或口袋拿出，沿用当前单一手持入口。拿出火把收起原武器；物品仍占原库存格，不创建额外装备储存位置。
- 手持选择列表提供火把，物品详情提供拿出/收起。当前手持火把时，既有使用输入和触控操作用于点燃/熄灭，并显示可读提示及剩余时间，不把攻击键解释为点火。
- 有余量才可点燃，重复请求幂等。手动熄灭保留余量；收起、切换到武器、转入仓库、丢弃或手持身份失效时先熄灭，不允许燃烧物藏在背包里继续照明。
- 燃尽后保留同一根耗尽火把，熄灭、不能再点燃，玩家可正常丢弃；首版不补燃料、不修复、不回收成木材，另做一根即可。
- 本轮在离线基地及离线远征可用。联机库存与手持由服务端权威管理，本轮不新增在线燃烧协议；联机不提供火把制作、拿出或点火操作，不以本地状态兜底。
- 不做火把近战、点燃敌人、火灾、热量伤害、雨水熄灭、双手持握或场景放置光源；基地天气现有改动不纳入本功能。

## 当前实现依据与职责

`WeaponEquipmentModel` 已保存背包/口袋的单一手持引用，并绑定 `ItemStack.RuntimeIdentity`；`WeaponEquipmentSystem` 管理拿出与收起。当前 `ValidateHeldWeapon` 只接受武器，且攻击类型投影会把非远程物品当成近战，必须明确支持无攻击能力的手持工具，不能给火把虚构伤害或空武器配置绕过验证。

`ItemStack` 已保存每实例装填状态、克隆时保留运行身份；`InventorySaveContracts` 保存格内物品数据。火把余量属于该库存实例，增加明确的可选燃烧余量字段，禁止复用 LoadedAmmo。库存移动、事务克隆、保存恢复、丢弃与拾取均保留余量，不按物品 ID 保存共享时间，也不因新格位恢复满燃料。

手持所有者负责当前燃烧意图与资格。持久余量归库存实例；共享生命周期由领域 System 推进，View 只显示火焰、点光源、声音与模型。若现有 Equipment System 不适合持有燃烧规则，实施计划须据实际调用链确定最小职责拆分，不为道具建立通用能源系统。禁止产品 MonoBehaviour.Update 扣燃料。

`CharacterWeaponPresenter` 负责模型与骨骼表现，火把接入需明确工具挂点与握持姿态，覆盖现有第三人称和第一人称表现；新工具不会启动武器攻击、瞄准、装填或采集。切换取消旧输入与未提交动作，避免一帧误攻击。

## 燃烧与保存语义

仅在合法离线地图已加载、AppState 为 Playing、当前火把有效手持且点燃时减少余量。暂停和加载不消耗，不补算退出期间的时间，不读取系统时钟作为燃料权威。昼夜视觉进度不影响燃烧，白天也可以点燃。

余量与点燃状态保存；普通保存不熄灭。退出保存保留当时状态，恢复到合法有效手持后继续燃烧，不额外扣时间。地图切换先暂时停止表现和推进，保存的手持状态经地图事务恢复后再继续；手持身份丢失则熄灭。死亡与远征风险清空沿用现有物品规则，不能单独复制火把或余量。

点燃状态只能对应当前手持的火把；非手持库存记录不得标记为燃烧。熄灭、切换、搬运、死亡与保存事务一起提交，失败恢复库存、手持及燃烧快照。非法余量（负数、非有限、超过配置上限）、非火把携带燃烧字段、数量大于 1 的火把记录均被拒绝。

新增物品在制作/新生成时初始化满余量；存档读取与转移绝不把 0 当成缺失值补满。旧存档不包含火把，不补发；新火把记录必须携带有效余量，缺失时报数据错误，防止重载无限续燃。

持续燃烧只更新领域状态及存档脏标记，由既有自动保存节流写盘；退出与地图切换捕获最新余量，不每帧写文件。保存失败沿用现有失败恢复语义。

## 配置与资源

在唯一 Luban 配置源增加工具物品、制作配方与按 ItemId 索引的可选燃烧定义，含初始秒数及表现资源地址；扩展手写 Provider 稳定定义及校验。生成统一走 `Config/gen.bat`，不手改生成 C# 或 bytes。具体 ItemId 在实施计划中检查双端配置后分配，避免占用既有或并行新增 ID。

本地 `Assets/Art/ARPG Effects/Prefabs/Environment/Fire/Torch/TorchFireNatural.prefab` 有自然火焰、烟、声音与点光源，没有完整火把杆模型。优先复用现有火焰素材；火把杆与燃烧头需补完整道具资源。仅筛选必需依赖到正式 Game/Art 目录，不改备用第三方原包。

先给木柄、包裹燃烧头和握持效果的可见预览，用户确认造型后接入正式资源。效果图与 Unity 实际截图明确区分。火焰不能贴到手或脸，点光源置于火焰区域，未点燃时不留光照、粒子或燃烧声音。

异步加载验证请求代次、手持实例身份、地图身份及 View 生命周期；过期结果释放，不显示上一根火把。快速切换、隐藏、销毁、地图卸载无模型或资源句柄残留。

## UI 与验证

沿用背包详情、手持选择列表及现有使用入口，Controller 显示快照并提交意图，不扣燃料。动态列表按现有 CustomListView/Box 契约处理；固定布局及新增引用写入 ReferenceCollector 并运行项目 UI 生成器，生成 View 不手改。名称、点燃/熄灭/耗尽提示和余量走本地化；界面关闭不额外点燃或消耗。

验收覆盖制作扣料一次、拿出不改变数量、火把不能攻击、切换熄灭、燃尽关闭、暂停冻结、退出重载保持、格位移动与交换保持各自余量、同类实例不能继承另一根余量、丢弃拾取守恒、失败回滚和异步过期释放。旧武器、拳头、弓与衣物行为需要定向回归。

Unity 测试只跑实际存在的短类名或全限定方法，调用前声明 Mode/过滤/最大执行数，includePassingTests=true，返回后核对所有结果，不跑全套或 Player Build。画面验收包括手部握持、第一/第三人称夜间周围受光、切换和卸载无残留；代码测试不替代视觉验收。
