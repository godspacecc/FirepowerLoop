# 街机测试指令补充实施计划

> 执行技能：subagent-driven-development。用户已确认四项功能并授权开工；遵守项目规则在当前分支实施，不再审批技术方案，不创建worktree。

**Goal:** 单人和双人测试入口补齐道具列表、跳关跳轮、无敌及指定刷怪。
**Architecture:** TestCmdSystem只解析意图，ArcadeCombatSystem管理现场，ArcadeRunSystem管理切关事务；双人由OnlineArcadeRunSystem及既有权威战斗宿主处理，不从客户端改联机现场。Config权威目录通过gen.bat发布。
**Tech Stack:** Unity C#、QFramework、ET服务端、Luban。
**Spec:** 执行总清单“街机测试指令补充（2026-10-29，本会话）”和用户对优先四项的“可以”。

## 约束与裁定
- 不改正式视觉，复用敌人现有配置与出生表现。不添加中优先级候选、不做旧目录清理。
- 跳关参数是当前路线中的关卡序号和该关轮号（从1开始），不是配置表排序；旧路线按保存的路线版本处理。
- 测试跳关不发跳过关卡奖励，不伪造胜利，不覆盖原正常局的可恢复进度；优先复用现有瞬时现场和地图事务，若需专用测试局状态必须明示并隔离正式保存。
- 无敌作用于当前现场，离场/新局清除，双人默认只作用于发起房主。保留受伤反馈逻辑的既有边界，不能靠超大生命或永久强化实现。
- 刷怪数量1至20且不得超过现役存活上限；全部验证后生成，拒绝未知ID和特殊场景不支持的敌人，失败不污染波次队列。
- drops输出实际配置ID与可读名称，无匹配名称时输出明确类型，不制造不存在的名字。
- 所有变更指令在结算、加载和不支持阶段拒绝。双人继续遵守房主、双方在线、权威广播约束。
- 原有海岛asset、中文字体asset、ProjectSettings差异保留。报告日志置Backup/Artifacts/ArcadeCommands-20261029。只做具名限定测试，includePassingTests=true，声明最大数；不全套、不Player Build。

## Review Focus
- 非法ID、负数、零、超大数不改变状态；刷怪容量边界。
- 跳关目标与真实地图/路线一致，失败回滚，不能写入正常进度或发跳过奖励。
- 无敌关闭恢复正常伤害，切图/新局不遗留；单人不操作联机现场。
- 双人非房主/掉线/暂停拒绝，成功状态广播双方一致。
- 目录可见且参数示例可用，生成产物与权威源一致。
