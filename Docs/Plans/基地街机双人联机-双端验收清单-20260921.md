# 基地街机双人联机双端验收清单

## 1. 验收边界

本清单用于两台真实客户端连接同一个 `OnlineLocal` 服务进程后的最终验收。源码、协议、服务端编译和定向 EditMode 测试只能证明静态与事务边界，不能代替 PC/Android 的输入、网络、渲染和性能证据。

项目规则禁止自动触发 Unity Player Build。验收人应使用发布流程生成的同版本客户端；本清单不要求也不允许在自动化步骤中打包 Player。

## 2. 前置条件

- 两个独立账号与两个不同 `PlayerId`，客户端 `Application.version` 相同。
- 两个客户端包含相同的 `ArcadeRuleConfig.ConfigFingerprint`，并指向同一 GameGate 地址。
- 服务端使用与客户端同一次生成的 `Config/`，端口默认 `31001`；Android 与服务端电脑位于同一 Wi-Fi 时使用电脑局域网 IPv4，不能填写 `127.0.0.1`。
- 保留独立验收 Store 目录与服务端日志；不要复用正式账号数据。完整协议日志可能包含密码，只能在隔离环境短时开启。
- 记录客户端平台、包版本、配置指纹、服务器提交、账号 PlayerId、开始时间和 Store 路径。

## 3. 主链路

1. 两端登录，分别从基地街机终端打开“双人联机”。A 创建双人房，B 输入 6 位房间码加入。
2. 确认街机房不会出现在公开房间列表；第三账号加入应被容量/成员锁拒绝；不同版本或配置指纹应得到明确拒绝。
3. 仅房主且两名成员在线时可以开始。进入安全商店后核对两人的金币、生命、商店报价和准备状态互相独立。
4. A 购买商品，确认只改变 A 的报价与资源；A 使用“转给队友 25 金币”，确认双方余额同时更新且重连后保持。
5. 两端分别准备。只准备一端时不得进入；双方准备后同时进入同一竞技场。
6. PC 验证 WASD、鼠标落点瞄准、按住射击、炸弹和冲刺；移动端验证左摇杆移动、右摇杆控制方向并持续射击、松开右摇杆停火、炸弹和冲刺。两端都应看到相同敌人、投射物、掉落和波次结果。
7. 让两名玩家同时靠近同一掉落，确认实体只消失一次、只有一个玩家获得资源；观察最近存活目标切换、死亡原地复活、零生命观战及双方全灭清局。
8. 完成竞技场回到安全商店，确认本场金币/奖励已落入安全节点；重新登录后报价、资源、下一竞技场和待结算奖励一致。
9. 双方确认结算，确认各自奖励只到账一次且运行局清理；重复请求、重连或再次领取不能重复增加余额。

## 4. 掉线与恢复

### 4.1 竞技场 60 秒窗口

1. 战斗中断开 B 的网络或主动退出，记录服务端时间。
2. A 应立即看到暂停提示；敌人、投射物、计时、移动、射击与拾取都停止，A 的摇杆/炸弹/冲刺不可提交。
3. 60 秒内以原账号恢复 B：两端返回同一暂停现场，恢复后继续推进，旧连接或旧输入不能覆盖新会话。
4. 再次断开并等待超过 60 秒：当前竞技场实体与收益全部丢弃，两端回到上一安全商店，生命不扣除。

### 4.2 服务端重启

1. 竞技场中记录两端生命、局内金币和安全节点 Revision，然后正常停止并重启服务器。
2. 两端用原账号重新登录并重新组队恢复：只能回到最后安全节点，不能恢复敌人、投射物、位置或本场收益，准备状态应清空。

### 4.3 安全商店十分钟

1. 在安全商店断开 B，确认 A 不发生竞技场回滚。
2. 未满十分钟时 A 不能单独结束；满十分钟后 A 可结算自己的奖励，B 的奖励进入个人待领取。
3. B 之后登录，客户端应在确认没有未结束运行局后自动领取待领奖励；重复登录不得重复到账。

## 5. 故障与幂等

- 对购买、转赠、准备、结算和放弃分别制造“请求已到服务端但客户端超时”，使用相同 OperationId 重试，确认不重复扣款、转账、发奖或清理。
- 在安全节点文件提交处注入一次保存失败：该次购买/转赠/竞技场完成不得部分可见，重试成功后只提交一次。
- 在两名玩家奖励写入间注入单方失败：成功方可离开且不回滚，失败方保留待结算并可重试。
- 双方放弃必须各自确认；仅一方确认不清局。双方确认或双方全灭后，基地原有余额保持不变。

## 6. 性能与可观测性

- 在最高配置波次记录两端平均/最低帧率、主线程峰值、GC Alloc、网络收发带宽和服务器进程 CPU/内存。
- 核对同屏上限：敌人不超过 24、投射物不超过 80、地面掉落不超过 18；对象池稳定后不应随波次持续增长。
- 连续运行至少三个竞技场，观察稳定实体 ID 是否导致残影、重复对象或旧 Revision 回跳。
- 记录 60 秒断线窗口内服务端 Tick 确实停止，并确认恢复时没有一次大步长追帧。

- EditMode `OnlineArcadeRunTests`：12/12 通过。

## 8. 通过标准与记录

主链路、三组掉线恢复、五类幂等/故障用例及性能预算必须全部有双端证据。每个失败记录客户端平台、时间、RunId、RoomCode、PlayerId、Run/Battle Revision、服务端日志片段和最短复现步骤；修复后从相关安全节点重新执行，不以单端编辑器结果替代。
