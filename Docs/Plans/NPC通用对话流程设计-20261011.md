# NPC 通用对话流程设计

状态：具体设计待审阅，尚未实施。用户已确认第三人称交谈的呈现方向，并要求先制作通用流程；本轮不编写正式剧情。

## 目标与首版范围

玩家靠近 NPC 后主动交互，NPC 面向玩家，镜头转向 NPC，屏幕底部显示名字、台词和回答选项。玩家可继续、选择分支、离开，或从选项进入已有功能界面。结束时恢复原视角和玩法输入。

首版交付可实际操作的通用流程，包含顺序台词、选项分支、功能跳转、正常退出和失效清理。测试台词均明确标注“对话流程测试”，不成为人物背景或正式剧情设定。

先在基地地图向导接入测试对话：主节点提供“演示连续台词”“演示分支”“打开地图选择”“离开”。其余基地 NPC 保留当前入口，后续配置正式对话后再接入同一流程。演示不授予奖励、不修改章节进度、不写存档。

首版不制作配音、头像、口型、自动电影运镜、好感度、招募或完整任务系统；不新增路过招呼内容。保留俯视、第一人称及街机现有玩法，不全局切换为第三人称。不新增联机对话或服务器剧情权威。

## 当前实现与接入边界

- `NpcCtrl.OnNpcInteractionRequested` 验证 NPC 所属活动地图，然后 `FaceInteractingPlayer` 更新 Unit 朝向及表现，当前直接打开地图选择、仓库、制作、商店或街机入口。
- `PlayerInteractionSystem` 仍拥有范围候选及准星焦点。对话入口沿用现有交互距离，不扩大触发盒，也不另开远距离入口。
- `PlayerCameraSystem` 拥有模式、镜头输入、共享生命周期和鼠标锁定；`IPlayerCameraPort` 与 `PlayerCameraCtrl` 提供镜头表现窄端口，UI 不直接操作 Camera 或 Cinemachine。
- `BaseUICtrl`、`UIHelper.HasUIOpen` 已承担窗口生命周期和玩法输入阻断。对话复用该能力，不改变 `AppState` 或 `Time.timeScale`。
- `Config/Defines`、`Config/DataCsv` 是配置源，`Config/gen.bat` 是唯一生成入口。手写运行时代码通过 `IRuntimeConfigProvider` 消费只读定义。

## 玩家操作与界面

1. 在范围内交互，校验 NPC、玩家、地图及台词图后开启会话。同一时刻仅存在一个会话，已开启时拒绝重复进入。
2. NPC 沿用现有面向玩家逻辑。越肩第三人称使用临时交谈构图，保持 NPC 上半身可见；台词区域位于底部，不遮住 NPC 的脸。
3. 台词一次显示完整文本，不自动翻页。顺序节点使用“继续”，选项节点使用明确的回答按钮，结束节点使用“结束交谈”。不采用容易与选项点击冲突的任意位置点击。
4. 对话提供始终可见的关闭入口；电脑 Esc 退出，对应移动端返回和关闭按钮。首版直接支持鼠标、键盘关闭与触摸，不额外承诺完整手柄导航。
5. 交谈期间阻断移动、攻击、再次交互和镜头输入，释放鼠标供选择。世界继续运行，不赋予无敌；玩家死亡或地图切换立即结束对话。
6. 选择地图等功能时，重验会话与 NPC 身份，结束对话并恢复镜头，再调用现有功能入口。新功能窗口继续通过自身的输入阻断保护玩法；失败显示既有错误反馈，可重新交互重试。
7. 正常离开恢复原相机模式、水平与俯仰视角。地图或玩家已经更换时只释放旧会话，不把旧相机状态写到新玩家。

UI 使用 Dialog 层、底部半透明台词面板和安全区适配。名字、正文、继续与关闭入口通过正式 Prefab 的 ReferenceCollector 生成 View 引用。长文本区域允许滚动；选项使用独立 Box Prefab、宿主直接引用的 CustomListView 与纵向布局，超出可视区域可滚动。Controller 只绑定快照和回调，不创建、销毁或池化按钮。

## 台词配置与剧情扩展

新增客户端对话配置，不把台词与图结构硬编码在 UI：

| 定义 | 内容 |
| --- | --- |
| 对话入口 | 稳定对话 ID、NPC 配置 ID、起始节点 ID |
| 台词节点 | 稳定节点 ID、所属对话 ID、台词本地化 Key、可选顺序下一节点 |
| 选项 | 稳定选项 ID、所属节点 ID、排序、回答本地化 Key、动作及可选目标节点 |
| 选项动作 | 前往节点、结束对话、打开当前 NPC 已有功能 |

节点只采用一种推进方式：顺序下一节点、选项集合或结束。允许返回话题节点；缺失引用、重复 ID、跨对话引用、孤立节点和含糊的推进方式在配置加载时拒绝。允许玩家选择驱动的循环，不增加自动跳转循环。

“打开功能”只能调用当前 NPC 已配置的功能，不允许台词数据任意指定 NPC、任意执行方法、扣物品或授予奖励。演示入口绑定地图向导，商店等既有业务仍由原领域入口裁决。

未来正式剧情由各剧情领域提供已确认的进度与入口选择，通用流程接收稳定对话 ID；本轮不新增永久对话标记、通用表达式引擎或虚构剧情条件。重新交互从入口重新开始，关闭不保存读到的行数。

## 职责与身份

- 新增 `DialogueSystem` 管理活动会话、节点转换及选择合法性，注册到 `Game.cs`。状态含会话代次、NPC UnitId、MapInstanceId、对话 ID 和节点 ID，不保存 Transform、View 或资源 Handle。
- 会话快照只提供稳定身份、台词 Key 和选项数据；UI 提交带会话及节点身份的选择。过期点击、重复提交和后来覆盖的 UI 回调均拒绝。
- `NpcCtrl` 负责活动 NPC 校验、对话与原功能入口的路由，继续拥有 NPC 的地图生命周期；不承担台词状态机。
- 对话 UI Controller 负责显示、语言切换、输入焦点及按钮绑定；隐藏、卸载均通知关闭原会话，不能结束之后新开的会话。
- `PlayerCameraSystem` 管理临时交谈镜头的开始与释放，`PlayerCameraCtrl` 负责实际构图和遮挡处理。只沿现有共享 LateUpdate 更新，不增加产品 MonoBehaviour.Update。
- 功能选择先由对话状态机确认，随后交给当前活动 NPC 的既有路由；正式业务结果仍归原 System。

## 相机与失败清理

第三人称构图以玩家与 NPC 的实时有效位置为依据，将 NPC 上半身置于上方可读区域，采用短距离平滑过渡与现有碰撞避障能力；NPC 原地交谈，不要求新增动画资源。镜头运动参数归正式相机表现配置，不散落到 UI 中。

俯视或第一人称进入同一测试对话时保留当前模式及镜头，底部 UI 正常工作；本次镜头构图验收以越肩第三人称为主。

进入前先验证数据、活动身份和相机端口；UI 或镜头准备失败撤销本次会话，清理已取得的临时控制权并给出失败反馈。地图开始加载、玩家或 NPC 移除/停用、玩家死亡、UI 销毁和架构释放均关闭会话；清理幂等，事件与共享生命周期注册成对释放。

另一阻断窗口取得前台时终止交谈，避免台词隐藏后仍占用镜头。切换相机模式前结束交谈，避免关闭时恢复过期的视角。回到主菜单、切图失败恢复及同地图重开都不得残留鼠标锁定或输入阻断。

## 验收

- 配置加载：缺失入口/节点/文本、非法动作、跨图引用、重复排序及不合法节点结构均拒绝；合法选择循环允许。
- 会话规则：连续台词、分支、返回话题、结束、重复进入、过期选择及功能请求只执行一次。
- 生命周期：正常关闭、UI 销毁、NPC 移除、死亡、切图和相机切换均释放旧会话；新地图与新会话不受旧回调影响。
- Prefab 契约：宿主和 Box 均使用生成 View，CustomListView 直接引用独立 Box，反序列化后引用有效；长台词、多选项与中英文切换可读。
- 相机契约：越肩交谈时朝向 NPC，退出恢复原视角；俯视/第一人称不改变模式；失败和重复清理不污染后续镜头。
- 只运行明确类或方法过滤的 EditMode 测试，调用前报告准确过滤及预期最大执行数，`includePassingTests=true`，核对结果范围。不开完整套件、不运行 Player Build。
- 实机验收：基地地图向导的测试入口可操作，连续台词、分支、地图选择与退出全程连通；越肩镜头、输入恢复、移动端安全区与文字大小需要实际画面核对。自动测试不替代画面验收。
