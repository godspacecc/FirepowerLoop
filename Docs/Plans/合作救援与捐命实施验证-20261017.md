- 轮节点保存独立计时和显式恢复资格，零命活动者可继续切轮；默认 RoundAlive 的旧状态不能被当成零命恢复授权。全员倒地仍失败，不靠倒地时钟无限续局。

- `SlayerMartRoundOnline`，声明最大 17、includePassingTests=true：17/17，确认现有商店及切轮事务仍通过。
- Unity：连接路径 `E:/GitHub/FirepowerLoop/Client/Assets`，Boot 干净，修改前最近十分钟 Console Error 为空；同步导入成功。`CasualPopulationFlowTests`（最大 10、includePassingTests=true）实际执行 10/10 通过，证明正式客户端配置加载与现有普通轮准备兼容。双端规则 bytes SHA256 均为 7C048196164953CB8F0CD508956EB64A9763B5585964E56FB69234357A017BBB。

## 第二段：靠近救援

复用当前轮障碍的线段遮挡判断；同区域、存活、2 米内的队友使独立倒地时钟按 Config 的 2 倍推进。离开范围保留进度；隔墙或宝藏内成员不能加速。断线、地图未确认、切轮、商店和全员宝藏冻结；出口等待可继续恢复。

`CoopRescueOnline` 扩至最大 20、includePassingTests=true；先 16/20（新增的加速、边界、离开与出口用例失败），接线后 20/20。该段仅服务端权威，不声称 HUD 或真实双人联机已验收。

## 第三段：主动捐命权威事务

Actor 提供绑定 RunId、地图代次、目标与单调操作序号的捐命事务。本人至少 2 命、存活，目标为同区域零命倒地成员才消费 1 命即时救起。保护计算和回执准备在扣命之前；最近 32 条回执可重放，淘汰旧序号也不能再次消费。成功与失败回执都保持原裁决；同号换目标拒绝，不新增中途存档。

`CoopDonationOnline` 最大 16、includePassingTests=true：先 0/16（入口缺失），实施后 16/16；覆盖最后一命、重复／冲突／过期请求、再次倒地重放、阶段／区域与断线门禁、轮节点扣命和恢复一致性。`CoopRescueOnline` 最大 20 回归 20/20。此段尚未接正式消息转发与客户端按钮。

## 第四段：正式输入协议

通过 Tools/gen-protocol.ps1 生成双端消息：外部及两跳内部输入均携带 DonationRunId、DonateLifeTargetId，已有 InputSequence 作为单调操作身份。权威输入在任何动作变更前校验捐命对局及地图绑定。战斗玩家消息追加 DownedSeconds、RescueRate，构造与克隆均保留。网络能力指纹追加 coop-rescue.v1，旧形状客户端在 RPC／推送门禁被拒绝。

`CoopDonationOnline` 最大 20：接协议前16/20，接入后20/20，新增正式输入重复／过期对局和生成消息身份／倒地投影检查。`SlayerMartProtocolGate` 最大10：10/10；`SlayerMartRpcOnline` 最大8：8/8（反射测试调用同步补齐两个可选参数）。客户端 HUD 投影和按钮单独继续。

## 第六段：独立审查及修正

独立只读审查无Critical，发现三个Important：零命活动者准备按钮仍按命数禁用；跨场倒地恢复后旧Ready=false阻止场内切轮；延迟击杀加命留下命数大于零却仍倒地的矛盾状态。三项均已补失败复现后修正：

- 正式玩家协议追加 CanReadyForArena，构造、克隆、客户端只读快照和准备界面完整传递。零命仍须显式恢复资格，不能凭旧默认Alive免费恢复。协议能力随新消息形状升至 coop-rescue.v2，正式生成双端代码。
- 场内切轮明确使用 PrepareBattle 的 requireReady=false，安全节点开场仍要求准备；地图代次确认仍控制后续时钟。额外执行真实临时文件的 TryCommitRoundTransition，先26/27失败、修正后27/27，确认文件及新轮一起保留零命活动身份。
- 正常击杀／财宝累计加命和商店下轮加命都归一零命倒地身份；正常下一轮／场的空库存补齐包含已恢复活动的零命成员，救起瞬间仍不发额外补给。
