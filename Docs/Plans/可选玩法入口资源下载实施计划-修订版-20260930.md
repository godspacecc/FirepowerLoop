# 可选玩法入口资源下载实施计划

## 目标与范围

玩家在离线基地与地图 NPC 交互时，普通远征资源若已就绪，按原流程打开地图选择界面；若尚未下载，先显示下载大小与确认框，确认后显示下载进度，成功后打开地图选择界面。拒绝、失败、断网或请求过期均不得进入远征，也不得影响基地和单人街机。下载当前已加载资源清单中的纯资源后不重启；新清单版本仍沿用现有重启更新流程。

本批只贯通地图 NPC 对应的普通远征资源集合。单人街机 NPC、联机登录与房间、远征解锁/扣费/进入/结算规则、资源构建与 Android 首包筛选不在修改范围。其它可选玩法以后可复用同一入口下载能力，但本批不增加未确认的入口映射。

## 当前实现与开始前检查

- `Client/Assets/Game/Scripts/Controller/Npc/NpcCtrl.cs` 的 `NpcInteractionKind.MapSelection` 分支直接调用 `MapSelectionUICtrl.TryShowOffline`；`NpcInteractionKind.Arcade` 分支直接打开街机界面。`MapSelectionUICtrl` 打开后才处理地图解锁和进入，因此下载门禁应放在地图 NPC 分支，不改变地图选择结果语义。
- `Client/Assets/Boot/Res/ResourceBoot.cs` 在 Host 模式更新 `DefaultPackage` 清单，按 `startup`、`arcade`、`arcade-online` 标签下载启动资源；`Client/Assets/Game/Scripts/System/ResourceUpdate/ResourceUpdateSystem.cs` 只检查更新并提示重启。玩法入口不能调用其更新检查来冒充下载。
- `Client/Assets/Game/Scripts/Controller/Base/Notify.cs` 与 `MessageUICtrl` 提供确认框；`LoadingUICtrl` 和现有 `Common/Loading` Prefab 提供进度条与百分比，当前仅由地图加载事件驱动。通过隔离显示模式复用这些既有资源，不新建下载用 Prefab。
- 开始编码前核对实际工作区的资源收集配置、当前包型的构建产物和 `DefaultPackage` 清单：普通远征须有唯一、非空、可下载的资源标签。用当前清单的 `ResourcePackage.GetAssetInfos(tag)` 得到该标签实际覆盖的地址；对 `MapCatalog.GetExpeditionMaps()` 中每张地图，通过 `IRuntimeConfigProvider.TryGetMap` 取得 `MapAssetDefinition.SceneAddresses`，逐个核对地址确实属于该标签。依赖 Bundle 须被按标签下载器包含；未缓存时，启动下载范围不能已经把普通远征专属资源全部下载完。共享依赖允许同时属于基础集合。记录标签、地址、清单版本和核对结果。若标签没有覆盖任一必需场景地址，停止入口实现并报告缺口；不得把零下载数解释成已安装，也不得在本批顺手改构建或资源收集规则。
- 确认基地状态与街机界面所需的 `Notify/Message`、`Common/Loading` 资源在弹窗前已可加载。`MapSelectionUICtrl.Path()` 所指的 `Expedition/MapSelection` UI、它的依赖和打开该界面所需配置，必须已在基础资源中就绪，或其清单地址也出现在 `GetAssetInfos(tag)` 的结果中；记录各自的清单地址与归属。若不成立，停止并报告；不得通过把可选玩法整个目录改成启动下载来掩盖入口资源问题。
- YooAsset 2.3.17 的按标签下载器还会纳入当前清单中需要下载的无标签 Bundle。开始编码前必须针对实际包型和当前清单列出该下载器的全部 Bundle、标签、依赖、大小与所属模块，确认其中没有其它可选玩法专属 Bundle、需加载的新程序集或不应在本入口下载的内容。`GetAssetInfos(tag)` 只能证明资产标签关联，不能证明下载范围。若实际下载范围不满足本批“普通远征纯资源”边界，停止并报告；不得把这些额外 Bundle 当成远征资源默默下载，也不得在本批修改收集器或构建规则来消除差异。
- 除场景与地图选择 UI 外，盘点普通远征从选图到进入后由代码动态加载的必要 Prefab、UI 和其它地址。逐项记录“启动已就绪／属于本标签／由已核对 Bundle 依赖覆盖”的依据；无法证明完整资源集合时，不能把标签下载完成称为普通远征已就绪，应停止并报告缺口。
- `Client/Assets/Tests/EditMode/NpcControllerTests.cs` 现有 `MapGuideInteractionOpensSelectionWithoutEntering` 通过真实 NPC 点击检查地图选择入口；该文件自建架构尚未注册本批新增 System，UI Prefab 测试加载器也未提供确认/进度界面。必须按新语义维护这个直接相关的测试及其专用接缝，保留真实 NPC 点击、打开地图选择且未进入地图的断言，不以私有回调或源码搜索替代。

## 确定的实现规则

| 编号 | 固定行为与职责 |
| --- | --- |
| R1 | 只有离线基地的地图 NPC 触发普通远征资源准备；街机 NPC 与其它 NPC 的原行为不变。地图 NPC 的请求绑定当时 `UnitId`、`MapInstanceId` 与当前基地地图。 |
| R2 | 资源准备者使用已初始化的 `DefaultPackage` 当前清单与开始前确认的普通远征标签。使用 `GetAssetInfos(tag)` 的地址集合，逐个核对由 `MapCatalog.GetExpeditionMaps()` 与 `IRuntimeConfigProvider.TryGetMap` 得到的全部 `SceneAddresses` 确实属于该标签；地图选择 UI 若不在基础资源中就绪，也必须属于此标签。还须满足开始前记录的动态加载资源覆盖与实际 Bundle 下载范围审计。缺失包、版本、标签、必需地址、地址与标签的关联或资源覆盖依据均返回“不可用”，不弹下载确认。上述核对通过后才创建按标签筛选的下载器；其零文件结果方可视为“已就绪”。 |
| R3 | “未就绪”时显示玩法名称、待下载大小和“下载／取消”确认框。取消不开始下载、不打开地图选择界面。已经就绪时不弹窗，直接走原地图选择入口。 |
| R4 | 确认后同一玩法同一时刻只启动一个下载操作。复用现有 `LoadingUICtrl` 的进度条、百分比和错误区，但增加独立的资源下载显示模式。下载请求持有唯一显示令牌；下载中返回按钮、背景关闭及其它控制器关闭路径不得隐藏仍在执行的下载。地图加载事件不能结束或覆盖资源下载；若地图加载与下载重叠，须保持地图加载的状态可恢复，并在下载模式退出后按当前真实地图加载状态显示，不能因忽略早到事件使地图加载界面丢失。失败后明确退出下载占用，错误允许关闭并重试；资源下载不得改变普通地图加载表现。 |
| R5 | 下载完成后再次确认下载操作成功、同一包版本仍是当前版本、NPC 请求未过期、原 NPC 仍属于活动基地地图，才关闭进度界面并调用 `MapSelectionUICtrl.TryShowOffline`。打开失败保留资源缓存并提示原入口错误。不要代玩家选择地图、扣除解锁材料或启动远征。 |
| R6 | 拒绝、下载失败、服务器不可用、应用退出、NPC/地图释放或晚到回调均不打开地图选择界面，也不修改远征解锁、存档或玩家进度。下载失败可重新交互并重试；已完整缓存的资源可直接复用。 |
| R7 | 本次只下载当前 `DefaultPackage` 清单中的资源，不请求或切换新清单，也不加载新程序集。成功后直接继续入口，不自动重启；若服务器版本更新，应由现有更新提示处理。离线内置或离线兜底模式下，资源若不齐则显示不可用，不显示无法完成的远端下载确认。 |
| R8 | 新增玩家可见文本同时写入 `Client/Assets/Game/Config/Localization/zh-CN.json` 和 `en-US.json`。确认、进度、失败与不可用文案通过 `Loc.T` 等现有入口读取；不硬编码玩家文案，不手改生成的 `TextsGenerated.cs`。 |

## 允许修改的文件与职责

- `Client/Assets/Game/Scripts/System/ResourceUpdate/OptionalGameplayResourceSystem.cs` 及 `.meta`：新增普通远征资源状态查询、下载与单操作门禁；持有资源操作的临时状态，不持久化“已安装”。必要的结果/进度值类型放在同目录的新手写 C# 与对应 `.meta`，不创建通用插件框架。
- `Client/Assets/Game/Scripts/Game.cs`：注册上述 System。
- `Client/Assets/Game/Scripts/Controller/Npc/NpcCtrl.cs`：仅在 `NpcInteractionKind.MapSelection` 分支加入查询、确认、下载后继续原入口，并用 NPC 与地图身份约束异步结果；`Arcade` 分支不改。
- `Client/Assets/Game/Scripts/Controller/UICtrl/Common/LoadingUICtrl.cs`：为现有进度界面加入资源下载显示模式，保持地图加载事件路径原状；不改 `LoadingUI.cs` 与 `Loading.prefab` 的序列化引用。
- `Client/Assets/Game/Config/Localization/zh-CN.json`、`en-US.json`：新增本批直接展示的文案键。
- 仅当现有测试无法低成本覆盖重复请求与过期回调的隐蔽行为时，可在 `Client/Assets/Tests/EditMode/Flow/` 增加一个聚焦 EditMode 测试文件及 `.meta`；不得修改共享测试夹具或公共测试构造器来扩大影响面。
- `Client/Assets/Tests/EditMode/NpcControllerTests.cs`：更新直接受影响的地图 NPC 交互测试和该文件私有架构/资源/UI 测试接缝，使它以可控的“资源已就绪”结果通过真实点击验证原入口；在同文件增加需要受控下载结果才能证明的确认、重复或过期行为断言，或使用上述单独聚焦文件。不得删除或弱化原测试对 NPC 分发与“只打开地图选择、不进入地图”的保护。

测试接缝应在编码前明确注入点、所有者、可控结果和所需文件，优先使用上述允许文件内的窄资源操作接缝，由 `NpcControllerTests.cs` 内的受控实现返回就绪、待下载、进度、成功与失败。它不得绕过真实 NPC 点击入口，不向生产 UI 注入假状态，不修改共享测试夹具；若可靠接线需要新增公共接口或修改上述允许范围外的文件，先按实施偏差规则取得确认，不以运行时全局开关或反射调用私有回调替代。

上述范围外的 `Client/Assets/Boot/`、`Client/Assets/Editor/`、`Client/Assets/AssetBundleCollectorSetting.asset`、场景、Prefab、生成代码、存档格式、服务器和构建脚本不得修改。开始前检查若表明必须修改这些范围，按下文偏差规则停止并报告。

## 按依赖顺序实施

1. 完成“当前实现与开始前检查”，记录当前普通远征标签、全部远征场景地址与标签的关联、地图选择 UI 及其必要配置的地址和归属、动态加载资源覆盖、对应资源清单版本和包型。用该包型的实际清单和下载器结果审计全部待下载 Bundle，特别标出 YooAsset 按标签下载额外纳入的无标签 Bundle；审计不过不得进入步骤 2。YooAsset 2.3.17 的 `ResourcePackage.GetAssetInfos(string tag)` 提供当前清单中按标签查询资源信息的入口；确认项目实际包中的该 API、按标签下载 API、进度回调、成功状态和离线行为可用。API 不满足 R2、R4、R7 时停止并报告，不改用单个资源的隐式加载假装整个玩法已准备好。
2. 在 `OptionalGameplayResourceSystem` 实现 R2、R4、R6、R7：查询只返回“就绪／需下载／不可用”及文件数、字节数和版本；下载持有单一操作，进度回调只发布不可变数值；成功状态须由 YooAsset 操作完成结果确认，不以进度达到 100% 代替。重复请求、异常、清单变化与释放路径均关闭操作占用，后续请求可重新检查缓存。
3. 在 `Game.cs` 注册资源准备者。在 `NpcCtrl.cs` 的地图 NPC 分支实现 R1、R3、R5、R6：先查询再弹确认，确认回调只发起当前 NPC 的一次请求；异步完成后重新查 `UnitId`、`MapInstanceId`、活动基地状态和控制器释放状态。保持原 `MapSelectionUICtrl.TryShowOffline` 的错误提示路径，不提前执行 `BaseMapSelectionSystem.InteractWithMapAsync`。
4. 在 `LoadingUICtrl.cs` 为 R4 增加资源下载显示模式：开始时重置进度并绑定下载请求的显示令牌；回调仅在令牌匹配且界面实例仍有效时更新百分比与已下载大小；成功后退出该模式并关闭界面；失败释放下载占用后显示错误，允许关闭并重新通过 NPC 发起。下载中逐一核对返回按钮、背景关闭、`UIHelper.HideUI` 等现有关闭路径，不得让它们隐去仍执行的事务；若必须改动允许范围外的 UI 基类或公共关闭行为，按偏差规则暂停。地图加载开始、进度、成功、失败事件在资源下载模式下不覆盖下载显示，但要保存足以恢复当前地图加载显示的状态；原地图加载路径在普通模式下行为保持一致。
5. 在两份本地化 JSON 加入 R8 所需键，检查每个键在两种语言中均存在且格式参数一致。检查新增 C# 与 `.meta`、System 注册、UI 引用与修改差异。重要类型与方法的设计型注释须就地说明：`OptionalGameplayResourceSystem` 的状态有效期、单操作门禁、包版本和失败结果；`NpcCtrl` 中异步入口为何在等待后复核 NPC/地图身份；`LoadingUICtrl` 两种模式的事件边界与退出条件。注释解释原因、时机、重复调用和失败后保留什么，不逐行复述代码。更新被本批行为改变的旧注释；生成代码和第三方代码不补项目注释，普通测试用清楚的名称、准备和断言表达意图。
6. 更新 `NpcControllerTests.cs` 的直接相关测试及其文件内专用夹具：以可控“资源已就绪”结果保留真实 NPC 点击后的原入口断言，并覆盖确认下载后成功继续的入口边界；测试加载器为实际触发的确认、进度与地图选择界面提供真实 Prefab 或等效可审查的测试 View。用受控资源操作接缝稳定触发重复和 NPC/地图过期结果，断言只启动一次下载、过期完成不打开地图选择；不扩大公共测试夹具。自动运行前列出准确的 EditMode 类名或完全限定方法名、预计最大执行数，并将 `includePassingTests` 设为 `true`；结果超出声明范围时立即停止后续 Unity 测试。

## 实施后验证

1. 先审查实际改动与允许范围，核对用于下载的标签、清单版本、资源地址、动态加载资源覆盖、实际待下载 Bundle 与无标签 Bundle 的审计记录、NPC 身份复核、下载操作完成状态和 UI 模式退出；确认没有把其它可选玩法资源加入本入口下载或启动下载，也没有修改街机分支、存档或远征扣费路径。
2. 在可用的 Host 资源环境中做一次短流程：清除本批可选资源缓存后从基地与地图 NPC 交互，观察确认框大小、取消结果、重新确认后的进度及成功后无重启打开地图选择；再交互一次确认不重复下载。街机 NPC 保持直接打开。
3. 断开资源服务或使用可控失败条件做一次失败与重试：失败不打开地图选择，仍能在基地活动；服务恢复后重新交互可完成。若当前只提供离线完整内置包，则只能核对已就绪路径；首次确认、下载进度、失败重试和下载后无重启继续入口均记为未验证，R2—R5、R7 的下载链路不能报验收完成，实施结果应报告 Host 环境阻塞并等待可用资源环境完成这条短流程。
4. 维护并聚焦运行 `NpcControllerTests.MapGuideInteractionOpensSelectionWithoutEntering`。在直接相关测试文件或一个聚焦 EditMode 测试中，用真实 NPC 交互入口与受控资源操作接缝稳定触发重复请求、确认后成功、NPC/地图释放后的晚到回调和下载 UI 与地图事件重叠；不调用私有结果处理方法，也不使用源码字符串断言代替行为。每次 Unity `tests-run` 仅使用准确存在的短类名 `testClass` 或完全限定的 `testMethod`，不得只按程序集或命名空间过滤；调用前在评论中声明 Mode、过滤器和最大执行数，设置 `includePassingTests=true`，调用后逐项核对结果名称和执行数。若过滤失效、范围越界或无法构造可靠过滤器，停止后续自动测试并记录偏差。不新增或运行 PlayMode 自动化，不要求完整 Player 构建或全量流程。
5. 人工步骤未执行时如实记为未观察，不写通过。若实际运行 Unity 测试，记录工具返回的 Mode、Filter、Status、目标范围、Passed/Failed/Skipped、Duration、Error Logs；没有返回的字段不推测，Unity XML 与完整日志不作为必需产物。

## 实施偏差处理

### 可直接修复

仅当已确认设计、目标行为和验收不变，修改仍在允许文件内，不增加依赖，不改变公共接口、协议、数据格式或职责边界，且只是消除编译、兼容、接线或等价实现障碍，并能由本计划验证或必要的聚焦验证证明时，才做最小修复。实施结果记录症状、证据、实际文件、修复、与计划差异、验证和剩余风险。

### 先请用户确认

无法确定上述全部条件成立、多个合理修复会改变可见行为，或必须修改未列出的直接相关文件但总体范围未明显扩大时，暂停受影响工作并请求明确授权；获准后在实施结果中标为“用户批准的实施偏差”。

### 停止并报告

需要改变架构、公共接口、协议、数据格式、依赖、已确认设计，或明显扩大允许范围；实际项目状态与本计划根本冲突且无法用最小修复继续；可靠实施需要计划未给出的研究或技术决策；用户要求停止或重做设计时，停止受影响事项并等待修订计划。用户新增目标不能作为默认偏差直接实施。
