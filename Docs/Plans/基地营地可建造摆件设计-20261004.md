# 基地营地可建造摆件设计

状态：方案待用户审阅，未开始产品实现。2026-10-04。

## 已确认目标

把目前基地的人工造物变成可建造、可拆除重建的独立摆件，沿用现有建筑入口、材料消费、预览、建造、拆除返还和基地持久化。当前营地作为初始布局，新旧存档更新后不变成空场地。玩家改动必须保存，已拆除物件不能在重进地图或更新时复活。

## 现有实现依据

- `Config/DataCsv/temp_building.csv` 已有箭塔、木路障、火堆；配置包含材料、工期、距离、占地半径和导航阻挡。
- `TemporaryBuildingSystem` 允许合法离线基地与远征建造，提交成功后消费材料、记录建筑并标记存档脏；拆除通过现有掉落事务返还材料。
- `BaseWorldSaveData.TemporaryBuildings` 已持久保存建筑；`TemporaryBuildingCtrl.PrepareMap` 根据 ConfigId 和 Pose 加载、恢复实例。
- 当前 `TemporaryBuildingView` 只有单一 FootprintCollider；预览和提交仅切换这个碰撞体。开放棚子和多碰撞摆件不能直接套用该行为。
- 当前基地存档主版本为 3。自然地表和人工造物现在同在 BaseMap 的 MapContentRoot 下，人工造物为场景实例，并非建筑运行对象。

## 物件和玩法范围

首批目录：木棚、布棚、大木箱、小木箱、水桶、麻袋组、木桌、长凳、短木栅栏、木料/柴堆、营火。每种建立正式业务 Prefab，引用已经整理进 Game/Art 的资源；不修改备用美术原包。选择列表显示标准规格，初始布置允许保存既有实例比例，首版不提供玩家缩放操作。

地面、土坪、道路、树木、灌木、草簇和外围岩石保留为固定环境。靠棚工具、扫帚等零碎小装饰保留为固定装饰，不占建造目录。

新增摆件仅在离线基地提供建造选择。原箭塔、路障、火堆的远征与联机规则保持；新增基地摆件须在配置、客户端消费边界和服务器请求校验处阻止用于其他地图，不能只靠 UI 隐藏。

仓库、制作、商人、导览、街机 NPC 保持当前身份、坐标和功能；这些摆件仅改变环境，不代替 NPC 功能。玩家拆掉设施旁的桌棚后 NPC 功能仍有效。NPC 面前的接近空间和出生点作为不可侵占区域。

## 建造、碰撞与拆除

沿用建造列表，摆件显示名称、图标、材料和工期；预览显示是否合法，旋转后的占地随姿态检查。摆放确认、取消及拆除仍由建筑领域系统决定，UI 只提交意图。

区分选择/占地体与实体碰撞：选择体用于建筑选择、预览和拆除，不把开放棚子封成实心盒。预览关闭所有实体阻挡、导航障碍及营火效果；提交成功后开启对应实体与效果。释放、取消和建造失败不能残留碰撞、灯光或粒子。

箱桶、桌凳等沿用简单实体碰撞；棚子沿实际支柱与棚顶保留开口。导航阻挡和物理阻挡分别表达，开放棚子不能用覆盖整片占地的雕刻盒封住入口。占地半径只作为粗筛，最终使用朝向相关的占地区域检查重叠，不用一个球代替长桌和栅栏的实际占地。

成功建造才扣材料；失败不扣，连续确认不重复扣。拆除沿用当前材料返还与掉落失败回滚，不额外设计新返还比例。初始免费物件也使用同种正常拆除返还规则；这是每份基地存档一次性的初始资产，不重复发放。

材料仅使用已有木材、布料和金属零件；尺寸较大的棚子高于小摆件，工期与材料最终数值在实施计划中列出供审阅。配置是唯一权威源，不在代码内隐藏费用。

## 默认营地与旧存档迁移

把当前人工造物的身份、ConfigId、位置、朝向、比例离线提取成配置中的默认布局；对照当前营地逐件核对，不在运行时遍历场景猜测建筑。

新建基地一次性写入默认布局和初始化标记；旧合法基地存档通过显式迁移追加默认摆件，同时保留已有建筑、掉落、背包、仓库及其他分区。分配 RuntimeId 时避开已有 ID。

已有玩家建筑与默认摆件冲突时保留玩家建筑：跳过有冲突的默认项，并将初始化标记设为完成，不在后续加载反复尝试补回。默认项互相之间允许现有场景中已经确认的摆放组合；与固定环境或 NPC 接近区冲突必须在离线校验时发现。

初始化标记独立于建筑列表是否为空：空列表可能是玩家已拆掉全部摆件，不能因此重新补建。标记、建筑记录、比例都纳入 Clone、校验和版本迁移。旧建筑没有比例字段时按 1 恢复；新值必须为有限正数，不保存 Unity 对象或 MapInstanceId。

初始化通过候选存档完成，资源加载或落盘失败沿用基地进入流程回滚；不得将半完成迁移提交为成功。当前离线远征进行中的基地也只迁移持久基地候选，不碰远征世界或结算标记。

BaseMap 移除对应人工造物的静态实例及碰撞，仅保留环境和固定小装饰。初始营地和玩家建造物统一从建筑存档恢复到现有 DynamicObjectRoot，防止场景与存档各生一套。地图卸载由既有控制器释放实例与资源句柄。

## 涉及范围与交付

- 正式摆件 Prefab、碰撞、预览高亮、图标和名称；BaseMap 静态人工造物的迁移。
- Luban 建筑配置、默认布局配置及生成的客户端/服务器产物。
- 建筑 View/Controller/System 的碰撞生命周期、占地、地图限制与比例恢复；建筑选择列表的新增数据接入。
- 基地存档 DTO、Clone、迁移、校验和初始化事务。细化文件和配置字段在实施计划中确定，生成代码不手改。
- 不提供额外的已建成物直接搬移编辑器；首版通过现有拆除、返还、重建流程调整布局。
- 不在本阶段制作联机共享基地装修，也不把每个摆件添加成独立背包物品。

## 验收

1. 新基地外观与当前基本布局对应，造物只有一套运行实例；原玩家建筑不丢失。
2. 旧存档迁移只执行一次，重载、重返基地、重启和再次更新都不会复活已拆摆件。
3. 建造消费、取消、创建失败、拆除失败及返还遵循已有原子语义；NPC 功能仍可接近并操作。
4. 开放棚子能进入；预览不挡玩家；提交后有效碰撞；拆除及地图卸载无残留。
5. 改摆位置、朝向、初始比例可以保存和恢复；入口及 NPC 接近区不能被新建筑占据。
6. 基地摆件不能在远征或联机地图经绕过 UI 的请求创建，原建筑规则通过针对性回归。
7. 只运行有效短类名或完整方法过滤的 EditMode 检查，调用前声明最大数量并核对每项结果；共享编辑器测试冲突时不把其他任务结果当证据。画面、操作手感和设备验收与自动测试分别报告。
8. 不执行 Player Build、包装或发布，不自动提交；若实现引入宿主边界变化，重新核对能否仅热更新。
