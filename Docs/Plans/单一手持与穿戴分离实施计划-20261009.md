# 单一手持与穿戴分离 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. 当前会话内原生执行；未授权子代理、自动提交或 worktree。步骤使用复选框追踪。

**Goal:** 移除双武器持有槽，物品保留库存归属，短剑和弓可拿出、收起并通过手机列表切换，旧数据无损迁移。

**Architecture:** PlayerBagModel 保有库存权威，WeaponEquipmentModel/System 演进为唯一当前手持权威；InventorySystem 的事务同步处理手持来源迁移和失效。联机由服务端处理相同规则，客户端只展示确认结果。现有 Presenter、第一人称副本、UIRoot 与生成器继续负责表现，不创建第二套装备系统。

**Tech Stack:** Unity C#、QFramework、Newtonsoft JSON、UniTask、ET/MemoryPack、现有增量存档与 UI 生成器。

**Spec:** [单一手持与穿戴分离设计](单一手持与穿戴分离设计-20261009.md)，用户已回复“继续”确认。

## Global Constraints

- 首批实际手持接入短剑和弓，保留现有短剑主动攻击与弓箭玩法。
- 物品仍属于原库存格；手持不是第三个储存位置，不额外增加容量。
- 仅迁移阶段把背包容量扩大到足以完整接收旧装备和已装弹药的最小值。
- 在线口袋尚未实现，继续显示其既有不可用状态，不创建本地口袋作为联机替代。
- 其他工具、衣物属性、叠穿、轮盘、全新换手动画、街机独立装备体系不在范围内。
- 不改武器配置数值，不导入新的美术资源，不打包、不默认提交、不创建 worktree。
- Unity MCP 优先；Boot 脏时从磁盘重载，不保存。UI Prefab 使用 ReferenceCollector 与匹配生成器，生成 View 不手改。
- Unity tests-run 必须过滤真实短类名或完整方法，includePassingTests=true；每次调用前声明模式、过滤和最大数量，之后核对 Results。禁止完整套件、程序集/命名空间宽过滤与 Player Build。
- 核心类、关键函数及重要字段补中文 XML 注释。原有 Boot、安卓构建、DLL、设置、材质、字体及其他工作区修改保留；只提交用户单独授权的任务文件。

## Review Focus

1. 同类物品进入旧格：不能继承上一实例的手持或接受旧 UI/异步回调。任务 1、4、5 验证。
2. 满背包旧档：武器和已装弹药全部保留，补偿容量仅取必要值，第二次读取不复制。任务 2、3 验证。
3. 服务端旧协议或伪造来源：明确拒绝，不能将旧双槽请求解释为新拿出请求。任务 3 验证。
4. 切换时射击/瞄准仍按下：清除旧输入，不发生一帧旧武器伤害或晚到模型覆盖。任务 4 验证。
5. 重开/销毁手机选择面板：回调和事件不重复，关闭恢复游戏输入，库存过期候选不提交。任务 5 验证。
