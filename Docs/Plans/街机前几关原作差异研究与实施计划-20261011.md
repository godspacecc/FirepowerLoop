## 本批设计与执行清单

1. 总量仅覆盖新 Casual 配置 1/2/3 普通四轮，排除挑战、独立最终 Boss、后期及旧局。轮次 = (本局竞技场序号−1)×4+局部轮次。复用已确认 OrdinaryRoundTotal；按既有敌群权重累计整数分配，保证总量准确，不复制一份总量给每种敌人。此分配为项目兼容政策，非原作敌种比例。同屏上限、间隔保持当前配置，人数在场创建时固定。
2. 使用既有 RoundRestSeconds / ExitRestSeconds，配置 2/3 填 120/300，增加独立 HasRest 合同；只在新 Casual 两分支启用，岛岸水火不启用。松开再射击沿用现有输入；超时首个有效配置出口是现有项目政策，不称原作已证实。
3. 新 Casual 前两场波次和整场清场不给购物现金，已有个人积分、应急补给、旧局钱和商店兼容不动。后期现金来源及商店迁移不在本批。

审查重点：两分支同为累计第 5 轮；多敌种之和准确；挑战不套总量/休整；旧局不被新规则覆盖；整场完成不额外发现金；刷怪队列未清空不能推进。

- 总量通过共享纯算法分配：累计权重向下取整之差，保证混合敌群之和准确。未调整后期 CSV 组、敌种、速度、间隔和同屏预算。基础/弓箭连续分批顺序仍沿用既有行为。
- 休整合同增加 HasRest，与 Enabled（水岸）分开；两个权威 System 使用同一前期范围判断。单人 HUD 快照读取规则，View 和 Prefab 未修改。联机规则可执行，但旧联机 HUD 未增加休整倒计时协议，仍待显示对齐。
- 单人及服务端前两场波次和整场提交现金均为零；已有余额不会清除。全局普通现金迁移仍不能称完成。
- 配置指纹 `arcade-20261011-v21-early-branches`；Config/gen.bat 成功完成双端生成，实际变更仅客户端/服务端 tbarcadearena.bytes、tbarcaderule.bytes；生成 C# 无变化，新测试 .meta 已由 Unity 生成。未重启正式服务端，运行中服务器需重新加载才使用新配置。
