# 现有人形武器动画兼容实施计划

## 目标与范围

修复已接入人形、武器和动画在造型库与实际游戏中的接线问题：敌人启停后保留配置武器、失败不残留旧动作、空手与持武器使用四方向移动、造型库切换模型或武器后延续兼容动画。完成现有组合后，使同类新资源主要通过导入设置、Prefab、表现资源和现有玩法表接入。

造型库可以试装实战中角色无法获得的武器。实战仍按装备、敌人配置、攻击规则决定行为；不增加武器获取规则、侧移 AI、可玩角色选择、网络协议、存档字段或新战斗类别。本批只处理角色武器表现链及其直接调用方，不重构地图、战斗、资源加载框架。

## 必要基线

- `CharacterWeaponCatalog` 保存稳定武器 ID、普通物品 ID、模型或 Mesh/Material、主手、副手握点、枪口以及 idle/move/attack 三段动画；`CharacterWeaponPresenter` 根据基础动画片段名称替换三段动作。
- 当前目录 `Client/Assets/Game/Art/Arcade/Weapons/CharacterWeaponCatalog.asset` 有 13 项：短剑、弓、大剑、刀、斧、镐及七种街机武器，普通物品映射为 5、6、15～25。造型库的五个正式人形 Prefab 已引用该目录。
- 普通敌人准备时先设置配置武器，再激活实例；`EnemyView.OnEnable` 又应用 Prefab 默认武器。街机路径先激活再赋配置；联机敌人准备路径尚未调用共享武器入口。
- `SetWeapon` 销毁旧模型后，若新资源校验失败，可留下旧 override。玩家还有旧异步外观与旧持枪姿态路径；不能让它们与共享路径同时写模型或骨骼。
- 造型库 `SelectCharacter`、`RefreshEquipmentOptions`、`RefreshAnimationOptions` 会释放动画并重置选择。共享武器路径只提供三段动作，不能据原始片段预览推断实战状态过渡正确。
- `Config/DataCsv/enemy.csv` 已有 `WeaponId`；`arcade_weapon.csv` 已收录上述 13 个稳定身份；`weapon.csv` 的对应物品具有 `WeaponKind`。复用这些字段，不修改 Schema、不重新生成配置、不手改生成代码或 bytes。
- 已有弓方向片段位于 `Client/Assets/Game/Art/Player/Animations/Mixamo/Imported/`，包括 Standing Aim Walk 系列及 `BowAimWalkRightComposite.anim`；同目录有 RifleWalk 四向资源。空手完整四向资源是否可用需要资源预检，不预设齐全。

实施前记录当前工作区和 Unity Console 基线。当前工作区已有和家村相关未提交改动，且 `LubanRuntimeConfigProvider.cs` 与本计划文件范围重叠；不得覆盖、暂存或归因这些改动。先核对该文件的现有差异和编译状态，再判断本批能否安全修改；若与 R1 的目标发生实质冲突，按偏差规则暂停受影响部分。

## 确定的实现规则

### R1 玩法与表现的职责

配置 Provider 只处理表数据，不读取 Unity 表现资源。Controller 从现有正式配置取得武器身份、近远程行为，再交给 View/Presenter。Presenter 只拥有模型、动画 override、握持与枪口引用；不得修改装备、伤害、弹药、掉落或角色位置。造型库只操作临时实例和预览状态，不调用装备或战斗命令。

删除 `CharacterWeaponIds` 的逐 ID 白名单和前缀分类用途。Provider 校验 `EnemyConfig.WeaponId` 时按 `TbArcadeWeapon` 精确查 ID：`Melee` 对应近战；`Direct`、`Piercing`、`Explosive`、`TimedExplosive` 对应投射；未知枚举失败。这里只核对身份及近远程一致性，敌人的伤害、弹药和攻击时序仍来自 Enemy 配置。错误含表名、行 ID、武器 ID 和原因。空或未知敌人武器 ID 仍失败。

普通装备以 `TbWeapon.WeaponKind` 为准；街机以 `ArcadeWeaponDefinition.Behavior` 为准。装配前检查目录的近远程表现标志与该值一致。目录 `WorldItemId > 0` 唯一且必须对应合法武器物品；`0` 表示不参与普通装备映射，允许多个预览专用项为 0。稳定武器 ID 非空、大小写敏感、全目录唯一。仅预览项不要求在玩法表中存在。已配置敌人或玩家实际使用的项必须同时通过玩法与表现检查。

### R2 显式动作与角色接线

新增三类数据，均只含表现配置：

1. `CharacterAnimationDefinition`（动作 ScriptableObject）：`clip`、`displayName`、`compatibleCategories`、`requiredBones`、`allowOffhandGrip`。资产引用是动作稳定身份，clip 是实际片段；不使用名称或下拉索引识别动作。类别为可组合标志：Unarmed、OneHandMelee、TwoHandMelee、Bow、Pistol、Rifle、Launcher、Throwing；数值从 1 开始依次左移，0 无兼容类别。只有有效 Humanoid 片段才可登记。相同 clip 不得登记互相冲突的兼容性或握持信息。
2. `CharacterAnimationSet`（可序列化数据，放在上述源码内）：`idle`、`moveForward`、`moveBackward`、`moveLeft`、`moveRight`、`attack` 六个动作引用及按序 `extras`。空手集合允许 attack 为空，此时保留 Profile 的原 attackSlot，不新增空手攻击规则；持武器六项必须齐全。Extras 用于已有受击、死亡、换弹等可检查片段，不创建新玩法。
3. `CharacterAnimationProfile`（角色动作接线 ScriptableObject）：`baseController`、该控制器中的 `idleSlot`、`moveSlot`、`attackSlot` 原始 AnimationClip 引用，以及 `unarmedAnimations`。三个槽位必须不同且能在 baseController 的 override 键中找到；不按原始片段名称猜测。受击/死亡等未列槽位不替换。每个使用不同基础控制器的人形配置相应 Profile。

`CharacterWeaponCatalog.Entry` 新增显式 `category`、`isProjectile`、`muzzleFlash`、`animations`，保留武器 ID、物品 ID、模型、主手、局部变换、枪口和副手握点。原 idle/move/attack 迁移为动作引用，已有 move 作为前进来源，其余方向逐项补齐。完成资产迁移后移除旧三字段及其运行时读路径，不能依赖字段默认值宣称迁移完成。

Presenter 序列化引用指定 `Animator` 和 `CharacterAnimationProfile`，不再通过第一个子 Animator 推断主体。必须校验 Avatar 有效且为 Humanoid、主手为左右手之一、必要骨骼存在、模型合法、缩放各轴为正有限值、枪口和变换为有限值。需要副手时按主手的相反手检查上臂/前臂/手骨。动作定义的额外必要骨骼逐个检查。

可在 Presenter 中配置按武器类别唯一的局部位置/旋转修正，仅用于已观察到的身材差异，默认零；不维护每角色每武器的组合表。原目录的挂载变换先应用，再叠加角色类别修正。

### R3 同步切换、失败与释放

保留 `SetWeaponId(string)`、`SetWeapon(CharacterWeaponCatalog.Entry)` 的 bool 返回入口，增加只读 `LastError`；二者均使用同一个内部切换过程。`null`/空 ID 是切为空手，未知非空 ID 是失败。

先验证候选引用、骨骼、槽位和动作；候选模型先隐藏创建、关闭内部 Animator/Collider、设置层和局部姿态，成功后再发布 `Current`、`Visual` 与 override。重复设置相同有效项不得重新实例化或重置动画状态。每个 Presenter 持有自己的 override，不修改共享 controller 或 clip；方向改变仅更新自己 moveSlot 的替换引用，不能每帧新建 override。

任何切换失败（包含未知 ID、缺骨骼、非法动作、模型实例化异常）均清空旧/候选模型和当前武器，停止旧握持，清除旧枪口引用，恢复 Profile 的空手动作覆盖；若 Profile 本身失效，则恢复首次绑定时记录的原控制器，报告错误，不假称空手可用。不得保留旧武器动作却移除模型。延迟 Destroy 前先隐藏对象，释放暂存引用；不要 Destroy 项目资产。成功后 `LastError` 清空，失败返回 false 并保存具体原因。

组件释放时销毁自己创建的模型与 override；重复清理安全。基础控制器、动作和目录资产不归实例释放。切换/失败通知由调用方同步消费；不新建全局事件或常驻 System。生成后尚未显示的角色失败沿已有准备失败路径清理；显示中的装备失败只清表现并报告，不回写装备身份。

### R4 四方向移动

新增 Presenter 入口 `SetMovementDirection(Vector3 worldDisplacement)`，保存最近水平位移；方向相对当前角色朝向计算。使用绝对值较大的局部 X/Z 轴选方向，相等时选 Z；Z 正前/负后，X 正右/负左。水平位移平方小于等于 0.000001 时视为停止，不凭上次方向保持移动。移动速度和进入待机仍使用既有 `MoveSpeed` 参数与阈值，不修改输入、导航或战斗移动规则。

玩家在 `CharacterController.Move` 前后取实际位置差，修正现有使用请求 motion 计算速度/方向的路径；转向后用最近实际位移重算，切换武器后立即用已存方向选择新集合。PlayerViewCtrl 的 `SnapLocal`、存活状态切换和移动端口不可用分支清空 lastHorizontalMotion，并向 View/Presenter 写入零速度和零方向；PlayerView 的禁用清理同样清零。不能将传送距离作为移动。

敌人由已有 `TickCombatFeedback` 表现刷新链在受击反馈早退之前记录相邻采样位置，用水平位置差除有效 deltaTime 统一更新 MoveSpeed，并相对本次更新后的朝向计算方向。普通导航、街机及联机表现共用此入口；移除 EnemyCtrl.TrySetEnemy 的重复速度计算/写入。联机 Tick 当前在连续插值 Snap 之前调用反馈刷新，须将本帧反馈采样移到导航或插值的位置、朝向更新之后；死亡分支仍显式归零。首次采样、deltaTime 非正、停止、死亡、禁用或新用途时速度和方向归零；不添加新的 Update、不改变 AI。

新增 `EnemyView.ResetMovementSampling()` 并由 `EnemyViewCtrl.ResetMovementSampling()` 转发：设置当前位置为基准、下次采样从零开始，同时清零速度/方向。EnemyViewCtrl.Snap 只设置位置朝向，不自动重置，因为它也用于连续插值。普通/街机出生与新用途通过 R6 的入口重置；联机准备初始 Snap 后，以及 `OnlineWorldEnemyCtrl.Apply` 的 snap=true（复活/导航接管等离散定位）分支在 Snap 后显式重置；联机 Tick 中连续插值的 Snap 不重置。死亡、Stop、OnDisable 从 EnemyView 自身重置。暂停后重新启用的第一帧不会计算隐藏期间的位移。

空手、弓、长枪必须有确实不同方向的可用动作；其余类别可复用兼容的已存在完整动作或已制作好的下半身组合片段。本批不开发运行时动作合成框架。不得把持枪上半身直接当空手，或将前进复制到另外三格作为完成。既有动画保持原地播放，Animator 不应用根位移。

### R5 握持、攻击和枪口只有一个表现来源

迁移五个人形的共享路径后，由 Presenter 负责主手挂载和副手约束；PlayerView 旧 AlignArcadeMainHand、SetWeaponVisualPose、AlignOffhandGrip 以及旧 bow override 不得再叠加到共享路径。保留旧入口给未迁移 Prefab，但共享路径不得按资源名、片段名、ID 前缀分支。

副手按相反手求解，并且仅在当前动作定义允许时应用。实战根据 Animator 当前及过渡目标的非零权重片段对应的动作定义判定；未登记片段、受击/死亡、任一有效贡献动作不允许握持时不约束。造型库显式传入当前动作定义；手动采样期间禁用 Presenter 自动 LateUpdate，采样求值后仅调用一次握持入口。保留现有有限距离修正，不用累计骨骼平移掩盖不可达问题。

共享攻击只触发一次既有 Attack 动作，不同时触发旧 PistolFire/ShotgunFire。动作集合承担姿势，既有战斗系统承担开火、命中和弹药。共享枪口始终来自当前 Visual 与目录枪口偏移；空手/失败立即清除，返回既有无武器后备位置。Presenter 新增 `TryGetProjectileOrigin(out Vector3 origin)`：仅当 Current 为有效投射项且 Visual 存在时按 TransformPoint 返回 true，否则返回 false，不提供旧模型位置。PlayerView.GetProjectileOrigin 与 EnemyView.TryGetProjectileOrigin 在共享组件存在时优先使用此入口，失败使用各自既有几何后备位置，不能重新读取旧枪口 Transform；无共享组件的角色保持旧路径。枪口火光由目录 `muzzleFlash` 驱动；保留既有粒子对象，但把位置对齐到当前共享枪口，不再依赖旧隐藏枪模型才显示反馈。旧身体/武器后坐不得二次叠加破坏动作；共享路径保留已配置攻击片段本身的后坐。弓/投掷物/发射器是否闪光使用显式配置。

### R6 敌人启停、对象复用与玩家入口

EnemyView 单独保存“是否已指定本实例武器”与所选 ID，区别未指定和显式空手。`SetCombatWeapon` 先记录指定状态，再调用 Presenter；即使失败也不能在 OnEnable 偷换成默认武器。OnEnable 有指定值时恢复该值，只有从未指定才用 Prefab 默认值；OnDisable 释放可见物但保留该实例选择。新增 `ResetWeaponSelection()`，只在结束实例用途/回池或开始新用途时清除选择；普通地图隐藏再显示不得清除。

新增 `EnemyView.BeginPresentationUse()` 作为新实例用途初始化入口：调用 ResetWeaponSelection、ResetMovementSampling，执行原 OnEnable 中的 ResetAnimationPresentation、清反馈时长、启用 combatCollider/NavMesh、关闭预警和 SetCorpsePresentation(false)。普通、街机与联机敌人必须从实例化开始就保持 `activeInHierarchy=false`，例如先放入已禁用的候选父节点；调用现有实例提供器前验证此语义，不能依赖实例化后再 `SetActive(false)`，也不能让街机路径先激活再配置。随后先调用此入口，再按本次 Enemy 配置设置武器，再执行本次导航/存活/尸体状态配置，成功后才显示或加入活动集合。造型库必须按“创建临时实例→取得 EnemyView 并调用 BeginPresentationUse→统一禁用实例及子物体的全部 NavMeshAgent/Collider→开启手动采样并恢复武器/动画选择”的顺序执行；不能在禁用组件之后再调用该入口，预览不参与导航或碰撞。无共享组件的旧非人形仍通过该入口完成原有初始化，不强制人形化。

OnEnable 只确保必要组件引用、恢复已选武器或未指定时的默认武器，以及原有界面引用初始化/可见性刷新；移除其中的上述新用途复位，不重置 Collider/NavMesh 的 enabled 值、死亡 Animator 状态或尸体状态。OnDisable 只做暂时隐藏清理与采样重置，不代表新用途。新用途绑定失败沿各自现有逆序清理路径移除实例、候选记录和资源 Handle，不注册新的战斗对象。联机只增加客户端表现装配，不改快照或服务端规则。

`ConfigureRuntime` 不清武器选择，因为普通地图可能先设置武器再由 ViewCtrl 配置运行身份。池回收清理不得误用地图临时隐藏；重用时无论相同配置还是不同配置均重新按本用途绑定。武器恢复不得重置存活/死亡、尸体、导航状态；原有恢复尸体/生命/导航配置在 BeginPresentationUse 之后应用，避免激活时把尸体复活。

玩家按装备物品进入共享目录；街机按稳定 ID 进入。共享目录存在的已迁移角色不因无映射或绑定失败退回旧外观，不允许旧模型遮住配置错误：清理旧异步外观并使在途请求失效，显示空手并报告错误。无共享组件的旧角色仍保留原回退。沿用 PlayerCtrl 的请求版本、MapInstanceId 与 Handle 清理，不新增异步加载链。实际战斗类别与目录不一致按 R3 失败，不能仅因目录有模型接受非法身份。

### R7 造型库延续、回退与不可预览

选择模型、武器和动画是三个独立状态。切换前记录正式 Prefab 引用、武器 ID（空串为空手）、动作资产引用、采样时间（秒）、播放/暂停状态；先销毁旧采样图再释放模型，不能由刷新下拉框覆盖这些记录。下拉选项更新使用不触发回调的赋值，禁止互相递归刷新。

兼容必须满足：模型 Avatar/骨骼有效、所选武器资源可绑定、动作 clip 有效且为 Humanoid、动作类别掩码包含当前类别及动作要求的骨骼齐全。不能用敌人实战能否获取武器、动画名称或是不是新武器默认动作判定。

更换模型保留武器 ID；若绑定失败，仍展示所选模型、武器选择与原因，但清除可见武器及旧图并停止播放，不偷偷切换武器。绑定成功后，更换模型或武器均执行同一动画恢复：原动作兼容则继续相同 clip、时间和播放/暂停状态；即使不在新武器默认列表，仍追加“延续：动作名”可选项并选中。该临时项不写回资源。

原动作不兼容时按“待机、前进、后退、左移、右移、攻击、extras 配置顺序”筛选出可用动作，按动作引用去重，选择第一项，从 0 秒开始并保留播放/暂停状态，提示具体不兼容原因。没有可用动作时选中索引为 -1、停止播放、禁用时间轴并说明，不残留旧图或旧索引。完整武器绑定失败与仅原动作不兼容是不同分支，前者不假称已绑定新武器。

兼容延续的同一 clip 使用原采样秒数，循环片段取模，非循环夹在有效范围；新图先设置时间、求值，再按之前状态播放或暂停，不闪回首帧。显式手选另一个动画从 0 秒开始并播放；此操作与自动切换恢复分开。组件禁用/销毁释放图和临时模型，清引用。统一当前五个角色的共享路径，移除其按资源名/片段名猜测的过滤和组合预览入口，保留目录 extras 中的原始片段预览；界面提示“片段预览，实战状态过渡需在游戏中观察”。

### R8 当前资产迁移和接入样例

先完成现有五个人形与 13 项目录。逐项配置类别：短剑/刀/斧/镐为 OneHandMelee，大剑为 TwoHandMelee，弓为 Bow，basic 为 Pistol，rapid/piercing/spread/raygun 为 Rifle，rocket 为 Launcher，grenade 为 Throwing；近远程标志对照 R1。握持开关与动作兼容掩码根据片段实际用途填写，不一律开放所有类别。
