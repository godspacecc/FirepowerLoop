# 基地天气测试指令样板实施计划

> 执行方式：在当前会话由主代理使用 executing-plans 技能逐项实施；项目不授权子代理、worktree、自动提交或打包。本计划待用户审阅，尚未实施。

**目标：** 在离线基地通过测试指令观察雨、湿地、放晴及逐渐干燥，保留现有昼夜。

**架构：** 新增 BaseWeatherSystem 持有会话内样板状态，通过共享生命周期推进并发布不可变快照；BaseWeatherView 持有地图雨粒子、音频与地面表现。DayNightView 及 MapProceduralSkyView 消费天气表现参数，由原所有者应用光照和天空。

**技术：** Unity、QFramework、URP 14、现有 TestCmdSystem 和 Unity 定向 EditMode 测试。

**设计：** [基地晴雨与地面干燥样板设计](基地晴雨与地面干燥样板设计-20261012.md)。

## 全局约束

- 只支持离线基地，Editor/Development Build 测试入口；无累计日历、存档、联机天气、季节表现或生存数值改动。
- 当前目录 E:/GitHub/AnotherDay；Unity MCP 优先；不创建 worktree、不派子代理、不提交、不打包。
- 不修改工作区既有相机、街机、Main 场景和生成产物。不改测试目录配置或 UI，只走自由输入。
- 直接命令即时切换，demo 展示平滑过渡；暂停停止天气推进和粒子模拟；切图复位天气并释放地图表现。
- 天气测试每次只运行存在的精确类/方法，声明最大数量并核对实际返回名称，includePassingTests=true。
- 核心类、状态字段、命令入口与释放方法补充中文 XML 注释。

## 审查重点

无效命令不终止 demo；重复 clear 不推迟干燥完成；切图迟到资源不得重建旧效果；天气不覆盖昼夜的太阳方向；地面修改不污染共享材质。

## 任务一：天气状态与指令

**文件：** 新增 `Client/Assets/Game/Scripts/System/Environment/BaseWeatherSystem.cs`、`Client/Assets/Tests/EditMode/BaseWeatherTests.cs`；修改 `Scripts/Game.cs` 和 `Scripts/System/TestCmd/TestCmdSystem.cs`（上述 Scripts 均位于 Client/Assets/Game）。

**接口：** 不可变 `BaseWeatherSnapshot`，包含 RainAmount、CloudAmount、Wetness（0～1）、Stage（字符串）、IsActive；`BaseWeatherChangedEvent.Snapshot`。`BaseWeatherSystem.GetSnapshot()`、`TrySetMode(string mode, out string message)`、内部 `Tick(float realDeltaSeconds)`。TrySetMode 完成地图、开发版及语法校验后才改变状态；status 由命令调用 GetSnapshot。

- [ ] 读取 TestCmdSystem 完整分派与结果枚举、MapSceneModel、AppStateModel、邻近测试夹具；确认现有生命周期和注册顺序。
- [ ] 写 BaseWeatherTests 的状态/命令用例：初始晴天；rain 为雨量与湿度 1；clear 保留湿度且 45 秒后为原值一半；重复 clear 不重置剩余时间；dry 立即归零；demo 在 30/50/110/130/220 秒边界正确；超大步长跨阶段正确；暂停及非基地不推进；非法语法不改变状态；非基地变更被拒绝；切图清空；真实 #weather 路由与 status 无副作用。参数化用例先逐一审计数量，再声明准确上限。
- [ ] 通过 Unity MCP 运行仅 BaseWeatherTests，确认失败源于尚未实现的规则而非夹具；编译未通过时先以诊断确认缺失接口，再继续。
- [ ] 实现快照、状态机及上述五种命令。System 的 Tick 只在 Playing 且基地已加载时推进；更新和注销通过共享 LifeCycle；指令分派只解析参数、返回现有结构化结果。
- [ ] 运行同一类验证；检查 invalid、重复调用、切图及边界语义。

## 任务二：正式基地表现

**文件：** 新增 `Controller/View/Environment/BaseWeatherView.cs`；修改 `DayNightView.cs`、`MapProceduralSkyView.cs`；修改 `Client/Assets/Game/Scenes/BaseMap.unity`；天气正式资源新增于 `Client/Assets/Game/Art/Environment/BaseWeather/`。新增 `Client/Assets/Tests/EditMode/BaseWeatherVisualTests.cs`。

**接口：** `BaseWeatherView.Apply(BaseWeatherSnapshot snapshot)`、幂等 `Release()`；由初始化时缓存的 DayNightView/MapProceduralSkyView 接收快照。采用 `ApplyWeather(BaseWeatherSnapshot snapshot)` 更新天气参数，再由各自现有 Apply 计算最终状态；Release 发送晴天参数并解除事件。BaseWeatherView 不直接写太阳光或天空全局状态。

- [ ] 通过 MCP/AssetDatabase 核对基地可湿润地面、主要遮蔽物、玩家位置入口及雨资源依赖；只指定实际地面 Renderer。检查 CampGround、CampDirt、CampGravel 的 Shader 支持后决定运行时参数方式；不对所有 Renderer 批量替换。
- [ ] 写 BaseWeatherVisualTests：晴天与原昼夜结果一致；同一时刻雨天弱光且太阳方向一致；晴天恢复；湿度只改变指定地面；共享材质不变；重复初始化不重复创建；暂停粒子停止；重复 Release 安全；释放恢复材质/全局天气参数；后继地图不受旧对象清理影响。运行前核对真实用例数。
- [ ] 制作项目自有 URP 雨粒子，提取必要雨线/溅水贴图和 rain_loop.wav 到正式目录并保存 .meta；原备用包不改。雨声音量跟随 RainAmount；雨线覆盖玩家附近可见区域，指定遮挡下停止或剔除雨线，溅水贴合实际可用地面。资源同步装配尽量避免异步；若必须异步，提交前检查地图身份、取消和所有者。
- [ ] 地面使用独立运行时材质或受控 MaterialPropertyBlock，按原颜色与光滑度计算湿润目标，Release 恢复。避免地表整体镜面化，不添加积水几何/碰撞。
- [ ] 基地 MapContentRoot 接入 BaseWeatherView，缓存资源与必要引用；不修改 Main 场景。天气与昼夜合成时保留太阳轨道及夜间最低可见度。
- [ ] 运行仅 BaseWeatherVisualTests，再运行已存在的 DayNightVisualTests 指定受影响方法；每次先列准确过滤与最大用例数。检查依赖无 Assets/Art 回指。

## 计划自检

本计划对应设计的固定 220 秒 demo、90 秒干燥及五种测试命令；累计日历延后。切图、暂停、重复命令、原昼夜、共享材质保护均有明确检查。BaseWeatherTests/VisualTests 是拟新增类，创建并确认发现成功前不得调用测试工具。地面和遮挡清单必须来自实际基地检查，不把计划当成存在证据。
