# 汉末首章实施计划

> 执行方式：用户已要求直接实施，由当前会话按 executing-plans 逐项执行；不创建 worktree、不自动提交、不派遣子代理。

**目标：** 在现有随机河谷中实现运输线索、独立剧情返程凭证和多科技生产成长。

**架构：** 配置定义奖励与制作内容，搜索 System 提交当局成果，结算策略原子写入基地永久科技及章节完成记录。工坊 Controller 只负责选择配方和提交制作请求，生成地图复用已有交互模板与导航验证。

**技术栈：** Unity、QFramework、Luban、Newtonsoft.Json、EditMode NUnit。

**设计依据：** `Docs/游戏世界观与产品设定.md` 第 1.6 与 17 节。

## 约束及实施取舍

- 只做汉末首章，不增加后续章节地图、经营系统或科技硬前置。
- 原物品及科技 ID 保持；新局加入内容，旧局保留原布局。
- 首批扩展锻造采集工具、钢制刃具、弓、加工口粮及储水容器。纺织与绳木暂保留候选，避免为凑节点引入未设计的装备系统。
- 数值为首版对照用值，需试玩校准：新工具采集效率 2、钢刀伤害 20、弓伤害 18、加工口粮恢复能量 80、陶水罐恢复水分 80。不宣称历史实物具有这些倍率。
- 新装备复用正式武器表现作为功能版本，历史服装及专用美术不假称完成。
- 首章完成独立记录；没有获批的第二章内容，不把旧测试地图伪装为第二章开放。
- 仅执行明确类/方法过滤的 EditMode 测试；不运行完整套件、不打包。

## 风险检查

1. 多科技同趟取得应可保存，重复 ID 仍拒绝。
2. 死亡不发放章节完成；结算失败不能部分写入科技或章节。
3. 新旧存档兼容，旧随机局不重新生成内容。
4. 所有新配方可选、锁定时不扣费，产物具有正式配置和武器表现。
5. 新点必须进入生成布局且有有效模板与导航可达验证。
