# 普通宝藏房首批实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use executing-plans to implement this plan task-by-task in the current local checkout. 本仓库未授权子代理、worktree 或自动提交，不能用通用流程覆盖这些约束。

**Goal:** 让单人和现有双人休闲局在起始地图第 3 轮实际发现、进入、领取并独立返回同一固定共享宝藏房，积分及资源遵守整场提交与回滚。

**Architecture:** 现有战斗领域持有区域、成员和领取现场；客户端和服务端链接同一纯规则源码。现有运行局所有者提交个人积分、倍率和生命，表现端只投影本机区域；不新增安全节点、架构 System 或独立存档。

**Tech Stack:** Unity C#、QFramework、Luban、ET/net8、现有协议生成器、NUnit EditMode 与独立 .NET 临时存档检查。

**Spec:** [已确认设计](普通宝藏房首批设计草案-20261011.md)。

## Global Constraints

- 在 E:/GitHub/AnotherDay 本地工作；Unity MCP 优先，不创建 worktree、不派子代理、不自动重启服务器、不打包。
- 首批：起始地图配置身份 1、第 3 轮；入口 (-15,-15)，发现/进入半径 1.5，返回 (-12,-15) 米。
- 首名进入起统一 60 秒；晚进入/重入/暂时全员离开不重置，超时返回仍在房内的成员。
- 共享 12 金条、4 宝石、1 炸弹、1 冲刺；房间半宽 9、半高 7 米，出生 (0,-4)，出口 (0,-5.5)，出口半径 1、领取半径 0.8 米。物品位置按设计配置。
- 金条基础 100 分/100 进度，宝石 250 分/250 进度；每 1000 进度升 1 倍，最高 9 倍，领取前倍率计算本次积分。
- 每累计 200000 分奖励本人 1 命，满 9 命消耗该计奖档位且无补偿；死亡保留积分、倍率归 1、进度归 0。
- 个人进出，全队共用发现和奖励；竞技场队友可继续第 4 轮，全员在房内才等待返回；房内有人时不切换竞技场。
- 配置及协议仅改源再生成；保留共享工作区已有路线/Boss改动及其它会话修改，核心代码补中文职责注释。
- 每次 Unity tests-run 指定真实短类名或完整方法、includePassingTests=true；执行前声明最大数，之后审核实际返回名称及数量。

## Review Focus

1. 其它玩家晚进入及房间无人时，统一时钟不能被刷新或冻结；任务 1/3 用时钟和成员测试覆盖。
2. 奖励应用失败或整数溢出不能丢失物品、部分加命；任务 1/2/3 用失败原子性覆盖。
3. 单人或双人本场保存失败及重连不能夹带未完成积分、重复发奖；任务 2/3/5 用真实保存入口及临时文件覆盖。
4. 区域变化与异步加载交错不能出现另一空间的敌人、过期物品或旧预测位置；任务 4 用同步投影和代次失效验证覆盖。
5. 旧局缺字段、已超过 9 命或其它地图第 3 轮不能错误迁移金币、扣命或开房；任务 1/2/3/5 用兼容及身份测试覆盖。
