## 5. 代码、配置与资源接入方案

这是跨客户端、服务端、协议和保存的关卡内容扩展，按架构级工作拆解；沿用 QFramework，不引入第二个战斗主循环。

### 5.1 配置权威与纯规则

新增双端轮级布局配置，建议源表 `Config/DataCsv/arcade_round_layout.csv`，在 `Config/Defines/beans.xml`、`tables.xml` 登记。定义稳定 `Id`、`ArenaConfigNumber`、`RoundNumber`、布局版本、主题表现 ID、出生位、障碍、入口批次、出口锚点、事件引用与持久对象 ID。数值、位置和时长只有这一份权威来源；不把七十六张可调配置硬写在 Controller。

同一个主题的四轮必须完整且唯一；入口、出生、出口位于可行走连通区。批次数从原轮预算分配，不新增敌人预算。静态地标表现与实际碰撞共用布局。配置缺失或资源未就绪应显示可重试失败，不能悄悄回退通用地图然后开始扣命。

`Client/Assets/Game/Scripts/Utility/Config/RuntimeConfigDefinitions.cs`、`IRuntimeConfigProvider.cs`、`LubanRuntimeConfigProvider.cs` 增加不可变布局读取和交叉校验；服务端 `Server/GameServer/Runtime/Model/Server/Config/ServerConfig.cs` 使用同源数据。纯几何/事件时间规则置于现有 `Utility/Arcade`，通过 `Server/GameServer/DotNet/Model/DotNet.Model.csproj` 显式编入服务端，延续现有 Hazard/Island 共享方式。

仅执行 `Config/gen.bat` 生成双端 C# 与 bytes，记录配置指纹及产物散列；不手改生成文件。当前 `arcade_support_visual` 等其他任务新增配置必须保留。

### 5.2 单人权威和保存

在 `ArcadeCombatSystem` 的开始轮、清场、出口和失败重试接入通用轮级状态机；由 System 持有规则与活动时钟，View 仅准备和显示地图。现有 `IslandRounds` 中与海岛无关的转场/恢复逻辑应提取为聚焦的 partial，岛岸几何仍独立保留。

顺序固定：校验目标布局 -> 冻结旧输入及活动时钟 -> 隐藏并准备候选地图 -> 校验资源/出生/相机 -> 捕获轮前节点并原子保存 -> 提交轮身份 -> 开始入口预警与生成。失败保留已提交节点，重试同一候选，不重新补满库存或刷新效果时长。加载过程中晚到的回调必须同时校验地图实例、代次和资源拥有者。

扩展 `ArcadeRunContracts`、`ArcadeRunModel`、`ArcadeRunSystem`、`ArcadeRunFileStore`：新增通用轮前节点而非直接放宽海岛专用校验。稳定字段含路线身份、本局场序、主题、轮次、布局版本、角色完整逻辑效果、积分/倍率/命数、已经提交的主题内箱体/奖励/一次性事件状态及确定性种子。临时枪和强化只存剩余量，不存敌人/弹丸/地面掉落、Unity 对象或资源句柄。

海岛旧节点由显式兼容分支读取；旧版只有整场节点的本项目存档继续从整场起点恢复。未知布局版本拒绝恢复并保留原文件，不猜坐标、不自动删档。不导入其他项目数据。

### 5.3 双人服务端、协议和表现

服务端修改以下现有拥有者：

- `Server/GameServer/Runtime/Model/Server/Online/Arcade/OnlineArcadeRunComponent.cs`：轮级安全记录、全员逻辑快照、运行态地图代次与事件状态。
- `Server/GameServer/Runtime/Hotfix/Server/Online/Arcade/OnlineArcadeRunSystem.cs` 及新的聚焦 partial：服务器裁决出口、原子提交、冻结/恢复、事件伤害和入口生成。
- `Server/GameServer/Runtime/Hotfix/Server/Online/Arcade/OnlineArcadeHandlers.cs` 与 Gate/Player 转发：加载确认和出口意图校验，不能让客户端直接报告伤害或完成。
- `Config/Proto/OnlineOuter_C_12001.proto`：追加轮级布局 ID/版本、地图代次、转场阶段及确认意图所需消息，不重用原字段号。仅通过 `Tools/gen-protocol.ps1` 生成双端。
- `Client/Assets/Game/Scripts/Model/Online/OnlineArcadeRunContracts.cs`、`System/Online/OnlineArcadeRunSystem.cs`、`OnlineArcadePresentationSystem.cs`：协议转换、过滤旧代次、加载地图、重置预测并确认就绪。

合作普通出口继续沿用任意存活成员可推进、同一 Tick 按稳定玩家 ID 仲裁一次的项目约定；增加明确确认以避免误触。两名玩家同时选择不同出口时只能成功一次。服务端仅接受当前地图代次和当前布局的有效意图。

所有应参与玩家资源就绪后才推进活动时钟与攻击；加载慢、失败和断线不能让另一人先消耗效果或遭受伤害。失败提供重试；断线按现有暂停/宽限/恢复政策处理，不新增“超时自动闯关”。重连收到完整布局及权威事件状态，不能重播旧伤害/旧奖励。

联机安全节点是一次全员事务：提交角色命数、分数、库存、效果及主题持久对象，全部成功后才公开新轮；磁盘失败不能一人进入下一轮、一人留在上一轮。服务端恢复从同一轮前节点开始，不存战场实体。旧配置/协议房间沿现有版本门禁处理，不自动迁移到新布局。

客户端预测必须使用当前轮的有效碰撞/地面规则；不能还读取 `activeArena.Obstacles` 而显示另一张图。飘移危险及冰面最终位置由服务器裁决，客户端只预测并校正。第一人称当前是单人限定，不因地图共享而暗中开放双人第一人称。
