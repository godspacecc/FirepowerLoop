# PC 当前用户安装与整包更新设计

状态：用户已确认安装器路线、当前用户安装及连续升级目标，并要求跳过独立实施计划直接实施。源码与范围内自动测试已落地；安装器编译及实际安装验收待人工执行。使用入口见 `Docs/PC安装器与整包更新使用说明.md`。

## 目标与范围

Windows x64 玩家首次运行正式安装器后，可由游戏发现新版、下载完整安装器，再主动退出游戏并覆盖升级。更新后保留同一安装身份与更新入口，支持跨过中间版本升级到服务器最新版本。首次引入功能需要重新生成 Player 和安装器；历史便携包不能自动获得 Boot 更新能力，需要手动安装一次。

首版包含 Boot 自动检查、开始界面主动检查、下载进度与取消、完整性验证、当前用户安装器、已有 Player 的安装器生成入口、资源服务器发布与下载、连续升级验证。不制作独立 ZIP 更新器，不做差分补丁、后台静默安装、强制更新、多发布频道或存档版本转换。安卓整包更新与既有 YooAsset 流程保持兼容。

开发中只编辑源码并执行有明确范围的测试；不调用 Unity Player Build、资源打包、发布到真实服务器或安装到开发者电脑。真实安装验收由用户手动生成与运行安装器。

## 已核实的实现边界

- `Client/Assets/Boot/Res/ResourceBoot.cs` 的 Windows Player 使用 Host 模式；Android 完整内置测试包才由专用宏切到 Offline。Host 配置读取成功后、资源清单请求前已有安卓整包检查阶段。
- `Client/Assets/Boot/Runtime/ApkUpdateFlow.cs` 已拥有候选检查、玩家选择、取消、临时下载文件与 SHA256 校验；`AndroidApkInstaller` 仅支持 Android。
- `Client/Assets/Boot/UI/HotUpdate/HotUpdateView.cs` 通过 Boot 场景已有按钮和进度显示 APK 更新意图，可复用这些控件，而非另建 UI 框架。
- `Client/Assets/Game/Scripts/System/ResourceUpdate/ResourceUpdateSystem.cs`、`Utility/ResourceUpdate/ApplicationUpdateChecker.cs` 和 `Controller/UICtrl/Home/StartUICtrl.cs` 已提供安卓主动检查链路；目前候选类型是 `ApkUpdateManifest`。
- `Client/Assets/Editor/Build/BuildUtility.cs` 输出 Windows 玩家目录与独立 Symbols 目录，Player 程序集清单已有安全校验；没有 PC 安装器生成或独立客户端版本递增。
- `Server/ResourceServer/resource_server.ps1` 的 `/app-update.json` 和 `/app-updates/android/` 专供 APK，必须保留，不能将现有安卓入口改成返回 Windows 描述。
- 存档和用户设置使用 `Application.persistentDataPath`；Windows YooAsset 默认缓存则在 Player 的 `AnotherDay_Data/yoo` 内。二者不能一并当作用户存档复制或删除。
- 当前命令搜索未找到 PATH 中的 `ISCC.exe`，不等于机器绝对未安装；安装器工具路径需显式配置，不自动下载或安装第三方编译器。

## 安装器选择与身份

采用 Inno Setup，使用 `PrivilegesRequired=lowest`，固定 AppId，固定当前用户安装目录 `%LOCALAPPDATA%\Programs\AnotherDay`，关闭安装模式提升选项，不创建 HKLM 注册项。用户目录要求可写，不把管理员权限作为更新的前提。

安装器写入当前用户卸载登记，创建开始菜单入口，桌面快捷方式作为可选项。同一 AppId 配合 `UsePreviousAppDir=yes` 识别前版，连续升级不创建第二个产品身份。首版固定目录，不开放迁移到任意磁盘的目录选择，以减少目录权限与错误覆盖风险。

安装源只包含已验证的玩家目录；Symbols、工程文件、Editor 日志和开发机本地配置不进入安装器。安装器显式管理所属文件清单，清理新版已废弃的受管文件；不对任意用户目录递归删除。

首次安装及升级均是可见安装向导，不用 `/SILENT` 或强制关闭进程。游戏内更新完成后提供“退出并安装”和“稍后更新”。安装器由当前用户启动，游戏正常退出后再进入文件替换。使用 Restart Manager 处理其他占用，允许玩家取消，不按进程名强杀游戏或其他应用。

安装器提供完成后启动游戏的选项；覆盖升级失败不能显示成功。文件恢复使用明确的安装事务：开始写入前检查备份空间，依据旧版受管清单备份文件并记录本轮新旧清单及未提交状态；成功写入全部文件、验证客户端身份后才提交。正常取消或安装异常在安装器退出路径恢复备份，删除本轮新增的受管文件；恢复失败保留备份和可读错误，禁止启动半安装客户端。若断电导致退出回调未执行，下次运行安装器先检测未提交记录并恢复旧文件，再允许继续安装。日志和备份只位于安装器受控目录，不涉及 LocalLow 用户数据。不把文件恢复等同于整个 Windows 注册表、快捷方式和卸载登记的原子回滚；这些登记项通过同 AppId 的安装修复收口，并在手动失败验收中单独检查。

卸载仅移除安装器登记的客户端与快捷方式；默认保留 LocalLow 下的存档、设置和诊断，不添加清空存档选项。公司名、产品名和存档格式保持不变。

## 玩家更新事务

1. Windows Host 启动读取既有资源服务器地址后，先限时检查 PC 整包描述；描述不存在、网络失败或非新版则继续既有资源流程。
2. 有新版时显示当前版本、新版、下载大小，以及“下载更新 / 稍后更新”。一轮启动对相同服务器与版本最多提示一次。
3. 下载使用文件流而非将安装器完整读入内存，写入用户数据目录 `Updates/Windows` 的 `.part` 文件。显示进度、速度与取消；无进度超时、超出描述大小或请求错误则清理本次临时文件并允许重试。
4. 长度和 SHA256 验证成功后提交为缓存安装器。缓存复用及启动安装器前再次验证，不执行未经验证的文件。取消、地址切换、所有者销毁或旧轮次返回不得修改新界面或发起安装。
5. 玩家点击“退出并安装”后，使用结构化进程参数启动安装器；创建进程失败时保留游戏并显示重试。成功交接后结束本轮 Boot 启动，不能继续加载 Game.dll 或 Main；仅调用 `Application.Quit()` 而不终止启动事务是不完整实现。
6. 交接携带当前游戏 PID 与启动身份，安装器等待该实例正常退出；超时显示占用提示，不继续覆盖。不以固定 sleep 认定进程已经结束。
7. 玩家取消安装保留旧版；安装完成后新版启动并基于新内置身份继续检查最新安装包。

从游戏内主动检查时，仍由 ResourceUpdateSystem 协调只读探测，Controller 只展示候选与重启到 Boot 的意图；下载和安装权威留在稳定 Boot。首版不允许在远征运行中直接退出覆盖升级。

## PC 客户端版本与描述

PC 使用独立于 Android 的版本身份：稳定 `productId`、`platform=Windows`、`architecture=x64`、三段 `versionName` 及单调递增整数 `releaseNumber`。服务器最新描述包含 schemaVersion、上述身份、安装器文件名、sizeBytes、sha256 与兼容要求。

资源版本不充当客户端发布序号，也不借用 Android bundleVersionCode。PC 构建前为本次最终 Player 写入独立 `StreamingAssets/windows-release.json`；安装器必须从该 Player 内置文件读取身份，不能在生成安装器时伪造更高客户端版本。预备 Player 不消耗发布序号；最终 Player 验证成功才推进 PC 发布记录，失败恢复原发布状态。

版本源在项目中共享，具体文件与元数据格式在实施计划中定义；开发机工具路径独立于共享版本源且不提交真实本地配置。Player 的原 Application.version 不作为 PC 整包更新的唯一比较依据。

安装器内身份、Player 内身份和服务器描述必须一致。相同发布序号不允许换成不同字节；只接受同产品、同平台架构的更高发布序号，安装器也拒绝降级。每份完整安装器具有完整升级能力，不依赖前一个版本，因此支持跳版本安装。

## YooAsset 与宿主兼容

整包检查先于 YooAsset 资源与热更 DLL 加载。第一版继续提供“稍后更新”，因此发布方必须保证旧宿主仍有兼容资源可启动；不能把“有新版安装器”视为旧宿主安全加载任意新资源的证明。

首版资源发布维持现有兼容基线，不在本功能中增加强制更新或多套资源路由。如果某次发行改变 Boot/AOT/原生依赖到旧宿主不兼容，发布必须先确定资源分流或最低宿主门禁，再切换公共最新资源清单；这属于后续独立的兼容发布设计。

安装器只携带 Player 构建时的干净内置资源，不把开发者运行后生成的 `AnotherDay_Data/yoo` 缓存封入新版。升级时旧 YooAsset 缓存及与它绑定的成功版本标记一起失效；不得保留指向已不存在缓存的旧标记，也不动 LocalLow 存档。缓存失效由 Boot 在识别客户端身份改变时处理，避免把运行时缓存生命周期交给安装器猜测。

## 资源服务器与发布

新增独立路由 `/app-update-windows.json` 与 `/app-updates/windows/<单一EXE文件名>`，使用 `AppUpdates/Windows` 保存 PC 描述和安装器，保留安卓路由与发布参数的兼容行为。GET/HEAD 支持，文件名只允许白名单字符和 `.exe` 扩展名，拒绝目录浏览、路径穿越及非公开文件。

发布先复制并验证安装器到唯一的临时文件，再提交不可变版本文件，最后原子替换最新描述；保留旧版本文件供在途下载使用。发布失败不能留下指向缺失安装器的描述。发布只接受已有完整安装器，不调用 Unity 构建，也不隐式切换 ResourceFiles。

新增“为已有 PC Player 生成安装器”的受控入口，读取已验证的 Player 身份与玩家目录，输出 Setup EXE 至独立发布目录；通过配置的 ISCC 编译。完整首包、完整内置包和快速 AOT 包均可在生成后转换为安装器；Host 资源更新不生成安装器，也不推进客户端发布号。

PC 安装器生成与资源服发布的成功/失败各自明确记录；安装器编译器缺失时保留已完成 Player 并提示工具配置，不把目录包误报为可下载安装的新版本。当前阶段不安装编译器、不签名、不发布真实安装器。

当前资源服务器允许用户配置的局域网 HTTP。长度及 SHA256 只保证文件与描述一致，不保证发布者身份；首版明确面向既有受控服务器测试。公开发行需要可信 HTTPS 或签名清单，以及安装器代码签名，不宣称 Hash 校验能够防止恶意服务器发布 EXE。

## 文件职责与预计影响范围

- Boot：新增 PC 描述、下载事务及安装交接适配；ResourceBoot/Launcher 接入，并明确安装交接后终止启动的返回语义。
- Boot View：复用 HotUpdateView 现有场景引用，将平台相关文案与按钮语义明确区分，避免 PC 显示“APK/安卓系统安装”。新增界面方法应只渲染状态。
- Game：在既有资源主动检查结果中增加 Windows 候选，保留 APK 字段兼容现有消费者与测试；StartUICtrl 展示平台对应候选。具体字段和注册方式以真实调用链为准。
- Editor：BuildUtility 增加独立 PC 发布身份及安装器转换入口；保留本次已修复的平台重载门禁与程序集清单校验。
- Tools：共享 Inno Setup 模板与已有 Player 的打包脚本；安装器只读校验、所属文件管理、占用等待、恢复与卸载边界由模板及脚本明确承担。
- ResourceServer：Windows 独立路由、发布脚本与测试；安卓路由不变。
- 配套说明：手动配置 ISCC、生成安装器、上传安装器及连续升级验收步骤。

具体新增类型、接口与测试类在书面实施计划中列出。没有依据时不把本设计的拟议接口写成已经存在的实现。

## 验证与验收

自动验证只运行明确类或方法过滤，并先声明每次最大执行数量，返回全部测试名称。不得运行完整 Unity 套件或触发 Unity 打包。

自动覆盖：候选身份/新旧版本/文件名校验、临时文件清理与篡改拒绝、取消及过期结果、启动安装器失败不退出、交接成功后不进入 Main、PC/Android 主动检查隔离、版本生成失败回滚、发布描述原子提交、服务器 GET/HEAD 和穿越拒绝、安装器受管文件及当前用户配置约束。安装器脚本只读或沙箱验证不得安装真实游戏。

用户手动验收至少包含：

1. 普通非管理员账户首次安装，检查安装位置、开始菜单、快捷方式和卸载登记。
2. 版本 A 游戏内下载 B，取消下载、稍后更新、下载完成退出并覆盖升级；确认存档与设置保留。
3. B 再发现并升级到 C；A 直接升级 C，证实更新入口与 AppId 连续稳定。
4. 断网、安装器损坏、空间不足、游戏未退出、玩家取消安装及覆盖失败；旧版仍可使用或恢复提示明确。
5. 更新后内置版本身份与服务器候选比较正确，旧 YooAsset 缓存标记不会导致读取不存在文件。
6. Android APK 更新继续正常；卸载 PC 后用户存档仍保留。

仅有测试通过不代表已验证 Windows 安装体验、权限、SmartScreen 或断电恢复。
