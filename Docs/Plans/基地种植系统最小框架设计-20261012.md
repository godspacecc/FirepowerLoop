# 基地种植系统最小框架设计

日期：2026-10-12。

状态：用户已确认选址、最小功能范围并通过本文审阅；实施计划编写中，尚未开始代码实现。本文不授权正式种子经济、作物奖励和科技解锁规则。

## 1. 目标与已确认范围

在基地提供能亲自靠近、聚焦、播种、观察生长和收获的试验田，先验证种植系统的状态、视觉、交互与持久化框架。它服务于基地准备，不扩展为独立经营玩法。

- 基地东南侧、入口土路右边，选址中心约为世界坐标 `(5.5, 0, -5)`，范围约 4×4 米。
- 四块固定地块，空土、幼苗、成熟三个状态。
- 沿用现有玩家交互入口，不新增热键或专用种植窗口。
- 播种免费，60 秒演示生长；收获后回到空地，不增加库存、金币或其它正式收益。
- 生长只在基地正常游戏时推进；暂停、离开基地和离线期间不推进。
- 每块田保存稳定身份、状态和剩余时间，返回基地及读档恢复。
- 不实施种子物品、浇水、施肥、枯萎、科技解锁、自动化、自由摆放或联机种植。

## 2. 选址与视觉

首版在已确认范围内布置 2×2 地块。每块土床约 1.3×1.3 米，中间留约 0.6 米十字通道，外围保留约 0.4 米余量。地块是固定可操作对象，土床与作物不增加实体阻挡，玩家可以靠近或穿过，以优先验证交互而不是导航障碍。

空地显示深色翻土，幼苗显示少量低矮绿色植株，成熟显示明显增高、增密的植株。首版使用通用试验作物，不由美术外观确定历史作物、食谱或科技内容。优先检索现有正式素材和备用库；必要副本及依赖整理到正式业务目录，不修改第三方原包、不让正式场景依赖 `Assets/Art`。

第三人称沿用当前准星聚焦：地块提供可命中的交互目标，提示为“试验田：可播种”“试验田：生长中（剩余秒数）”“试验田：可收获”。成长中仍可聚焦和读取状态，按交互键只提示尚未成熟，不重播种、不重置计时。提示依据当前语言刷新，倒计时向上取整显示；成熟后不再显示倒计时。

现有选址图来自正式场景网格与材质的隔离渲染，黄框是临时标记。它不含运行时加载的全部基地对象，也不是玩家实际镜头验收。实施后必须检查四块田和实际玩家、NPC、其它交互物的关系。

## 3. 状态与计时规则

| 当前状态 | 输入或条件 | 结果 |
| --- | --- | --- |
| 空地 | 有效播种请求 | 幼苗，剩余 60 秒 |
| 幼苗 | 基地有效游戏时间推进 | 剩余时间递减，最小为 0 |
| 幼苗 | 剩余时间到 0 | 成熟，剩余时间为 0 |
| 幼苗 | 交互请求 | 状态不变，提示生长中 |
| 成熟 | 有效收获请求 | 空地，剩余时间为 0 |

计时单位为现实游戏秒，使用共享生命周期的帧间隔，不能使用系统日期或远征游戏分钟。四块田独立计时，无植物逐个 `MonoBehaviour.Update()`。

推进条件：应用处于 `Playing`，当前地图为正式提交的离线基地，当前存档域为基地且存在有效基地存档；加载、暂停、死亡、应用失焦或阻断玩法的窗口打开时不推进。进入远征或主菜单后保持原剩余时间，回来继续。成熟地块无自动收获。

60 秒是首版演示值，作为单一正式配置来源接入既有 `IRuntimeConfigProvider` 和 Luban 配置流程，不在 System、View 和测试中分别复制产品默认值。配置只提供一种试验作物与生长时长，不添加种子、配方、奖励或解锁表。

## 4. 代码职责与接入边界

采用独立种植模块，复用交互、地图生命周期和存档基础设施，不把种植塞进文明搜索或干粮生产规则。

- Model：保存四个稳定地块 ID、三个状态、剩余秒数；向表现提供只读快照。实现 `IScopedSaveSectionProvider` 的 `BaseOnly` 分区。
- System：裁决播种、计时、成熟与收获，持有保存事务与操作失败语义，通过共享 `LifeCycle` 推进并对称注销。
- 地图 Controller：在基地成功提交后查找并绑定该地图内容根下的地块，持有当前 `MapInstanceId`，地图释放时解绑、移除订阅与对象引用。
- 地块 View/ViewCtrl：基于现有 `PlayerInteractableView` 与 `IPlayerInteractable` 路由意图，显示状态、土床和作物；不写库存、领域状态或文件。
- `Game.cs`：沿用现有 Model/System/Controller 注册与释放顺序，不创建第二个架构入口。

所有操作重新检查地图身份、根归属、玩家存活与同地图身份、2.25 米交互距离、应用状态、玩法输入阻断和建造模式。旧地图回调、卸载后的对象、重复点击不能作用于新地图。成长中重复点击只读状态；状态切换后下一次有效操作按新状态裁决。

无需独立屏幕 UI、列表、Box 或 UI 生成 View。世界提示作为地块场景表现序列化，中文预览可读，动态文本由 Controller 负责；复用已有准星提示与手机通用交互入口，不另造输入通道。

## 5. 存档与失败语义

新增版本化基地分区，以稳定地块 ID 保存，不使用 `instanceID`、Transform 或场景对象引用。旧存档无此分区时初始化四块空地；已存在但版本错误、重复或未知 ID、缺少地块、状态非法、剩余时间非有限数或超出配置范围时返回明确校验错误，不静默重置。

空地、成熟状态剩余时间必须为 0；幼苗状态剩余时间必须大于 0，且不超过所保存的该次播种总时长。分区同时保存该次播种总时长，配置之后改变不会使旧作物突然成熟或存档失效；新播种才读取新配置。

播种和收获参照现有 `CivilisationProductionSystem` 保存事务：捕获运行时快照，提交领域候选，标脏并 `Flush`，成功后发布表现事件；失败恢复操作前状态并提示失败。保存失败不能让地块画面显示操作已成功。

计时更新标脏并沿用 `SaveSystem` 的自动保存、切图和退出保存路径，不每帧写文件。自动保存失败保留脏状态并沿用重试；退出后恢复最后成功保存的进度，不承诺崩溃时最后一帧进度。计时到达成熟时通过保存事务提交成熟状态；保存失败保留可重试的幼苗状态，不显示已成熟，避免重复提交的每帧错误提示。

新游戏重置四块田；远征成功或失败不会重置基地种植。实现时须定向验证基地分区在进入远征、返回和读档的实际捕获与恢复顺序。

## 6. 修改范围

仅涉及种植领域模块、地图地块 View/Controller、`Game.cs` 注册与释放、最小试验作物配置及 Provider、种植本地化条目、必要美术副本与 Prefab、`BaseMap.unity` 的四个地块和定向测试。

不修改远征故事、章节解锁、库存经济、已有制作配方、基地布局主通路、街机、联机与其它地图。保留工作区已有未提交修改；不自动提交、推送，不创建 worktree，不触发打包或 Player Build。

## 7. 验收

- 四块地可分别聚焦和操作，土床、幼苗、成熟清楚可辨；正常玩家视角能看清目标与提示。
- 免费播种，无库存变化；60 秒后成熟，收获一次回空地，可再次播种。
- 四块田独立计时；暂停、阻断窗口、失焦、离开基地不推进。
- 保存、返回基地、重启读档能恢复；旧存档兼容，损坏数据拒绝，保存失败回滚。
- 过期地图请求、超过距离和卸载对象被拒绝；反复加载基地不会重复订阅或残留提示。
- EditMode 使用实际存在的类或完整方法过滤，调用前声明最大数量，并审计所有返回名称；不执行完整测试套件。
- 实际场景渲染与运行交互分别验收，测试通过不代替画面验收。不自动新增 PlayMode 测试或执行打包。
