# 基地种植系统最小框架实施计划

> 执行者：使用 `executing-plans` 在本会话逐项实施。仓库规则覆盖通用流程：不自动委派代理、不自动提交、不创建 worktree。

**目标：**在已确认的基地东南侧区域实现四块可播种、生长、收获、保存的试验田。

**架构：**独立种植 Model/System 持有状态和保存事务；地图 Controller 在正式地图提交后绑定 View，复用现有交互与提示。配置经 Luban 唯一生成入口接入，存档使用版本化 BaseOnly 分区。

**技术：**Unity、C#、QFramework、Newtonsoft.Json、Luban、现有共享 LifeCycle 和 EditMode 测试。

**设计依据：**[基地种植系统最小框架设计](基地种植系统最小框架设计-20261012.md)。状态：设计已通过，本文等待审阅和执行方式确认。

## 全局约束

- 使用 `E:\GitHub\AnotherDay` 当前工作区与 Unity MCP；不打包或运行 Player Build。
- 四块固定田，区域中心 `(5.5, 0, -5)`，范围 4×4 米；2×2 排列，土床约 1.3×1.3 米，十字间距 0.6 米。
- 免费播种，配置演示时长 60 秒；收获只清空地块，不产生库存或金币。
- 只在有效离线基地 Playing 状态推进；暂停、失焦、阻断窗口、加载和离开基地停止。
- 正式地块无实体阻挡；交互距离上限 2.25 米，实际准星聚焦沿用既有系统。
- 所有新 Unity 资源及目录含 `.meta`；核心类、函数和重要字段补中文职责注释。
- 保留已有工作区修改，特别是本地化、Game.dll 与其它功能文件；只追加本次必要内容，不手改生成文件。
- 每次 Unity 测试只用真实类名或完整方法过滤，`includePassingTests=true`，调用前声明上限，调用后审计结果；不以总发现数代表执行数。
- 不自动执行 PlayMode 测试或改变普通用户存档。实际试玩使用隔离存档，并先核对运行 DLL 与源码是否一致。

## 重点失败条件

1. 连续倒计时不能因每帧标脏永远延后自动保存；任务 2 验证。
2. 成熟保存失败不能显示成熟或每帧重试弹错误；任务 2 验证。
3. 原基地 View 延迟操作不能改动返回后新地图状态；任务 3 验证。
4. 旧存档缺分区兼容与已存在损坏分区拒绝必须区分；任务 2 验证。
5. 准星能选中地块而不被成熟植株夺走或被已有交互物覆盖；任务 3、4 验证。

## 任务 2：地块状态、计时与存档事务

**新建：**`Client/Assets/Game/Scripts/Model/Planting/BasePlantingModel.cs`、`Client/Assets/Game/Scripts/System/Planting/BasePlantingSystem.cs`、`Client/Assets/Game/Scripts/System/Planting/PlantingEvents.cs`、`Client/Assets/Tests/EditMode/BasePlantingTests.cs`。事件沿用现有 System 业务目录归属，不新增通用 Event 根。

**修改：**`Client/Assets/Game/Scripts/Game.cs`，只添加 Model/System 注册。

**接口：**`PlantingPlotState { Empty, Growing, Mature }`；只读 `PlantingPlotSnapshot` 含 PlotId、State、RemainingSeconds、DurationSeconds。Model 提供 `TryGetPlot(string plotId, out PlantingPlotSnapshot snapshot)`。System 提供 `TrySow(long expectedMapInstanceId, string plotId, out string error)`、`TryHarvest(long expectedMapInstanceId, string plotId, out string error)`；距离与玩家身份重验从已绑定地图内的静态地块位置获取，不能接受调用者任意位置。

稳定 ID 固定为 `base.plot.01`～`base.plot.04`；保存分区 `another-day.base-planting`，版本 1，BaseOnly。每块保存状态、剩余秒数、当次总秒数；空地总时长为 0，成熟保留当次总时长。界面不能获得可变存档对象。

- [ ] 写 10 个非参数化测试：`MissingSectionCreatesFourEmptyPlots`、`MalformedSectionIsRejected`、`SowPersistsGrowingPlotWithoutInventoryChanges`、`PlotsAdvanceIndependentlyAndBecomeMature`、`BlockedContextsDoNotAdvanceOrMutate`、`HarvestPersistsEmptyPlotAndAllowsResowing`、`SaveFailureRestoresBeforeOperation`、`MaturityFailureRetriesWithoutPerFrameNotification`、`ContinuousGrowthIsSavedAndSurvivesReturnAndReload`、`SavedDurationSurvivesConfigChange`。分别覆盖设计状态表、身份/输入阻断、旧档/损坏档、回滚及时间保存；使用临时存档根，测试不写产品资产。
- [ ] 未实现类型先通过反射测试缺失行为；EditMode 类 `BasePlantingTests`，最多 10 项，确认失败后实施。
- [ ] Model 实现 `IScopedSaveSectionProvider`，验证完整四地块、唯一 ID、版本、枚举和有限时间；缺分区唯一兼容为空地。
- [ ] System 注册存档分区与共享 Update，释放时注销；播种与收获依现有保存快照/Flush 流程原子提交，成功后才发 `BasePlantingChangedEvent`，事件只带稳定 ID。
- [ ] 逐帧更新计时、每现实游戏秒标脏一次，给既有 0.5 秒自动保存留出窗口；离开基地和停止有效推进时把最后不足一秒进度标脏。核对真实切图顺序，确保基地捕获前标脏，不能在远征域 Flush 基地数据。
- [ ] 到期先捕获仍为正剩余的快照，再提交成熟并 Flush；失败回滚、至少间隔一秒重试，只在首次失败提示，成功清除重试状态。禁止留下 Growing 且剩余为 0 的不可保存状态。
- [ ] 无效/负/非有限帧间隔不推进；禁止基于系统日期补算离线生长。重跑同类最多 10 项并审计。
