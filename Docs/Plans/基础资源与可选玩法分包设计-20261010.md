# 基础资源与可选玩法分包设计

## 目标与已确认选择

减少新玩家首次进入游戏所需的安装和资源下载量。首包是下载器；首次启动只准备基地、文明河谷和必要共用资源。街机是额外玩法，选择时才下载；其他地图随游戏进度逐个开放，首次选择时下载。完整包继续保留全部资源内置逻辑。

采用一个 YooAsset DefaultPackage 清单，按基础、街机和每张地图划分独立 Bundle 与下载范围。这里的独立资源包表示独立下载的内容集合，不增加多个 YooAsset Package 或独立清单版本。

用户已确认按新安装包路线实施。代码与收集配置已修改；实际构建产物、首启下载范围和真机离线体验仍需手动验收。

## 安装包与资源内容分开管理

| 名称 | 内容与行为 |
| --- | --- |
| 首包 | 保留 Boot、资源清单及下载器运行必需内容，不内置游戏资源 Bundle；首次安装且无缓存时需要联网下载基础资源。 |
| 基础资源包 | 基地、文明河谷及使它们完整可玩所需的代码、配置、角色、物品、界面、美术、音效和依赖。首包用户首次下载，之后可离线游玩。 |
| 街机资源包 | 单人和双人共用的街机竞技场、专属敌人、武器、掉落、特效、战斗与商店界面，以及缺失依赖。 |
| 各地图资源包 | 每张非基础地图的全部场景、专属内容、动态加载资源和必要依赖，分别查询与下载。 |
| 完整包 | 保持全部正式收集资源内置；可选资源已齐全时不显示下载确认。 |
| Host 基础安装包 | 保持现有全部回退资源内置及连接资源服更新的包型；名称不等同于基础资源包。 |

基础资源下载范围与安装包类型正交，不将首包改为内置基地和河谷的安装包，也不新增包型。

## 资源归属与依赖

基础范围必须闭合覆盖基地和河谷的实际运行需要，包含河谷运行时生成模板、天空、水面、植被、导航构建所需资源及存档恢复路径。基础与共用角色、装备、拾取、输入 HUD、字体和音效按实际消费者归属，不以目录名字推断。

基础需要的素材只保存一份。可选内容复用基础素材；只有可选玩法需要的共用素材保持可选，可由多个可选下载范围覆盖，不因此提前放入基础资源。必须结合静态引用和配置驱动的动态地址审计。

现有 Characters、Characters/Weapons、SceneObjects 目录 Bundle 混装基础、街机和远征内容，必须重划 Bundle 边界。可以调整收集规则与标签，尽量保留正式资源地址和 GUID；只有规则无法满足边界时才搬移实际资源及对应 meta。

TaskSampleMap 被街机与任务地图复用，可同时属于两个下载范围。下载任何一个入口后，另一个入口复用缓存；不承诺同一地图场景具有两份物理 Bundle。

YooAsset 当前按标签下载会纳入缺失的无标签 Bundle。资源审计必须核对最终 Bundle 下载集合，拒绝无标签资源或错误标签让基础下载携带全部可选内容的情况。

## 下载与玩家流程

### 启动和基础游玩

启动下载器、启动资源可用性校验、首页更新规模查询和资源体积审计使用同一基础范围定义，替换现有 startup 加 arcade 加 arcade-online 的必需集合。首包初始化只下载基础；完整包和 Host 基础安装包继续复用内置资源。

首次基础下载失败保留下载器和重试入口，不初始化不完整的运行世界。基础就绪且版本兼容时可以离线进入基地和河谷；远端不可达沿既有缓存或内置回退路径处理。缺失可选资源不使基础启动校验失败。

### 地图选择和恢复

地图选择界面及其必要显示资源属于基础，可以在没有其他地图资源时打开。移除基地地图 NPC 当前的全部 expedition 下载门禁。

地图解锁继续由现有领域规则决定，解锁不会触发下载，也不修改当前解锁费用、默认解锁状态或开放条件。设计支持后期逐地图开放，开放节奏和数值不属于本次改动。

首次选择合法的已解锁地图时，从活动清单查询该地图全部缺失资源，显示真实字节量和文件数。用户确认后下载；成功后重新核对地图、清单版本、入口身份及当前状态，再执行原有地图进入事务。河谷资源属于基础，正常情况下无额外下载。

下载取消或失败不解锁地图、不消费远征费用、不创建或覆盖远征存档。恢复已有远征前同样检查目标地图资源；缺资源时允许确认下载，失败保留存档，不删除或重建已有远征。

联机世界的地图选择和加入恢复路径也须检查目标地图资源。已有房间中的成员切图、重连收到服务器当前地图时复用同一准备门禁，避免绕过手动选择路径。

### 街机入口

街机选择与恢复入口、登录和大厅所需的小型界面保持基础可用。单人开始和继续前检查街机资源；确认下载成功后才创建新局或进入竞技场。已有局的结算或放弃不应为了不需要的战斗内容被迫下载整个街机。

双人街机在创建、加入或快速匹配前完成街机准备，房主和成员均受约束。重连恢复已有联机局也检查本机资源；服务器推送不得绕过准备门禁而加载缺失的战斗界面或竞技场。下载流程不改变服务器战斗和结算权威。

### 操作、错误与生命周期

复用现有确认、进度和错误提示界面，下载准备由资源 System 持有，UI 仅展示数值和提交意图。下载保持单操作门禁，拒绝重复请求；显示实际缺失量，不保存永久已安装标记。

下载终态以 YooAsset 操作成功为准，不能以进度达到 100% 判断成功。网络失败可以重新检查缓存并重试。下载中使用现有禁止关闭的进度界面合同；架构释放取消下载并释放回调，地图、界面或账号身份变化后的旧完成结果不得继续进入玩法。

## 更新与兼容

所有内容使用统一清单版本。发布新地图只更新清单及必要基础变更，不强制下载新地图；可选内容在进入时补齐当前活动清单所要求的 Bundle。未变化且有效的内置或缓存 Bundle 继续复用，变化的 Bundle 整文件下载。

清单与 Game.dll 生效继续服从现有重启更新流程，不在玩法下载过程中切换活动清单。街机、地图资源不建立独立代码版本，仍使用现有客户端与服务器配置兼容检查。

Windows 整包升级当前会使旧资源缓存失效；本次保留该策略并明确其可能导致可选内容重新下载。普通资源热更新不新增全缓存清理。

## 实施边界

涉及资源收集配置与构建产物校验、基础范围定义、启动和更新检查、资源发布审计、可选资源 System、街机和地图选择及恢复入口、必要本地化，以及提前加载资源的地图控制器。

重点消除普通地图准备阶段遍历全部投射物等提前加载行为，按实际地图模式及需求准备，防止基础游玩隐式下载街机内容。资源句柄的候选准备、提交、回滚、过期释放继续遵循现有地图事务。

不更改街机战斗数值、奖励结算、地图解锁规则、远征费用、存档格式、服务器权威或完整包内置范围。不增加多 Package、资源删除管理页或后台预下载，不自动提交或发布。

## 验证与验收

1. 读取正式构建清单并核对基础、街机、每张地图的全部动态地址及 Bundle 依赖；基础下载集合不得包含街机和其他地图专属内容。
2. 首包首次启动联网只下载基础。基础齐全后断网，实际进入基地和河谷，覆盖生成、交互、战斗、音效及保存恢复。
3. 未选择街机或其他地图时，不因界面显示、基地控制器准备、解锁或更新检查下载其专属资源。
4. 街机单人新局、继续与双人匹配、加入、重连均覆盖已就绪、需下载、拒绝、失败、重试和过期结果；下载失败不创建新局或丢失存档。
5. 每张其他地图的进入及存档恢复覆盖同样状态，联机目标地图路径不能绕过资源准备；多个入口复用已下载的共用 Bundle。
6. 完整包和 Host 基础安装包资源齐全时，原入口直接可用；首包仍不内置资源 Bundle。
7. 对比更新前后清单，确认不变 Bundle 可复用，可选更新在对应入口补齐；声明尺寸为真实文件字节量，拆分后的体积以实际构建报告为准。

自动验证仅运行可靠的 EditMode 类或完全限定方法过滤，调用前声明最大执行数并核对返回范围。不得运行全套测试、自动打包或 Player Build。需新构建产物和真机画面的验收由用户手动运行包流程后完成；源代码和单元测试通过不能替代下载范围、离线和画面验收。

## 当前实现依据

- Assets/Boot/Res/ResourceBoot.cs：DefaultPackage 初始化、启动标签下载、内置和缓存回退、启动可用性校验。
- Assets/Editor/Build/AndroidBuildUtility.cs 与 Assets/Editor/YooAsset/YooAssetBuildUtility.cs：完整内置、Host 回退内置及首包仅清单的独立流程。
- Assets/AssetBundleCollectorSetting.asset 与 Assets/Editor/YooAsset/ResourceModuleAuditUtility.cs：资源目录打包、模块标签、首次下载范围审计。
- Assets/Game/Scripts/System/ResourceUpdate/OptionalGameplayResourceSystem.cs：按地图稳定标签查询与下载，核对活动清单版本与场景地址。
- Assets/Game/Scripts/Controller/Npc/NpcCtrl.cs、Controller/UICtrl/Arcade/ArcadeResumeUICtrl.cs、Controller/UICtrl/Online/OnlineRoomUICtrl.cs：地图整体准备和街机入口。
- Assets/Game/Scripts/System/Map/MapSceneSystem.cs、Controller/Projectile/ProjectileCtrl.cs：地图候选事务及投射物预加载。
- Assets/Game/Scripts/System/Online/OnlineArcadePresentationSystem.cs 与 Utility/ResourceUpdate/YooAssetResourceUpdateRuntimeChecker.cs：推送后的联机场景准备及统一版本检查。

以上 Assets 路径相对于 Client Unity 项目根目录。

## 后续新增地图与道具

新增地图、道具、Prefab、贴图、音效及配置，可以发布资源热更新；地图目录及行为代码在 Game.dll 中更新。新增地图仍需接入正式地图配置和目录，不是只上传一个场景文件。

非基础地图标签由稳定地图 ID 将点号替换为连字符生成，例如 map.another-day.mission-sample 对应 map-another-day-mission-sample。场景、导航数据和通过地址动态加载的专属资源都要归入该标签。街机专属内容使用 arcade，基地与河谷必需内容使用 startup。新物品若只有后期地图使用，其重资源应归对应地图；地图选择列表必须提前展示的小图标可以保留在基础范围。

新增专属资源不能放进仍按整目录收集为 startup 的共用目录；应新增明确归属的收集器或拆分目录。已改为逐文件收集的目录，新增文件必须显式加入收集设置。Prefab 的静态引用依赖会跟随下载，动态地址引用则必须手动纳入对应范围。

每次发布仍需手动生成热更 DLL、资源 Bundle 和清单，并同步到资源服；这是资源发布，不要求每次重新发布安装包。未变化且缓存仍有效的 Bundle 可复用，下载器只补当前范围内缺失或变化的文件，不会因普通热更主动重下所有地图。

修改 Boot、原生插件、Unity 引擎或新增安装包未包含的 AOT 依赖，仍需新安装包。本次更改了 Boot 启动标签，因此必须先出一次新安装包，不能只将新的 Game.dll 与资源清单发布给旧 Boot。
