# 单一手持与穿戴分离设计

状态：用户于 2026-10-09 回复“继续”，已确认本设计；进入实施计划审阅。尚未修改运行时代码或 Prefab。

## 目标与范围

统一管理界面继续由背包入口打开，底部六个分页不变。装备页只表达身体穿戴，现有衣物部位继续占位；武器通过库存拿出或收起，同一时间只有一件当前手持物品。

首批实际手持接入短剑和弓，保留现有短剑主动攻击与弓箭玩法。物品仍属于原库存格；手持不是第三个储存位置，不额外增加容量。手机提供当前物品图标、点击选择列表与收起操作。现有第一人称和第三人称武器表现读取同一手持状态。

此次包括离线与联机一致性、现行存档和服务端账户数据的旧双槽迁移。其他工具、衣物属性、叠穿、轮盘、全新换手动画、街机独立装备体系不在范围内。不改武器配置数值，不导入新的美术资源，不打包、不默认提交、不创建 worktree。

## 当前实施证据

- `Client/Assets/Game/Scripts/System/Equipment/WeaponEquipmentSystem.cs` 装备会移出来源，替换把旧武器放回来源，卸下要求背包容量并归还已装弹药。
- `Client/Assets/Game/Scripts/Controller/UICtrl/Inventory/ItemTransferPorts.cs` 暴露 ClickEquipment、DropEquipment 和 GetEquipmentView；这些接口及其消费者需要迁移。
- `Client/Assets/Game/Scripts/Controller/Player/PlayerCtrl.cs` 当前以两套 WeaponAppearanceSlotState 表达外观；共享 Presenter 与第一人称副本已经存在，无需新建战斗表现框架。
- `Client/Assets/Game/Scripts/Controller/Player/PlayerInputCtrl.cs` 的 1、2 绑定固定近战与远程槽。
- `Client/Assets/Game/Scripts/Controller/UICtrl/Player/MobileJoystickUICtrl.cs` 读取双槽判断远程瞄准。
- `Config/Proto/OnlineOuter_C_12001.proto` 的 OnlineEquipmentInfo 和库存操作协议仍表达双槽；服务端库存事务、攻击校验、初始发放、死亡掉落、账户持久化都消费它们。
- 当前离线基地领域版本为 4、远征领域版本为 3，现行文件使用 incremental-v1；`SaveFileStore` 明确不支持更早的旧测试 JSON。此任务仅迁移现行增量文件中的装备结构，不扩展到这些已不支持的旧文件。
- 服务端账户 SchemaVersion 为 2，容量校验要求等于配置容量；迁移补偿容量必须由服务端记录并校验，不能信任客户端任意容量。

## 物品归属与当前手持

保留现有 PlayerBagModel 对背包、口袋的权威。WeaponEquipmentModel/System 演进为当前手持的记录与唯一写入口，避免另建一个与原装备系统并行的权威系统。

手持记录包含来源容器、格号和 ItemId；空手是显式空状态，不是可移动物品。只允许手持已在随身库存中的合法短剑或弓。仓库及搜索容器内物品必须先移动到随身库存，才能拿出。

拿出校验来源与当前状态后只改变手持记录，不扣数量、不挪格子。再次拿出同一个物品幂等；拿出另一件替换当前手持。收起仅清除手持记录，满背包也能收起。空手沿用已有拳头攻击。

移动手持物品到另一个随身格时，库存与手持身份在同一事务中跟随更新。放入仓库、丢弃、消费、死亡清空或来源失效时，在同一事务中收起。失败回滚库存与手持，成功后发布事件。替换同类物品到原格也必须先结束原手持，不能仅凭 ItemId 与格号相同自动继承。批量变化和载入统一校验手持引用；普通 UI 预览不改变手持。

既有装填型武器的弹药行为须保持物品守恒：本次新增手持只开放短剑和弓；旧双槽中的已装弹药在迁移时归还库存，不能遗失或复制。不新增枪械手持功能，未接入项不提供拿出按钮。弓沿用既有箭矢消费与投射物事务。

## 界面与输入

### 装备分页

移除固定近战、远程卡片、武器候选列表和装备/卸下/设为当前按钮。人物轮廓、七个身体部位及对应未开放说明保留。右侧仅展示选中部位名称、占位说明；不显示虚构属性、无效物品操作或手持槽。

### 背包与伴随窗口

随身武器详情操作改为拿出/收起，当前实例标记手持中。背包与口袋共享这套语义。移除旧装备格、拖入装备槽、卸下到背包及固定槽切换；材料、消耗品、移动数量、拆分、仓库扩容和搜索事务保留。仓库或搜索的物品详情提供正常转移操作，不直接拿出。

### 手机与 PC

MobileJoystick HUD 增加一个当前手持图标；空手显示拳头。点击打开由现有 UI 框架加载的手持选择面板，列出当前可拿出的随身短剑和弓，并提供收起。列表来源是库存快照，按背包格号、口袋格号稳定排序，显示名称、来源及当前状态。打开期间阻断战斗输入，关闭后恢复；库存或手持变化、语言变化同步刷新。

PC 的 1、2 固定槽快捷键改为各自循环随身近战/远程候选，H 收起；它们都是同一手持入口，不保留隐形双槽。没有对应候选时保持原手持。手机点击列表为首版，不实现长按轮盘。

攻击、瞄准和使用读当前手持类型。短剑显示近战交互，弓显示既有瞄准/攻击交互，空手使用拳头。当前选择变化时取消旧瞄准、持续攻击及未提交输入，避免切换后一帧误用旧武器。

### 模型表现

PlayerCtrl 和在线玩家表现只展示当前手持的一件物品；收起或失效后显示已有空手姿态。复用当前武器资源、挂点、共享 Presenter、第一人称手臂采样，不新增模型或动画。异步外观加载须检查手持身份、请求代次、地图和 View 生命周期，过期结果释放而不显示。

## 持久化与迁移

采用手持分区结构版本标识，明确区分现行手持格式与旧双槽格式。读取旧文件时先在候选数据中迁移，校验成功才进入正常恢复和持久化流程。未知结构或损坏引用报错，不按空手静默吞掉。

迁移顺序：保留所有现有背包与口袋格，近战武器、远程武器、旧已装弹药依次放回背包，先利用合法合并和空格。原 ActiveSlot 对应武器为本批支持的短剑或弓时，手持引用绑定其迁入的实际格；原来为空近战或其他未接入武器则迁为空手，但保留实际物品与弹药。迁移重放不可再次添加物品，失败不覆盖旧存档。

容量不足的具体取舍：仅迁移阶段把背包容量扩大到足以完整接收旧装备和已装弹药的最小值；保留原有容量更大的历史数据，不降低容量。这是旧装备容量的一次性补偿，新增角色仍使用原默认容量，正常手持不扩容。联机补偿容量由服务端从旧合法数据计算并持久化，不接受客户端提交的补偿值。UI 显示实际容量。

现行基地与离线远征增量文件都要处理，保持 SharedPlayer 恢复优先级及风险规则；成功撤离保留随身物品和有效手持，死亡/异常远征恢复清空两者。已有不支持的旧测试 JSON 保留原“不支持”提示，不删除它们。

服务端账户 SchemaVersion 升级，旧数据迁移一次后以新库存和手持结构保存。初始短剑先进入背包再标记为手持；死亡掉落只枚举库存，不能再额外复制一份手持武器。断线、退出、重连沿用权威账户保存事务。

## 联机权威与协议

协议源在 `Config/Proto/OnlineOuter_C_12001.proto` 修改，经实际项目生成入口生成双端代码，不手改生成 C#。新结构传递手持来源、格号、ItemId 与结构版本；不复用旧双槽字段来伪装新状态。双端同步升级，旧客户端不能继续按双槽协议操作新服务端；版本不兼容应明确拒绝而非造成库存差异。

拿出、收起经已有 OperationId、ExpectedInventoryRevision、LifecycleRevision 事务提交。服务端验证随身来源和合法物品，幂等重放不重复状态变化；攻击请求要求武器匹配当前手持来源，空手仅在无手持时合法。来源移动、尸体转移、死亡、账户迁移与手持更新必须原子完成。客户端以服务端确认刷新，不在联机模式修改离线库存；在线口袋尚未实现，继续显示其既有不可用状态，不创建本地口袋作为联机替代。

## 验证与完成标准

1. 单一手持：拿出不改变物品数量与格位，互换/重复拿出/满背包收起符合规则；库存移动跟随身份，转出/丢弃/死亡收起，同类替换不能继承旧手持。
2. 战斗：短剑、弓、拳头继续可用；切换取消旧输入，箭矢成功消费一次，失败不扣；异步模型快速切换和地图卸载无过期显示或资源泄漏。
3. 存档：空装备、单/双武器、满背包、已装弹药、已迁移、损坏数据、写入失败和回退；数量守恒、迁移幂等、补偿容量最小化，离线风险与服务端账户行为一致。
4. UI：正式 Prefab 经 Unity 反序列化所有引用有效；穿戴页无武器槽，背包标记与操作正确；手机选择列表空数据、隐藏重开、销毁重载、语言切换及输入恢复正确。
5. 联机：修订冲突、重复请求、伪造来源、未手持攻击、死亡掉落、初始发放、重连及旧数据迁移不复制或丢失武器；不通过离线状态兜底。
6. 定向测试每次用真实短类名或完整方法名，includePassingTests=true，调用前报告模式/过滤/最大数量，之后核对实际 Results。禁止完整套件与 Player Build；视觉用实际 Prefab 多尺寸预览，真机验收另行标注。
