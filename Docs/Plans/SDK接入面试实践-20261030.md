# SDK 接入面试实践：范围与候选方案

日期：2026-10-30。目标是获得可以如实讲述的客户端 SDK 实践，不以商店上线或商业收益为验收条件。

## 用户已确认的目标

用户澄清面试客户端岗位需要 SDK 接入经验，并对“选择容易取得测试参数的 SDK，完成一条功能链路并记录问题处理过程”回复“可以”。此前 TapTap 发行方向不再作为本项前置；没有开发者账号不等于必须先办理商店认证。

本项允许调研与方案准备。新界面具体预览尚未确认；本会话不操作 Unity、不编译、不运行测试、不触发 Player Build 的限制继续有效，不能把静态代码或模拟回调称为真实 SDK 接入验证。

## 候选与依据

优先候选：Google Mobile Ads Unity 插件的 Android 激励广告测试链路。

- 官方提供独立于个人 AdMob 账号的测试广告单元，适合先做个人实践。
- 官方 Unity 接入文档当前列出 Unity 2019.4+、Android 最低 API 24、目标 API 35+；项目使用 Unity 2022.3，编辑器版本满足文档要求，Android 工具链和插件版本仍需进一步核对。
- 使用官方测试应用/广告参数，不接入真实广告位或商业支付。正式选择版本时需锁定插件及原生依赖版本，不能直接追随 latest。
- 当前项目依赖中未发现 Google Mobile Ads 或外部依赖管理器；本次未修改 manifest、插件、正式资源、构建配置或网络权限。
- 用户回复测试手机是否能访问 Google 服务为“还不确定”。不能由当前电脑浏览文档推断手机能请求广告；真机广告可达性仍是候选是否适合的条件。

## 练习范围草案

优先做独立测试场景/练习工程，具体位置与界面在实施方案中确定，不把广告挂到正式游戏启动流程，也不改变现有纯离线包。

拟提供“初始化、加载测试广告、显示、清理”四个操作，以及状态、最后错误和回调事件记录。完成展示后的奖励回调只增加练习计数，不进入游戏分数、货币、账号或存档。

重点处理：重复初始化、重复加载、尚未加载就点击显示、加载失败与有限重试、广告关闭与奖励回调的区别、重复奖励防护、切后台后的状态、销毁后到达的回调、主线程更新与对象释放。使用官方 Unity 包装层不等于亲自实现 JNI；如后续增加原生桥接练习，应另行记录真实实现范围。

具体UI属于待预览内容；不得在正式资源上先制作后补确认。

## 验收证据

1. 依赖解析与实际Android构建成功：保留版本表、关键Gradle/Manifest配置及日志。
2. 真机初始化并加载官方测试广告，实际展示、关闭与奖励回调各有记录。
3. 重复操作、未就绪显示、断网/请求失败、前后台和释放后回调均有预期行为和真实验证记录。
4. 记录实际遇到的问题、定位证据、修改和复验；没有遇到的故障仅列为待验证用例，不编造排错经历。
5. 视频、截图及日志统一放 Backup/Artifacts/ 下独立批次，不能把编辑器模拟表现当成真机证据。
6. 简历只写实际完成范围，个人练习不写为商业上线、支付接入或渠道审核经验。

## 当前状态与接续条件

完成：明确面试目标；核对官方测试参数与当前项目依赖；形成候选和验收范围。

未完成：最终SDK选定、独立实施设计与界面预览、依赖接入、代码实现、真机验证。尚未声称接入完成。

现有限制：没有测试手机网络可达性证据；仍禁止Unity操作、测试和打包。可继续准备官方版本/依赖核对与代码设计，但不能执行依赖导入、Unity编译或构建，也不能宣称真机链路完成。若手机无法请求 Google 测试广告，再核对国内 SDK 的测试资格与参数获取要求后选型；不凭空宣称国内 SDK 无需账号。
