## 已确认目标

实现类似吃鸡的直观分部位穿戴：保留角色身份，穿什么就显示什么。七个槽位为头部、上衣、裤子、手套、鞋、护甲、背包。帽子与头盔共用头部槽，护甲覆盖上衣；空衣裤槽显示基础内搭。从背包穿戴、替换、卸下，卸下容量不足时保持原状态。本机、其他玩家、装备预览保持一致，第一人称同步袖口和手套。

首版包括存档和联机同步，不加入保暖、潮湿、多层衣物、新防护数值、捏脸或染色。现代资源仅用于技术验证，不视为汉末首章正式美术。手持继续使用现行单一手持系统，不恢复双武器储存槽。

## 推荐资源路线与验证门槛

优先验证候选包自己的身体与衣物组合，保持项目现有角色逻辑、输入和武器系统。Humanoid 只解决动作重定向，不能保证不同套件网格的骨骼顺序、bind pose 或体型兼容；不得直接把候选衣服挂到 City 身体并假定成功。

备选路线是为当前 City 角色人工拆分、补齐基础身体和衣物，保留风格但需要建模与蒙皮制作。整套模型显隐虽成本低，却不满足用户确认的分部位目标，因此不采用。

资源验证须先取得具体包的导入授权，选择必要身体、帽子、上衣、裤子、鞋及其材质、贴图、骨架依赖；不接入包内移动控制、换装 UI 或存档。先确认导入选择可以完整表达依赖，否则停止并报告扩大范围的原因。正式采用后仅将必要资源整理到 Game/Art，保留原始包，解决 GUID 引用，正式 Prefab 不依赖备用目录。

验证内容为：Humanoid Avatar 有效、基本动作可重定向、握持与枪口不偏移、遮挡身体后无孔洞、不同衣裤鞋组合可正常弯曲、材质适配项目渲染管线、第一人称袖口可实现、移动端预算合理。验证通过前不替换正式玩家 Prefab。骨架和人物风格变化须展示对照让用户验收。

七部位目标保持不变；候选包仅覆盖其中四部位。资源验证阶段的四部位样例不能作为完整功能交付，其他三部位需要另选资源或制作，并单独确认具体来源。

## 状态归属与穿脱事务

建议新增身体穿戴领域状态和唯一穿脱入口，独立于当前手持。Model 只保存槽位中的实际物品数据；System 校验槽位、归属、容量与当前玩法状态，完成库存与穿戴的原子变更。具体类名和存档版本在正式实施计划中按当前代码确定。

建议穿戴槽成为独立物品位置：穿上后物品离开背包，卸下后返回背包，同一物品不会同时存在于两个位置。与手持只引用库存的语义不同，界面必须明确表达。替换优先把旧装备放回新装备原占的背包格；候选事务完成容量和合法性检查后一次提交，失败恢复原装备与库存。重复请求不能复制装备。

首版背包外观本身不增加容量；增加容量会扩大到扩容、卸包溢出与服务端规则，需后续独立设计。衣物也不新增伤害减免。所有衣物均为可转移的物品，耐久和品质不在本批引入。

这部分是本文提出的具体规则，尚待用户审阅，不将“确认查资源”视为已确认全部物品事务。

## 外观与生命周期

共享身体表现组件读取穿戴快照，按稳定外观 ID 选择部件。帽子、头盔和刚性背包可按各自配置挂骨骼；上衣、裤子、手套、鞋与可弯曲护甲使用经验证的蒙皮绑定。固定基础身体与脸，不在穿衣时随机更换人物身份。

每套装备声明遮挡的身体区域；护甲与上衣使用经过验证的覆盖组合，避免简单缩放造成穿模。卸下后重新计算所有仍穿着装备的遮挡集合，不直接打开整副身体。没有适配资源的组合不得标记为可装备内容。

外观加载由拥有角色实例的 Controller 管理；捕获穿戴版本、MapInstanceId 与 View 生命周期，候选隐藏加载并校验，全部准备好后替换。旧请求晚返回只释放资源。失败保留旧可见外观并报告表现失败；领域装备仍以权威快照为准，重试成功后收敛，不能由表现层改回物品状态。

第一人称本机不显示整副身体；装备袖口和手套需要匹配候选身体的专用手臂表现，并沿用既有相机资源释放契约。当前 PolygonPrototype 手臂不能算作候选套件的袖口已经适配。

## 界面 配置 存档与联机

装备页沿用现有宿主与 BasePageCtrl，七个部位显示实际装备及卸下操作；背包详情增加穿戴意图。人物预览使用无碰撞、无业务脚本的展示实例，读取同一穿戴快照。UI 只发意图，不持有第二份库存。Prefab 字段通过 ReferenceCollector 与项目生成入口更新，不手写生成 View。

物品可穿戴部位和外观身份通过根 Config 的 Luban 数据源维护；客户端使用表现资源目录，服务端只需要物品合法性与槽位规则，不引用 Unity 对象。沿用 Config/gen.bat，禁止手改生成的 C# 或 bytes。

旧存档没有穿戴数据时初始化为空槽和基础内搭，不赠送物品；未知槽位和损坏数据明确拒绝，不能静默丢掉物品。身体穿戴与库存一同保存、回滚。建议穿戴物品遵循既有随身风险语义：成功撤离保留，死亡或失败按当前模式的损失/尸体规则处理，不能另建绕过风险的安全装备仓。

联机由服务端校验穿脱并提交库存与穿戴，客户端收到快照后刷新。独立穿戴字段使用新协议编号，不改变旧手持编号。出生、进入视野、重连和房间模型展示都需完整快照；只发即时换装事件不足以恢复状态。服务器账户保存和死亡掉落需纳入物品守恒事务。

## 交付与验收条件

1. 先验证具体资源，展示固定身份下帽子、上衣、裤子、鞋独立组合的效果；补足手套、护甲、背包资源后再进行七部位完整验收。
2. 正式闭环覆盖穿上、替换、卸下、满包拒绝、切图、读档、死亡/撤离，以及联机重连和远端初见。
3. 每类部件检查站立、走跑、蹲伏（若当前动作支持）、攻击及持弓/枪姿态；第一人称检查袖口、手套、武器遮挡与视角切换。
4. 定向逻辑测试验证物品守恒、重复请求、失败回滚、旧档空槽、过期加载释放；画面必须人工验收，自动测试不能替代。
5. Unity 测试仅使用真实类或完整方法过滤，调用前声明模式与最大执行数并核对返回范围。不运行全套，不触发 Player Build，不自动提交或推送。
