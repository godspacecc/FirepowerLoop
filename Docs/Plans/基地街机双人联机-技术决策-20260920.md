# 基地街机双人联机技术决策

> 2026-10-11 休闲路线功能版：新双人局持久化场地身份与场序，任意存活队员进入普通竞技场出口即可选路；同一 Tick 不同出口由稳定玩家 ID 仲裁一次。每条路线十场四轮后进入独立最终 Boss，经胜利出口提交通关节点，双方走既有个人结算事务。旧局保持顺序推进。客户端新快照检查与独立服务端规则检查通过，真实双端连接及自动结算时序尚待验收；奖励房、暗黑墓穴商店与四人扩展未完成。详见[实施计划](街机休闲路线与最终Boss实施计划-20261011.md)。

> 旧局字段兼容不等于跨配置版本继续开战：已有指纹门禁保持有效，旧联机局指纹不匹配时须使用结算入口结束；本次没有自动升级旧房间版本。

> 2026-10-11 后续设计修订：用户已要求将最多四人合作扩展纳入街机设计，范围见 [街机总设计第 2.0.2 节](../基地街机小游戏/基地街机小游戏总设计.md)。本文保留双人阶段的技术与实现基线；“固定两人”“两名原始玩家”等表述不再代表最终人数目标。四人扩展尚未实施，开局人数、救援、多人路线选择、旧局兼容及掉线恢复等细则继续逐项确定。

## 1. 状态

- 房间码主路径、服务器权威战斗、安全节点、断线恢复、独立结算及玩家可见 UI 已完成实现与定向自动化验证。
- 本文确定双人联机街机的权威边界、数据合同、失败语义与实施阶段；好友邀请仍因项目没有好友身份链而未接入，跨 PC/移动端真机验收仍需使用发布包完成。
- 现有单人街机继续保留；联机模式是独立运行路径，不把本地 `ArcadeCombatSystem` 改造成服务器逻辑，也不让同一局同时存在客户端和服务器双重权威。

## 2. 已确认产品规则

### 2.1 队伍与入口

- 首版固定两人合作。
- 通过好友邀请或房间码组队，不做公开匹配。
- 联机局创建后锁定两名原始玩家，不允许中途加入或替换队友。
- PC 与移动端可以跨平台组队，但游戏版本和街机配置版本必须一致；不一致时禁止进入并明确提示。
- 恢复未结束联机局时必须由原来的两名玩家组队。

### 2.2 战斗

- 战斗必须连接现有游戏服务器，由服务器裁决敌人、目标、生命、伤害、投射物、掉落、波次、金币和奖励。
- 玩家在本机预测自己的移动与射击反馈，服务器验证输入并下发权威结果；客户端预测不能直接修改生命、金币、掉落归属或竞技场进度。
- 两名玩家各有三条生命。死亡消耗自己的生命并在死亡位置复活，只提供配置化短暂无敌。
- 一名玩家生命耗尽后进入观战；另一名玩家仍可继续当前竞技场。只有两人都耗尽生命时本局失败。
- 生命耗尽的玩家到达安全商店后必须购买额外生命才能继续，不免费恢复。金币不足时队友可在安全商店转赠金币；仍无法购买时不能进入下一竞技场，只能结算或放弃。
- 双人难度按进入竞技场时的玩家人数确定；本竞技场内有人掉线不降难度，下一个竞技场再按实际参战人数计算。
- 敌人优先选择距离最近的存活玩家，并可在战斗中切换目标；观战和掉线玩家不是合法目标。
- 关闭友军伤害。玩家投射物穿过队友，两名玩家之间没有实体碰撞和距离牵引。
- 两名玩家各自使用独立跟随相机，不要求同时出现在一块屏幕内。
- 炸弹、冲刺、临时武器和支援均为个人资源；个人消耗炸弹后，效果作用于整个竞技场的敌人。
- 打开普通设置或菜单不会暂停联机战斗。

### 2.3 金币、掉落与商店

- 场上每件掉落只有一个共享实体，两名玩家都可靠近拾取；同一服务器 Tick 内按距离最近、玩家 ID 稳定决胜，实体移除后另一人不能重复获得。
- 拾取的局内金币进入拾取者个人金币账户，不进入团队共享池。
- 每名玩家拥有独立商店、个人商品生成结果、购买状态、强化和局内装备；一人的购买不占用另一人的商品。
- 安全商店允许玩家向队友转赠任意非负整数数量的个人局内金币。转赠成功后立即写入安全节点且不可撤回；保存失败则整笔转赠回滚。
- 生命耗尽的玩家在商店固定获得额外生命报价，不受随机商品位影响。
- 购买成功后立即更新安全节点；购买保存失败只回滚该次购买，不影响此前已保存状态。

### 2.4 准备、结算与放弃

- 进入下一竞技场必须两名玩家都处于可参战状态并点击准备；任意一人取消准备，队伍继续停留在商店。
- 正常结束本局并结算需要两人共同确认。两人的正式奖励分别累计、分别写入各自档案。
- 一名玩家生命耗尽并观战时，只要队友完成竞技场，两人都累计该竞技场的正式奖励。
- 一名玩家结算成功、另一名失败时，成功者可先返回基地；失败者保留独立待结算记录并可重试。成功者的幂等账本禁止重复领取。
- 主动放弃整局需要双方确认；确认后两人的局内金币、强化和未结算奖励分别清空，基地原有数据不变。
- 队友离线超过十分钟后，在线玩家可单独结束整个队伍存档并结算自己的奖励；离线玩家的待结算奖励转为个人待领取记录，之后上线单独领取。
- 两人都耗尽生命导致失败时，两人的局内金币、强化和未结算正式奖励全部清空，基地原有数据不变。

### 2.5 掉线、暂停与异常恢复

- 任意玩家在竞技场中掉线或主动退出，服务器立即暂停整个竞技场模拟。
- 暂停期间在线玩家只能等待、打开设置或退出，不能移动、攻击、拾取或提交其它战斗操作。
- 断线玩家有六十秒重连时间。宽限内恢复同一玩家身份、同一联机局和同一暂停现场，然后继续战斗。
- 六十秒超时后放弃当前竞技场全部瞬时进度，两人恢复到上一个安全节点且不扣生命。
- 在安全商店掉线时不触发战斗回滚；安全节点保持不变。在线玩家等待离线累计满十分钟后可单独结束本局。
- 服务器异常重启、街机 Actor 崩溃或现场无法恢复时，两名玩家恢复到上一个安全节点，当前竞技场进度作废且不扣生命。
- 安全节点保存失败时保持房间与当前状态，禁止进入下一竞技场并允许重试；不得以客户端快照代替服务端已确认存档。

## 3. 当前实现证据与复用边界

### 3.1 可以复用

- `OnlineAccount`、`OnlinePlayerActor`、GameGate、TCP RPC、推送、Session Epoch、顶号与断线重连基础设施。
- `OnlineRoomActor` 的成员身份、RoomCode、成员 Revision 和连接状态同步模式。
- 根 `Config/Proto/` 的协议权威源、独立协议生成器与双端生成流程。
- 根 `Config/` 的 Luban 权威源与双端分组生成能力。
- 客户端 `MapSceneSystem`、正式玩家/敌人/投射物/掉落表现控制器，以及街机 HUD 和安全商店的布局能力。
- 单人街机的竞技场、轮次、敌群、掉落、商店、强化和奖励配置语义。

### 3.2 不能直接复用为权威

- `ArcadeRunFileStore` 只负责本机单人 `arcade-run.json`，不能保存联机局。
- `ArcadeRunSystem` 和 `ArcadeCombatSystem` 当前是单人本地权威；联机模式只能把它们的已验证规则作为迁移参考，不能在收到服务器快照后继续本地裁决同一状态。
- 当前 `OnlineWorldComponent` 使用共享 `MainWorldId`，并包含客户端敌人导航租约。联机街机要求每局隔离、服务器完整推进敌人与波次，因此不能把现有全局 World 直接当作街机房间。
- 当前在线玩家档案只保存联机背包等既有字段，没有联机街机安全节点、待结算奖励或奖励幂等账本；必须显式扩展服务器档案与迁移版本。
- 当前 Room 默认容量为四且支持公开房间列表。联机街机必须使用容量二、私有可见性和玩法用途锁，不能依赖客户端隐藏公开入口来实现限制。
- 当前好友系统与好友邀请链路未在同步实现中找到。好友邀请是已确认产品需求，需要独立最小纵向切片；房间码可以先复用现有能力。

## 4. 总体架构

```text
客户端 A / 客户端 B
    -> GameGate：鉴权、RPC 转发、推送
    -> OnlinePlayerActor：玩家身份、当前房间与当前街机局路由
    -> OnlineRoomActor：两名成员、私有房间、准备与玩法用途锁
    -> OnlineArcadeRunActor：一局一个 Actor，全部战斗与安全节点权威
    -> OnlineArcadeRunStore：安全节点、恢复索引与操作幂等记录
    -> OnlineAccount/Profile：个人正式奖励账本与离线待领取奖励
```

### 4.1 服务端职责

- `OnlineRoomActor` 只管理组队关系、邀请/房间码、成员连接状态和创建街机局意图，不保存战斗细节。
- 每个联机局建立独立 `OnlineArcadeRunActor`，以 `RunId` 作为稳定身份并锁定两个 `PlayerId`。
- `OnlineArcadeRunActor` 串行处理输入、战斗 Tick、敌人、投射物、掉落竞争、死亡、暂停、商店、转赠、准备、结算和放弃。
- `OnlineArcadeRunStore` 只保存安全节点与幂等操作记录，不保存敌人位置、子弹、玩家现场位置或未完成竞技场进度。
- `OnlinePlayerActor` 保存当前联机街机 `RunId` 路由与离线领取状态，不复制战斗字段。
- 正式奖励通过账号档案事务写入个人奖励账本；`RunId + PlayerId + SettlementRevision` 是幂等身份。

### 4.2 客户端职责

- 新增只读的联机街机快照 Model，保存服务器最近确认的阶段、自己与队友状态、实体快照和操作状态。
- 新增联机街机 System，负责 RPC、推送 Revision、输入上报、客户端预测、重连恢复和地图事务；不直接修改权威金币、生命、敌人或奖励。
- 街机战斗 ViewPort 继续负责正式 Prefab、对象池、相机与 HUD 表现。单人模式读取本地 `ArcadeCombatRuntime`；联机模式读取服务器快照，两者不得同时驱动同一 View。
- UI 只提交创建房间、邀请、准备、购买、转赠、结算、放弃和重试意图，并渲染不可变快照。

## 5. 服务端运行数据

### 5.1 联机局安全节点

- `RunId`、SchemaVersion、状态 Revision、配置指纹与创建/更新时间。
- 锁定的两个 `PlayerId`、原始房间身份和成员顺序。
- 已完成竞技场、下一竞技场编号及下一场双人难度人数基准。
- 每名玩家独立的剩余生命、局内金币、紧急资源、强化、装备、商店、准备状态和待结算正式奖励。
- 每名玩家的结算状态、结算 Revision、奖励账本键与离线待领取状态。
- 金币转赠、购买、准备、结算和放弃的有界幂等操作记录。
- 当前阶段：安全商店、进入中、竞技场、掉线暂停、回滚保存中、结算中或已结束。
- 掉线玩家、掉线开始时间、六十秒战斗宽限截止时间和十分钟单独结束资格时间。

### 5.2 不保存的战斗现场

- 玩家位置、瞄准、动作和客户端预测缓存。
- 敌人位置、生命、目标和行为状态。
- 投射物、特效、掉落实体、当前波次击杀与当前竞技场金币。
- 当前竞技场中的暂停现场只存在于 Actor 内存；服务器异常后统一回滚安全节点。

## 6. 关键事务

### 6.1 创建与进入

1. 房间验证用途为街机、成员恰好两人、成员在线、未绑定其它未结束街机局。
2. 双方提交客户端版本与街机配置指纹；不一致则拒绝。
3. 服务端创建 `RunId`、两份个人初始状态和两份独立商店候选，先保存安全节点。
4. 保存成功后锁定房间成员并发布联机街机快照；失败时不公开半成品局。

### 6.2 战斗推进

- 客户端上报带连续序号和当前生命周期 Revision 的移动、瞄准、射击、炸弹与冲刺意图。
- 服务端固定 Tick 推进，验证速度、射速、资源、身份、生命周期和输入序号。
- 客户端可预测本地移动与开火表现；权威快照按 Revision 校正，旧推送不能覆盖新状态。
- 敌人、投射物、掉落和难度全部由服务端生成；不使用现有 `OnlineWorld` 的客户端导航执行租约。
- 掉落由 Actor 自动做距离拾取判定；同一 Tick 内按距离、玩家 ID 稳定裁决，并在一次 Tick 中删除实体、增加获胜玩家个人资源。

### 6.3 安全商店

- 每名玩家的商品与金币独立；购买请求必须携带 `OperationId`、商店 Revision 和 OfferId。
- 转赠在一个候选安全节点中同时扣减赠送者金币、增加接收者金币；保存成功后才发布，失败不改变双方状态。
- 生命为零的玩家固定出现额外生命报价；未恢复到至少一条生命时不能准备。
- 双方准备后，服务端再次检查生命、配置指纹和安全节点 Revision，先标记进入事务再创建战斗现场。

### 6.4 暂停与回滚

- 竞技场内任一成员掉线或主动退出，Actor 停止战斗 Tick 并拒绝战斗命令，记录六十秒截止时间。
- 原玩家在同一 Session Epoch 路由下恢复后重新获取全量现场快照；双方确认加载完成后恢复 Tick。
- 超时则销毁现场实体，重新载入上一个安全节点并保存新的阶段 Revision；不扣生命、不保留本场收益。
- 安全商店掉线不改变节点。掉线累计十分钟后，在线玩家获得单独结束权限。

### 6.5 结算

- 正常结算先锁定队伍结算 Revision，再分别提交两个玩家的奖励事务。
- 每个玩家的奖励写入以幂等账本为准；部分成功不会回滚已经成功的一方，也不会重复发奖。
- 离线超过十分钟后的单独结束会关闭团队运行记录；在线者立即结算，离线者的奖励转入个人待领取队列。
- 两名玩家的奖励状态都完成后，才可删除团队运行记录和恢复索引。

## 7. 配置与协议要求

- 当前街机表是客户端配置。服务器权威实施前，竞技场、敌群、武器、掉落、商店、强化、奖励和规则参数必须进入服务端 Luban 生成组，保持根 `Config/` 单一来源。
- 新增稳定的街机配置指纹；房间创建、加入、恢复和每次进入竞技场前都校验客户端声明与服务器版本。
- 协议只在根 `Config/Proto/` 定义，通过正式生成器同时生成客户端和服务端消息；不手写生成 C#。
- 战斗快照按稳定实体 ID 和 Revision 同步。高频变换与低频领域事件分离，奖励、购买和转赠不用高频广播通道。
- 所有可重试写操作携带 `OperationId`；同一操作 ID 与不同参数组合必须拒绝为身份冲突。

- 验收重点：事务原子性、保存失败回滚、OperationId 幂等、生命固定报价和恢复一致性。

当前进度（2026-09-20）：

### 阶段三：服务器权威战斗灰盒

- 迁移竞技场、波次、敌人、目标、伤害、投射物、掉落竞争、生命和观战规则。
- 客户端接入预测、快照校正及现有表现对象池；保留单人本地路径。
- 验收重点：双端确定性边界、旧生命周期拒绝、同一掉落只能一人获得、双人难度与全灭失败。

当前进度（2026-09-20）：

- 双方准备事务现在会在落盘前完整构造并校验战斗现场候选；安全节点成功后才发布 `Arena`，避免准备状态与现场半提交。
- 已建立仅存在于 `OnlineArcadeRunActor` 内存的竞技场运行态、玩家初始位置/生命、首轮双人生成队列、权威敌人 RuntimeId/生命/目标和独立 `BattleRevision`。
- 首轮敌人按 Luban 生成间隔持续进入，队列数量按参战人数计算，同时受敌群与全局同屏上限约束；服务器重启不会恢复瞬时敌人，而是回到安全节点并清除旧准备状态。
- 服务端已接受带单调序号的移动、瞄准和按住射击意图；输入向量会归一化，超过 250 毫秒未续报即停止移动和射击，客户端不能上传位置、命中或伤害。
- 玩家移动、障碍/边界约束、配置化射速/散射/弹速/寿命、投射物预算、敌人受伤与死亡，以及清场后的后续轮次切换均由服务器 Tick 推进。
- 敌人已按最近存活玩家动态选目标；近战执行追击与接触伤害，远程从现有敌人/投射物配置读取射程、冷却、速度和最大飞行距离，敌群移动后按稳定 RuntimeId 做预算内防重叠。
- 玩家受击、短暂无敌、死亡扣除个人生命、死亡原地延迟复活和生命耗尽观战已由服务器裁决；双方都在等待复活时不会误判全灭，只有两人生命都归零才停止战斗模拟。
- 客户端只读快照已可接收竞技场、玩家、敌人和投射物状态，RPC 与推送乱序时拒绝覆盖更新的 Run/Battle Revision。
- 每轮清场金币按现有增长配置累计到双方个人账户；最终轮完成后，服务器构造下一商店与每人独立待结算正式奖励，安全节点文件原子提交成功后才切换回商店。保存失败时冻结完成态并延迟重试，不公开半成品节点。
- 双方生命归零后，服务器先原子删除运行局，再清理成员索引、向客户端发布无运行局状态并解除房间成员锁；删除失败时保持冻结现场并重试，基地数据不变。
- 敌人死亡按运行局、竞技场和敌人身份确定性抽取配置掉落；共享实体受全局数量上限约束，两人靠近时按距离及玩家 ID 稳定决胜。个人金币、炸弹和冲刺写入本局运行数据，临时武器与自动支援只保留到当前竞技场，玩家与掉落状态均进入只读战斗快照。
- 炸弹与冲刺作为带递增序号的一次性意图贯穿双端协议；炸弹由服务器扣除个人资源并清除当前敌人，冲刺由服务器计时并提供短时加速和无敌，死亡或已结束现场不能消耗。
- 已接入键鼠、手柄与移动端双摇杆输入，移动端右摇杆同时表达瞄准和持续射击；20Hz 意图发送只在服务器确认后消费一次性炸弹/冲刺，正式玩家、敌人、投射物和掉落表现按稳定实体 ID 复用现有 Prefab/对象池，本地玩家仅做轻量移动预测并由权威快照校正。

### 阶段四：暂停、重连与异常恢复

- 实现竞技场掉线立即暂停、六十秒现场重连、超时回滚和十分钟单独结束。
- 实现服务器重启后的安全节点恢复，不尝试恢复未保存现场。
- 验收重点：暂停期间零推进、主动退出等同掉线、重连身份、超时不扣命与无收益泄漏。

当前进度（2026-09-21）：

- 竞技场内断线或主动退出会立即清空输入并暂停 Tick；客户端 HUD 显示暂停并禁止摇杆、炸弹和冲刺意图。
- 60 秒内原身份重连恢复同一 Actor 内存现场并重置 Tick 时间；超时原子回滚到上一个安全节点，不扣生命且不保留本场收益。
- 服务端重启只恢复安全节点并清除准备状态，不尝试从客户端或磁盘恢复瞬时战斗现场；安全商店断线时间会进入快照并计算十分钟单独结束资格。

### 阶段五：独立奖励结算

- 实现双方结算、部分失败、单独结束、放弃和失败清局。
- 验收重点：恰好一次发奖、成功方不回滚、失败方可重试、运行记录最终清理。

当前进度（2026-09-21）：

- 双方结算与放弃均需各自确认；结算按玩家分别原子提交，单方成功不会被另一方失败回滚，重放只重试未完成玩家。
- 队友离线满十分钟后，在线玩家可单独结算，离线玩家奖励进入待领取记录；客户端重新登录时先恢复运行局，无运行局时自动幂等领取个人待领奖励。

## 9. 明确不做

- 首版不支持三人或四人街机。
- 不做公开匹配、中途加入、替换队友、排行榜、赛季或付费内容。
- 不让房主客户端承担权威战斗，因此没有主机迁移。
- 不保存战斗现场，不从客户端上传现场恢复服务器。
- 不把本地单人存档转换为联机存档，也不把联机局降级成单人继续。
