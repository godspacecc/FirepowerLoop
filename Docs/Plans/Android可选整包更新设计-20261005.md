# Android 可选整包更新设计

用户已确认产品方向，并明确要求直接实施，不另写实施计划：Android 游戏启动时发现新版 APK，可直接通过现有资源服务器下载到手机，随后由玩家确认安装。玩家可选择稍后更新并继续既有热更新流程。源码实现与针对性自动验证已完成，手机上的权限、覆盖安装与存档保留等待手动打包后验收。

## 玩家流程

仅 Android Host 资源模式接入。Boot 读取当前资源服务器地址后、请求 YooAsset 远端资源版本前，检查整包更新。离线完整测试包保持原有离线启动策略；Windows 和编辑器模拟资源模式不显示 APK 更新。

有更高安装包版本时显示：

- 标题：有新版本可下载
- 正文：新版游戏安装包已发布，是否下载更新？你也可以稍后更新，继续游戏。
- 补充信息：当前版本、新版本、下载大小。
- 按钮：下载更新、稍后更新。

点击下载更新后，在游戏内显示 APK 下载进度和大小，提供取消下载入口。取消后回到更新提示，玩家仍可稍后更新。下载完成并验证通过后显示安装更新、稍后更新；安装入口按玩家操作触发，不自动弹出系统安装界面。

检查无新版本、配置不存在、超时或无效时，直接继续原资源流程。下载失败时显示简短原因，提供重新下载和稍后更新。安装取消、权限未授权或安装入口失败时保留已验证文件，允许再次安装或继续游戏。

每轮启动对同一个服务器和版本最多提示一次；稍后更新只跳过本轮，下次启动仍可提示。资源服务器地址更改会取消旧请求，清理旧临时文件，并基于新地址重新检查。下载和安装界面期间暂时关闭地址编辑入口，防止交叉提交。

## 当前实现证据

- `Client/Assets/Boot/Launcher.cs` 串接资源初始化、热更新程序集和 Main，拥有 Boot 覆盖层与地址编辑串行重启边界。
- `Client/Assets/Boot/Res/ResourceBoot.cs` 决定资源模式；Host 模式通过 `BootstrapConfig.LoadAsync()` 读取安装包默认地址与玩家覆盖地址，负责资源在线、缓存和内置回退。
- `Client/Assets/Boot/UI/HotUpdate/HotUpdateView.cs` 及 `Client/Assets/Game/Scenes/Boot.unity` 提供启动文本、下载进度和失败按钮，目前没有整包更新交互。
- `Server/ResourceServer/resource_server.ps1` 是 GET/HEAD 文件服务器；资源文件限制在 ResourceFiles 下，公告文件有独立路由。
- `Client/Assets/Editor/YooAsset/ResourceServerPublishUtility.cs` 发布模板和 ResourceFiles，资源更新使用临时目录、替换和回滚。
- `Client/Assets/Plugins/Android/AnotherDayRestart.androidlib/` 已有原生重启组件，没有安装更新入口。
- `Client/Assets/Editor/Build/AndroidBuildUtility.cs` 最终 APK 命名为 `AnotherDay-{appVersion}.apk`，应用版本采用 major.minor.patch 并在最终构建前递增补丁号。项目当前 `AndroidBundleVersionCode` 为 1。

以上是同步源码证据。Unity MCP 已成功读取 Boot 场景，场景未修改；尚未运行游戏、测试或构建。

## 职责与启动接入

整包更新必须位于稳定 Boot 程序集，不依赖尚未下载或加载的 Game.dll，也不向 QFramework 游戏架构注册业务状态。

在 ResourceBoot 的 Host 地址读取成功后插入可等待的更新阶段，整包处理结束才进入既有 YooAsset 资源阶段。Launcher 继续拥有启动与场景生命周期；新增窄职责的 Boot 更新协调器管理版本检查、玩家选择、下载和安装桥接。HotUpdateView 仅渲染快照与发送按钮意图，不决定版本和文件有效性。具体新增类型在实施计划中按现有调用边界定名。

旧服务器不提供整包路由时返回 404，客户端正常继续。整包更新失败不得转换成阻断启动的 BootFailure。既有资源初始化失败、资源回退与 Main 启动失败仍由原流程处理。

每个请求捕获服务器地址、轮次和取消令牌；异步返回后校验轮次与所有者存活。所有者销毁、地址切换或取消下载时终止请求，不让旧请求修改新界面。按钮等待只能完成一次，重复点击不得并发下载或重复调起安装。

## 资源服务器与发布

在服务器发布包增加独立 `AppUpdates/Android/` 目录，避免替换 ResourceFiles 时删除 APK。提供两个受限路由：

- `/app-update.json`：Android 最新整包描述，无缓存，GET/HEAD。
- `/app-updates/android/{文件名}.apk`：APK 文件，GET/HEAD，类型为 `application/vnd.android.package-archive`。

路由只允许访问整包目录内的正式 APK；不开放目录浏览、服务器包根目录或任意磁盘路径。现有资源和公告路由保持原语义。

整包描述包含 schemaVersion、platform、packageName、versionName、versionCode、apkFileName、sizeBytes 和 sha256。它不包含强制更新选项；APK 地址由当前资源服务器根地址和受限文件名生成，不能任意跳转到其他站点。版本号必须是严格的三段非负整数，按数值比较，例如 0.1.10 高于 0.1.9。

新增独立的本地发布脚本：接收用户已经手动生成的 APK、版本名和版本码，验证 APK 存在、扩展名和参数，复制后计算字节数与 SHA-256，最后原子替换描述文件。脚本不构建 APK。新 APK 使用不同文件名；发布新描述时保留旧文件，避免中断已有下载。

发布模板默认不提供有效的新版本描述，未配置时无提示。现有资源服发布和更新工具需同步服务器脚本与启动参数；更新 ResourceFiles 时保留已经发布的 AppUpdates。README 补齐发布、检查、替换和回滚说明。

## 下载与安装

客户端读取自身应用版本与 Android 版本码，只接受版本名按数值更高且版本码不低于当前安装包的描述；后续正式发布的版本码逐包递增。下载写入应用专用更新目录的临时文件，不把整个 APK 放入内存，不申请公共存储权限。首版不提供断点续传；中断文件删除后重新下载。

下载完成先验证实际字节数与 SHA-256，再原子移动为可安装文件。再次使用已有 APK 时重新验证；失败文件不能调起安装。整包描述最大 64 KiB，检查超时 5 秒；下载超时或取消时及时释放网络与文件句柄。只清理本功能拥有的更新文件，不删除资源缓存或存档。

Android 原生桥接还需检查 APK 包名、版本名、版本码和签名兼容性；不接受不属于当前应用或不可覆盖安装的包。安装使用系统支持的 content URI 与临时读取授权，不使用 file URI 暴露文件。首版采用独立原生库内的窄范围 ContentProvider，只提供专用更新目录里已验证 APK 的只读访问，拒绝其他目录、写入和路径穿越，不引入 AndroidX 依赖。

Android 8 及以上检查当前应用是否允许发起未知来源安装。未授权时，在玩家点击安装更新后引导至该应用的系统授权页；返回游戏后保留安装按钮，玩家再次点击安装。授权或安装取消均可稍后更新。低版本按对应系统安装机制处理。系统界面打开只表示已发起安装，不宣称安装成功；重新启动后读取实际安装版本。

原生库与 Manifest 新增安装请求权限、受限 URI 提供组件以及必要的 C# 桥接。Android 官方依据：[安装请求权限查询](https://developer.android.com/reference/android/content/pm/PackageManager#canRequestPackageInstalls())、[文件共享 URI](https://developer.android.com/reference/androidx/core/content/FileProvider)。

## 兼容与首版上线

包含新 Boot 代码与 Android 安装组件的第一版 APK，必须由开发者手动分发一次；旧安装包不能仅通过 Game.dll 热更新获得这一完整流程。

本功能只做可选更新，不承诺旧包可运行任意未来资源版本。开发者发布资源时仍须保证面向旧包的资源兼容性；涉及宿主不兼容变更时不能用可选整包提示替代资源兼容策略。本批不新增资源按宿主版本分流，也不增加强制更新。

版本发布需保持包名和签名一致。实施中对最终 APK 构建逻辑增加版本码单调递增，并与版本名一起在构建失败时回滚；不改签名配置、不改现有资源版本规则、不执行任何打包或 Player Build。安装结果与数据保留需手机实际验收。

## 实施范围与验收

预计涉及 Boot 更新协调、ResourceBoot 接入、HotUpdateView 与 Boot 场景、独立 Android 原生更新库、资源服路由及发布脚本、资源发布工具和 Android 最终包版本码管理。现有游戏业务、Luban 配置、存档格式、联机协议和其他玩法不在范围内。工作区已有其他玩法改动，实施不得覆盖或提交这些改动。

自动验证覆盖版本数值比较、旧服务器 404 与检查失败放行、稍后更新继续一次、下载失败及取消、错误字节数与哈希拒绝、过期请求、重复点击、发布保留 APK、路由目录隔离及 GET/HEAD。Boot 场景引用通过 Unity 反序列化检查。Unity 测试只运行明确类或方法；执行前声明模式、过滤器和最大测试数，结果逐项审计，不运行全套。

用户手动生成新 APK 后，在手机验收：发现新版、稍后更新进入游戏、下载进度、断网失败与重试、权限拒绝与授权返回、取消安装、覆盖安装后版本变化、存档保留，以及首次手动分发闭环。自动测试通过不替代这些真机结果。

首版不包含后台下载、断点续传、浏览器跳转、应用商店、公网部署、静默安装或自动重启游戏。

现象：Boot 新版 APK 提示中点击“稍后更新”后，按钮消失，但更新标题和正文仍停留一段时间。源码原因：`ApkUpdateFlow.RunAsync` 退出时仅调用 `HotUpdateView.HideAllButtons()`；该方法不清除标题和正文，后续 `ResourceBoot.SetStatus()` 也只更新状态文本，直到后续界面渲染才清除旧提示。

本次修改目标已落实：玩家点击“稍后更新”后立即清除 APK 更新标题和正文，恢复可见的启动状态提示，继续原有资源检查流程。涉及 Boot 宿主代码，需随下一版完整安装包交付，不能仅通过 Game.dll 资源热更新生效。验收须检查点击后的即时画面与继续启动行为。

本记录仅覆盖提示残留问题；开始界面“检查更新”接入 APK 检查已另行确认并实施，见下节。

## 安装交接与错误复制修复（2026-10-06）

用户报告下载完成后点击“安装更新”没有打开系统界面，随后“稍后更新”也无响应。电脑 ADB 未连接手机，因此尚无该次安装失败的手机日志证据。源码已确认旧选择任务完成后回调仍保留、安装失败也进入无期限焦点等待；旧原生桥接又同步等待 UI 线程，存在与 Unity 暂停交叉等待的风险。

改为原生工作线程验证 APK、UI 线程发起系统意图、Unity 异步读取结构化结果。使用请求 ID 与原子交接状态拒绝过期或取消后的排队意图，不持锁跨线程调用 startActivity；Unity 探测使用不受 timeScale 影响的等待，并限制交接等待为 8 秒。选择稍后立即清除提示并取消尚未发起的安装；已交给系统的安装由玩家在系统界面确认或取消。

安装失败显示简短原因、阶段和错误码，并提供重试安装、稍后更新、复制错误详情。复制包括当前/目标版本、包身份、目标版本码、APK 文件与 SHA-256、原生异常，最多 16 KiB；原生堆栈与本地路径只出现在复制详情，屏幕不直接展开。复用 Boot 现有三个按钮，离开 APK 状态后恢复启动失败的原按钮角色和标签，未修改场景或 Prefab。

验证：ApkInstallInteractionTests 修复前 4 项失败，最终 5 项通过；ApkInstallResultTests 4 项、ApkUpdateFlowTests 11 项、BootFailureFlowTests 16 项通过，共 36 项相关测试。每次使用 EditMode 安全类过滤并逐项审计。Unity 返回 compiling=False、failed=False；ApkInstaller 与 ApkProvider 通过 javac UTF-8 独立编译，仅有 Java 8 引导类路径与旧 API 警告。插件检查脚本补充异步桥接接口源码和已有 APK 的 DEX 标识检查。未触发 Unity 打包或 Player Build。

用户须手动生成新首包，并手动覆盖安装到手机一次；旧 APK 的 Boot 和原生插件不能由资源热更新修复。手机需验收安装授权、系统安装页、取消返回、错误详情复制与稍后继续启动。旧 0.1.15 产物不能当作本次修复后的 APK。

## 开始界面主动检查 APK（2026-10-06）

用户确认实施第一项：开始界面手动“检查更新”同时检查资源与安装包。`ResourceUpdateSystem` 通过注册于 `Game.cs` 的 `IApplicationUpdateChecker` 复用 Boot 的 APK 请求及兼容校验，返回独立于资源版本的 APK 候选。资源已最新但安装包有新版时，`StartUICtrl` 优先复用现有更新弹窗显示当前安装版本、新版和大小；选择“立即重启更新”沿现有 Android 重启入口进入 Boot 下载、校验和安装流程，选择稍后后可再次手动检查同一版本。

静默检查维持原资源检查语义；主动并发检查复用一次事务，开始页检查按钮覆盖整个请求期间。界面隐藏或卸载后的请求不弹出提示，服务器切换或架构取消后晚到的 APK 候选丢弃。未修改 Boot、Prefab、Android 原生组件或安装包版本；提示残留仍按上一节延后。

验证：ManualApkUpdateTests 实际执行 5 项，覆盖资源最新但 APK 有新版、静默检查、再次手动检查、并发复用和服务器切换后的过期候选；修复前 4 项失败、1 项通过，修复后 5 项通过。ResourceUpdateTests 15 项及 ApplicationRestartTests 4 项通过，共 24 项；每次使用 EditMode 类过滤并逐项审计执行范围。Unity 返回 compiling=False、failed=False；中英文语言表校验 issues=0，文本常量通过正式生成器更新。未执行打包或 Player Build，手机画面及实际重启进入 APK 下载仍需发布资源后验收。
