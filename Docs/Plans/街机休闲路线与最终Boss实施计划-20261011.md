# 街机休闲路线与最终 Boss 实施计划

> 执行方式：当前会话按 executing-plans 连续实施；不创建 worktree、不调用子代理、不自动提交或打包。

**目标：** 真实选路经过十场四轮主线后，另打最终 Boss，经胜利出口提交并结算；保留旧局兼容与失败重试。

**设计依据：** [街机总设计第 2.0 节](../基地街机小游戏/基地街机小游戏总设计.md)，用户已确认最终 Boss 的追击、预警冲锋、射线与普通敌群干扰，暂缓矿车彩蛋及专用结束动画。合作竞技场依据玩家实测采用任意在线存活队员触发出口、服务器首个有效选择裁决；奖励房不沿用此推断。

**架构：** Luban 保存地图身份、后继地图与最终 Boss 规则；Run 系统拥有安全节点和结算，Combat 系统拥有路线出口检测、独立 Boss 阶段、攻击与刷怪；View 仅呈现出口和权威战斗状态。本局场序独立于场地配置身份，难度、奖励和商店仍按场序计算。

## 约束与边界

- Unity MCP 优先；仅使用精确类或方法过滤的 EditMode 测试，预先声明最大执行数并审核结果。
- 不制作原作全部地图或新美术：使用已同步的二十份竞技场功能配置与现有角色、弹丸表现。原作地图名称只作为路线研究索引，不冒称场景已还原。
- 宝藏房与第十一轮暗黑墓穴商店仍是后续独立迁移项，不在本步骤补造奖励房。
- 旧局不自动删除或结算，不把缺少路线身份的旧存档直接猜成休闲路线；新局进入新路线。
- 配置数值为可调项目初值，不冒称原作数值；配置源修改后只运行 Config/gen.bat 双端生成。

## 重点检查

1. 分支选择不能用配置编号提高难度，不能恢复后重抽已保存的目的地。
2. 第四轮结束不能提前完成末场；独立 Boss 不计为第五轮、第四十一轮或第十一场。
3. 普通敌人必须保持预算，Boss 死亡即停止增援与危险攻击。
4. 保存或奖励写入失败须可重试，不能推进到下一场或重复发奖。
5. 旧局、断线、同时进入不同出口及客户端晚到的快照不能覆盖已经裁决的路线。
