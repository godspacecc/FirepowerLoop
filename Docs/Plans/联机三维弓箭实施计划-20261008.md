# 联机三维弓箭实施计划

> 实施方式：在当前本地工程内由当前代理连续执行，使用 `executing-plans`。仓库不授权默认 worktree、子代理、自动提交或 Unity 打包；本计划遵守这些限制。计划审阅后开始产品代码改动。

**Goal:** 联机玩家弓箭在三维空间实际飞行，服务器根据沿途碰撞结算伤害，第一/第三人称使用同一套准星瞄准。

**Architecture:** World 持有弹体状态、推进、碰撞和终止事务；Gate/Player 转发意图与权威快照。客户端输入计算发射方向，OnlineWorldSystem 合并状态，纯表现系统复用 ProjectileCtrl 资源与三维 View。静态碰撞从正式地图资源离线导出，双端校验一致性。

**Tech Stack:** Unity/C#、QFramework、ET/.NET 8、MemoryPack、现有 Luban 配置、Unity Editor 资源导出。

**Spec:** [联机三维弓箭设计](联机三维弓箭设计-20261008.md)，用户已于本次会话确认。

## Global Constraints

- 本次保持直线匀速，不新增重力、风偏、穿透、爆炸、爆头或玩家之间的伤害。
- 枪械、敌人攻击、临时箭塔和独立街机规则不顺带转换。
- 第一/第三人称保留垂直瞄准；俯视角和近战保持水平规则。
- 仅正式修改协议源，经 `Tools/gen-protocol.ps1` 生成，不手改生成代码。
- 速度、最大距离与回收物品继续读取正式 Projectile 配置。
- Unity MCP 优先；只运行有效类/方法过滤的测试，声明并审计最大执行数。
- 当前 checkout 连续实施，不自动提交、不推送、不打包；保留其他待改内容。

## Review Focus

1. 射手与地图根变换不同：发射点、服务器位置和表现必须使用一致地图本地坐标。
2. 静态碰撞缺失或源资源改变：拒绝新弓箭请求，不能静默回退到穿透命中。
3. 消息终止先于出生：晚到出生不能复活已经结束的箭。
4. Tick 延迟或跨越多帧：沿完整位移段检测，不重复命中，也不能穿过薄障碍物。
5. 地图准备中断或玩家生命周期改变：撤销候选表现、释放 Handle，旧消息不能写入新地图。
