## 总体设计说明

### 目录与职责

```text
Server/
├─ ResourceServer/   YooAsset 资源发布服务模板
└─ GameServer/       ET8.1 游戏服务器源码与工具基线
```

- `Server/GameServer/DotNet/` 是独立服务端构建和运行入口。
- `Config/Proto/ET/` 是当前 ET 网络协议唯一权威源，`Tools/ProtocolGenerator/` 与 `Tools/gen-protocol.ps1` 是不依赖客户端或服务端 Runtime 的唯一正式生成能力。
- `Config/Defines/`、`Config/DataCsv/`、`Config/luban.conf` 是双端 Luban 权威源，`Config/gen.bat` 是唯一正式生成入口。客户端生成物位于 `Client/Assets/Game/`，服务端生成物位于 `Server/GameServer/Runtime/Model/Generated/Config/` 和 `Server/GameServer/Config/Luban/`。
- `Server/GameServer/Share/` 继续保存 ET 分析器与源码生成器；旧 ExcelExporter 和 Proto2CS 正式入口已移除。
- `Server/GameServer/Runtime/` 保存纯 .NET 服务端 Core、Model、Hotfix 与第三方源码；服务端构建不依赖 Unity 工程、PackageCache 或客户端源码。
- `Server/GameServer/Tools/start-local-online-server.ps1` 是本地开发和发布包共用的受控启动器：在同一个可见控制台中托管一个 `dotnet App.dll --AppType=Server --StartConfig=OnlineLocal --Console=1` 子进程，只控制自己持有的进程。启动器独占物理键盘并按完整行转发服务端命令，窗口使用中文标题、前缀和操作提示，支持 R、Ctrl+C、关窗和异常等待；未知 TCP `127.0.0.1:31001` 占用只会拒绝启动，不会结束占用者。Unity 以 `Client/Library/ServerTools/LocalOnlineServer.json` 保存启动器进程身份并防止重复窗口，发布包则以根级 BAT 委托同一启动器。
- `Server/GameServer/Publish-win-x64.bat` 是无 Unity 的 Windows 发布包装入口；它只从自身位置规范化 `GameServerRoot`、调用 `Publish-win-x64.ps1` 并返回实际退出码。`Server/GameServer/global.json` 将构建选择限定在稳定 .NET 8。
- `Server/GameServer/Publish-win-x64.ps1` 是 Windows 框架依赖发布入口：生成 App 与 Hotfix 项目到独立临时目录，检查完整后替换 `Publish/win-x64/` 的程序、配置与工具，并复制完整 `Config/`、受控启动器和根级 `启动联机服务器.bat`。脚本不传 `--runtime` 或固定 `--source`，只对本次发布关闭 NuGet 漏洞审计；清理目标均经过规范化边界校验，使用独占锁隔离并发发布，替换前失败保留旧包，替换失败尝试恢复并核对旧产物；恢复无法确认时保留备份与临时包并阻止再次覆盖，正式目录的运行数据保持原位。详见[打包工具使用说明](../打包工具使用说明.md)第二十一项。
- FirepowerLoop 正式客户端位于 `Client/` 并保留 QFramework；客户端网络生成物与底层适配编译进既有 `Game.dll`，不引入 ET Unity Loader、View、Editor、EUI 或第二套 CodeLoader。

### 基线约束

- 游戏服务器业务只在 `Server/GameServer/` 内演进，不修改工作区外的上游 ET 源目录，也不以链接或绝对项目引用依赖外部源码。
- 基线固定为 ET8.1、`net8.0` 与 MemoryPack `1.10.0`。协议源位于根中立目录，客户端消息、服务端消息和双端共享消息由同一独立生成器产生；不得恢复两份协议源或手写两端消息结构。
- `Bin`、`Logs`、`obj` 与 `Unity/Library` 是生成或缓存目录，不作为服务端源码职责的一部分。
- 静态基线脚本只验证源码结构和必要文件，不依赖 Git/SVN，也不因开发机本地存在构建、日志或 Unity 缓存而失败；跨设备同步范围由同步清单控制。
- ET Demo、EUI 和原生网络组合只作第三方框架来源参考，不作为 FirepowerLoop 产品规则或新增玩法授权。

### 已实现的连接与身份职责

```text
Unity 客户端/测试客户端
    -> GameGate Session + GatePlayerProxy
    -> Account Fiber -> 本地身份仓库
    -> Player Fiber -> 唯一 Player Actor
    -> ET Location -> PlayerId 当前路由
```

- `GameGate` 只管理外部连接、鉴权白名单和轻量代理，不保存玩家档案权威副本。
- Unity 客户端以 TCP Transport 负责后台 Socket 与帧收发，`NetworkRuntime.Update()` 在主线程消费事件、完成 RPC 和分发推送；连接与账号操作分别使用 generation 隔离旧异步结果。
- `OnlineAccountSystem` 只依赖网络、部署配置与用户名偏好接口；注册成功后复用同一连接登录，完整登录成功才保存最后用户名。退出、远端断线和顶号都会清除本地认证，首版不自动重连或自动登录。
- `Account` 串行处理用户名规范化、密码校验、稳定 ID 分配、首次建档和档案检查点。仓库写入使用同目录临时文件、落盘刷新和替换；损坏 JSON、版本、ID 映射或密码材料在启动时失败，不静默重置。
- `Player` 以 Actor 邮箱串行处理连接 Epoch、顶号、断线宽限、主动退出和保存重试。旧连接、旧定时器和旧保存重试不能影响更高 Epoch 的新连接。
- `Location` 只维护 PlayerId 到当前 Player ActorId 的路由，不保存账号、在线状态或玩家档案字段。
- `Server/GameServer/Store/` 是被忽略的运行数据目录，不属于源码或同步产物；测试使用独立临时 Store 并精确清理。

### 本地完整协议日志

- 根提示符只接受 `netlog on`、`netlog off` 和 `netlog status`，命令名与动作不区分大小写；它们只通过本机启动器标准输入进入 ET Console，不存在客户端协议、远程管理入口或管理员账号权限链。
- `netlog on` 会把之后所有 Send/Receive 协议按统一 `[Protocol]` 格式同时写入当前服务器窗口和 Debug 文件。正文不脱敏、不截断，登录与注册消息中的密码会以原文留下；只应在隔离测试环境短时使用。
- `netlog off` 恢复敏感 opcode 过滤和原有普通 Debug 行为，但不会清理、轮转或覆盖已产生的明文记录。需要处置历史凭据时必须单独按运行环境的数据保留规则处理日志。
- 状态只存在于当前进程内并由线程安全开关持有；默认关闭，R 重启、异常后重启或重新启动发布包都会回到关闭。

### 已实现的 Room 职责与生命周期

```text
Unity Room UI
    -> GameGate 鉴权与 Player 路由
    -> Player Actor 当前 RoomId / Operation journal
    -> Room Directory RoomCode 路由
    -> Room Actor 成员、房主与 Revision 权威
```

- RoomCode 固定为排除易混淆字符的 6 位安全随机码；活动码、预留码和销毁后 10 分钟 Tombstone 共同避免并发冲突和立即复用。街机保持双人，容量由服务端单点裁定，协议与成员 UI 消费权威房间状态。
- 创建、加入和离开使用客户端 32 位小写十六进制 OperationId；服务端 Player Actor 保存有界幂等记录，客户端只在超时或普通断线重试时复用同一意图 ID。
- 成员 Snapshot 使用稳定 PlayerId、显示名快照、房主标志、连接状态和单调 JoinSequence；Room Actor 每次成员变化递增 MembershipRevision，客户端只接受当前 RoomId 的更新 Revision，并允许推送先于同 Revision RPC 到达。
- 房主主动离开或宽限超时后，优先选择最早加入的在线成员；没有在线成员时才从仍在宽限期的成员中选择。最后成员离开时先提交最终清空通知，再进入 Closing、注销 Location 并销毁；关闭中的 Room 拒绝新加入，并以 Tombstone 阻止 RoomCode 立即复用。
- 被动断线只改变 Room 成员连接状态，不立即移除。Player Actor 对 Room 同步失败保存唯一目标和 generation，每 5 秒单次排队重试；更高 SessionEpoch 替换旧目标。宽限内重连恢复同一 Room，主动退出账号或 60 秒超时执行真正离房；连续离房失败保持 Offlining 并继续重试，避免幽灵成员。
- Room 当前只存在于内存，服务器重启不恢复临时房间。Room Chat 与公开发现已由后续切片补齐；好友邀请和 Team 尚未实现。双人街机房间固定私有容量二，并由独立运行局存储在房间消失或服务器重启后按原玩家恢复安全节点。
