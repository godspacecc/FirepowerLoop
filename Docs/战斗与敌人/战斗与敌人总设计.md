# 战斗与敌人总设计

## 1. 已完成内容

### 单手冷兵器按用途区分动作（2026-10-14）

- 短刀 `weapon.knife`、战斧/精锻斧 `weapon.axe`/`weapon.han.axe`、战镐/精锻镐 `weapon.pickaxe`/`weapon.han.pick` 在共享武器目录中使用独立单次劈砍定义，复用钢刀第一刀的举起与挥落片段。短剑仍前刺，双手剑仍双手攻击，钢刀仍使用专属四段连击；不替换共用 `MeleeAttack` 或钢刀控制器。
- 普通单刀表现时长为 0.35 秒并预留收刀混合；街机读取原有实际攻击间隔，移动起手仅在新单刀定义下覆盖尚未结束的移动混合。只调整 Attack 播放速度，切装、受击、死亡及失活清理，单刀结束复位；不修改伤害、冷却、范围、命中次数、输入接受或原结算时刻。
- 变更沿既有普通战斗、采集表现、街机及远端共享目录入口生效；没有新增第一场冷兵器掉落、装备入口、连击输入或额外命中。
- 验证：Unity 编译检查通过；EditMode 的 `SingleMeleeAnimationTests` 14 项、`ArcadeMeleePresentationTests` 17 项、`WeaponInputAndMeleeTests` 26 项、`CharacterPresentationTests` 8 项，共 65 项通过，均核对类过滤和执行数量。五种目标武器使用正式配置检查立即单次命中、0.45 秒冷却及无自动续刀；钢刀原落刀时机和四段输入缓存检查通过。
- 正式人物与模型在隔离预览场景采样四段候选，并检查五种武器静止/移动攻击序列和短剑、双手剑对照。预览与结构化验证记录位于 `Client/Assets/Tests/Results~/SingleMeleeSlash/`；仅证明资源与 Animator 接线和采样表现，连续操控手感、移动端及远端实机画面仍待试玩。没有打包或提交。

### 钢刀点击连招

- 内容：钢刀使用 Mixamo 的 One Hand Sword Combo 挥砍动作。单击播放第一刀；攻击中继续点击只缓存下一刀，停止点击后完成当前刀并收刀。完整连招为四段，最后一刀结束后再次点击从第一刀开始。
- 职责：`WeaponSystem` 沿共享生命周期拥有段号、单次输入缓存、落刀结算和中断清理；运行时端口与 `PlayerView` 只执行已接受的段号和表现时长。换手、死亡、失活、地图离开或加载清除缓存，并保留剩余全局冷却。
- 接入范围：仅物品 34 的钢刀；原武器伤害、0.45 秒冷却、距离、角度和采集效率保持原配置。每刀对有效目标最多结算一次，离线在落刀点调用原近战结算，联机在段起手时沿原入口提交服务器裁决。
- 资源：正式资源位于 `Assets/Game/Art/Arcade/Weapons/Animations/`，来源和分段记录在该目录的 README；没有修改第三方备用资源。
- 验证：2026-10-11，EditMode 的 `WeaponInputAndMeleeTests` 21 个用例与 `CharacterPresentationTests` 8 个用例通过；生成正式角色离屏预览。游戏内手感、联机远端连招表现尚未实机验收。

### 世界伤害飘字

- 内容：玩家、敌人和联机单位受到实际伤害时，在单位头顶显示上浮并淡出的伤害数字。
- 目的：增强命中确认和战斗节奏反馈，不改变伤害、生命和死亡结算。
- 修改简介：
  - 离线表现读取 `CombatDamageAppliedEvent` 的实际扣血值；联机表现读取权威快照前后的 HP 差值，不预测客户端伤害。
  - 玩家受伤使用红色，敌人受伤使用金色；数字持续约 0.75 秒并向上漂移，多个数字使用轻微横向错位。
  - 玩家、近战敌人和弓箭手 Prefab 序列化引用同一个正式世界 HUD 飘字 Prefab；`DamageNumberEmitter` 独立管理实例池和回收，Controller 不创建重复 UI 元素。
- 完成时间：2026-09-16。

### 鼠标指向短剑战斗

- 内容：玩家使用鼠标左键按鼠标方向挥动当前短剑，以配置扇形攻击同地图内的全部有效敌人。
- 目的：替换 Space 自动选择最近敌人的旧入口，建立由正式武器装备驱动、无锁定的近战决策链。
- 修改简介：
  - `PlayerInputSystem` 发布携带水平朝向的 `PlayerAttackRequestedEvent`；本地第三人称额外携带同帧准星射线供远程射击使用。数字键 `1/2` 循环随身近战和投射武器，`H` 收起回到空手；Space 不再绑定攻击。
  - `WeaponSystem` 读取当前装备与 `TbWeapon`，使用单一全局武器冷却处理攻击；换手不能绕过剩余冷却。
  - 短剑读取 10 点伤害、0.45 秒冷却、2.2 米半径和 90 度总角度；一次挥击对扇形内每个敌人最多结算一次，不做锁定、最近目标选择或障碍遮挡。
  - 玩家在已接受攻击时立即朝向鼠标方向；`GrayboxPlayer` 根据当前手持显示短剑，并播放不参与命中判定的短暂挥击表现。
- 完成时间：2026-07-27 建立最小近战；2026-08-01 完成鼠标短剑替换。

### 空手徒手拳击

- 内容：玩家没有当前手持武器时使用自带拳头，并继续使用鼠标左键朝鼠标方向攻击。
- 目的：在武器发放和重新获取规则尚未建立时保留最小战斗能力，同时不把拳头伪装成物品或配置武器。
- 修改简介：
  - 徒手规则由独立只读定义保存，固定为 3 点伤害、0.6 秒冷却、1.4 米距离和 75 度总角度。
  - `WeaponSystem` 在手持引用为空时执行拳击，筛选同地图、活动、存活的敌对目标，只命中鼠标方向范围内最近的一个；等距时选择较小 UnitId。
  - 命中和挥空都复用玩家整体短暂缩放反馈并开始共享武器冷却；徒手不播放短剑挥动，不消耗弹药、体力或背包物品。
  - 短剑继续使用配置伤害、多目标扇形和短剑挥动，弓继续使用箭矢与投射物事务；切换拳头、短剑和弓不能绕过冷却。
- 完成时间：2026-08-03。

### 玩家弓箭、正式箭矢与直线投射物

- 内容：玩家装备基础弓后，使用鼠标左键按固定方向立即发射一支直线箭矢，并把箭矢作为背包中的正式消耗物。
- 目的：建立古代风格远程武器的最小完整链路，同时保持输入、库存、投射物和生命结算职责分离。
- 修改简介：
  - 基础弓读取正式武器和投射物配置；点击立即射击，不蓄力、不锁定、不追踪、不连射；箭矢先经换弹动作装入当前库存武器实例，射击只消费已装填弹药。
  - 本地第三人称与第一人称远程射击共用准星射线寻找最近有效目标，再从实际发射点朝三维目标发射；无命中时取射线远处目标，投射物保留垂直分量。自身 Collider 和非战斗 Trigger 不参与瞄准；目标在发射点后方时拒绝射击，不消耗弹药或启动冷却。角色转身、近战与俯视仍使用水平规则；玩家联机弓箭已通过三维协议接入服务器真实飞行。
  - 换弹完成时以背包事务移除正式箭矢并增加该库存武器实例的装填数；投射物创建失败不开始武器冷却，库存和装填状态保持一致。
  - ProjectileModel 与 ProjectileSystem 保存并推进非存档投射物运行态，按攻击者、阵营、MapInstanceId、碰撞和最大距离统一结束；有效命中复用 CombatSystem 显式伤害入口。
  - 撞击障碍或达到最大距离时，ProjectileSystem 仅在配置了回收掉落 ID 时请求生成可拾取弹药；空 ID 表示不回收。普通子弹与等离子弹不回收，箭矢保留回收；正常弹药掉落不受影响。命中玩家或敌人时不生成回收物，敌我与临时箭塔投射物共用该规则。
  - 单次回收掉落提交前向下探测场景地表，排除 Trigger 与运行根下的动态实体，再按拾取 Collider 底部落地；没有可探测地表时保留请求高度。不能把投射物飞行高度直接当成地面高度。
  - ProjectileCtrl 与 ProjectileView 参与地图准备、回滚、提交、停用和释放，只管理 Prefab、实例和碰撞转发，不保存权威伤害。
  - `GrayboxArrow` 由 Combat Prefab Collector 纳入 DefaultPackage；构建工具在打包前核对现用 Prefab 来源和 Collector，在打包后读取真实 Manifest 核对 Location 映射。
  - 异步资源加载 Handle 统一交由调用方释放；加载器失败回调不再提前释放同一 Handle。资源工具提供只重建完整内置资源的独立入口。
- 完成时间：2026-08-01 完成主体；2026-08-03 完成资源包与 Handle 返修复审。

### 弓箭手与生存地图固定敌群

- 内容：新增会保持距离、撤退并在明显预警后向捕获位置射箭的灰盒弓箭手；生存样例地图固定配置两组、每组 2 个近战敌人和 1 个弓箭手。
- 目的：在不引入行为树、波次、群体 AI 或对象池的前提下，建立近远程混合敌群和可躲避的敌方远程压力。
- 修改简介：
  - TbEnemy 以 `EnemyAttackKind` 区分近战和投射物攻击；`enemy.graybox.archer` 使用独立生命、伤害、警戒、攻击距离、撤退距离、预警、冷却、速度和投射物配置。
  - EnemySystem 继续集中更新所有敌人；弓手使用 Idle、Approach、HoldRange、Retreat、Telegraph 状态，预警开始时一次性捕获玩家位置，完成后从实际发射点向捕获位置发射敌方直线箭矢。
  - 撤退点必须形成有效的远离玩家位移；无法得到有效撤退点时原地进入预警，避免边界或障碍附近无限重试。
  - 地图停用、敌人死亡、注销或释放会取消未完成预警；暂停和普通 Loading 只冻结移动、预警与冷却，不产生晚到攻击。
  - 敌箭复用 ProjectileSystem、玩家 Collider 解析和 CombatSystem 显式伤害入口，不消耗玩家背包箭矢、不追踪、不预测，同一箭只结算一次命中。
  - GrayboxArcher Prefab 提供独立造型、弓、发射点和默认隐藏的预警表现；表现端口不保存目标、伤害、冷却或生命权威。
- 完成时间：2026-08-04。

### 弓箭手有限弹药、连续命中与保底掉落

- 内容：弓箭手每次战斗固定拥有 10 发箭，耗尽后以同一单位切换近战；敌人死亡原子地产生保底武器、弓手剩余弹药和既有额外掉落。
- 目的：让敌方箭矢稳定伤害玩家，并为短剑、弓和箭矢建立可重复获取的正式世界来源。
- 修改简介：
  - `EnemySystem` 保存当前地图实例内的弓手弹药；只有投射物创建成功才扣除一发，0 发时复用近战伤害与冷却，只有有效玩家离开警戒范围并使弓手回到 Idle 时补满。
  - `ProjectileSystem` 在提交本帧位移前按距离处理连续碰撞候选；同阵营单位被忽略，敌对目标继续通过 `CombatSystem` 的统一入口结算一次伤害，障碍可在目标之前结束投射物。
  - `EnemyDropSystem` 对每个敌人死亡只形成一次固定顺序批次：保底武器、弓手非零剩余箭矢、既有额外掉落。普通敌人保底短剑，弓箭手保底弓。
  - `LootCtrl` 在候选地图阶段按 Prefab 地址共享加载和唯一有效 Handle，同时按 LootConfigId 保留物品与数量身份；批次先隐藏创建并顺序登记，全部成功后统一显示，任一失败反向清理 Unit、Loot 和表现且不重放死亡。
- 完成时间：2026-08-10。

### 能量耗尽伤害与统一失败链

- 内容：能量归零后通过统一玩家环境伤害入口持续扣除生命。
- 目的：让生存压力复用现有生命权威、受击反馈、死亡事件和远征失败返回，不建立第二套死亡流程。
- 修改简介：
  - CombatSystem 提供玩家环境伤害入口，只修改 CombatModel 中存活玩家的生命。
  - 成功伤害发布既有生命变化、播放受击反馈并标记玩家生命存档脏。
  - 首次降到 0 时以无攻击者身份发布一次 CombatantDiedEvent；死亡后的重复请求不会重复发布。
  - PlayerConditionSystem 负责按能量归零后的真实时长计算伤害，并在大跨度结算中把远征时间裁剪到死亡发生时刻。
- 完成时间：2026-08-01。

### 敌人生命与 NavMesh 行为

- 内容：灰盒敌人具有生命、警觉、追踪、攻击和死亡状态。
- 目的：建立不依赖大型行为树的最小普通敌人。
- 修改简介：
  - CombatSystem 保存敌人权威生命和死亡状态。
  - EnemySystem 维护活动敌人稳定集合，并解析 Idle、Chase、Attack 意图。
  - Chase 使用 NavMeshAgent.SetDestination() 追踪玩家；Attack 停止移动并按冷却伤害玩家。
  - 暂停、加载、远征失败或缺少玩家时停止敌人行动。
  - SurvivalSampleMap 和 TaskSampleMap 均具有烘焙 NavMesh 和配置好的敌人 Agent。
- 完成时间：2026-07-27。

### 战斗事件与职责拆分

- 内容：使用最小事件连接输入、伤害结果、任务、掉落和失败流程。
- 目的：避免战斗系统直接操作地图、库存和远征事务。
- 修改简介：
  - PlayerAttackRequestedEvent 携带玩家鼠标瞄准方向，只表示一次攻击意图。
  - WeaponSystem 负责当前武器、冷却与具体攻击执行；CombatSystem 只统一校验并结算生命伤害。
  - CombatHealthChangedEvent 表示玩家或敌人的生命变化结果。
  - CombatantDiedEvent 只携带死亡单位和击杀者身份，由 ExpeditionSystem、EnemyDropSystem 和 CombatFlowSystem 分别处理任务、掉落和玩家失败返回；同一死亡只发布一次。
  - CombatSystem 不读取键盘、不驱动敌人移动、不直接修改库存、不推进任务、不切换地图。
- 完成时间：2026-07-27。

### 玩家生命与失败流程

- 内容：玩家受伤、归零、基地恢复和失败返回使用统一生命模型。
- 目的：保证战斗死亡与存档、地图和远征状态一致。
- 修改简介：
  - CombatModel 统一保存玩家和敌人的生命、攻击力、目标和死亡状态；UnitModel 不保存战斗数据。
  - 玩家最大生命、攻击力、攻击范围、冷却和基地恢复速度来自 TbPlayer。
  - 生命归零事件防止重复发布；生命恢复为正数后允许下一次死亡。
  - CombatFlowSystem 将活动远征标记为 Defeated，并以 `UniTask` 调用既有失败返回流程，不保留 `async void` 死亡处理入口。
  - 状态通知异常单独记录后继续返回；业务失败和意外异常都通过 `finally` 复位死亡返回防重状态，意外异常保留类型与消息诊断。
  - CombatFlowSystem 不自动重试或重复执行背包、装备和地图回滚；仍为 Defeated 时继续使用现有远征 HUD 重试入口。
  - 失败返回不提交临时物资；加载失败时保留失败状态并允许重试。
- 完成时间：2026-07-27；死亡异步异常边界于 2026-08-11 收口。

### 急救包治疗与死亡背包隔离

- 内容：有效远征中的存活玩家可以使用急救包恢复 `CombatModel` 生命；死亡返回只清空玩家背包。
- 目的：让治疗物品复用统一生命入口，并保持战斗、物品和仓库职责分离。
- 修改简介：
  - `CombatSystem.TryRestorePlayerHealth` 拒绝非正数、死亡、满生命和无实际恢复，并发布既有生命变化与存档标脏。
  - `InventorySystem` 读取急救包配置，只有实际恢复生命后才扣除一个物品；失败恢复背包快照。
  - 玩家死亡后立即禁止继续拾取和使用；基地加载成功后清空背包，仓库逐格不变。
  - `UnitModel` 不保存生命、治疗量或物品使用结果。
- 完成时间：2026-07-31。

### 战斗世界信息与反馈

- 内容：玩家生命由屏幕 HUD 展示，敌人保留头顶生命条；敌人受击和玩家受击具有最小颜色反馈。
- 目的：在灰盒资源阶段提供必要战斗可读性。
- 修改简介：
  - 玩家生命条始终显示绿色填充。
  - 敌人满血且未警戒时隐藏红色生命条；进入警戒或受伤后显示。
  - 敌人生命恢复满且退出警戒后隐藏生命条。
  - 生命条朝向由现有系统集中更新，不增加独立逐帧 HUD MonoBehaviour。
  - 玩家和敌人生命填充共用关闭深度测试的 World HUD 材质；显示中的生命条不会被角色、地形或墙体遮挡，既有 World Space Canvas、位置和显隐条件不变。
- 完成时间：2026-07-27 建立战斗世界信息；2026-08-04 完成生命条置顶材质接线。

### 敌人实体掉落

- 内容：敌人死亡事件在死亡位置生成一个测试物资拾取物。
- 目的：让击杀结果通过场景实体进入远征物资，而不是直接增加库存。
- 修改简介：
  - EnemyDropSystem 从死亡时仍有效的 Enemy Unit 和 TbEnemy 取得 MapInstanceId、位置与 LootConfigId，并发布掉落请求。
  - LootCtrl 使用 TbLoot 和已提交 Prefab 缓存创建运行时拾取物；数量不由战斗事件或 View 携带。
  - 去重规则保证同一敌人死亡事件不会重复生成掉落。
  - 实际收集由 LootSystem 校验，库存仍只在拾取成功后增加远征临时物资。
- 完成时间：2026-07-27；配置驱动实体创建于 2026-07-31 完成。

### 配置驱动的动态敌人和统一伤害

- 内容：敌人按照地图生成记录和敌人配置动态创建，玩家与敌人共用统一伤害入口。
- 目的：删除场景预摆敌人和 View 中的玩法权威值，使敌人生命周期能够参与地图准备、回滚和释放事务。
- 修改简介：
  - EnemyCtrl 在候选地图的 RuntimeUnitRoot 下创建隐藏敌人，提交时依次登记 Unit、Combat 和 AI 状态。
  - 敌人 Prefab、生命、攻击、警戒距离、攻击距离、冷却、速度和掉落配置均来自 TbEnemy。
  - CombatSystem 统一校验攻击双方的 Unit、活动状态、MapInstanceId、阵营和死亡状态；伤害值只从攻击者 Combatant 读取。
  - 敌人死亡时先保留 Unit 与 Combatant 供任务和掉落规则读取，下一次更新才释放领域状态和表现。
  - SurvivalSampleMap 与 TaskSampleMap 已删除预摆 EnemyView，MapContext 不再保存敌人数组。
- 完成时间：2026-07-30。

### 显式武器伤害入口

- 内容：统一伤害结算支持由武器明确提供本次伤害值，同时保留基础敌人按 Combatant 攻击力造成伤害的旧入口。
- 目的：让不同武器共享生命、死亡、掉落和任务链，而不把武器数值重新写入玩家 Combatant。
- 修改简介：
  - `CombatSystem.TryDamage(attackerUnitId, targetUnitId, damage)` 校验正伤害、双方活动 Unit、存活 Combatant、敌对阵营和相同有效 `MapInstanceId`。
  - 旧双参数入口从攻击者 Combatant 读取 `AttackDamage` 后委托显式入口，基础近战敌人的调用方式保持不变。
  - 武器执行系统不能直接写 `CombatModel` 生命；成功伤害继续发布既有伤害、生命变化和死亡事件。
- 完成时间：2026-08-01。

### 地图卸载销毁态安全

- 内容：地图场景对象先于控制器销毁时，敌人、掉落物和撤离点表现访问、敌人停止与 Collider 映射释放仍能安全收口。
- 目的：保留地图卸载失败恢复顺序，同时避免 Unity 已销毁对象在控制器释放前的一帧窗口中触发 `MissingReferenceException` 或残留 Collider 映射。
- 修改简介：
  - `EnemyViewCtrl`、`LootViewCtrl` 和 `ExtractionViewCtrl` 统一以 Unity 对象语义取得存活 View；销毁态公开表现调用变为安全空操作，位置、旋转和有效性返回稳定默认值。
  - 三个 ViewCtrl 的释放先清空字段并注销 Registry，只对仍存活的 View 执行事件解绑和实例释放，重复调用保持幂等。
  - `EnemySystem.StopAll` 只停止仍有效的导航端口，已销毁敌人表现对应的端口等待地图控制器完成领域注销。
  - `EnemyCtrl` 能以原引用移除 Unity 已销毁 Collider，并在整图释放后统一清空 Collider 映射。
  - 地图事务仍保持停用旧地图、卸载场景、反向释放控制器的既有顺序；LifeCycle 异常策略和 View 内部逻辑未改变。
- 完成时间：2026-08-03。

## 3. 总体设计说明

### 3.1 目标

- 保持少量明确武器类型、少量普通敌人类型和清晰的伤害反馈。
- 战斗规则、敌人驱动、远征失败、任务推进和库存掉落彼此解耦。
- 使用稳定集合与事件更新，避免战斗帧中的场景搜索和稳定临时集合分配。
- 灰盒阶段优先保证玩法可读性和失败可恢复性。

### 3.2 系统边界

- CombatSystem
  - 统一校验攻击双方和显式伤害，管理环境伤害、基地恢复、生命变化和死亡判定。
  - 发布战斗结果事件。
- WeaponSystem
  - 读取当前装备和武器配置，维护玩家全局武器冷却并执行具体武器攻击规则；空手使用独立徒手规则。
  - 当前实现拳头最近单目标、短剑多目标扇形和弓箭创建；弓箭消费通过背包快照事务提交，不保存生命，不直接操作地图事务。
- ProjectileModel / ProjectileSystem
  - 保存并推进非存档投射物运行态，按地图实例、阵营和碰撞类型统一结束。
  - 有效命中只调用 CombatSystem 显式伤害入口，不直接写生命或奖励。
- ProjectileCtrl / ProjectileView
  - 分离当前地图与候选地图资源所有权，参与地图准备、回滚、提交、停用和释放事务。
  - 只管理 Prefab、实例、姿态和碰撞转发，不保存阵营与伤害结论。
- EnemySystem
  - 只保存导航端口和 AI 运行状态，解析行为意图并驱动 NavMeshAgent。
  - 基础近战敌人使用 Idle、Chase、Attack；投射物敌人使用 Approach、HoldRange、Retreat、Telegraph，并通过 ProjectileSystem 发起敌方远程攻击。
  - 按配置冷却向 CombatSystem 或 ProjectileSystem 发起统一攻击请求，不保存生命与奖励。
  - 世界状态阻断时只停止仍有效的导航端口；无效端口等待所属地图控制器完成领域注销。
- EnemyCtrl
  - 按地图生成记录和 TbEnemy 准备、提交、停用、恢复并释放动态敌人。
  - 候选提交前校验全部敌人出生位置的 NavMesh 可用性；提交期任一 Unit、Combatant 或 AI 注册失败时反向清理本批已登记领域与表现。
  - 负责受击、警戒、生命条和死亡表现，不保存权威生命。
  - 负责 Collider 到敌人 Unit 的运行时映射，并在逐项注销和整图释放时清除映射，包括 Unity 已销毁 Collider。
- EnemyView
  - 持有 Collider、NavMeshAgent、Renderer、生命条、可选投射物发射点和预警表现引用。
  - 只执行移动、停止、NavMesh 采样、预警显隐、受击、死亡和生命条直接表现。
- CombatFlowSystem
  - 把玩家死亡事件转换为远征失败与返回事务，并维护死亡返回防重状态。
  - 隔离 Defeated 状态通知异常；正常结果保留既有成功与业务失败语义，意外异常只记录诊断和复位自身防重状态，不承担第二套领域回滚或自动重试。
- EnemyDropSystem
  - 从死亡时仍有效的 Enemy Unit、配置和弓手弹药快照取得地图、位置及掉落身份，并发布一次原子掉落批次。
  - 对同一敌人死亡去重；批次失败保持已处理，不自动重放或复制掉落。
- ExpeditionSystem
  - 根据去重后的敌人死亡事件推进任务目标。

### 3.3 战斗链路

    鼠标左键与鼠标 XZ 方向
      -> PlayerInputSystem
      -> PlayerAttackRequestedEvent
      -> WeaponSystem 校验当前武器与全局冷却
      -> 短剑：扇形筛选同地图存活敌人
      -> 弓：原子消费一支箭并创建固定方向投射物
      -> CombatSystem 显式伤害入口扣除敌人生命
      -> CombatantDiedEvent
           -> ExpeditionSystem 推进任务击杀
           -> EnemyDropSystem 发布配置驱动的掉落请求
    
    EnemySystem
      -> 近战：Idle / Chase / Attack -> CombatSystem.TryDamage
      -> 弓手：Approach / HoldRange / Retreat / Telegraph
      -> ProjectileSystem 创建指向预警捕获位置的敌方箭矢
      -> CombatSystem 显式伤害入口
      -> CombatModel
      -> CombatantDiedEvent
      -> CombatFlowSystem
      -> Defeated 与失败返回基地
    
    能量归零后的持续时间
      -> PlayerConditionSystem 计算环境伤害
      -> CombatSystem 修改玩家 Combatant 与生命
      -> CombatantDiedEvent(killerUnitId = 0)
      -> CombatFlowSystem
      -> Defeated 与失败返回基地

### 3.4 长期原则

- View 不保存权威战斗生命。
- UnitModel 只保存共同身份和空间状态，不保存生命、攻击力或其它战斗数据。
- CombatSystem 不直接操作库存、任务进度或地图事务。
- 玩家武器输入、攻击执行与生命结算分层；输入不选目标，WeaponSystem 不直接写生命。
- 敌人驱动不放入 CombatSystem。
- 敌人死亡、任务推进和实体掉落通过事件连接，并分别去重。
- 第一版敌人行为保持少量显式状态：近战使用 Idle、Chase、Attack，弓手增加 Approach、HoldRange、Retreat、Telegraph；不提前建设行为树或大型群体 AI 框架。
- 没有正式模型和动画时继续使用简单模型、颜色和缩放反馈。
- 玩家生命条、玩家体力圆环和敌人生命条共用唯一 World HUD 置顶材质；即使单位位于墙体或地形后方，满足现有显示条件的生命条仍保持可见。
