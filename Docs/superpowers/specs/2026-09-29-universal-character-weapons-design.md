# 五人物通用武器与动作设计

## 目标与范围

造型库当前的五个人物（`GrayboxPlayer`、`ArcadeEnemyBasic`、`ArcadeEnemyBrute`、`ArcadeEnemyArcher`、`ArcadeEnemyBossArcher`）均可选择本次目录内的每把武器。同一把武器在五个人物身上使用同一组 Humanoid 待机、移动、攻击片段；角色只允许有骨架和手部挂点校准，不允许另选一套角色专用的武器动作。造型库选择与正式战斗读取相同的武器表现定义，不再区分“原配”和“试装”。

正式战斗沿用现有入口：玩家由装备/街机武器选择决定当前武器，敌人由生成配置决定；不加入战斗中拾取或切换武器的新操作。范围覆盖这五个人物参与的街机和普通地图战斗。受击、死亡、移动控制、敌我阵营、资源 Handle、掉落与存档遵守各自现有权威边界。

## 当前实现与问题

- 造型库从 `AppearanceGallery.unity` 引用上述五个 Prefab。玩家的七把街机武器来自 `GrayboxPlayer` 内置子物体，弓另按 `TbWeaponAppearance` 创建；敌人试装从 `EnemyWeaponVisualCatalog` 取三种近战网格和玩家武器子物体。
- 玩家姿态由 `PlayerViewCtrl.ResolveGripPose` 按资源名分手枪、步枪、无专用动作三类；`PlayerView` 绑右手挂点、设置枪身旋转并在动画后修正双手。弓通过 `AnimatorOverrideController` 替换基础片段。
- 敌人动作来自各自 Controller 和配置的 `AttackKind`，`EnemyView.SetWeaponPresentation` 只切换可见模型，不改变攻击动作及规则。重装敌人有七份玩家武器局部姿态，其余敌人退回玩家右手姿态。
- 普通地图玩家正式 `TbWeapon` 目前只有短剑与弓；街机七把枪另由 `TbArcadeWeapon` 定义。三种敌人近战试装网格尚无正式武器身份和战斗配置。因此不能靠调整 Transform 就宣称所有组合在正式战斗中可用。

## 本次武器集合

以造型库现有可见资源闭合武器集合：短剑、弓、敌方双手剑、短刀、战斧、战镐，以及街机手枪、步枪、穿透枪、手榴弹、火箭筒、科幻霰弹枪、科幻等离子步枪，共十三种。敌方基础剑映射到短剑、弓手原有弓映射到弓；不同外观若实际不是同一件资源，在资源核对时纳入相应武器身份，而不能隐藏在“原配”选项里。没有武器是独立的徒手状态，不计入十三种。

## 设计

### 武器身份和表现

建立一份项目自有的武器表现目录，以稳定武器 ID 为键，引用已进入 `Assets/Game` 的可见武器 Prefab、Humanoid 动画组（待机、移动、攻击）、主手握点、副手目标、枪口或投射物发射点、武器轴向和缩放。每个武器 ID 必须有完整三段动作；不同武器可以显式引用同一片段，但不得由角色 Prefab 隐式决定动作。第三方 `Assets/Art` 只用于筛选候选，正式引用复制必要资源与 `.meta` 到 `Assets/Game`，不改原包。

五个人物使用各自 Avatar 重定向同一组片段。各人物的持握适配只记录骨架坐标与挂点差异；每把武器自身只记录一次规范握点。若单靠规范握点不能让某个组合对齐，记录该组合的最小局部偏移及原因，仍保持相同动画片段。装配顺序固定为：角色 Animator 求值 → 主手挂载武器 → 枪身/刀身规范轴向 → 副手约束（适用时）→ 发射点/特效。失去 Avatar、骨骼、动作或武器资源时，该组合报告错误并保持无武器表现，不退回另一人物的姿态。

造型库提供十三种武器的同一顺序选项；“无武器”仅用于观察徒手。选择武器时呈现该武器的待机、移动、攻击和必要的受击/死亡预览，攻击时调用与正式战斗相同的表现入口。去掉“原配”“仅试装”“不会开枪”等语义；预览不修改角色装备、存档或战斗状态。

### 正式战斗规则

表现目录不持有权威伤害、冷却、弹药、目标和阵营。普通地图的 `WeaponSystem`/`EnemySystem` 与街机的 `ArcadeCombatSystem` 仍管理各自模式的规则，但从当前武器身份选择攻击方式，并把武器身份及动作事件交给对应 View。敌人使用枪时按该枪规则发出敌对投射物；使用近战武器时按对应近战规则结算；玩家同理使用现有装备入口。角色本身不再固定决定“只能近战”或“只能射箭”。

现有短剑、弓、七把街机枪保持已有战斗数值与消耗规则。短刀、战斧、战镐和双手剑新增正式武器定义，首版复用短剑的近战数值与已有物品/装备事务，之后再独立平衡。普通地图新增枪械身份时沿用现有远程槽和投射物/弹药事务；枪械弹药物品、容量、来源及持有规则必须与武器一起配置、验证，不允许使用无限弹药作为隐式默认。敌人的武器由敌人配置或生成参数指定，保留现有初始敌群的武器和攻击数值，故默认关卡节奏不因目录改造而改变。街机初始敌群同理保留默认武器，只有配置明确选择其他武器时才改变行为。

配置源位于 `Config/Defines` 与 `Config/DataCsv`；需要变更表结构时使用唯一生成入口 `Config/gen.bat`，不手改生成文件或 `.bytes`。玩家、敌人和街机通过稳定 ID 关联表现目录，加载时验证缺失资源、非法武器类别、无对应动画、缺弹药或错误的发射点。

## 备选方案与取舍

1. **推荐：武器驱动的共享目录。** 动作和握点按武器集中维护，各角色只做骨架校准；投入较大，但造型库与两类正式战斗能够保持一致。
2. **五个角色分别维护十三套覆盖。** 初期可少改规则入口，但同一武器有五份配置，容易再次出现各人动作和旋转不一致，不满足长期目标。
3. **仅统一可见模型和 Animator。** 可改善截图，却仍让敌人拿枪挥剑、让枪口与权威攻击脱节，不满足正式战斗要求。

## 实施边界与验收

按依赖顺序实施：确认十三种资源与动作来源；建立稳定武器身份和表现目录；将五人物挂载/动画入口接入；统一造型库；接入普通地图与街机的武器规则；最后逐组合验证。现有用户工作区改动必须保留，不顺手修改无关资源。核心类、关键函数与重要字段补充简洁中文注释。

验收矩阵为五人物 × 十三武器，分别检查待机、移动、攻击，共 195 个组合状态；双手武器检查双手接触，投射武器检查枪口/发射点方向及实际弹道，近战检查可见挥动与规则命中方向。造型库与正式战斗要抽样比较同一人物/武器/动作的姿态；默认关卡和默认敌群的行为要回归。自动化只运行已确认的短类名或完整方法过滤的 Unity 测试，声明最大数量并审核返回范围；画面准确度以逐组合视觉检查为准，不以测试通过代替。不得触发 Player Build 或打包。
