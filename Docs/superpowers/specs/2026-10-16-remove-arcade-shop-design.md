# 单人及双人商店功能清理设计

## 目标与范围

依据用户 2026-10-16 的要求，彻底移除单人和双人街机的商店功能，保留必要的恢复、结算和准备流程，不影响现有强化道具。此次只修改 FirepowerLoop，不提交、不推送、不触发 Unity 打包或 Player Build。

此变更涉及客户端、服务端、配置、协议及存档契约，属于结构清理。用户要求保留资源和 .meta，因此商店美术与 Prefab 资源保留为未接入资源；“彻底清理”指产品运行链路、业务接口和商品数据不再提供商店能力，不以删除美术资源为验收条件。

## 已核实的依赖

- `ArcadeRunSystem` 普通开局生成空报价节点，但仍保留报价生成和购买 API。
- `ArcadeHudUICtrl` 空报价时直接继续，胜利仍可打开 `ArcadeShopUICtrl`。
- `ArcadeShopUICtrl` 同时处理商品购买、金币转移、继续、挑战、结算、放弃及双人准备。
- 单人存档仍有 `Shop`、报价、已购强化等字段；`SafeShop` 阶段用于安全节点。
- 服务端 `OnlineArcadeRunSystem` 仍有商品生成、购买、转账、补生命商品及商品快照逻辑，准备与结算也通过安全阶段操作进入。
- 战斗中的 `arcade_powerup` 强化道具与 `arcade_upgrade` 商店属性升级是两套不同规则。支援视觉还有对商店商品定义的读取，不能直接删表后留下依赖。

## 方案比较与选择

1. 仅禁用界面：改动少，但购买接口、商品表和旧流程继续存在，不满足本次要求。
2. 删除交易能力，将恢复、准备和结算迁至明确的安全节点流程：覆盖双端，职责清楚，采用此方案。
3. 重写整个街机状态机：影响过大，不属于此次清理范围。

## 单人流程

- 安全节点以恢复目的地、挑战尝试状态和对局快照表达，不再以商品数量决定能否继续。
- 普通开局及场间按现有规则直接继续；地图加载或保存失败保留可重试节点。
- 继续、结果结算、结算重试、主动放弃迁移至独立的对局流程控制器，移除对商店控制器的调用。
- 挑战进入与返回保留现有事务边界，移除“挑战胜利购物”依赖。
- 删除商品生成、购买、价格、购买次数和商店专属属性升级入口。

## 双人流程

- 使用明确的安全准备阶段承载 ready、取消 ready、挑战准备、双方结算确认和放弃确认。
- 保留修订号校验、成员身份校验、权威保存先于公开状态、失败重试、断线恢复及重复请求幂等规则。
- 删除购买、金币转移、补售生命和报价刷新逻辑；零生命玩家的处理遵循既有失败及观战规则，不再等待购买复活商品。
- 同步移除客户端商品快照和服务端商品记录、请求及处理分支；必要准备请求从商店命名中拆出。
- 协议只修改权威源并运行 `Tools/gen-protocol.ps1`；配置只修改 `Config` 权威源并运行 `Config/gen.bat`。

## 数据与旧局处理

- 保留本项目现有对局的分数、生命、炸弹、冲刺、地图进度、结果和恢复边界。
- 旧存档商品报价不再恢复或执行；仅在确实需要时保留单向读取兼容，兼容层不得注册购买接口或依赖商品表。
- 旧局已经持有的装备和属性效果不在此次清理中静默扣除。需要保留的效果转换为中性的对局状态，不能继续依赖商品身份解析；不添加新的获取入口。
- 不读取、迁移或导入 AnotherDay 数据，不新增局外钱包。
- 商品表删除前逐项处理装备、支援视觉等非交易使用者，将必要数据放回其现有业务权威源，避免为了保留表现留下商品表。

## 强化道具保护

- 保留 `arcade_powerup` 配置、拾取入口、单人结算和服务端权威行为。
- 保留效果时长、次数、周期、同类刷新、不同类型并存、锚点与区域隔离规则。
- 保留地图切换和恢复期间现有的效果继承及视觉重建。
- 不因移除商店而新增、删除或调整道具掉落权重、数值、临时武器获取方式。

## UI、资源与文档

- 从现有正式 UI 生成流程建立必要的准备及结果界面；新组件和资源引用必须配有 .meta。
- 旧商店 Prefab 和美术按用户要求保留，但解除业务入口；不手改生成 View。
- 清理交易专用本地化、格式化逻辑、音效调用和测试契约。必要流程使用恢复、准备和结果命名。
- 当前文档标记旧商店方案已被此次决定取代；历史记录保留，不能再充当实施要求。

## 验证与完成条件

- 静态核对生产代码中没有可调用购买、转账、报价生成或商品发放入口；残留商店命名仅允许存在于明确标记的旧局读取兼容或保留资源中。
- 单人验证新局、普通继续、节点恢复、保存失败、胜利/失败结果、结算重试和放弃。
- 双人验证准备/取消准备、挑战返回、断线恢复、过期修订号、双方结算与放弃、零生命玩家流程。
- 强化道具验证拾取、同类刷新、并存、到期、次数及换图继承，覆盖单人与服务器。
- 只执行真实存在的定向测试类或完整方法名，每次预先声明范围及最大数量，`includePassingTests=true`；不得完整套件或无效过滤回退。
- 当前会话未提供 Unity MCP。可先完成源码和独立检查；涉及场景、Console、UI 生成和反序列化验证时需恢复可用连接，并先确认项目为 `E:/GitHub/FirepowerLoop/Client`。不把静态检查当作编辑器或双客户端实玩通过。

## 执行顺序

1. 列出生产调用、配置及协议依赖，并固定恢复、结算、准备和道具回归范围。
2. 拆出必要单人与双人流程及 UI，再移除交易业务。
3. 清理契约与权威配置/协议源，执行正式生成，处理旧局读取兼容。
4. 更新定向验证与当前文档，完成编译、回归和残留扫描。
