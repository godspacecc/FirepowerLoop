# 第二代前三场替换设计

用户已要求保留第一场海岛，将实际第二、三场换成二代码头与农场；2026-10-21进一步明确：巴比伦、弹幕林地、墓园和雪镇保留资源与配置，暂时不接入主线。

## 玩家看到的变化

- 第一场海岛保持现有内容。
- 第二场（累计5—8轮）为码头，水边来敌；载桶敌人、会吞物资的漩涡桶与电塔在同一个场地出现。第5轮突出载桶敌人的威胁，其余轮继续普通战斗，不再叠加旧巴比伦的护甲、破坏箱或固定军械库。
- 第三场（累计9—12轮）为农场，开放移动空间，围栏、草堆和建筑作为局部阻挡。第9轮突出牛群冲撞，牛能撞击玩家和僵尸。牛冲撞采用可识别预警和方向锁定，玩家可以侧向躲开，正式伤害仍经过护盾、冲刺和无敌保护。
- 第11轮清场后插入车辆竞速，包含行驶、转弯、撞僵尸和沿路收集；结束或超时后返回农场第12轮。这个插入区域不增加主线累计轮数，不引入局外奖励。竞速结果、奖励与返回以一次提交处理，不重复发放。
- 农场第12轮后接回原第四场巨石环阵，后段顺序不变，每局仍为10场40轮。

二代内容依据[关卡与流程对照](../../参考游戏/DeadOpsArcade2关卡与流程对照.md)所列路线与小游戏来源，并使用用户提供的[单人实录](https://www.bilibili.com/video/BV1t4411e7wD/)核对画面。05:21为码头挑战轮：主体是宽阔木板平台，边缘有吊架、箱体及泊船，右侧有水槽；11:27与12:08显示农场的浅色积雪地表、草料堆、树木、围栏和成群牛；16:21为岩壁、轮胎护栏及坡台组成的土路竞速区域；18:18已回到积雪场景，实录当时处于临时第一人称。视频画面用于确定场景结构，不从画面推算敌人数、速度或伤害值。

据此撤销第一版预览的大面积码头泥地、草地红谷仓和草地椭圆赛道。码头以连续木板平台为主；农场以浅色积雪地面和局部草料堆、围栏为主，第9轮突出成群穿场的牛；竞速以岩壁和轮胎夹道、转弯及坡台为主。黄色牛群预警是本项目提出的可读性提示，折返赛道是临时结构示意，均不声称为原版画面或完整测绘。

## 路线和原主题保留

现有1—20主题不重编号，不覆盖旧主题内容。追加21号码头和22号农场，新局改为1→21→22→5；2、3、4、15原配置、布局ID、版本、资源与旧后继保留。新增8张轮级布局，目录共88张，本局仍只经过40个普通轮。

新主题ID仅标识地图；血量成长、敌人总量、掉落开放进度继续使用实际第2／3场。新增主题不开放原有后期清场收益，也不继承旧第二场固定军械库。旧主题存档恢复时使用原主题与原后继，不被替换成新关卡。

## 实施接线

1. 配置权威源在 `Config/DataCsv/arcade_arena.csv`、`arcade_round_layout.csv` 及必要的新牛群／竞速参数定义；全部通过 `Config/gen.bat`双端生成，更新配置指纹。
2. 调整 `ArcadeRunFileStore` 的主题编号上限，保留恢复时的目录身份与布局版本校验。原存档规则分支保留，联机旧指纹只做明确版本的有限迁移。
3. 在既有轮级内容规则与单双人权威System中增加牛群活动、扫掠命中和回收；View只读取状态，不裁决伤害。暂停、加载、切轮和奖励区域冻结活动，轮前恢复不保存半次冲撞。
4. 竞速作为独立活动阶段，使用现有输入与权威帧入口；单人和双人使用同一轨迹／收集规则。地图代次隔离输入，返回不重复加资源或奖励。规则1局与原商店节点的先后要显式处理，不能同时进入两个活动区域。
5. 视觉确认后接入docks／farm主题表现、正式牛和车辆。仅采用已确认资源，不整体引入第三方驾驶系统。
6. 定向验证新路线可达和40轮长度、旧四主题新局不可达／旧档可恢复、第三轮清场与军械库隔离、牛冲撞保护与敌人结算、竞速超时和重复返回、双人同步与加载冻结。使用真实短testClass或完整testMethod，声明范围和最大数量，includePassingTests=true，不运行完整套件或Player Build。
