# 存档与开始流程总设计

## 1. 已完成内容

### 基地昼夜时刻跨启动保存（2026-10-14）

- 基地昼夜时刻由 `BaseDayNightModel` 持有，作为 `another-day.base-day-night` 基地专属分区进入现有增量存档；仅保存一天内的游戏分钟，不保存 Unity 对象，也不补算关闭期间的现实时间。
- `DayNightVisualSystem` 沿用共享生命周期和原推进条件，每游戏分钟标脏。正常退出和应用挂起时强制标脏并刷新，保存自动存档后不足一个游戏分钟的精确变化；保存失败沿用既有脏状态重试，不假装成功。
- 正式基地读档恢复上次保存时刻；旧档缺少该分区时兼容为原默认正午。新建游戏写入默认时刻，避免继承同会话内另一份存档的时间。远征时刻恢复、新远征早晨出发、基地恢复结算及联机昼夜规则保持原实现。
- 验证：Unity 脚本编译检查通过；EditMode `DayNightVisualTests` 实际执行 27 项，全部通过，覆盖真实写盘与跨架构正式读档、旧档缺失分区、新游戏、挂起保存小数分钟、非法时刻和原昼夜行为，已核对执行范围。
- 邻接验证：`ExpeditionClockTests` 实际执行 10 项，9 项通过，`LegacySave_RestoresZeroStart` 失败。该未修改测试仍构造版本 3 副本存档，而未修改的现行恢复入口要求版本 4；此失败不作为验收通过证据。本轮没有扩展旧副本文件兼容范围。
- 未执行打包或提交；实际玩家关闭并重开后的画面验收仍待试玩，自动化检查不代替画面验收。

### 单一手持分区与旧库存迁移

- 当前手持分区 `schemaVersion=1` 只保存随身容器、格号与物品 ID；弹匣数量保存于库存格。载入候选交叉校验实际来源，恢复后重绑库存实例。
- 已支持本地存档里的旧双武器槽子分区迁移，属于当前存储格式内部的业务数据迁移，不扩展旧存储文件格式支持范围。旧武器和已装弹药归回背包，满格时最小追加容量，原候选不变，重复迁移幂等。
- 联机账号库从 schema 2 迁移到 schema 3，先构造并校验候选，再原子提交；异常不覆盖原文件。新版库存操作携带协议版本、来源物品 ID、预期库存版本及生命周期，拒绝旧客户端操作。
- 完成时间：2026-10-09。


### 测试阶段增量存档

- 首次建档写入完整快照，后续保存只追加变化字段、物品格与稳定实体 ID 的增改删；没有实际变化时不写文件。普通远征保存不再复制、序列化或逐高度检查初始地形。
- 每条记录包含完整事务边界、序号、身份和摘要；失败保留脏状态，半写尾部可恢复，已完成但返回异常的写入先核对结果，完整记录损坏拒绝继续。基地入口备份恢复同时保留远征归属。
- 新文件位于 `Saves/incremental-v1/`。测试阶段旧格式不迁移、不删除；开始界面提示新建游戏。

### 开始界面手动检查安装包更新

- Android 在线启动后的“检查更新”同时检查资源版本与 APK；资源已经最新但 APK 有新版时，优先显示安装包版本和下载大小。
- 复用既有更新弹窗，玩家选择“立即重启更新”后进入 Boot 下载及系统安装流程，选择稍后后可再次手动检查；开始界面不下载或安装 APK。
- 静默资源检查不重复提示 APK；重复点击复用请求，开始界面离开后不展示晚到结果。Game 代码与中英文语言表可随资源热更新交付；Boot 提示残留与安装交接问题已一起修复，需要新安装包交付，旧客户端须先手动覆盖安装一次。
- 完成时间：2026-10-06。源码、编译及 24 项定向测试已验证，手机画面与重启下载待发布资源后验收。

### 存档名称与槽位规则

- 内容：存档名称具有统一建议名、长度和唯一性规则，创建与重命名由 `SaveSystem` 最终校验。
- 目的：保证不同入口使用相同规则，避免绕过 UI 后写入无效或重名存档。
- 修改简介：
  - 名称先去除首尾空格，不能为空，最多 20 个字符。
  - 名称冲突忽略英文大小写；重命名校验排除当前存档自身。
  - 默认名称按当前本地化前缀匹配已有编号，并使用最大有效编号加一。
  - `SaveId`、存档文件名、地图事务和存档分区格式保持稳定。
- 完成时间：2026-07-29。

### 启动入口与新游戏命名

- 内容：启动界面按真实存档状态显示新游戏、继续和存档入口；新游戏直接打开命名弹窗。
- 目的：减少无意义入口，并让首次进入流程不经过空存档列表。
- 修改简介：
  - 没有任何槽位时只显示新游戏。
  - 只有损坏槽位时显示新游戏和存档，保留处理损坏档的入口。
  - 存在有效槽位时显示继续和存档，不再显示新游戏。
  - 新游戏命名成功后显示 Loading，并沿用统一进入存档流程进入默认地图。
- 完成时间：2026-07-29。

### Boot 到开始界面的连续启动反馈

- 内容：Boot 资源准备完成后继续显示启动覆盖层，并由 Main 初始化流程回报架构、配置和开始界面准备阶段。
- 目的：让 Windows Player 从资源加载到开始界面可见之间持续提供明确反馈，不暴露空场景或部分初始化的 Main UI。
- 修改简介：
  - `GameStart.Awake()` 在架构初始化前回报初始化阶段；异常会停止后续 Start 流程并进入统一失败终态。
  - `GameStart.Start()` 在运行配置和三个启动 UI 边界回报阶段，只有 `StartUICtrl` 非空且实际显示后才回报就绪。
  - 包、Boot 启动信息、运行配置、开始界面和未预期异常统一记录详细技术错误，同时只向玩家显示固定失败提示。
  - 库存 UI 目录同时归属 `startup` 与 `expedition`，由启动下载器提前准备；Boot 将快捷栏、背包、仓库和搜索窗口列为必需地址并校验 Bundle 可用性，避免进入基地同步加载 UI 时才尝试远程下载。修改 Boot 或资源标签后需手动重新打包宿主并发布资源；验证记录位于 `Client/Assets/Tests/Results~/InventoryStartup-20261004/`。
  - 没有活动 Boot `Launcher` 的编辑器直接 Main 路径继续按原有依赖初始化，不因阶段回报返回 false 而中断。
- 完成时间：2026-08-10。

### 开始界面按钮自动补位

- 内容：开始界面的六个入口按钮由同一个纵向布局容器统一排列，条件隐藏后其余可见按钮自动补齐。
- 目的：消除新游戏、继续游戏或存档入口隐藏后留下的固定视觉空位，同时保持既有入口规则不变。
- 修改简介：
  - 六个按钮按新游戏、继续游戏、存档、检查更新、设置、退出的固定顺序作为 `ButtonGroup` 直接子节点。
  - `VerticalLayoutGroup` 统一控制顶部起点、按钮尺寸和间距；Inactive 按钮不占布局位置。
  - 无存档、存在有效存档和仅有损坏存档三种状态均保持既有显隐语义，可见按钮首项位置和相邻间距稳定。
  - `StartUICtrl` 只决定入口显隐，不计算坐标、不调整兄弟顺序，也不为单个按钮维护布局参数。
- 完成时间：2026-08-10。

### Rift2D 风格存档列表

- 内容：存档页采用“新增项 + 真实存档行”的循环列表，并把操作按钮收进每一行。
- 目的：移除顶部输入框和独立新建按钮，保证长列表中的加载、重命名和删除始终可操作。
- 修改简介：
  - 列表索引 0 固定为新增项，真实存档从索引 1 开始。
  - 无真实存档时仍显示新增项，同时隐藏清空按钮。
  - 真实行显示名称、最后保存本地时间和本地化地图名，不显示内部地图 ID。
  - 损坏存档显示红色损坏摘要并禁用加载，仍可重命名或删除。
  - 行内加载、重命名、删除按钮尺寸为 `76×34`，文字使用 `10–14` 自动字号。
- 完成时间：2026-07-29。

### 输入消息用于新建与重命名

- 内容：新建和重命名统一使用通用 Message 输入模式。
- 目的：让输入、确认、取消、留窗校验和错误显示复用现有消息生命周期。
- 修改简介：
  - 新建预填自动生成名称，重命名预填当前名称。
  - 提交失败时弹窗保持打开，并在输入框右下显示红色本地化错误。
  - 输入变化清除旧错误；取消不提交；普通消息不会继承输入状态。
- 完成时间：2026-07-29。

### 配置到达前的玩家生命存档

- 内容：玩家生命由 CombatModel 持久化，并处理新存档早于玩家配置创建的时序。
- 目的：避免新游戏在尚未读取最大生命时把 0 误存为真实死亡生命。
- 修改简介：
  - 分区 ID 为 `another-day.player-health`，版本 4 字段为 `hp`。
  - 新存档在玩家配置到达前使用空生命段表示“尚未初始化”，首次进入地图后按 TbPlayer 最大生命恢复满血。
  - 当前存档显式保存的 `hp: 0` 表示真实 0 生命，不会被改成满血。
  - 配置到达前 CombatModel 不建立玩家战斗记录，也不假设固定最大生命。
- 完成时间：2026-07-30。

### 物品存档版本 2 与旧库存迁移

- 内容：存档版本提升到 2，并把旧的单一测试库存迁移为独立玩家背包和基地仓库。
- 目的：保留已有玩家的基地物资，同时建立长期可扩展的正式物品存档结构。
- 修改简介：
  - 旧 another-day.inventory.testResourceCount 完整转换为仓库中的金属零件，并按每组 20 个从低格号排列。
  - 玩家背包迁移后为空，容量为 12，风险状态为 BaseSafe；仓库初始容量为 40，旧数量超过容量时只在迁移中扩展到完整容纳所需的最小格数。
  - 迁移成功后删除旧库存分区，保留其它存档分区并写入 another-day.player-bag 和 another-day.warehouse。
  - Sections、旧库存分区、旧数量以及新背包和仓库槽位均执行严格类型和范围校验；存在但损坏的数据不能按缺失处理或静默丢弃。
  - SaveFileStore 默认使用正式迁移注册表；迁移失败不返回部分数据，也不覆盖原存档文件。
- 完成时间：2026-07-31。

### 非安全远征存档恢复

- 内容：读档发现玩家背包处于非安全风险状态时，不恢复未完成远征现场，而是进入基地并清空风险背包。
- 目的：在尚未持久化完整地图、敌人、掉落和任务现场前，避免异常退出绕过远征失败规则。
- 修改简介：
  - `EnteringExpedition`、`InExpedition` 和 `RecoveryRequired` 都触发安全恢复。
  - `GameSessionFlowSystem` 使用克隆的提交数据把 `MapContext.MapId` 固定写为基地，不改写调用者传入对象。
  - 基地加载和存档提交后清空玩家背包和武器装备、保留仓库、保存 `BaseSafe`；运行时与持久数据的地图都保持基地。
  - 恢复保存失败时保持已清空背包和装备并进入 `RecoveryRequired`，不能回滚到风险远征地图。
- 完成时间：2026-07-31；装备风险清空于 2026-08-01 补充。

### 武器装备存档与版本 3 迁移

- 内容：武器装备使用独立严格分区，存档版本从 2 提升到 3。
- 目的：使已装备武器与背包物品一样持久化和承担远征风险，同时保持旧存档可连续迁移。
- 修改简介：
  - 分区 ID 为 `another-day.weapon-equipment`，只保存 `meleeWeaponItemId`、`rangedWeaponItemId` 和 `activeSlot`。
  - 空槽固定写 JSON null；读取拒绝空字符串、空白、未知物品、非武器、槽位类别不匹配和空远程槽被激活。空近战槽是合法 Melee 状态并代表非物品拳头。
  - `SaveMigrationRegistry` 增加 2→3 单步迁移，只加入空装备分区，不改背包、仓库、生命、地图和未知分区。
  - 既有“两槽都空且 ActiveSlot=None”数据继续通过校验，Restore 后规范化为 Melee；存在正式武器但 ActiveSlot=None 仍拒绝，新 Capture 的空装备状态写 Melee。
  - 死亡返回或非安全远征读档恢复会在基地地图成功加载后同时清空背包和装备；保存失败进入既有 RecoveryRequired，重试持久化已确定的清空结果。
- 完成时间：2026-08-01 建立版本 3 分区；2026-08-03 完成空近战 Melee 语义兼容。

### 玩家能量、体力存档与条件运行态隔离

- 内容：独立玩家条件分区持久化 Power 和 Tili，并在存档恢复时重置冲刺锁与隐藏结算状态。
- 目的：让能量与体力跨存档保持，同时避免上一存档的伤害小数累计、按键边沿或冲刺等待状态泄漏到新提交存档。
- 修改简介：
  - 分区 ID 为 `another-day.player-condition`，版本 4 字段为 `power` 和 `tili`；二者严格校验有限数值和各自 `[0, Max]` 范围。
  - Restore 和 Reset 恢复保存值或正式默认值，并清除冲刺释放锁、伤害小数累计、重启等待、按键边沿和显示脏标记基线。
  - 运行态修订号、冲刺释放锁和条件系统隐藏累计不写入存档 JSON。
- 完成时间：2026-08-01 建立条件分区；2026-08-04 统一为 Power/Tili 并持久化两项。

### 玩家 MaxHP 与 MoveSpeed 覆盖

- 内容：新增独立玩家属性分区，保存每个存档的 MaxHP 和 MoveSpeed 可空覆盖。
- 目的：让测试指令修改最大生命与移动速度后长期保留，同时维持配置为默认权威。
- 修改简介：
  - 分区 ID 为 `another-day.player-attribute`，字段为可空 `maxHP`、`moveSpeed`；非空值必须分别为正整数和有限正数。
  - 覆盖为空时读取 `TbPlayer.MaxHP` 与 `TbPlayer.MoveSpeed`；执行真实变化的对应指令后保存具体覆盖。
  - 属性事务使用 SaveSystem 运行时快照，异常恢复各存档 Provider、事务前 `dirty/dirtyAt` 及 MoveSpeed 实际运行缓存。
- 完成时间：2026-08-04。

## 3. 总体设计说明

### 3.1 存档身份与显示名称

- `SaveId` 是稳定内部身份，不随玩家重命名变化。
- 玩家名称只用于显示和选择，创建与重命名必须经过 `SaveSystem` 的同一校验入口。
- 默认编号只统计符合当前本地化前缀和正整数格式的名称；自定义名称不参与编号。
- 名称校验失败不得写文件，也不得改变原有存档名称。

### 3.2 启动界面职责

- 启动界面只根据 `hasAnySlot` 和 `hasValidSlot` 决定入口可见性。
- 继续加载最近的有效存档；损坏存档不能成为继续目标。
- 新游戏只负责取得名称并创建默认地图存档，实际进入复用统一 Loading 和地图进入事务。
- 存档入口负责管理已有槽位，不承担首次新游戏命名。
- 开始按钮的顺序、尺寸、起点和间距属于 Prefab 布局职责；Controller 只切换 Active 状态，隐藏入口不得留下占位。

### 3.3 Boot 到 Main 启动交接职责

- Boot `Launcher` 是资源准备和 Main 初始化期间覆盖层的唯一所有者；Game 只能使用阶段、就绪和失败三个窄回报入口。
- Main 初始化顺序保持架构、资源适配与本地化、Boot 启动信息、运行配置、设置应用和启动 UI，不为显示进度重排实际依赖。
- `StartUICtrl` 真正可见是释放 Boot 覆盖层的提交点；无异常但界面不可见仍按启动失败处理。
- Main 初始化失败不提供进程内重试，以免在部分初始化状态下重复执行；Main 场景尚未加载成功时继续使用 Boot 原有重试。
- 编辑器直接进入 Main 时允许没有活动 Launcher，阶段回报失败本身不改变 Main 业务流程。

### 3.4 存档列表职责

- `SaveUICtrl` 保存真实槽位快照，列表数量始终为真实槽位数加一。
- LoopScrollRect 负责元素复用和滚动，Controller 按索引重新填写字段并清理、绑定按钮事件。
- 新增项不是持久存档，不显示时间、重命名或删除。
- 删除和清空使用普通确认消息；新建和重命名使用输入消息。
- 数量变化可以回到顶部；仅名称或语言刷新时应尽量保持当前滚动位置。

### 3.5 玩家可读存档摘要

- 地图摘要通过 `MapCatalog.DisplayNameKey` 和本地化系统解析，不能直接显示 `MapId`。
- 地图不存在或没有显示名 Key 时使用“未知地图”本地化回退。
- 保存时间由 UTC 数据转换为本地时间；当天和昨天使用本地化前缀，同年和跨年使用稳定日期格式。
- 无法解析时间时显示空文本，不向玩家暴露解析错误。

### 3.6 存档版本与物品分区

- 当前存档版本为 4；默认迁移表只保留历史 1→2、2→3，不注册 3→4，因此版本 1～3 旧存档明确拒绝，不部分读取或静默重置。
- PlayerBagModel 和 WarehouseModel 使用不同分区，并共用严格的物品槽位保存合同；WeaponEquipmentModel 使用独立装备分区，只保存正式武器 ItemId 和当前槽。
- 版本 2 迁移到版本 3 时增加空装备分区，不改变已有背包、仓库和未知分区。
- 缺失字段只有在合同明确允许时才能使用空初值；存在但类型错误的数据必须拒绝，不能通过默认值掩盖损坏。
- 迁移只操作存档 JSON 和固定迁移常量，不依赖运行时配置是否已经加载。

### 3.7 玩家条件与属性分区

- `another-day.player-condition/power` 与 `tili` 分别保存当前能量和体力。
- 冲刺耗尽锁定、Shift 按键边沿和能量伤害小数累计只属于当前运行态，不持久化。
- `another-day.player-attribute/maxHP` 与 `moveSpeed` 保存可空配置覆盖；空值回退玩家配置，非法非空值拒绝。
- 版本 4 分区存在但缺少必填条件字段、类型错误、非有限或越界时必须拒绝。
- 同一运行内提交或回滚存档时，System 必须依据 Provider 的恢复修订重建隐藏运行态，不能依赖架构重启。
