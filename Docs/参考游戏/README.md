## 按玩法问题查资料

每代正文分别说明一局如何推进，再查生命与计分、武器和拾取、命运、奖励区域及Boss。研究时应对照同一种模式和阶段：

- **战斗节奏**：区分整轮敌人总量、同屏上限、生成间隔和轮结束条件；它们不能互相推算。
- **本局构筑**：区分临时拾取、命运强化、武器等级、购物升级和主游戏账号进度。
- **奖励与商店**：宝藏房、军械库、挑战、危险区和SlayerMart分别核对，不能因都出现在轮间就共用进入或退出条件。
- **合作与恢复**：逐代核对借命、倒地救援、队伍失败及检查点。原作的检查点开局不等于本项目安全节点保存。
- **通关后**：先确认当前模式是结束本局还是进入下一循环，再比较Boss时机和后续难度。

“确定资料”包含有来源的攻略记录，也保留冲突与具体缺口；不表示已经取得完整游戏数据库、逐帧录像或所有平台的最新参数。各代正文的来源版本与待核实项是后续补查入口。

## 如何判定一条资料

- **官方确认**：开发者／发行方原文能直接支持；仍注明文章时间，不将发售前计划当成当前补丁实测。
- **攻略记录**：作者明确描述的玩法或实测表；注明作者、资料版本、模式，不提高为官方底层合同。
- **历史研究**：仓库曾记录来源与结论，本次未能重新取得对应正文；保留出处，不能冒充本次复核。
- **项目规则**：用户已选定或代码已经实现的取舍，仅属于 FirepowerLoop；写入项目功能文档。
- **待核实**：缺少直接依据、存在冲突或依赖具体补丁的内容，不填补推测数值。

这是一组可持续维护的资料，不是原作完整数据库。不同代、同代不同模式、同模式不同补丁均不能互相替代。官方介绍存在数量口径差异时保留各自日期，不拼出一份虚假的精确清单。

## 维护方式

参考资料每条补充来源链接、文章／攻略日期和适用模式；观察录像还应补时间码。项目功能随已验证的实现分段更新，并分别标记代码接入、默认开放和实际验收状态。不能因为写入设计稿或定向检查通过就写成正式开放、完整通关或真实双端验收通过。

工程历史方案及逐段证据继续保留在 [Docs/Plans](../Plans)，实际实现文件和最新证据由项目功能文档链接。本文不改变现有玩法、发布开关或实施范围。
