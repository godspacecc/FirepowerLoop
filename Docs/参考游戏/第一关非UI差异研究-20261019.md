# 第一关非 UI 差异研究：Dead Ops Arcade 1–4 与 FirepowerLoop

核对日期：2026-10-19。范围是第一次到达的首个竞技场 Island 第1–4轮，以及第三轮奖励房、第四轮离场衔接。FirepowerLoop 的主要比较对象为 **DOA4 Casual 俯视普通新局，分别比较单人及双人**。DOA1、DOA2、DOA3用于历史对照；DOA4 Normal／Hardcore及第一人称另列，不能混用它们的参数。

本文只做资料研究与磁盘源码／配置核对，不修改玩法，不构成后续开发授权。未操作 Unity，未进入 Play，未执行 Unity 测试、生成配置、提交或打包。现有工作区有其他会话改动，本文反映核对时文件内容，不是某个干净提交的运行验收。HUD、界面内容、位置和显示样式由另一会话负责，本文不覆盖。

## 1. 先读结论

当前首岛已经具备四轮专用基础敌群、符合 DOA4 Casual 攻略的单／双人整轮总量、水岸移动限制、第四轮营火、第三轮财宝房和 Babylon／Barrage 分支。不能继续使用早期计划中的“首岛只有32敌人、没有水火规则”描述当前状态。

本次确认的主要差异与实现分歧如下；“确认”指下述源码和来源能够支持，不代表本次实际试玩过。

| 主题 | 核对结果 | 判定 |
| --- | --- | --- |
| 开局火力 | 当前基础武器是18伤害、0.24秒间隔、每次1弹的手枪；DOA4默认是无限弹药 LMG | 已确认差异；射速和击杀耗时未做原作定量对齐 |
| 战斗中换枪 | 单人击杀抽中 TemporaryWeapon 后留空、不重抽；服务端击杀没有该跳过分支 | 已确认单／双人差异；不能写“全项目不掉枪” |
| 水域 | 玩家浅水移速乘0.55；普通敌人移动没有水域系数；单人开火也不因浅水禁用 | 项目事实明确。对DOA1／2的水中敌人减速及玩家禁射存在差异；DOA4敌人水中速度细则待核实 |
| 地图 | 当前四轮分别重建轮廓、障碍与起点；首轮四侧均为较宽浅水 | 项目制作明确；与原作精确几何的差距待实机／原图核对，不能称已逐图复刻 |
| 来敌方向 | 首轮双端都是四向连续轮换；单人第2轮西→东→西、第3／4轮南→北分批；服务器第2–4轮南／北逐个交替 | 已确认单／双人行为分歧；原作方向切换时刻未核定 |
| 休息与推进 | 当前正式轮级流程走实体出口确认；120／300秒通用计时没有控制首岛清场等待 | 对DOA4攻略记载的2／5分钟休息与超时推进存在差异；不是缺少配置值 |
| 财宝房 | 已有第3轮后60秒财宝房，内容固定；入口发现、本人接触和奖励账本为项目规则 | 节点／时长与DOA4攻略基本同向；入口机制、布局和合作离场语义尚未完整对齐 |
| 承伤 | 基础100 HP，普通僵尸10伤害，受击保护0.65秒；未见首岛普通受伤后按时间恢复HP的规则 | 项目参数明确；DOA4 Casual完整承伤／恢复基表不足，不能判定差几个数值 |

## 4. 当前地图与出怪：配置值及实际生效路径

### 4.1 地图不是只读一行CSV

[arcade_round_layout.csv](../../Config/DataCsv/arcade_round_layout.csv)有 `arena.1.round.1` 至 `.4`，各图2处矩形阻挡，特殊敌人、事件、Boss种类均为0；首岛没有配置箱体或预置地面爆桶。[arcade_arena.csv](../../Config/DataCsv/arcade_arena.csv)的首岛后继为2、3。

单人首岛走 `UsesIslandRounds` 特例：`ObstaclesFor`、`StartIslandRound`调用[ArcadeIslandLayout](../../Client/Assets/Game/Scripts/Utility/Arcade/ArcadeIslandLayout.cs)的固定障碍与起点，岸线由[ArcadeIslandRegion](../../Client/Assets/Game/Scripts/Utility/Arcade/ArcadeIslandRegion.cs)按轮号计算。当前固定障碍和CSV值一致，但这两份来源是**两条读取路径**，不能声称单人首岛所有位置都直接由轮级CSV驱动。

双人服务器的 `EffectiveObstacles`、轮级出生／出口读取正式轮布局；`IslandFor`同样按当前轮号创建岸线。参见[单人首岛事务](../../Client/Assets/Game/Scripts/System/Arcade/ArcadeCombatSystem.IslandRounds.cs)、[服务端轮内容](../../Server/GameServer/Runtime/Hotfix/Server/Online/Arcade/OnlineArcadeRunSystem.RoundContent.cs)、[服务端岛岸](../../Server/GameServer/Runtime/Hotfix/Server/Online/Arcade/OnlineArcadeRunSystem.Island.cs)。

首轮轮廓四周水带宽约4.6–4.8米，敌人从外缘向内留半径后出生；后续三轮岸形、水带与阻挡均改变。单人每轮清场后确认出口才重建地图，并回本轮固定起点；不是在同一张未重建地图上自动开下一波。原作“同一竞技场四轮”不等于已证明其网格完全不变，也不等于已证明有当前四张岛形。**原作各轮岸线、礁石、沉船、出生和出口精确对应关系均待核实。**

| 轮次 | 单人当前入口 | 双人服务器当前入口 |
| --- | --- | --- |

两条路径生成后都追踪当前目标并绕障，不存在“必须先走到固定登陆点才开始追人”的阶段。服务器可选择存活玩家目标，单人只有本机玩家／诱饵目标；双人实际夹击压力不能仅用额外50只解释。

## 5. 武器与掉落：表内候选不等于单人可掉

### 5.1 基础手枪与原作LMG

项目基础枪为 `arcade.weapon.basic`，手持资源 `ArcadePistol`，18伤害、0.24秒间隔、单弹、弹速16、寿命1.6秒；实际`TryFire`不消耗弹药、没有弹匣换弹限制。基础敌人20 HP，在无伤害强化、每弹命中且没有其他伤害时通常需两发。这是项目计算，不能反推原作也需两发。

DOA4默认为无限弹药LMG，同枪和Max Ammo可升档；项目虽同样可持续开火，但当前基础枪的攻击类型和火力节奏尚非同一武器配置。[原作S8](https://gamefaqs.gamespot.com/pc/539641-call-of-duty-black-ops-7/faqs/82246/weapon-arsenal)；[项目武器表](../../Config/DataCsv/arcade_weapon.csv)和[TryFire](../../Client/Assets/Game/Scripts/System/Arcade/ArcadeCombatSystem.cs)。

| 护盾／靴子 | 7／8 | 正常生成 | 正常生成 |
| 临时第一人称 | 5 | 可生成，持续20秒，仅首场 | 不在服务端表中 |

单人 `KillEnemy`先将所有合格候选计入权重，再在选中后执行 `if (candidate.Kind == TemporaryWeapon) break`。因此单人总权重98中有20的空结果；不能把这20重新分配给其他物品。服务端 `KillEnemyWithImpact`选中后直接建立掉落实例，没有上述跳过。两端均有掉落机会0.32和场上最多18个物品等前置限制，不能把表中权重当每次击杀的绝对掉率。

单人权威目录确实合并普通掉落和SoloDrop，参见[LubanRuntimeConfigProvider](../../Client/Assets/Game/Scripts/Utility/Config/LubanRuntimeConfigProvider.cs)的 `BuildArcadeSnapshot`构造段；[tables.xml](../../Config/Defines/tables.xml)将SoloDrop限制为`c`组，[gen.bat](../../Config/gen.bat)检查该表不得进入服务器。核对点为[单人KillEnemy](../../Client/Assets/Game/Scripts/System/Arcade/ArcadeCombatSystem.cs)和[服务端KillEnemyWithImpact](../../Server/GameServer/Runtime/Hotfix/Server/Online/Arcade/OnlineArcadeRunSystem.cs)。

这意味着：**默认新单人首岛，不能靠普通击杀捡到两把候选临时枪**。首岛财宝房也没有武器奖励，首岛没有箱体；不能用“军械库可领六枪”来证明第一关有普通换枪体验。军械库是下一实际场第3轮后的独立来源，应用奖励直接调用发奖，不经过击杀跳过逻辑。此结论不涵盖诊断注入、恢复已有武器或未来配置变更。

原作Island攻略明确将移动中拾枪列为基本体验，但没有给出每枪的首岛概率和必出次数。由此可以确认项目单人缺少这条击杀换枪路径，**不能进一步断言原作某轮必掉某枪**。[原作S5](https://gamefaqs.gamespot.com/pc/539641-call-of-duty-black-ops-7/faqs/82246/the-island-1-4)

### 5.3 临时倒计时不等于原作武器能量分级

项目应用临时枪时替换武器ID、将剩余秒数设为条目Duration；`TickTimers`通常按活动时间直接递减，清场拾取等待也消耗，军械库有专门的保留例外。未见红／紫武器等级、重复同枪升档、Max Ammo补能及按射击耗能这一组合同。DOA4同枪／Max Ammo升档见S8；官方Pristine Belt也明确涉及射击时能量消耗。[S10](https://www.callofduty.com/patchnotes/2026/02/call-of-duty-black-ops-7-season-02-patch-notes)

这里只确认机制类别不同；不填原作武器伤害、耗能速度、层级系数或临时时长。商店本局属性强化和武器红紫分级是不同系统，不能互相充当实现证据。

## 6. 移动、水域、伤害与战斗结束

### 6.1 水域同时核对判定、速度与开火

`WaterMinY=-13`是保留的旧兼容阈值；当前海岛用`ArcadeIslandRegion.IsShallow`的内外双轮廓判断浅水，不能简单写成“Y小于-13才减速”。玩家基础移动6.5米/秒，无其他效果时浅水乘0.55，即3.575米/秒；冲刺／靴子另有乘数，仍经过当前岛岸边界与障碍约束。

单人 `TickEnemies/MoveEnemyTowards`、服务端 `TickEnemies/MoveEnemy`都未按敌人坐标施加浅水系数，水陆追击基础速度相同。涉水水花或从水中上岸的表现，不构成水中移动减速的证据。

单人`TryFire`不检查`IsShallow`，所以水中仍可开火；没有一／二代攻略所述禁射。DOA4的S5仅明确玩家水中减速，未明确敌人减速或玩家禁射，不能因一／二代记载而认定当前违反四代规则。深水游泳、溺水、海域离场和载具入水也没有在当前首岛普通路径中形成独立规则。

代码：[单人TickPlayer／TryFire／MoveEnemyTowards](../../Client/Assets/Game/Scripts/System/Arcade/ArcadeCombatSystem.cs)、[服务端玩家与敌人移动](../../Server/GameServer/Runtime/Hotfix/Server/Online/Arcade/OnlineArcadeRunSystem.cs)、[双轮廓](../../Client/Assets/Game/Scripts/Utility/Arcade/ArcadeIslandRegion.cs)。

### 6.2 营火已经有伤害，精确参数仍是项目值

首岛第4轮活动战斗启用营火，中心(4,3)、半径1.3、每0.8秒尝试造成12伤害，接触按火圈半径加玩家半径判断；单人有约0.65秒初始营火预告。伤害经过护盾、冲刺、复活与无敌保护，清场及房间／复活阶段不照常扣火伤。服务端同样调用权威伤害入口，但未执行单人这段营火预告门禁。

原作只确认第4轮营火持续灼烧，坐标、半径、伤害频率、是否同样伤敌以及单／双人预告均待核实；不将项目值标成原作还原参数。依据：[原作S5](https://gamefaqs.gamespot.com/pc/539641-call-of-duty-black-ops-7/faqs/82246/the-island-1-4)、[arena配置](../../Config/DataCsv/arcade_arena.csv)、[单人火伤](../../Client/Assets/Game/Scripts/System/Arcade/ArcadeCombatSystem.Opening.cs)、[服务端火伤](../../Server/GameServer/Runtime/Hotfix/Server/Online/Arcade/OnlineArcadeRunSystem.Opening.cs)。

### 6.3 清场、受伤与资源的边界

当前普通轮需要生成队列耗尽且场上敌人清空才判清场；第3轮还须走完已配置奖励房。未见首岛普通轮通过“存活固定时长后敌人自动消失”结束，也未找到按长期零击杀触发加速敌人的首岛规则。S9有反拖延加速敌人的作者观察，但首岛适用性、触发时间和模式未核定，**仅列待验证差异，不据此新增反拖延系统**。

基础玩家100 HP；普通接触10伤害、0.65秒保护、付命后1.5秒复起。这是一套血量累积承伤规则。检查正常计时与受伤入口，未见默认首岛普通受伤后延迟自动回血；不能将“复活补满”“新现场初始化”或商店护甲挡伤称为自然回血。DOA4 Casual的精确承伤、回血延迟、第一人称与俯视差别尚缺完整可信参数，因此不估算原作命中次数或恢复秒数。

开局3命、1炸弹、2冲刺。新普通轮只将零炸弹／零冲刺补到1，非零不额外增加，持有上限9。这与S9描述的基础补空方向一致。DOA1／2的特殊补足、命运保底不用于覆盖本项目。

首岛普通击杀100×当前倍率，击杀不直接增长财宝倍率进度；财宝领取先按旧倍率计分，再增长进度，每累计20万分跨档加命、上限9。死亡倍率重置到1。当前没有从本局得分向局外成长钱包发奖的路径声明。数值来自[财宝配置](../../Config/DataCsv/arcade_treasure_room.csv)与[ArcadeTreasureScoreRules](../../Client/Assets/Game/Scripts/Utility/Arcade/ArcadeTreasureRoomRules.cs)，不能由原作存在倍率系统推导二者精确公式相同。

## 7. 第三轮房间、清场休息与双人流程

### 7.1 第三轮后的财宝房

DOA4具体表项将Island第3轮后列为Poppy’s Pirate Plunder，一般收集窗口60秒；合作奖励区域离场要求至少半队承诺。[S7](https://gamefaqs.gamespot.com/pc/539641-call-of-duty-black-ops-7/faqs/82246/bonus-rooms-areas)

项目首岛第3轮财宝房为固定12金条、4宝石、1炸弹、1冲刺，60秒；金条100分／进度、宝石250分／进度。没有本房武器。需要靠近发现，清敌后本人再次接触入口才进入；清完敌人还没进入／完成房间时，普通下一轮出口不开放。单人离房直接准备第4图，保存轮前状态；不是先回第3图再等120秒。

双人共享房间实例、奖励账本和时钟，各人自己接触入口进入，领取归当前玩家；不能将每人看到同一件物品写成各领一份。当前服务端允许个人离房，`room.Members`仍非空时普通出口确认被阻止；房间结束后再推进。该行为与原作“半队共同离场”未建立完整对应。对**两人**而言半队也可能是一人，不能仅凭措辞认定数量门槛不同，应实测是否一人离开就带走全队、如何处理未入房者和倒地者。

配置和调用：[宝藏房源](../../Config/DataCsv/arcade_treasure_room.csv)、[单人TickTreasureRoom／ReturnFromTreasure](../../Client/Assets/Game/Scripts/System/Arcade/ArcadeCombatSystem.Treasure.cs)、[服务端财宝房](../../Server/GameServer/Runtime/Hotfix/Server/Online/Arcade/OnlineArcadeRunSystem.Treasure.cs)、[共享房间状态](../../Client/Assets/Game/Scripts/Utility/Arcade/ArcadeTreasureRoomRules.cs)。入口坐标与收集价值是项目数值，原作精确房型与物品数未核。

### 7.2 120／300秒为何不能当当前首岛行为

`arcade_arena.csv`首岛确有 `RoundRestSeconds=120`、`ExitRestSeconds=300`。但正式单人Casual首岛同时满足 `UsesRoundLayouts`与`UsesIslandRounds`：

1. `TickWaveTransition`在首岛分支直接将剩余过渡时间置0；第1／2轮置`IslandRoundAwaitingExit`，第4轮置`AwaitingExit`并返回。
2. 后续`UsesRoundLayouts`门禁跳过旧波次倒计时。
3. `Tick`在`AwaitingExit`中只有`!UsesRoundLayouts`才递减场末超时，首岛不进入该分支。
4. `TickIslandExit`接触出口后提交确认；第1／2轮确认后`StartIslandRound`，第3轮由奖励房返回启动第4轮，第4轮确认后选场结算。

因此在保持活动、不暂停、不处于其他失败流程的前提下，当前首岛可以留在清场状态超过这些通用时限；不能靠表内120／300证明已实现自动推进。此处描述出口确认对推进的业务影响，不评价确认窗口的UI样式。

服务器也有轮级出口路径：`TryAdvanceWave`清场后置`AwaitingExit`，后续活动帧进入`TickRoundExit`等待确认意图；`TryAdvanceWave`开头排除`AwaitingExit`，没有在这条路径上兑现旧休整计时。因此这不是单人独有的配置缺失，而是当前轮级正式流程共同绕过通用计时；双人还需要全员当前地图代次就绪。

原作S6给出普通轮2分钟、场末5分钟并有强制自动推进，构成可比较的流程差异；具体倒计时何时开始、奖励房是否中止／重置、何种操作提前结束还需原作录像核验。[S6](https://gamefaqs.gamespot.com/pc/539641-call-of-duty-black-ops-7/faqs/82246/faqs)
