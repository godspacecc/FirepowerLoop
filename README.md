# FirepowerLoop

低多边形风格的俯视角僵尸生存射击游戏。当前主菜单的“开始游戏”进入角色选择，再进入幸存者模式：角色自动射击，玩家在敌人围攻下生存、收集掉落并选择本局强化。界面显示生存时间、生命、金币和三个武器槽；死亡后可再来一局或返回主菜单。

## 当前可玩内容

- 主菜单提供开始游戏、商店、设置和退出；选角界面提供免费默认主角及可解锁外观。
- 幸存者模式包含经验升级、强化选择和支援武器。本局强化与角色购买是不同机制：金币余额、已购买角色和上次选择会保存在本项目的本地存档中。
- 闯关、经典挑战与双人联机仍保留相关实现，通过内部测试入口检查；它们不是当前主菜单向玩家开放的模式，也不代表已经完成发布验收。
- 不提供基地、远征、撤离、搜刮背包、仓库或制造玩法，不读取或迁移 AnotherDay 玩家数据。

## 开发与启动

- Unity 工程：`Client`。打开该目录后使用 `Assets/Game/Scenes/Boot.unity` 启动。
- 预览及验证资料：[Backup/Artifacts](Backup/Artifacts/)，存放于 Unity 工程外；目录用途见[备用资料说明](Backup/README.md)。
- 配置源：`Config/Defines`、`Config/DataCsv`；唯一生成入口：`Config/gen.bat`。
- 协议源：`Config/Proto`；生成入口：`Tools/gen-protocol.ps1`。
- 游戏服务：`Server/GameServer`，本地 GameGate 默认 `31011`，诊断服务 `31012`。
- 资源发布：本项目 `Server/ResourceServer/ResourceFiles`；默认资源服务 `8001`。
- 资源准备：进入玩法时按对应范围检查和准备资源，幸存者、闯关与经典挑战使用不同资源标签；资源不足或准备失败时不能直接进入战斗。不能把 EditorSimulateMode 中可运行等同于发布包资源已经齐备。
- 发布模式：`FIREPOWERLOOP_OFFLINE_SINGLE_PLAYER` 控制纯离线单人发布策略，隐藏联机及更新入口；未启用此标记的编辑器／内部候选版本保留更新相关功能。
- Android 增量更新：首包保存 Boot 内容指纹；Boot 代码、资源或启动场景变化后，“Host代码+资源更新”会在切换平台与编译发布前停止，必须重新执行“首包完整打包”并安装新 APK。旧首包记录没有指纹时同样需要重新打首包。
- 应用标识：`com.firepowerloop.game`；产品名：`FirepowerLoop`，存档使用本应用的 persistentDataPath，不扫描旧项目。
- 游戏版本与 YooAsset 资源版本分别维护；具体发布版本以当前工程配置和发布台账为准，不以本说明中的历史版本为准。

## 维护与验证边界

`Docs/Plans` 中街机工作材料是历史上下文，是否完成以当前代码和验证记录为准。从复制工程保留的公共代码、配置与工具按本项目分别维护，不自动同步另一工程。搜打撤任务不属于本项目路线图。

旧美术资源、场景和 UI 序列化 View 按资源保留约定留存；文件存在不代表该内容仍由当前入口加载或向玩家开放。当前玩法与进度见[执行总清单](Docs/Plans/执行总清单.md)，判断运行行为时仍须核对实际入口、配置和加载实例。

配置由唯一入口双端生成，不手改生成代码或 bytes。协议变更后客户端与服务端需同步生成和更新；不导入或迁移 AnotherDay 玩家数据。

本次核对为 Unity 编辑器内的短流程，不代表连续整局、双人实机对局或发布包验收通过。Unity Player 打包由用户手动执行。复制的旧热更新 DLL 不作为本项目可发布产物，发布前必须由正式流程重新生成。
