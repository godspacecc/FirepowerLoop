# Windows 电脑—安卓同 Wi-Fi 联机部署说明

## 适用范围

本说明用于一台 Windows 电脑运行 FirepowerLoop `OnlineLocal` 联机服务器、安卓手机通过同一 Wi-Fi 连接的测试部署。一次启动同时运行 GameGate TCP `31011` 和诊断 HTTP `31012`；此方案不用于公网暴露。

## 一、发布并启动服务器

源码设备可双击 `Publish-win-x64.bat`，也可在 Unity 使用 `Tools/游戏服务器/生成联机服务器包`。生成结果位于 `Publish/win-x64/`。先在独立临时目录生成并检查，再替换程序、配置和启动工具，保留正式目录的运行数据；生成本身不会上传或启动服务器。更新已有部署前请停止使用该目录的服务器。

生成失败看窗口结果：替换前失败不改旧包；替换失败会尝试恢复并按文件哈希核对旧产物。若提示无法确认恢复，保留 `Publish/.win-x64-backup-<批次>/` 和 `.win-x64-new-<批次>/`，先核对备份中的 `recovery-info.json` 与正式包，完成恢复后再清理备份、重试。不要在恢复未确认时启动正式包或删除备份。强制关窗留下备份时，下一次生成会拒绝覆盖。成功但备份清理失败时，新包已通过检查，按提示核对后手动清理备份即可。

把整个 `win-x64` 目录复制到目标 Windows 电脑，不要只复制 `Bin`。目标电脑需安装 .NET 8 Runtime。双击根目录的 `启动联机服务器.bat`，窗口应显示：

- `GameGate 监听: 0.0.0.0:31011`
- `本机客户端联机地址: 127.0.0.1:31011`（仅供服务器电脑上的客户端）
- 一个或多个 `局域网客户端联机地址: <局域网 IPv4>:31011`（供同一局域网的手机或其它电脑）
- `服务器进程已启动`

保持此窗口开启。按 `R` 可重启；按 `Ctrl+C` 或关闭窗口会停止该窗口拥有的服务器进程。

复制 `IP:端口` 到客户端“设置 → 网络 → 联机服务器”，或 `networkConfig.json` 的 `gameGateEndpoint`，不要加 `http://`。多网卡地址是候选，请选择与客户端同一局域网的地址；资源服务器配置则使用资源服窗口打印的 HTTP 根地址。

## 二、允许 Windows 防火墙入站

推荐先把当前 Wi-Fi 设置为 Windows“专用网络”。在“Windows 安全中心 → 防火墙和网络保护 → 高级设置 → 入站规则”中新建规则：

- 规则类型：端口
- 协议：TCP
- 特定本地端口：`31011,31012`（分别用于联机和错误统计）
- 操作：允许连接
- 配置文件：仅勾选“专用”
- 名称：`FirepowerLoop 联机与诊断 31011-31012`

不要为公用网络开放此规则，也不要在路由器上配置端口转发。停用部署时可在同一界面禁用或删除该规则。

## 三、打包安卓客户端

在源码设备上找到 `Client/Assets/StreamingAssets/networkConfig.json`，把 `gameGateEndpoint` 改成服务器窗口显示的局域网地址，例如：

```json
{
  "gameGateEndpoint": "192.168.1.20:31011"
}
```

该文件只提供首次打开联机界面时的初始值；玩家可在未登录状态填写并保存服务器窗口显示的 `host:port`，后续启动会优先使用玩家保存的地址。因此电脑 IP 变化时无需重新打包 APK。

然后在 Unity 中执行以下任一入口：

- `Tools/打包/Android/完整打包`
- `Tools/打包/Android/启动包（首次下载资源）`

构建批次目录会同时生成 APK 和 `安卓联机玩家说明.md`，交付时请一起发送给玩家。Host 基础包还需把 `hostConfig.json` 的资源服务器地址配置为手机可访问的 HTTP/HTTPS 地址，这与 GameGate 的 TCP 地址是两个独立配置。

## 四、部署验收

1. 电脑和手机连接同一 Wi-Fi。
2. 电脑启动服务器，记录窗口显示的安卓地址。
3. 在手机联机界面保存该地址、端口。
4. 手机安装 APK，注册或登录，并创建或加入房间。
5. 至少完成一次双设备进入同一房间；服务器窗口与日志中不应出现连接异常。

若电脑 IP 因 DHCP 发生变化，让玩家在退出登录后保存新地址即可。仍建议在路由器中为服务器电脑设置 DHCP 地址保留，减少重复配置。

## 诊断统计入口

`OnlineLocal` 另开 HTTP `31012` 接收匿名程序错误统计，与 GameGate 的 `31011` 独立。Windows 服务账号必须预先有 `http://*:31012/` 的 URL ACL，否则 RouterManager 无法监听。本地启动器会在启动前检查并提示。部署管理员可在管理员 PowerShell 中为实际运行账号执行：

```powershell
netsh http add urlacl url=http://*:31012/ user="电脑名\运行账号"
```

这是 Windows 的 HTTP 监听权限，不是防火墙放行；请按实际账号替换示例值。运行数据位于发布根 `Store/Diagnostics`，重新发布不会删除它。只读聚合命令是 `Tools/get-diagnostic-stats.ps1`。

仓库自带 `Client/Assets/StreamingAssets/diagnosticConfig.json` 使用 `{"mode":"LocalGameServer","reportUrl":""}`，用于同一 Wi-Fi 的电脑—手机测试。客户端优先读取玩家已保存的联机地址，没有覆盖时读取包内 `networkConfig.json`，自动使用同一电脑的 `http://<IP>:31012/diagnostics/errors`。只接受 10/8、172.16/12、192.168/16 内网 IPv4 和 127/8 回环地址；不接受公网 IP 或域名使用此 HTTP 模式。保存或重置联机地址会刷新诊断目标；上报无需登录，也不读取资源服务器地址。

服务器启动正常且防火墙允许 31012 后，客户端会自动补传最多保留 7 天的统计。旧 APK 仍需由打包者重新打包并覆盖安装；覆盖安装须保持同一应用标识与签名且保留应用数据，卸载、清除应用数据或清理待上传记录会删除队列。Boot 发送器属于稳定程序集，不能只更新 Game 热更 DLL 代替新 APK。Android 项目当前已配置允许 HTTP 请求。

客户端的“设置 → 网络”提供“立即上传”：点击后跳过自动重试等待，按每批最多 20 组连续补传，上传期间按钮禁用。页面显示剩余组数、上传结果、实际上传地址、最近尝试时间以及失败后的下一次自动重试时间。连接失败、超时、HTTP 状态码、无效配置和本机存储失败分别提示；失败不会删除待上传批次，只有服务器返回 200 且本机确认持久化成功才扣减。关闭设置页不会取消上传，无需联机登录。该入口仍只发送匿名错误统计，不发送完整本地日志。

公网发版前将诊断配置改为 `{"mode":"Fixed","reportUrl":"https://实际诊断域名/diagnostics/errors"}`，该模式不随玩家编辑的联机地址变化；旧版未填写 mode 的配置仍按固定地址处理。服务器诊断处理器目前仅对 `OnlineLocal` 启用，改用其它配置部署前需重新评估。

公网入口应由受控反向代理终止 HTTPS，代理覆盖并发送单值 `X-Real-IP`，限制请求体不超过 16 KiB；服务端显式设置 `DiagnosticTrustedProxyIp` 为代理来源 IP 才采信该头。防火墙应只允许该代理访问源站 `31012`，不要将源站 HTTP 端口直接暴露给公网。上述代理和防火墙规则需由部署管理员配置与验收。
