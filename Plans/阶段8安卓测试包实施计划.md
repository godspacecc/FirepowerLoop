# 阶段 8 安卓测试包实施计划

## 实际基线

- Unity 为 `2022.3.55f1c1`，Android Build Support 可被 Unity 识别；内置 SDK、NDK、OpenJDK 目录均存在。
- 当前构建入口集中在 `Assets/Editor/Build/BuildUtility.cs`，Windows 构建状态写入 `BuildStateStore`。
- `HybridCLRBuildUtility` 已按 `BuildTarget` 接收目标平台；`YooAssetBuildUtility` 按当前激活平台构建。
- 实施前激活平台仍为 `StandaloneWindows64`；Android PlayerSettings 为 Mono、ARMv7、允许竖屏，与确认设计不一致。
- `YooAssetBuildUtility.cs` 存在未提交的 Prefab 材质校验改动，本次保留该改动。

## 实施步骤

1. 新增独立 `AndroidBuildUtility` 与菜单 `Tools/打包/Android/最新代码资源完整打包`，不改现有 Windows 菜单及状态。
2. 前置校验 Android 模块和内置工具链目录、激活平台、Boot 场景、IL2CPP、ARM64、包名、横屏和调试签名。
3. 依次执行 Android HybridCLR 构建前生成、临时 APK、构建后生成、DLL 复制校验、Android YooAsset 完整内置资源、最终 APK。
4. 最终 APK 固定使用 Development、关闭 Script Debugging/Profiler、APK、LZ4；调用结束恢复这些临时编辑器选项。
5. 使用独立本次临时目录和 `Build/Android/yyyyMMdd_HHmmss/AnotherDay-test.apk`；失败时仅删除本次临时目录与未完成批次，不写 Windows 构建状态。
6. 通过 Unity API 持久修正 Android PlayerSettings 为确认配置；先在 Windows 激活平台验证失败分支，再在菜单外切换 Android 平台执行完整构建。

## 验证边界

- 验证 Unity 编译、前置失败分支、Android HybridCLR/AOT、YooAsset 完整内置资源、BuildReport 和非空 APK。
- 不运行 PlayMode 或全量 EditMode 测试，不执行 Windows/Host/资源服务器流程。
- Shader、原生依赖、刘海/圆角/导航区和后台恢复只能由最终 APK 与 ARM64 真机检查确认；未执行前不记为通过。
